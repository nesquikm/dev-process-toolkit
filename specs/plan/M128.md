# Implementation Plan

## M128 — Driver Verdict Integrity {#M128}

**Goal:** Close the two 2026-08-16 driver-level findings so a capture-only conformance run can produce its own deliverable, and so every leg's roster is machine-readable in the documented spelling.

**Prerequisites:** M127 merged. No hard coupling — the ordering is the program's serial invariant, not a dependency.

**Release target:** v2.66.2 (provisional; patch — dogfood-only)

**Migration:** `none` — the changed surface is `.claude/skills/conformance-loop/SKILL.md` and the per-leg findings-file rendering; neither ships in a consumer artifact.

### Notes

- **This is a design collision, not a typo.** STE-420 made the exit code carry the verdict; the pre-existing gate treats any non-zero as a crashed subprocess. Both decisions were correct when made. Grepping for `64`, `RC_VERDICT`, and `declared` across both driver SKILLs returns only prose — there is no carve-out anywhere, and § RC collection states the abort-on-any-non-zero shape as deliberate.
- **It has already recurred once.** The 2026-08-01 run recorded the same lesson — "rc=64 is a findings verdict, NOT a crash — read trigger declared" — and it was not fixed. AC-STE-490.6 puts the recurrence in the record rather than smoothing it over.
- **How the 2026-08-16 run coped.** The operator did not let the gate abort; each leg was graded off the corroborating evidence the skill itself names as authoritative — the verdict artifact's declared trigger, the leg-completeness check (all three legs 6/6 captures present, non-empty, fresh, result-bearing), and a clean orphan scan. The deviation was recorded rather than hidden behind a green report.
- **STE-491 is preventive.** No automated consumer depended on the roster spelling at the time of the fix. It is filed because zero matches for the documented spelling is indistinguishable from a leg that skipped the roster entirely — the same silent-skip shape the toolkit treats as worse than a loud failure.

### Deviations — ACs that were not literally satisfiable, both sides named

Three of STE-491's clauses could not be met as written. Each was implemented on the satisfiable reading and both readings are recorded here rather than absorbed into the difference.

- **AC-STE-491.3 / task 5 — "one statement, not two" undercounts the duplication by eleven.** *As written:* the spelling is stated twice, generally and inside group 12's contract, so reconciling group 12 leaves one statement. *As measured:* `grep -c 'runtime check:'` on the shipped SKILL returns **fourteen** — the general statement plus **all thirteen** fixture-group footers, each spelling `STE-<sut> runtime check: <LABEL>` inline; seven footers additionally restate the general rule's NOT-REACHED / N/A semantics, five in the operative wording "rather than nothing at all". Group 12 was singled out only because two shipped suites (`m124-ste-467`, `m117-ste-425`) read its PASS/FAIL literals. *Shipped:* the rule is now stated once normatively in § Phase 3 — Capture, § Phase 2.X's bullet and group 12's footer both defer to it in one shared idiom, and the audit confirmed by mutation that exactly one section satisfies the "states the rule" predicate. *Residual, stated plainly:* 1 of 13 footers reconciled, 12 still spell the token inline, 6 of the 7 semantic restatements survive. The AC is satisfied under its own three-conjunct definition of "statement" — a definition under which the twelve footers were never statements — not by reconciling them. The FR's Technical Design has been corrected in place to say so.
- **AC-STE-491.2 / task 6 — the named artifact does not exist and cannot.** *As written:* assert one match per rostered group "against archived findings files from all three legs". *As measured:* no findings file is ever committed — they live at `/tmp/dpt-smoke-findings-<date>-<tracker>.md`, are LLM-rendered per run, and `find` returns zero in-repo. *Shipped:* the assertion runs against the authority module's real per-leg output (`smoke_fixture_groups.ts render --leg …`) for all three legs with the group count derived from the roster, paired with four discriminators — a compact `·`-joined rendering, a compact line containing `runtime check:` once, a roster short by one group, and an unrecognized label. The FR's Testing section has been corrected in place.
- **AC-STE-491.2 is PRESERVATION, and the audit measured it rather than assuming it.** Restoring the pre-change SKILL and FR in a scratch mirror and running the shipped test gives 17 pass / 12 fail — 6 red in AC.1, 3 in AC.3, 3 in AC.4, and **zero in AC.2**. The renderer already emitted one canonical line per rostered group on every leg, jira included, before a byte of M128 landed; `smoke_fixture_groups.ts` is untouched by this milestone. The four discriminators falsify the *check function* (mutating the renderer in scratch reds 8 AC.2 tests), not the delivery — none of them could have been red on the pre-change tree. AC.2's stated subject is a **leg**, and the compaction was never a renderer output but what hand-tallying produces when a leg does not run the module; no in-repo assertion can reach that subject. The shipped work that actually addresses AC.2 is § Phase 3's "produced, not typed" prose — which is AC.1's deliverable. Recorded as Partial by the audit and not upgraded here.

### Advisory findings carried out of implementation

- **The RC fence's outer three-way guard is semantically dead.** `[ "${RC_LINEAR}" -ne 0 ] || [ "${RC_JIRA}" -ne 0 ] || [ "${RC_NONE}" -ne 0 ]` wraps the per-leg classification loop, but every `RC_*` is pre-defaulted to 0 and normalized before it and the loop's own `[ "${LEG_RC}" -ne 0 ] || continue` already skips clean legs. Confirmed empirically: replacing the guard with `if true` changed zero of four fence outcomes. It survives as a short-circuit and as the only line satisfying `tests/conformance-loop-aggregator.test.ts:71`'s 80-character proximity pin. It does **not** weaken any STE-490 AC — the real decision path is independently killed by two other mutations — but see the follow-up below.
- **The fence hardcodes the literal `64` and the leg list `linear jira none`.** Both are second copies of values the modules own (`RC_VERDICT_NON_PASS`; `SMOKE_LEGS`). Both are defence-in-depth rather than the decision: `classifyLegRc` independently rejects every non-64 code (removing the shell guard still aborts at 65 and 137), and the `EXAMINED_LEGS`/`SELECTED_COUNT` accounting guard immediately above aborts on any selected token that is not one of the three, so a fourth registered leg can never reach the loop silently.
- **AC-STE-490.4's offender filter is word-level, not clause-level.** It exempts any line matching `/64|declared|classif/i`, and on the pre-change tree the second flat statement already escaped it on the unrelated phrase "both legs declared failure in prose" — so one candidate survived, not two. The test is still genuinely RED before the fix (the § opener survives the filter), so AC.4 is closed; the comment overstating it has been corrected in place.
