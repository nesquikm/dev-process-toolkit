### Notes

- **This is a design collision, not a typo.** STE-420 made the exit code carry the verdict; the pre-existing gate treats any non-zero as a crashed subprocess. Both decisions were correct when made. Grepping for `64`, `RC_VERDICT`, and `declared` across both driver SKILLs returns only prose — there is no carve-out anywhere, and § RC collection states the abort-on-any-non-zero shape as deliberate.
- **It has already recurred once.** The 2026-08-01 run recorded the same lesson — "rc=64 is a findings verdict, NOT a crash — read trigger declared" — and it was not fixed. AC-STE-490.6 puts the recurrence in the record rather than smoothing it over.
- **How the 2026-08-16 run coped.** The operator did not let the gate abort; each leg was graded off the corroborating evidence the skill itself names as authoritative — the verdict artifact's declared trigger, the leg-completeness check (all three legs 6/6 captures present, non-empty, fresh, result-bearing), and a clean orphan scan. The deviation was recorded rather than hidden behind a green report.
- **STE-491 is preventive.** No automated consumer depended on the roster spelling at the time of the fix. It is filed because zero matches for the documented spelling is indistinguishable from a leg that skipped the roster entirely — the same silent-skip shape the toolkit treats as worse than a loud failure.
