# Implementation Plan

## M_c46877 — Each run records what it ran under {#M_c46877}

**Goal:** Milestone B of the self-tuning settings work: instruments only, no new knob. Each toolkit run records the settings it started under. Token rows are claimed by the FR whose run produced them, forked children included. The trend reports one row per (FR, skill) with its own quality signals. A settings change leaves a receipt that a revert is checked against. TDD rounds record whether they changed a file (STE-795). Nothing here changes a setting, a default or a gate.

**Prerequisites:** v3.6.2 on main (8f0d892a). PR #137 ships v3.7.0 separately; whichever lands second rebases.

**Release target:** v3.8.0, a minor: six Added FRs, one Changed FR and one Fixed FR.

**Design:** the approved 2026-11-16 brainstorm, "B — instruments", as amended by the 4-reviewer pass (all amendments adopted by the operator). Gate policy for this run is delegated in the kickoff: spec approval, plan freeze, FR commits, the release and the PR are approved by the worker.

**Decisions.**

- Settings are keyed by skill only; size and category stay report columns, never a settings key.
- The snapshot is taken at run START (a PreToolUse hook on the Skill tool and the UserPromptSubmit route), not in the SessionEnd/Stop ledger hook.
- The snapshot is gated on ANY `tracking.<name>.enabled` being true, not on `token_stats` alone, so a sibling repo with token stats off still records it when another switch is on. A tree with every switch off records nothing.
- Privacy: the snapshot holds the `PROPOSABLE_SETTINGS` keys only, plus the plugin version and the capture registration state.
- STE-795: TDD rounds record tree changes from the round's claimed `files:` list, labelled `claimed`. A measured per-round git diff needs a tree snapshot at both edges of a background fork, which nothing takes today. The reasons are in STE-795's Notes.
- Fork-child tokens join on undocumented Claude Code internals (`subagents/agent-*.forked-skill.json` plus the parent Skill result's `agentId`), so the join fails open and is pinned with a fixture. Totals are incomplete while a child still runs, and the rows say so.
- Out of scope: milestone C (trials, the trial engine, the effort knob), the optional `review_findings` proposable row and its "trial precondition unmet" trigger (item 7, deferred to C because it only matters once a trial exists), and the `requires_explicit_approval` audit of migration entries (a C safety item). STE-798..809 stay as filed.

**Migration:** none. Every new file lives under the git-ignored `.dpt/` tree. The hooks ship in the plugin's own hooks.json, and no consumer artifact changes shape.
