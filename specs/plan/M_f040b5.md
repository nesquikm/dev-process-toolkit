### Why F4 is first

`push_ac_toggle` was withheld on a green gate with a Done ticket, and four acceptance criteria never toggled. The branch read `feat/m_b11423-greet-helper`: the default template is `{type}/m{N}-{slug}`, and under tracker-first minting `{N}` renders `M_<6-hex>`, so Tier-1 branch-regex resolution finds no ticket id and Tier-2 needs a human. The template and the resolver disagree by construction on every Linear project using the defaults, which makes an already-shipped feature unreachable rather than merely awkward.

### What made F1 and F2 findable

Neither leg could see it. Different groups, different probes, different legs — only aggregation across both put them side by side, and the none leg records it as the fourth occurrence of the class. The diagnosis came from a contrast rather than from a failure: sub-fixture 3c keys on the probe **name** instead of a bold marker and passed on the same runtime that failed the others. An assertion pinned to how something renders dies the day the rendering is standardised, and says nothing about whether the subject is healthy.

### Measured corrections to this plan

Recorded because each one changed the work rather than merely annotating it.

**The tracker allocation was intended, not created.** The three FR ids in the table above were written as the intended allocation. They were verified against Linear before use: the milestone rename HAD applied, and no FR ticket existed. STE-563/564/565 were then created and read back — the allocator returned exactly those numbers, so the plan needed no substitution. One create reported a TIMEOUT and had in fact LANDED; find-before-create caught it and a blind retry would have minted a duplicate.

**F9 has a second face, and it fails OPEN.** Giving the termination harness its second shell immediately surfaced a defect beyond the accounting guard: with the green probe's missing-findings guard stripped, bash leaves the status unset while zsh reports `green`. The "fail-closed by luck" the suite recorded is BASH-ONLY luck. On the shell an agent actually runs, that guard is the only thing between a missing findings file and a green verdict. Measured per shell and recorded rather than averaged away.

**Two shipped checks graded a spelling rather than a subject — the milestone's own class, arriving twice in its own work.** `conformance-loop-dry-run` required the literal `Bun.spawnSync` as proof that a cited file "executes something", and red on two files that now execute strictly more. A pin in the rc-verdict suite fired on the rationale COMMENT quoting the expression it retired. Both were widened to their properties, the second anchored on the assignment so an explanation may still be written down.

**2b's clause changed KIND, and the falsifiability harness cannot express the new one.** Group 2b's discriminating clause is now an ABSENCE. That harness models falsifiability as REMOVING a subject and requiring failure; removal makes an absence MORE satisfied, and `classifyMutation` scores the inverse mutation `rewording-only` and refuses it. The registry row therefore scores 2b's identifier clause — which is removal-falsifiable — and 2b's discrimination is measured in both directions in the STE-564 suite. Stated in the registry rather than glossed. Teaching the harness an injection class is a follow-up.

**A measured roster moved.** `harness_artifact_paths` left the entry-point-with-no-importer class because `fixture_arm_subject` now imports it. It stays reachable under both halves of the rule; only the boundary membership changed, so the roster was edited as the measurement it is.

**The briefed baseline was wrong by one in two places.** The kickoff stated 11890 pass / 15 skip at `fdb0c9e`. Measured by running the suite at that state: 11889 pass / 16 skip / 0 fail, 11905 tests across 543 files. Re-measured rather than recited, so the skip delta reads 0 rather than a phantom +1.

**A shipped guard forbids the accurate tier count.** `cross_skill_contract_drift` blocks the strings `3-tier ticket-binding` and `3-tier resolver`, and five surfaces are pinned to carry `2-tier ticket-binding resolver`. The new tier is therefore Tier 1b, an arm of Tier 1 rather than a third tier — which is also the truthful description: both arms resolve from the branch name with no question asked, and Tier 2 remains the only tier that involves a human.
