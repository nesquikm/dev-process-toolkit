# Implementation Plan

## M136 — The Ratchet That Never Ran {#M136}

**Goal:** Make M132's skip ratchet execute. Its read side runs at step 14 of every `/implement` and treats an absent baseline as a refusal ground; its write side has never fired once in this repository. Two independent gates stand in front of the only caller — an optional `branch_template:` key this project does not set, and a `git checkout -b` an already-acceptable branch never performs — and the capture point they guard is wrong anyway, because `/spec-write` cuts the branch AFTER writing the FR files. This milestone re-chooses the capture point, gives the capture an order that always fires, replaces the scalar comparison with a named one, and makes an unmeasurable baseline refusable with a command the reader can run.

**Prerequisites:** M135 merged (v2.73.1). Serial invariant only — no FR here depends on anything M135 introduced.

**Release target:** v2.74.0 (provisional; MINOR — the set is mixed, two `Added`, one `Changed`, two `Fixed`). **The bump trap must be falsified BOTH ways and the pair reported at ship**, per the M135 finding: `inferBump` reads a camel-cased `changelogCategory` while the frontmatter writes the snake-cased `changelog_category`, and on M135 — the program's first pure-fix milestone — the two disagreed by a whole release line, the wrong key asserting six `Fixed` FRs were additive. This set is mixed, so the readings are expected to agree; **an agreement is not a pass unless both were run and both numbers are stated, naming which key was fed.** Codename decided at `/ship-milestone`.

**Migration:** `none`. The store this milestone reshapes lives at `.dpt/skip-baseline.json`, which `.dpt/.gitignore` keeps untracked, so no consumer artifact under version control changes shape. The v1 records a project may hold locally are dropped by the reader with no operator action and are reported by name when dropped. No consumer-authored file gains or loses a key.

**Scope boundary — deliberately excluded, not to be folded in:**

- **No new `/gate-check` probe.** Registering probe #82 moves counts pinned across roughly two dozen test sites, and STE-531's guard is equally binding as a test in the suite that IS the gate. The reachability probe's own pin is re-measured (AC-STE-531.4); nothing else about it changes.
- **No general "does this order fire" classifier.** STE-531 closes the gap for the skip-baseline order alone. Modelling the firing condition of an arbitrary ordered reference would be a partial model reporting confidently, which is worse than the existing honest silence.
- **Flutter identity extraction.** STE-529 covers the junit format, which bun and pytest both emit. Flutter's machine format is different and takes the documented scalar degrade rather than a guess.
- **The four unrelated carried findings** — the NFR-1 line cap pinned at the wrong number, the README `kind: regex` codename staleness, the unguarded sibling-surface class, and M130's two shipped HIGHs — stay carried. None is on this subject.

**Measurement this milestone rests on**, taken on 2026-08-26/27 at commit `9b420ec`, and correcting a mechanism the project memory had recorded twice and wrongly:

| where | pass | skip |
|---|---|---|
| primary working tree | 10077 | **15** |
| detached worktree, same commit | 10065 | **27** |

Identical tree bytes, identical test count (10092 across 495 files), zero failures both. The twelve differing tests guard on capture fixtures `.gitignore:13` deliberately ignores; eight more of the fifteen turn on an absent python documentation tool and one on an environment variable. **The skip count is a property of the tree, the git-ignored local state, and the installed tooling together.** This disqualifies a merge-base worktree measurement outright — it renders a delta of minus twelve with no code behind it — and it is why the capture must happen in place, in the same checkout, on a clean trunk.

**Pre-work baseline for this milestone's own branch:** 15, measured on clean `main` at `9b420ec` before any FR file was written.
