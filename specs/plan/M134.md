# Implementation Plan

## M134 — Reachable Workers {#M134}

**Goal:** Give every worker the delivery pipeline spawns a name, and let the operator confirm, edit or drop the remote-control bridge before anything is spawned. The orchestrator hands the spawning skill the kickoff text and the milestone identity and nothing else today, so its workers launch nameless onto a machine where session names are global — and a worker blocked on a question can only be cleared by a human at the keyboard. The bridge argument is opt-in because it hard-exits before the session starts on an account whose organization disables remote control, and an unconditional flag would break every spawn for those operators.

**Prerequisites:** M133 merged (v2.72.0). Real dependency, not merely the serial invariant: STE-519 appends to the field list M133 introduced and relies on the render predicate M133 built to grade the new field, which it does by importing the field list rather than restating it.

**Release target:** v2.73.0 (provisional; minor — two `Added` FRs alongside one `Changed`). Codename decided at `/ship-milestone`. Falsify the inferred bump with an all-`Fixed` control before trusting it: the helper reads a camel-cased key and the frontmatter writes a snake-cased one, so a pure-fix milestone silently infers a minor bump.

**Migration:** `none` — the derivation, the eighth field and the hand-off are all toolkit-internal. No consumer-authored file changes shape, and no consumer artifact gains or loses a key.

**Scope boundary:** this milestone is the orchestrator half only. The opt-in argument on the two spawning-skill launch lines lives in the `agent-toolkit` repository and is delivered separately with no SDD ceremony. Neither half requires the other's version, and neither may.
