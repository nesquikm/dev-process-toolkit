# Implementation Plan

## M142 — Stack-Aware TDD Hook {#M142}

**Goal:** The commit guard that requires a test-driven run recognises every stack the toolkit bootstraps, and says so when it recognises none.

**Prerequisites:** None. Ships after M139 and M140.

**Release target:** the next minor after M140 ships. M139 and M140 both currently name v2.77.0, so one of them must move before this milestone can name a number; check the shipped versions rather than the plans.

Reported externally against v2.74.0 and reproduced on this tree at v2.76.0 by executing the shipped classifier. A Dart commit carrying a source and its test classifies as carrying nothing to guard, and so do Python, Go, Kotlin, and TypeScript whose tests use an extension outside a three-item list. The toolkit ships example configurations for six stacks; the guard covers one.

The documented trigger and the implemented trigger disagree: the reference names a test directory the code does not match. Neither the documented name nor any non-TypeScript layout can fire.

The second half is what let the first survive. An unrecognised layout resolves to the same outcome as a commit with nothing to guard, so a guard that never looked reads exactly like a guard that passed. The reporter found it only because a spec-only carve-out working as designed made the asymmetry visible.

A longer list of extensions is the same defect spelled differently. The stack is already detected from marker files elsewhere in the toolkit, and the predicates should follow that detection rather than keep a private copy.
