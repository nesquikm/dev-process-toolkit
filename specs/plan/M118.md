# Implementation Plan

## M118 — Unmanaged-Tree Probe Guards {#M118}

**Goal:** Stop `/gate-check` from failing a project the toolkit does not own, and stop the same defect class from recurring. Probe #18 hard-fails any tree with a hand-written `CLAUDE.md` because its only scope guard is file existence; probe #37 scans every fenced block as a directory tree because it never reads the info string. Both probes state a narrower scope in their own prose than their code implements. The third FR is the structural fuse that keeps the managed-tree question in one place.

**Prerequisites:** None. STE-432 must land before STE-434 — the conformance probe asserts zero violations on this repo, which is only satisfiable once the shared module exists. STE-433 is independent and may land in any position.

**Release target:** v2.58.0

**Migration:** `none` — no consumer-artifact convention changes. Both probe fixes make the gate *more* permissive on trees the toolkit does not own, and the new probe reads only this repo's own adapter sources. No consumer file needs rewriting, so there is no registry entry to bind.

**Provenance:** field report from a live `/gate-check` run of v2.57.1 on a non-toolkit-bootstrapped Flutter consumer project, 2026-07-31. Design session and claim-by-claim verification: `/dev-process-toolkit:brainstorm`, same date.
