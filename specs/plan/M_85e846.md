# Implementation Plan

## M_85e846 — Hooks by Repo {#M_85e846}

**Goal:** The three blocking hooks judge a commit or a pull request by the repository it actually lands in, and they accept only evidence produced for that repository. Every shell shape that carries a commit or a pull request gets a stated verdict. That verdict is graded on two real checkouts and on replayed real traffic, never on the prose alone.

**Prerequisites:** This milestone ships third of four, after M_947c79 and M_685ff6 and before M_2306b6, whose live two-repo smoke re-proves it. It reuses M_947c79's receipt store (STE-602) (`receiptsDir` in `dpt_paths.ts`, `writeReceipt` and `readSessionReceipts` in `tracker_receipts.ts`, receipts under the already-ignored `.dpt/ledger/receipts/`) and adds no second one. The hooks read no tracker configuration, so this milestone needs no tracker container: every fixture is a local git checkout.

**Release target:** v2.89.0, MINOR, the next minor after M_685ff6's v2.88.0 (or after whatever release lands between). One FR is `Changed`, which is not fix-class, so `inferBump` answers minor. Validate the version against `CHANGELOG.md` at kickoff instead of trusting this line. The release is a behaviour change for every consumer, confirmed by the operator: every commit and PR in any toolkit-managed checkout, shared or not, then needs a gate receipt in that checkout, and the CHANGELOG entry says so. After release, sharing repositories raise `min_dpt_version` to this version, the readiness precondition M_947c79 documents.

**Migration:** none. Receipts live in the machine-local `.dpt/ledger/` store that `.dpt/.gitignore` already ignores, so no consumer file changes shape. The template's gate paragraph reaches new bootstraps only, and existing consumers learn the receipt from the refusal text.

### Risks

| Risk | One side | The other side |
|------|----------|----------------|
| The harness stops exporting its session id | every commit in a managed repository is refused (confirmed scope: every managed checkout, shared or not) | measured present on Claude Code 2.1.276; the front door refuses as `session-id-unavailable` naming `CLAUDE_CODE_SESSION_ID`; the live check and M_2306b6 re-prove it |

| Sessions started before the install keep the old hooks | those sessions keep the old leaks | restart them, as measured on 2.85.0 |
| Wider recognition refuses a command that commits nothing | a false refusal on real work | the replay hand-classifies every new refusal before release |
| The unresolved leg admits a dynamic-directory commit elsewhere | a narrow leak, shown to the operator on exit 1 | the replay measures it, and the fixed forms shrink it |
| A receipt is minted by hand, with no gate behind it | the hook would trust a self-issued file | vouching: one Skill call vouches for one root, and no remedy prints the minting command |
| The implementing session is guarded by the hooks it edits | a hook change blocks its own commit | the installed hooks guard the session, not the working tree |
