# Implementation Plan

## M_947c79 — Declared and Owned {#M_947c79}

**Goal:** A repository that shares one Jira project or one Linear project with other repositories says so in one place, and code reads it. Every ticket decision on the live path — create, import, claim — is made by a command that reads that declaration and records what it decided, and a hook refuses writes that skipped the commands. Clients too old to carry the hook meet a plain-language stop paragraph, a version floor, and a detector that names the untagged tickets they and people leave behind.

**Prerequisites:** Ships FIRST of four serial milestones: M_947c79 → M_685ff6 → M_85e846 → M_2306b6. M_685ff6 builds the honest milestone join and gates container writes on this milestone's reader, receipts and hook; M_85e846 makes the commit and PR gates repository-aware; M_2306b6 proves all of it live in throwaway containers. None starts before this one merges: parallel milestones collide on probe-count pins, the reachability ledger and the release files.

**Release target:** v2.87.0 — a minor bump, because three FRs are Added (the declaration reader, the setup declaration and the hook) and three are Fixed. Verify with `inferBump` against the FR frontmatter and the CHANGELOG rather than trusting this line. `FIRST_GATED_DPT_VERSION` must equal the version this milestone actually ships in; the release task below checks it. Readiness precondition, documented by STE-603: every participating repository declares `repo_tag` (probe #25 green in each), and every sharing repository raises `min_dpt_version` after each programme release, this one first.

**Migration:** none. The declaration is opt-in and written only when an operator declares; receipts live under the already-ignored `.dpt/ledger/`; an undeclared repository's files, gates and hook output are byte-identical.
