## M_79b1f6 — Releases That Know Their Sibling {#M_79b1f6}

### The defect found at design time

STE-590 carries the most important finding of this milestone. The previous milestone collapsed both resume scopes onto one sibling predicate, but that predicate is only consulted for ACTIVE plans. Measured on 2026-09-10 with the two-root fixture: a milestone-scope resume over an ARCHIVED unstamped spanning plan whose sibling holds an active FR orders `/implement`, `/ship-milestone` and `/pr`; the same fixture with the plan LIVE orders nothing. A plan is normally archived at ship time, so the archived case is the state the ship path actually runs in. This is the seventh recorded occurrence in this repository of a fix landing on one path while a second stays open. Unifying the callers does not help when the thing they share reads half the world.

### Risks

| Risk | One side | The other side |
|------|----------|----------------|
| An unlocatable sibling is a note, not a violation | Probe #63 is error severity and archived plans are permanent, so a violation would fail every machine without the sibling checked out, forever, with no local edit able to clear it; probe #75 already rules that an unlocatable sibling leaves the verdict intact | The design brief's criterion C1x.5 made it a violation; that text was not taken. Decided 2026-09-10 at the design prompt, answered by the orchestrating session |
| A sibling with a plan but no stamp is a note | It is the normal state between the two releases of one milestone, and clearing it needs the sibling's own release | A sibling that never releases stays a note indefinitely; the note names it on every gate run, so it is never silent |
| The shared classification has no per-plan catch | Kept as the previous milestone shipped it: one malformed declaration raises one loud refusal | That refusal is tree-wide — it silences probe 75's rows, the close offer and every live-plan resume classification until fixed. This milestone's new readers (the gate, the probe #63 leg, the archived resume leg) read one plan each, so they do not widen it |
| The spanning declaration is something nothing forces | This programme makes the honest state representable and visible | A repo that omits the key is ship-ready again and can release the shared milestone alone — the dishonest state stays possible |
| No smoke leg drives two roots | The two-root unit fixture stands in, and the first shared milestone runs as a supervised experiment | A green conformance run is not evidence this path is covered |
| The reader lands before the writer, in separate commits | The design brief asked for the probe leg and the partial flag in one commit, because a decorated stamp would red the probe; the stamp is not decorated, so the remaining coupling is one-directional | Ordered commits satisfy it: STE-588 reads `ship_partial:` before STE-589 can write it, and the `git log` order is the witness |
