# Implementation Plan

## M115 — Tracker-less milestone identity minting {#M115}

**Goal:** Close the cross-branch milestone-number allocation race in `mode: none` by construction. `/spec-write` stops picking a sequential `M<N>` in tracker-less mode and instead mints an opaque `M_<short-ULID>` from `Provider.mintId()`, bypassing `nextFreeMilestoneNumber` exactly as the Jira Epic-first path does. Reverses STE-377's deliberate tracker-less carve-out on the grounds that its premise — no key to claim from — is false. Linear and Jira allocation stay byte-unchanged; existing `M<N>` plans coexist with no migration.

**Prerequisites:** none. The union milestone-token grammar (STE-376) already accepts `M_<key>`, `mintId()` / `mintUniqueId` already exist and are offline-safe, and `/ship-milestone` already treats `M_<key>` as a valid milestone token. This milestone adds a producer, not a grammar.

**Release target:** TBD (single-FR milestone; M112/M113/M114 are also unshipped and may land first — re-bump at ship time).

**Migration:** `none` — existing `M<N>` plan files keep resolving, archiving and shipping unchanged, so no consumer artifact needs rewriting and no registry entry is required. The change is forward-only: it governs milestones created after adoption.
