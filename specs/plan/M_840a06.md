# Implementation Plan

## M_840a06 — Writes That Ask First {#M_840a06}

**Goal:** Four outward writes to a tracker that has no delete tool stop firing on their own judgement — an import that never asked, a create-idempotency probe that could not match, a milestone mint with no look-first order, and a repoint flag with nothing behind it.

**Prerequisites:** None. First milestone of the shared-tracker programme. It blocks the GB→GF repoint: until it merges, two repos must not share one Jira project.

### What each one costs the operator if it stays

Every FR here hardens a write the agent performs outward, into a board where nothing the toolkit can invoke removes what it created by mistake. On a single-repo board the first two are latent bugs: a surprising import, an occasional duplicate. On a shared board the import mints local files for a sibling repo's work and rewrites the sibling's tickets, and the probe binds this repo's FR onto a sibling's issue so every later write lands on someone else's ticket. Both are undoable. The third orders the second repo to join rather than mint a rival container. The fourth makes the one instrument that can perform the repoint actually exist, and writes down what must be true before it runs.

### Risks

**Container identity is out of scope, deliberately.** STE-579's mismatch arm fires on a ticket whose repo tag differs from this repo's. Containers are shared by design, carry no owning repo, and so have no tag to differ on. Nothing governs container identity today; what will is a near-miss title refusal in a later milestone, not a tag. Shipping the arm for containers would ship a dead branch, so it is not shipped and the gap is recorded here rather than assumed closed.

**The mint helper's find leg stays optional.** The bind path refuses without an enumerator; the mint path — the one that creates — degrades to an unconditional create. STE-580 closes that in prose only, on a seam no type check governs. Promoting the guard into the helper is a later milestone's job, where a join option already introduces the place to put it.

### The registration branch, and what is not validated

The uncertainty signal ships registered. `tracker_idempotency_uncertain` enters the canonical capability set and the key-owner map in STE-579, taking the length pin from 44 to 45, and the emit directive lands in the same commit: the registry is bidirectional and either half alone reds the gate. Two sibling keys, `tracker_config_write_mcp_unavailable` and `workspace_binding_deferred`, stay unregistered — they are green only because their directives live outside the one file the reverse leg scans. That latent gap is recorded, not closed.

No automated leg exercises a Gateway-Timeout on a shared board. The create-idempotency work is validated by doc-conformance greps plus the live read-only tracker measurements recorded in STE-579. This repository has a recorded incident of a fabricated smoke leg leaving the gate byte-identically green, so no smoke validation is claimed for this milestone.
