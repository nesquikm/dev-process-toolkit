# Implementation Plan

## M_94e6f7 — One home for project settings {#M_94e6f7}

**Goal:** Move every project setting the toolkit reads into one committed file, specs/settings.yaml, read by one loader. Today the settings sit in six CLAUDE.md sections, two standalone lines, the tracker config file and two video files. Each of those homes has its own parser. CLAUDE.md keeps the model-facing prose and gains a pointer. Through 3.x it also keeps a generated binding stub for older plugins. Projects that have not moved are still read from their old homes. An upgrade step moves them and then removes every old copy.

**Prerequisites:** v2.101.4 merged at 8b107a45 (PR #126).

**Release target:** v3.0.0, a major under NFR-2. A fresh setup no longer writes the CLAUDE.md headings NFR-2 protects. STE-710 carries the breaking flag, which the release bump reads. One consumer-artifact migration. Verify against CHANGELOG.md before shipping.

**Operator rulings.** 2026-11-04: a programme of four milestones, this one first, as v3.0.0. Hard invariant: no knob lowers generated-code quality or disables a deterministic gate. One settings file holds all project settings, named specs/settings.yaml. Inventory: six CLAUDE.md sections with the tracker binding, and two standalone lines. It also covers the tracker config file and two video files. Never moved: the local env file, the per-user tracker write gate setting, and Claude Code's own settings file. CLAUDE.md keeps the shared-container stop paragraph and the Key Commands and gating-rule prose. Skills learn the tracker mode from a bun front door, not a prose grep. The repository is public: synthetic ids only.

Defaults unchanged (operator rule, 2026-11-04). "These changes SHOULD NOT change toolkit behavior by default (only config moves to specs/). All optimizations should be changes in config files after /retro, and they should be approved by the user." So the upgrade offer of STE-712 is opt-in through close_out.upgrade_offer, off by default. A legacy section that is malformed still breaks only its own readers. On an unmanaged tree only /setup creates the settings file. Neither /setup nor the migration writes a key with no legacy home.

Binding stub (R1). Through all of 3.x, the migration and /setup also write a minimal legacy Task Tracking stub into CLAUDE.md. It holds the mode line and the Linear or Jira binding keys, generated from specs/settings.yaml. It keeps pre-3.0 cached hooks guarding, the tracker write gate above all. Probe #25 grades the stub byte-equal to its render from the settings file. The 3.x loader never reads the stub and never counts it as a second home. Stub removal is scheduled for 4.0, and the NFR-2 amendment says so. This replaces the earlier floor-and-pointer-only residual.

Dogfooding (R2). This plan ends with an ops task on this repository, done before M_7bc805 starts. Refresh the installed plugin cache to v3.0.0 and reload plugins. Then run /upgrade here and verify the cleanup on this tree.

Cleanup after migration (R3). The migration removes everything it moved. That covers the moved CLAUDE.md sections, the tracker config file and both video files. Kept in CLAUDE.md: the stub, the generation marker, the setup audit and Key Commands. The human Testing Conventions prose and the new pointer section stay too. After apply no moved setting exists in two places. A second /upgrade run leaves the tree byte-identical, and its detector reports nothing to apply. Probe #69 reports a leftover legacy file or section as a pending migration.

Gate-check freeze (R5). The AC-STE-618.8 freeze of the gate-check SKILL.md is pre-granted once for this milestone. Re-base the AC-STE-618.8 KICKOFF once at this milestone's gate-check edit commit, listing the new permitted lines. The re-base lands as its own reviewed commit with the freeze test green. So every gate-check edit of this milestone lands in one commit owned by STE-713. STE-708 and STE-709 leave that file byte-identical on their own commits.

**Migration:** settings-file moves every inventoried setting from CLAUDE.md, the tracker config file and the video folder into specs/settings.yaml. It adds the pointer section and, in a tracker mode, the binding stub. On a shared container it raises the floor to 3.0.0. It then removes every moved section and deletes the three retired files. Its cleanup arm removes a leftover equal to the settings file and refuses one that differs. Explicit approval required.
