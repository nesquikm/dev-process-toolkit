# Implementation Plan

## M138 — Bootstrap Identity {#M138}

**Goal:** A tracker-less project's bootstrap plan carries the identity its own mode uses, from the moment `/setup` writes it.

**Prerequisites:** None.

**Release target:** v2.75.1 (provisional, patch — both FRs are Fixed).

Observed 2026-09-02: `/setup` with no arguments on a fresh Flutter project produced `specs/plan/M1.md`. Step 8 writes that filename in every mode, and `mode: none` names its plans `M_<short-ULID>`. Probe #73 exempts `kind: scaffolding`, so nothing reds; the mismatch waits for `/spec-write` to consume it.

STE-481 already rejected "do not scaffold under `mode: none`" — the scaffold's pre-filled paths, gate commands and live `<scaffolding>` FR row are read downstream by `plan_only_archival` and `tracker_local_reconciliation_drift`. Minting at `/setup` keeps every one of those and fixes the name, so that rejection stands unchallenged.

Repairing existing bootstrapped projects is out of scope by operator decision (2026-09-02).
