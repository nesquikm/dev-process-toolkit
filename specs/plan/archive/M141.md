# Implementation Plan

## M141 — Release Tooling Front Doors {#M141}

**Goal:** The release ceremony's three write-and-check steps are executable orders against runnable modules, not prose an operator carries out by hand.

**Prerequisites:** None. Runs before M139 and M140 so both ship through a fixed ceremony.

**Release target:** v2.76.0 (provisional, minor — STE-546 is Changed; the other two are Fixed).

Measured 2026-09-02 while shipping v2.75.1. Three defects, one cause: the modules that would do this work carry no entry point and no non-test importer, so the ceremony is prose. Probe #81 cannot see them because all their references score `descriptive` — the class-(b) blind spot its own source documents against itself.

The bump inferrer reads `changelogCategory` while the frontmatter writer emits `changelog_category`, so an FR passed as read defaults to the additive category: measured, a pure-fix milestone returns 2.76.0 with a rationale stating the wrong thing. The decisive control is in-repo — `branchTypeFor` has the identical shape and is safe solely because both its prose call sites spell the mapping out.

The release-file writer is never called; the closing test-count line is typed by hand and has been typed wrong three times on one release. The surface-agreement detector is written and tested with zero callers, and the check that does run fires before the bump, when both surfaces still describe the previous release and agree by construction.

### Probe #81's pin fell 133 to 131

AC-STE-545.7's claim held for its own subject: landing the entry point flipped `release_config.ts`'s references to ordered-and-reachable with the pin still measuring 133. It fell later, for a different cause. Closing the `changelog_ci_owned` gap made that module import `./docs_config`; the door carries `import.meta.main` and reachability is transitive, so `skills/docs/SKILL.md:23` and `skills/implement/SKILL.md:221` became ordered-and-reachable. A lowering, the sanctioned direction — two more orders here are now carryable. Re-measured against a pristine `41cb1e8` tree by diffing the ordered-unreachable SETS, never the counts. The pin, `skills/gate-check/SKILL.md`, and the two sibling FRs citing the number (STE-541, STE-543) all moved in step.

### Ordering the writer made eleven promises checkable

Each was false. Three came from STE-545's own reword: the `changelog_ci_owned` skip was a promise the module could not keep; the ordered command wrote before the step-6 approval, so a declined run left a bumped tree; step 4 sourced the counts from the codename prompt rather than the pre-flight gate run. Auditing those fixes found eight more — the reference still declaring `--dry-run` unshipped, step 6's diff losing its producer once step 4 stopped writing, the branch gate sitting after the rewrites it would have had to undo, an orphaned edit-in-loop, a quoted refusal the door never printed, CRLF and BOM blindness in both readers of `CLAUDE.md`, unknown flags failing open and swallowing the next argument, and an envelope claiming nothing was written from a catch wrapping the write loop.

### The lesson, and two authorized test amendments

A description is never wrong, so nothing had ever graded these; an order can be. The milestone's thesis turned on itself, and all eleven are closed. Separately, two shipped legs were amended under authorization, each by adding a `testCount` to the opts it hands `bumpFile`: `release_config.test.ts` ("routes changelog with metadata") and `tests/release-config-fixtures.test.ts` ("changelog bump round-trips"). Both encoded the pre-FR contract that a count-less changelog write succeeds, which AC-STE-545.4 deliberately supersedes. Neither assertion was weakened.
