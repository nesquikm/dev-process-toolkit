# Implementation Plan

## M132 — Evidence Ledger and E2E Authoring {#M132}

**Goal:** Make completion provable rather than asserted. A stage can report success in prose today and be believed; the hand-off block describes a gate section carrying pass and skip counts and nothing checks that it does. This milestone makes every count machine-read from captured output, makes newly introduced skips red while pre-existing ones ride free, and makes the end-to-end suite something a change updates rather than drifts away from.

**Prerequisites:** M131 merged (v2.70.0). STE-512 reads the `e2e_cmd` key STE-503 adds, and STE-510's `drive:` row reports the outcome of the drive STE-505 makes mandatory. This is a real dependency, not just the serial invariant.

**Release target:** v2.71.0 "Receipt" (provisional; minor — four `Added` FRs alongside one `Changed`)

**Migration:** `none` — the hand-off fence is a toolkit-internal contract between orchestrator and worker, and the skip baseline is a generated artifact rather than an authored one. No consumer-authored file changes shape.

### Tasks

1. Add `skipped` to `TestCount` and extract it per stack — AC-STE-508.1, .2, .5, .6.
   verify: bun, pytest and flutter each parse their own counter; the unknown fallback and the existing three-field consumer are unchanged.
2. Anchor skip parsing on last-match and keep parse failure distinct from zero — AC-STE-508.3, .4.
   verify: a multi-file fixture whose per-file skip counter precedes the summary goes RED under a first-match implementation; unparseable output yields the parse-failure shape, never zero.
3. Capture the skip baseline at the branch point under `.dpt/` — AC-STE-509.1, .4.
   verify: the baseline is written through the shared path module at branch creation and does not move when a capture runs twice in one run.
4. Compute the delta and give absence its own outcome — AC-STE-509.2, .3.
   verify: positive fails, zero and negative pass; an absent baseline yields `unmeasured` and is asserted NOT to render as a clean pass.
5. Mutation-verify both skip guards — AC-STE-509.5.
   verify: a baseline reader stubbed to zero goes RED; an inverted delta comparison goes RED.
6. Add `drive:` and `e2e:` to the fence in fixed order and raise the line cap — AC-STE-510.1, .2, .6.
   verify: the new sections sit after `gate:`; `gate:` carries pass, fail, skip and the baseline delta; the sections stay inside the fence.
7. Derive every fence count by code from captured output — AC-STE-510.3.
   verify: a round trip from real captured output through the parser to a rendered fence, asserting the numbers match the capture rather than a fixture restating them.
8. Refuse `status: ok` without evidence and route disagreement through the existing halt path — AC-STE-510.4, .5.
   verify: a missing count and a failing count are each refused; a count disagreeing with the capture takes one scoped retry then a deterministic halt naming the stage.
9. Mutation-verify the evidence guards — AC-STE-510.7.
   verify: a worker-authored count that disagrees with the capture goes RED; a fence rendered with no capture present goes RED.
10. Carry the same rows in the step-14 report from one renderer — AC-STE-511.1, .2, .4.
    verify: the fence path and the report path produce the same rows from the same input, compared directly; counts machine-derived on both.
11. Assert the standalone-run guarantee on its own path — AC-STE-511.3.
    verify: a run not under the orchestrator carries the rows; asserting only that the report carries them is a different and weaker claim.
12. Author or edit e2e tests for the change and run the suite — AC-STE-512.1, .2, .4.
    verify: a change with e2e-observable behaviour lands an added or edited test before the gate is declared; the suite runs and its counts reach the evidence rows; `e2e_cmd` absent is byte-identical to today.
13. Make the none-needed decision explicit and machine-readable — AC-STE-512.3, .5.
    verify: a change with no e2e-observable surface records that decision rather than silently adding nothing; four capability tokens distinguish authored, edited, none-needed and suite-red.

### Risks

| Category | Risk | Severity | Mitigation |
|---|---|---|---|
| Unclear acceptance criteria | **AC-STE-510.3 is the criterion most likely to ship fail-open.** A worker that composes the fence from memory produces a block that passes every shape check — correct section order, correct line count, plausible numbers — and is evidentially worthless. The wrong implementation is invisible in a green run. | high | AC-STE-510.7 names both mutations explicitly rather than leaving the choice to the implementer: a worker-authored count that disagrees with the capture, and a fence rendered with no capture. The subject of every assertion is a capture artifact, not a document. M129 shipped two Tier-1 guards fail-open; this is the clause written against a third. |
| Unclear acceptance criteria | **AC-STE-509.3's `unmeasured` outcome is the second fail-open candidate.** Reading a missing baseline as zero makes every pre-existing skip look new (loud and wrong); reading it as equal to current makes every new skip invisible (quiet and much worse). | high | The outcome is specified as a third value rather than a boolean, and the AC states directly that it is never rendered as a clean pass — so collapsing it either way contradicts a written criterion. AC-STE-509.5 mutation-verifies the stubbed-to-zero reader. |
| Unclear acceptance criteria | AC-STE-512.3's none-needed path is always available and never obviously wrong. Most changes genuinely have no e2e-observable surface, so "none needed" is the answer that is right often enough to become reflexive. | medium | The decision must be recorded and tokenised (AC-STE-512.5), so a silent skip and a considered decision stop producing identical output. |
| Breaking changes | Raising the fence line cap changes a contract M129 shipped, and the shape validator, its tests, and the smoke fixture group that asserts against a captured worker report all pin the current value. | medium | Land the cap change with the section addition in one sweep so the pinned value moves once. AC-STE-510.6 records why the sections stay in the fence rather than spilling into a companion artifact. |

Both high-severity risks are mitigated by named mutations rather than by review attention, because both are invisible to review in a passing run.

### Notes

- **The operator's rule for skips is a ratchet, not a threshold.** Stated verbatim in the design session: skips count against a run "only if they already were, not ones this change introduced". A zero-skip rule would have reddened this repository on the day it shipped.
- **M129's own record is the specification for how NOT to verify STE-510.** All eighteen shipped ACs of the FR that introduced this fence were greps of `/deliver`'s own SKILL prose, "which is precisely why a fence with no producer passed every one of them". Every assertion here takes a capture as its subject.
- **STE-508's anchoring clause is not defensive over-engineering.** The module already carries a fix for exactly this bug: STE-323 found that Bun emits per-file counters before the summary block, so a first-match extractor captured a per-file count rather than the total. A new counter written the naive way reproduces a defect the file has already been patched for once, and `lastCountedMatch` is hoisted precisely so a new counter can share it.
- **STE-511 is what makes the guarantee a property of the work rather than of one invocation path.** `/implement` is invoked directly at least as often as it runs as a `/deliver` stage; without it the milestone's promise reads as "`/deliver` proves things", which is not what was asked for.
