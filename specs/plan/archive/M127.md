# Implementation Plan

## M127 — Fixture Falsifiability {#M127}

**Goal:** Close the eight 2026-08-16 conformance findings that are assertion defects in the maintainer's own harness. Every canonical chain ran 6/6 green on all three legs — these findings are false REDs (and two false GREENs) produced by the fixture layer's own evidence methods, not behavioural regressions in the systems under test.

**Prerequisites:** M126 merged. STE-488 repairs the propagation-commit grep whose subject literal STE-477 retires, so M126 must land first.

**Release target:** v2.66.1 (provisional; patch — pure Fixed, dogfood-only). Driver-side milestones ship as plugin releases per the M95 / M96 / M98 / M112 precedent.

### Notes

- **Two directions of defect, not one.** Six of these are false REDs against healthy subjects. Two are false GREENs: group 2's sub-fixture 2a matched spuriously in the same run its sibling 2c false-failed, and 2b passed for a reason its own assertion does not check. A fixture that can pass without evidence is the more dangerous half, which is why STE-483's non-vacuity requirement runs in both directions.
- **Out of scope by construction.** Fixture 10a's carve-out is not tightened. STE-456 AC.2 states the reason: a group that false-reds on a healthy short run gets disabled, which is worse than the hole. STE-486 extends the carve-out to Phase 4 rather than removing it from 10a.
- **Recurrence.** Fixture 3c has now drifted twice — it already carries a note about a prior doc-drift on the same surface. STE-485 AC.5 generalises the fix (verify each asserted token against its emitting source) because instance-level corrections have demonstrably not held.
- **Two ACs are not literally satisfiable as written, and both sides are named here rather than absorbed.** The M126 precedent applies: implement the satisfiable reading, record what the AC says and what is true, never let the difference vanish into a green checkbox.

  - **AC-STE-484.1's parenthetical.** The AC reads "(linear 8, jira 6+1 and 5+1, none 12)". Measured, those figures are not reproducible — not against the shipped reduced slices and not against the original `/tmp/dpt-smoke-{linear,jira,none}-implement.log` captures either, which the STE-484 audit re-scored independently: the forked `tool_result` projection yields **linear 8 / jira 6 / none 6**, with raw 18/14/14 and synthetic 2/2/2. Only the linear 8 survives. The divergence is in the FR author's tally scope, not in the reduction — the slices are byte-faithful. The **binding** requirement, and the one shipped, is *non-zero on each leg*; the measured figures are pinned in `tests/m127-ste-484-group7-fork-tool-result.test.ts` and the parenthetical is not.
  - **AC-STE-488.5's premise.** The AC says the propagation-commit greps at SKILL lines 998 and 1006 must be "updated to STE-477's new fixed-length subject, so the M126 change does not silently break group 3a" — on the stated ground that the old literal is gone from main and the greps now match nothing. **That premise is false and was checked before any code was written.** The grep is `git log --grep 'propagate.*removal to cross-cutting specs'`, written path-agnostic precisely because the pre-M126 subject interpolated the removed path; `.*` still absorbs `" file "` in the new fixed subject `chore(specs): propagate file removal to cross-cutting specs`. Run directly, it **matches**. Group 3a is not broken and never was. What is true, and what shipped, is the weaker-but-real version: now that STE-477 made the subject a fixed literal, a `.*` that only needed to be loose for a variable path is needlessly loose, and tightening it to the fixed string is strictly stronger.

- **The deepest finding of M127, and it reframes STE-485 entirely: `/gate-check` output is LLM-rendered, so probe-id spelling and verdict wording are RUN-DEPENDENT.** Fixture 3c has drifted three times, and the reason is not that anyone read the evidence carelessly — it is that each correction pinned **one run's** rendering as the contract. The proof is a same-leg inversion nineteen days apart, both captures on disk:

  | jira leg, fixture 3c probe capture | `cross_cutting_spec_stale_file_refs` | `cross-cutting-spec-stale-file-refs` |
  |---|---|---|
  | 2026-07-27 (STE-421 AC.4's evidence) | 17 | 0 |
  | 2026-08-16 (STE-485's evidence) | 0 | 2 |

  Both measurements are correct about their own run. Neither is a contract. Consequences, all shipped:

  - **AC-STE-485.1 is not satisfiable as a literal.** It requires the hyphenated id "the runtime emits" — but the `none` leg of 2026-08-16 rendered the **underscored** form and the hyphenated form zero times (assistant-scoped: hyphenated 1 / 1 / 0, underscored 0 / 0 / 2 across linear / jira / none). What shipped is an `any-of` clause that still **names** the AC's spelling but tolerates the documented variance. A fourth single-literal correction would have drifted a fourth time; that was the live risk and it is the reason the repair is shaped this way.
  - **AC-STE-485.2 turned out to BE satisfiable, and the first attempt at this plan entry claimed otherwise. Recording the retraction, because the mistake is the instructive part.** The draft reading kept `ADVISORY` inside the verdict `any-of` on the ground that "the Linear leg rendered exactly that word", and wrote the AC's second half off as refuted. The STE-485 spec-review audit refused that and executed the counterfactual instead. Two things came back. First, Linear's **only** `ADVISORY` belongs to a different probe — `Probe #14 \`ticket-state drift — active side\` — PASS + ADVISORY` — while probe #37's own Linear row reads `— NOTES`; the justification was a wrong-subject attribution, the very error class this FR exists to retire, arriving a fourth way. Second, the arm was a live **false green**: strip every #37 trace from the Linear capture and the three-arm clause still exited 0, measured. `any-of "GATE PASSED WITH NOTES" NOTES` names the AC's phrase, omits `ADVISORY` exactly as the AC's second half demands, passes all three genuine firings (`NOTES` assistant-scoped 1 / 1 / 1), and reds the stripped capture. It is strictly stronger and it is what shipped. **The general lesson, which is why this stays in the plan rather than being quietly corrected: "this AC is not literally satisfiable" is itself a claim that has to be falsified before it is recorded, and here it survived one review only because nobody had run the stronger clause.** `GATE FAILED` does appear on every leg (probe #22 co-fires on 3c's staging), which is why the verdict clause scores #37's own row and never the run's closing line.
  - **AC-STE-485.3's premise is false.** It says the underscored occurrences "come from the module path … a filename, not an emission". The probe's own `buildMessage` (`adapters/_shared/src/cross_cutting_spec_stale_file_refs.ts`) emits the underscored token twice as real message text, and the `none` leg's capture carries it (raw 12, assistant-scoped 2 — the assistant-scoped figure is the one that means "the runtime rendered it"; quoting the raw count here would repeat the very scope conflation STE-421 identified). The underscored form is an emission at the module layer AND reaches captures. What is recorded instead is the true reasoning error: **conflating what a probe module builds with what a non-deterministic renderer puts in a capture** — the same layer confusion as groups 9a/9b in STE-488.
  - **A shipped M116 pin was unsatisfiable against AC-STE-485.1 and has been re-scoped, not deleted.** `tests/m116-ste-421-assistant-scoped-capability.test.ts` forbade the hyphen form on any assertion line — correct for its 2026-07-27 evidence, wrong as a universal. It now requires assertion lines naming this token to carry **both** spellings, with a non-vacuity guard so a fixture that stopped asserting the token cannot pass it silently. STE-485 is the authorizing FR (AC.1 mandates the spelling the old pin forbade); the supersession and its evidence are recorded in the test body.

- **The harness caught five vacuities inside M127's own machinery, which is the milestone justifying itself.** Each was live, each survived at least one implementer pass, and three survived a refactor as well. Recorded because the pattern — not the instances — is the deliverable.

  1. **An inert `process.env` assignment.** A test set `process.env.PLUGIN_DIR`, but Bun snapshots the environment at process start, so `spawnSync` children never saw it. `${PLUGIN_DIR}` expanded to empty and the span only resolved by Bun falling back to cwd. Run from the repo root, the assertion *"goes RED when the subject is absent"* **passed for the wrong reason** — `count 0 / exit≠0` is indistinguishable from a command that never launched.
  2. **Count-scoring a runner that prints a verdict line.** `capability_row_assert` signals through its exit status, so scored on stdout every clause reads 1-vs-1. Forced to `stdout-count`, the STE-485 clauses return `vacuous`; `exit-code` separates them 1-vs-0. Every CAP_ASSERT-invoking clause in the registry now declares `scoreBy: "exit-code"`.
  3. **An unset `CAP_ASSERT` making `bun ""` exit 0.** The usage banner exits successfully, so both halves of the experiment scored 1. Closed by `harnessEnv()` defaults.
  4. **A false-green `ADVISORY` arm belonging to the wrong probe.** Fixture 3c's verdict clause admitted `ADVISORY` on the ground that "the Linear leg rendered that word" — measured, Linear's only `ADVISORY` is probe **#14**'s row, while #37's reads `— NOTES`. A capture with every #37 trace stripped still exited 0.
  5. **A substring hazard across two sub-fixtures.** 9a's arm was the bare key `identity_mode_conditional`, which is a substring of 9b's `plan_identity_mode_conditional` — so 9a exited 0 against 9b's capture, where probe #13 never fired. Both clauses are now keyed on the probe's rendered ROW, two shapes each, and the missing pin was added: a clause must not only pass on its own capture, it must **fail on its sibling's**.

  Four of the five are the same shape — an assertion that could not distinguish its subject from something adjacent — and #4 and #5 are the same defect the milestone was opened to fix, recurring inside the fix. The generalisable lesson is #5's: **passing where it should is half a test; a clause is isolated only when it also fails where it should.** Three of the five were found by the spec-review audit after implementer passes reported clean, which is the argument for keeping the audit adversarial rather than confirmatory.

- **Prior art applied.** STE-445 supplies the harness-with-halt shape. STE-423 supplies STE-487's tracker-segment rule, which this run falsified for Phase 9. STE-456 AC.7 and STE-461 AC.12 supply the extract-and-execute method; STE-461 AC.13's erratum supplies the mutate-the-right-subject constraint.
