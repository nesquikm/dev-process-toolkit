# Implementation Plan

## M131 — Runnability Contract {#M131}

**Goal:** Make the agentic drive happen when the project says it can be run. Today the check skill is opt-in, its failure is advisory by default, and under non-interactive stdin both the adopt offer and the scaffold offer decline themselves — three separate paths that each end with the pipeline reporting done about an app nobody started.

**Prerequisites:** M130 merged (v2.69.0). No hard code coupling; the ordering is the program's serial invariant.

**Release target:** v2.70.0 "Ignition" (provisional; minor — four `Added` FRs alongside one `Changed`)

**Migration:** `verification-run-keys` — this milestone widens a deliberately closed CLAUDE.md key set, which is a consumer-artifact convention change. STE-507 binds the plan to that registry entry so an existing project gains the keys through a previewed, approved `/upgrade` rather than a hand edit prompted by a probe failure.

### Risks

| Category | Risk | Severity | Mitigation |
|---|---|---|---|
| Unclear acceptance criteria | **An over-eager `detectRunnability` is the failure mode, not a missed detection.** A probe that reds ordinary library repos trains authors to write `run_cmd: none` without reading the question, and a contract everyone silences is worse than no contract because it looks like coverage. | high | AC-STE-504.5 mutation-verifies every source in BOTH directions, with the near-miss half named per source. AC-STE-504.6 requires the probe message to name the fired source so the author can answer correctly in one step rather than reflexively. This repository is itself a negative fixture. |
| Breaking changes | **STE-505 reverses a shipped, deliberate, well-argued default.** M93/STE-347 chose advisory on purpose and the authoring guide states the rationale plainly. A reviewer who does not follow the argument will correctly reject the change. | high | AC-STE-505.7 requires the supersession argument in writing inside the FR — the same shape M129 shipped for STE-493 and STE-494. The flip is additionally gated on an explicit author declaration, so no project's behaviour changes until someone writes `run_cmd` into its config. |
| Breaking changes | Widening a closed key set touches the reader, the config-error probe, `/setup`, `/upgrade`, the authoring guide and every worked example. Registering a new probe has historically moved pinned counts across many test files. | medium | STE-503 lands the config surface alone so it can be reviewed on its own terms; land the probe registration in one sweep so the count-pin update happens once. |
| Unclear acceptance criteria | AC-STE-507.2 (write `none` at bootstrap for a non-runnable project) is a quiet clause whose omission is invisible — the tree looks identical and the failure surfaces later as a probe error on someone else's first gate run. | medium | The task list states "NEITHER path leaves the key absent" as the verify line, so a silent skip fails a written check rather than passing unnoticed. |

Both high-severity risks are mitigated rather than resolved: the detection heuristic can only be validated against the fixtures we think to write, and the supersession argument can only be made, not proven.

### Notes

- **"Agentic tests" means bring the real artifact up and drive it.** That is the operator's own definition from the design session, and it is the shape `docs/verification-skills.md` already names — a `glacy-drive`-style check that boots the app and walks a journey, or a `glacy-progress-e2e`-style check that brings a service up and fires a real request sequence. The mechanism exists; what is missing is that it is optional and non-binding.
- **The gate is an author's declaration, not an inference.** Nothing here fires on a repo whose author has not said the project can be run. That is what keeps the reversal in STE-505 narrow enough to argue.
- **STE-506 is the smallest FR and the one that makes the rest honest.** A contract the shipping repository exempts itself from is a contract nobody has run.
- **The slug heuristic is deliberately not widened.** Adding conformance and smoke shapes would make this repo discoverable and would also make discovery guess more often, at the cost of the property that makes the offer trustworthy. The narrow net plus an explicit declaration is strictly better, and AC-STE-506.2 records that as a decision so it is not quietly revisited.
