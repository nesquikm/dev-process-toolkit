# Implementation Plan

## M136 — The Ratchet That Never Ran {#M136}

**Goal:** Make M132's skip ratchet execute. Its read side runs at step 14 of every `/implement` and treats an absent baseline as a refusal ground; its write side has never fired once in this repository. Two independent gates stand in front of the only caller — an optional `branch_template:` key this project does not set, and a `git checkout -b` an already-acceptable branch never performs — and the capture point they guard is wrong anyway, because `/spec-write` cuts the branch AFTER writing the FR files. This milestone re-chooses the capture point, gives the capture an order that always fires, replaces the scalar comparison with a named one, and makes an unmeasurable baseline refusable with a command the reader can run.

**Prerequisites:** M135 merged (v2.73.1). Serial invariant only — no FR here depends on anything M135 introduced.

**Release target:** v2.74.0 (provisional; MINOR — the set is mixed, two `Added`, one `Changed`, two `Fixed`). **The bump trap must be falsified BOTH ways and the pair reported at ship**, per the M135 finding: `inferBump` reads a camel-cased `changelogCategory` while the frontmatter writes the snake-cased `changelog_category`, and on M135 — the program's first pure-fix milestone — the two disagreed by a whole release line, the wrong key asserting six `Fixed` FRs were additive. This set is mixed, so the readings are expected to agree; **an agreement is not a pass unless both were run and both numbers are stated, naming which key was fed.** Codename decided at `/ship-milestone`.

**Migration:** `none`. The store this milestone reshapes lives at `.dpt/skip-baseline.json`, which `.dpt/.gitignore` keeps untracked, so no consumer artifact under version control changes shape. The v1 records a project may hold locally are dropped by the reader with no operator action and are reported by name when dropped. No consumer-authored file gains or loses a key.

**Scope boundary — deliberately excluded, not to be folded in:**

- **No new `/gate-check` probe.** Registering probe #82 moves counts pinned across roughly two dozen test sites, and STE-531's guard is equally binding as a test in the suite that IS the gate. The reachability probe's own pin is re-measured (AC-STE-531.4); nothing else about it changes.
- **No general "does this order fire" classifier.** STE-531 closes the gap for the skip-baseline order alone. Modelling the firing condition of an arbitrary ordered reference would be a partial model reporting confidently, which is worse than the existing honest silence.
- **Flutter identity extraction.** STE-529 covers the junit format, which bun and pytest both emit. Flutter's machine format is different and takes the documented scalar degrade rather than a guess.
- **The four unrelated carried findings** — the NFR-1 line cap pinned at the wrong number, the README `kind: regex` codename staleness, the unguarded sibling-surface class, and M130's two shipped HIGHs — stay carried. None is on this subject.

**Measurement this milestone rests on**, taken on 2026-08-26/27 at commit `9b420ec`, and correcting a mechanism the project memory had recorded twice and wrongly:

| primary working tree | 10077 | **15** |
| detached worktree, same commit | 10065 | **27** |

Identical tree bytes, identical test count (10092 across 495 files), zero failures both. The twelve differing tests guard on capture fixtures `.gitignore:13` deliberately ignores; eight more of the fifteen turn on an absent python documentation tool and one on an environment variable. **The skip count is a property of the tree, the git-ignored local state, and the installed tooling together.** This disqualifies a merge-base worktree measurement outright — it renders a delta of minus twelve with no code behind it — and it is why the capture must happen in place, in the same checkout, on a clean trunk.

**Pre-work baseline for this milestone's own branch:** 15, measured on clean `main` at `9b420ec` before any FR file was written.

### Follow-ups carried out of M136

Each is a MEASUREMENT taken during this milestone, not a suspicion. None is closed by it.

1. **`implement_report_evidence.ts` is unreachable AND invisible to the guard built for that class.** Measured with the shipped `buildModuleGraph`: `entryPoint=false`, `nonTestImporters=[]`, `reachable=false`. It is the module that renders **every** `/implement` report's `## Verification evidence` section, so it is a module the reader is expected to use and nothing can run. Probe #81 never flags it because `classifyReferenceLine` scores BOTH of its references — `skills/implement/SKILL.md:284` and `docs/implement-reference.md:229` — as `descriptive`: the phrase "render … through … from" carries none of the `ORDER_PHRASES`. **`descriptive` is therefore a hiding place**: an unrunnable module named in prose the classifier does not read as an order is invisible to the reachability guard entirely. AC-STE-531.5 records this limit and MONITORS it (a real non-test value importer, or one reference made ordered, reddens the note's legs) — it does not close it. Closing it means either giving the module a front door or teaching the classifier that "render X through Y" is an order; both are real decisions, neither was in M136's scope.

2. **M136's own guard catches 2 of the 6 recurrences it was written against.** Proven, not estimated: mutating `capture_skip_baseline.ts`'s entry point to `if (import.meta.main) { process.exit(0); }` — the exact M132 shape, a front door that exits clean and calls nothing — reddens 10+ legs across AC-STE-531.2 and .3. It would NOT have caught the other four (`classifySkipSetDelta`, `skip_identities`, the `skipNames` supply site, `gate_capture.ts` itself), because `ORDERED_MODULE` is the literal string `capture_skip_baseline` and the verdict grades only `typeof record.skipped === "number"`. The FR's Technical Design declares that scope deliberately ("the generalisation to all orders is deliberately NOT attempted"); this records what the declared scope costs.

3. **The measured skip-verdict lines still say "at the branch point".** `measuredAgainstBaseline` renders `N now vs M at the branch point (delta D)` on every `pass` and `fail` row, and the baseline is no longer taken at a branch point — STE-527 re-keyed it to the trunk commit. The phrase is byte-pinned by AC-STE-530.7, which exists to stop a silent reword during the enum extension and did its job. Changing it is therefore a deliberate, tested reword that has to move the pin with it, which is a decision rather than a fix. The **refusal** lines, which are the ones that tell a reader what to do, were corrected in M136.

4. **`skills/implement/SKILL.md` is at 358 lines against a 358-line pin — zero headroom.** The next line added to that file cannot be added without moving a pin or giving a line back. Two further traps were measured while working there, both worth knowing before anyone edits it: the pins measure `split("\n").length`, which is ONE GREATER than `wc -l`; and `tests/m120-ste-444-jira-binding-prose.test.ts:510` positionally pins probe #26's row at `skills/gate-check/SKILL.md` line 81, so edits above that line must be strict byte-trades rather than merely cap-respecting.

5. **`captureBaselineCommand`'s "one spelling" promise is not true of the shipped surfaces.** STE-530's Technical Design says the command in the refusal and the command in the skill are the same string from the same function. Measured: the composer emits an absolute path, while the three shipped fences emit `${CLAUDE_PLUGIN_ROOT}`-relative forms, and they differ in the quoting of `<projectRoot>` as well. Markdown cannot call a function, so the achievable form is a test that renders the composer and matches the fence modulo placeholder. No test references `captureBaselineCommand` at all today.

6. **`skip_baseline.ts` is 1200 lines and fuses six concerns.** Raised by the Phase 3 Stage B quality review and NOT fixed here; recorded with the reason. It was 311 lines at the merge-base and now holds versioned-envelope storage, git checkout/trunk identity, the capture precondition guard, capture + migration, scalar and set classification, and human-facing rendering. The reviewer named a clean seam — the rendering half (`renderSkipVerdict`, `incomparableLine`, `entryCommand` and the command composers) depends only on the `SkipVerdict` type and touches no mutation anchor. **Why it was not taken:** extracting it gives `deliver_stage_evidence.ts` a SECOND local import, and the AC-STE-530.4 harness materialises that module beside a hand-built stub tree, resolving exactly the relative imports it copied. A second specifier dangles there. So the extraction is gated on reworking that harness, which is real work and was not worth starting at the end of this milestone. The seam is real and the reason it is still there is a test harness, which is worth knowing before the next attempt.

7. **Capture and checkout-id minting are non-atomic, with no lock.** Also from the Stage B review. `readCheckoutId` is check-then-write and `captureSkipBaseline` is read-modify-write; two concurrent runs against the same fresh checkout, or the same trunk sha, can each pass their precondition before either writes. The "first capture for a sha wins" rule the module calls load-bearing is therefore not enforced against concurrency. Severity is genuinely low — capture only fires on a clean trunk, and two racing captures at the same sha in the same checkout would write the same number — and every failure mode is fail-SAFE (a mismatched checkout id refuses as `incomparable`, never passes falsely). The toolkit already ships a lock idiom at `.dpt/locks/`; using it here is the obvious fix if this ever matters.

8. **A record-level anchor marker was NOT added, and the reason bounds the risk.** Skip identities are now anchored on the git working-tree top, so a baseline and a run captured from different roots share an identity space. A record written BEFORE that fix stores raw cwd-relative names; where the capture ran at the top of the working tree — which is what `capture_skip_baseline` does, and the only shape its own trunk/sha resolution supports — the old and new strings are byte-identical and keep comparing correctly with no migration. A capture taken from a SUBDIRECTORY is the one case that moves, and it does not mis-compare subtly: every stored name carries a directory prefix no current build can emit, so the whole set goes disjoint and presents as "everything is new" rather than a plausible one-test delta. Stamping the anchor into the record would make that mechanically detectable rather than merely visible, and was declined here because it changes `SkipBaselineRecord`'s shape, which AC-STE-529.8's byte-identity legs and STE-530's export discovery both pin.

**How defect 8's parent was found, because the method is the transferable part.** Nothing in 44 ACs and five per-FR audits caught it. It surfaced when the milestone's own step-14 evidence was rendered through the shipped renderer against a baseline captured on real trunk — a baseline taken from the repo root, met by a run taken from the plugin directory. The verdict came back FAIL naming all fifteen skips as newly introduced on an unchanged tree: a confident wrong answer, strictly worse than the count-only weakness the milestone was convened to fix. No test caught it because no test had ever captured from two different roots. **Dogfooding the deliverable against the repository that produced it found what the tests for it could not.**
