# Implementation Plan

## M129 — Deliver Pipeline Contract Repair and Resume {#M129}

**Goal:** Repair the `/deliver` orchestrator contract against two 2026-08-17 field reports from a live three-repo run, and give the pipeline the two entry shapes it lacks — a milestone that names its own repo, and a milestone resumed mid-pipeline.

**Prerequisites:** M128 merged (v2.67.1). No hard coupling; the ordering is the program's serial invariant.

**Release target:** v2.68.0 "Compact" (provisional; minor — five `Added` FRs alongside two `Fixed`)

**Migration:** `none` — every change is additive with unchanged defaults. The optional plan-level target-repo declaration, the gate taxonomy, and the conversational merge-policy override all leave existing consumer artifacts behaving byte-identically when they say nothing.

### Findings about the process, not the code

These are recorded as first-class findings because each is a statement about how this milestone was built, and none of them is visible from the shipped diff alone.

**1. We repaired a defect class in FR 1 and reproduced it in FR 5.** STE-492 exists because `/deliver`'s operative skill file dropped a contract that lived only in `docs/deliver-reference.md` — a file the skill itself marks *"not required reading"*, immediately after saying *"The sections below are sufficient to operate"*. Four FRs later, STE-495 landed every target-repo routing rule into that same optional reference and **nothing at all** into `skills/deliver/SKILL.md`, which still stated the unconditional inline-phases clause and the unconditional single chain with no branch. A live run would never have learned the routing existed.

No cap pressure excused it: the skill was 119 of 358 lines. The audit caught it and rated AC.3/AC.4 Partial on exactly that ground.

What the FR-1 fix did not capture, and what this second instance teaches: **the optional-reference surface is load-bearing by default.** "Not required reading" is not a description of that file, it is an instruction the next author will follow — including the next author who has just finished repairing the damage it caused. A fix that moves one contract onto the operative surface does not change where the *next* contract will be written. That is a property of the two-surface split itself, and it is why STE-492 AC.2 asserts cross-surface agreement rather than merely asserting the SKILL's content.

**2. Three predicate/routing splits are one design finding, not three incidents.** STE-492's capture predicate disagreed with routing it grades three separate times in this milestone, each found by a different mechanism:

| # | The split | Found by |
|---|---|---|
| 1 | prose promised `milestone` and `gate` both omit on a reduced chain; the predicate demanded a concrete `milestone` | the STE-492 `/tdd` audit |
| 2 | the predicate hand-rolled `/^M\d+$/` while three mint paths emit three shapes | the worker, unprompted — no AC named it |
| 3 | the predicate validated `stage:` against the full-ceremony triple while routing added `work` and `spec-write` | the STE-495 refactor pass |

Every one is the same shape: **one source of truth split into two copies that then drifted**, and in every case the consequence was identical — fixture group 14 would have failed a *healthy* run. The grader failing correct work is worse than the grader missing incorrect work, because it trains operators to ignore it.

`DELIVER_STAGE_IDS` is now the single stage vocabulary and `milestone_token` the single identity grammar, so a fourth instance cannot take either of those forms. The general defence remains cross-surface agreement asserted directly, which is what AC-STE-492.2 already requires.

**3. A clean audit is weaker evidence than it reads.** The STE-496 audit explicitly *cleared* the `--draft` flag path — "the `--draft` flag path is unaffected" — and the path was defective: `--draft,` and `--draft.` matched nothing, so a punctuation-terminated flag was neither detected nor stripped and the run silently opened a normal pull request. Two of the three defects found after that audit (the whole-utterance negation window and the punctuation-terminated flag) are the **silent-downgrade class AC-STE-496.5 exists to prevent**, reached through paths the AC did not name.

This calibrates what a clean audit buys: it confirms the paths it examined, and its confidence about a path it did not exercise is worth no more than a guess. Both defects were found by *running the parser over adversarial inputs*, not by reading it.

### RESOLVED cross-FR intersection — AC-STE-498.4 amended (operator decision, 2026-08-17)

**Both readings named, and the amendment recorded here because an AC that changed after its FR went green is the first thing a reviewer must see.**

Found by the STE-498 refactor pass, after both FRs had shipped green.

| AC | Rule as originally written | Status |
|---|---|---|
| **AC-STE-498.4** | `/spec-write` passes for review-flagged FRs run **inline in the invoking session, never in a spawned worker** | **AMENDED** — scoped by target repo |
| **AC-STE-495.3** | a milestone targeting **another toolkit repo** runs its spec-writing **inside that milestone's worker**, so tracker and specs bind to the target tree | unchanged, stands as shipped |

**The collision.** A *resumed* milestone declaring a `target_repo:` at another toolkit repo **and** carrying review-flagged FRs satisfied both preconditions, with nothing ordering them. AC-STE-498.4's own rationale — that any `/spec-write` in a worker is the forbidden Socratic proxy — additionally read as an indictment of AC-STE-495.3's shipped route.

**The evidence the decision rested on.** The prohibition `/deliver` actually carries is *"answering on the operator's behalf, paraphrasing, or pre-filling answers"*, plus batching — a rule about **who answers and how the question is conveyed**. The only *where*-based statement anywhere in the toolkit is a **cost** argument in `docs/deliver-reference.md`: *"running it in a spawned worker inserts a relay hop into every question."* That cost is **zero** for a **visible** worker the operator types into directly — no relay hop, therefore no proxy. `never in a spawned worker` was over-broad phrasing, not a load-bearing invariant.

**The amendment.** Placement now follows the milestone's route: inline for the invoking repo, inside the target repo's worker for a declared cross-repo toolkit target. The Socratic guarantee is stated identically on both branches — `/deliver` never answers, paraphrases, pre-fills, or batches, wherever the skill runs. The rejected alternative (forcing cross-repo resumes inline) would have broken the tracker/specs binding AC-STE-495.3 exists to establish — a real capability loss to preserve a phrase protecting nothing extra.

**Second face, fixed by the same decision.** `resumeChain` had no target-repo awareness and always emitted the full `/implement → /ship-milestone → /pr` tail, so a resumed milestone whose target repo has no toolkit received a chain naming two stages that cannot exist there. It now takes the resolved route and emits the reduced chain (`/work`, `/pr`).

**Process note, deliberately preserved.** The implementing session **declined to resolve this on its own**, because adopting the reconciliation would have closed an AC by reinterpretation — which its brief forbade. It shipped a fail-safe interim (name the collision, ask the operator), escalated with all options and the evidence, and the operator chose the amendment. That sequence is the record: the worker was right to refuse, and right that the reconciliation was probably correct; those are not in tension, and only one of them was the worker's call to make.

**Mutation evidence for the amendment** (it changed shipped behaviour, so it carries its own): dropping the cross-repo branch kills 2 tests, dropping the reduced branch kills 2, and ignoring the route entirely — exactly the pre-amendment behaviour — kills 3. The operative-surface clause is pinned so a future trim still goes RED, re-pointed from the interim wording to the scoped rule.
