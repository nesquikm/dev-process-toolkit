# Implementation Plan

## M133 — Executable Delivery Decisions {#M133}

**Goal:** Make the delivery pipeline's placement decisions executable rather than prose. Every module `/deliver`'s SKILL.md orders "never by eye" is unreachable at runtime — none of the eight carries an `import.meta.main` entry point, and `runResume` has no consumer outside its own test file, so `placement: "worker"` lives only in a data structure no real run materializes. Measured on M130 (2026-08-24): the ceremony ran inline in the orchestrating session, the confirm gate was never presented, the spawn pre-flight probe never fired, and the worker narrated a by-eye classification in the modules' own names. This milestone gives the decision one runnable front door, makes the confirm gate render that command's bytes rather than a retelling, and makes a spawn a thing the report cannot fake.

**Prerequisites:** M132 merged (v2.71.0). STE-516 grades the `summary` section of the `deliver-stage-result` fence STE-510 raised to 26 lines, and rides the fixture group STE-492 registered. Real dependency, not merely the serial invariant.

**Release target:** v2.72.0 (provisional; minor — two `Added` FRs alongside three `Changed`). Codename decided at `/ship-milestone`.

**Migration:** `none` — the front door, the receipt and the reachability probe are all toolkit-internal. No consumer-authored file changes shape, and no consumer artifact gains or loses a key.

### Deviations from the approved design

Three, all measured rather than argued, all recorded here because a spec that silently departs from its design is worse than one that says so.

1. **Reachability rule corrected.** The design defined it as an entry point present AND at least one non-test consumer. Measured, that rule calls nine shipped modules unreachable that are working command-line front doors — `capability_row_assert`, `claim_witness_assert`, `classify_diff`, `fork_tdd_result_assert`, `harness_artifact_paths`, `smoke_verdict`, `socratic_first_turn_assert`, `template_source_analyzer`, `upgrade_staleness` — the last of which is probe #69's own entry point. It would also condemn this milestone's new front door on the day it ships, so the fix would fail its own test. The rule becomes: an entry point present, OR transitively imported by something carrying one. The second clause's purpose survives intact — the resume classifier carries no entry point and has no non-test consumer at all, so nothing with an entry point reaches it, and `runResume` stays exposed.
2. **Scan scope widened from "found in a skill" to both shipped trees.** Skills-only leaves an evasion hole: move an order into the docs tree and it escapes the check, which is documenting a claim away rather than fixing it. Four references are ordered and unreachable in the docs tree today — two in the setup reference, one in the skill-anatomy doc, one in the setup-template reference. It also keeps the existing shared walk rather than forking a narrower second answer. Not widened past that pair, which is the engine's existing scope.
3. **The ordered classifier is line-scoped, not file-scoped.** The design points at the shared engine, whose phrase test is file-scoped. Reused verbatim that would classify every reference in any file containing one carrier phrase as ordered, collapsing the distinction the three classes exist to draw. The question is per-reference, and a proximity window reaching into adjacent pre-existing text is the wrong-subject shape recorded here twice.

### Numbers deliberately NOT carried from the design

The design states "136 module references, 128 with no CLI entry". Measured now, the skills tree alone holds 193 distinct surface-module pairs in path form, and the design's own per-skill breakdown has drifted from disk. The design also states a 20-line fence cap; the cap has been 26 since STE-510. Neither number is pinned anywhere in this milestone. That the design's own hand-authored inventory went stale within a day is the argument for its own constraint — generated, never hand-authored.

### Risks

| Category | Risk | Severity | Mitigation |
|---|---|---|---|
| Vacuous guard | The assembly-only criterion is easy to satisfy by reading the source for branches, which proves nothing about whether a delegate is consulted | high | AC-STE-513.7 stubs each delegate and requires the output to move; a stub that changes nothing fails naming the delegate |
| Vacuous guard | Registering an already-correctly-classified gate passes a before-and-after verdict comparison either way | high | AC-STE-515.4 mutates the unknown-gate fallback and requires the classification to hold, with an unregistered control that must move |
| Wrong subject | An acceptance criterion asserting the gate was shown would have passed on the run that caused this milestone | high | AC-STE-514.4 uses that run's actual prose rendering as the falsifying fixture; a predicate that accepts it fails |
| External dependency | The ownership check couples to another plugin's script path and exit-code contract | medium | Accepted: the pipeline already hard-depends on that plugin — its pre-flight halts without it. Every documented exit code gets a case, driven through an injected runner |
| Fail-open | A guard that cannot run has a plausible reason to pass anyway, and two guards shipped fail-open one milestone ago | high | AC-STE-516.5 makes every non-zero outcome a named halt with no fall-through, and AC-STE-516.10 mutation-verifies that none of them produces a pass |
| Pinned counts | Two new probes flip counts across nine test files plus README | medium | Task 19 enumerates every pinned site; the contiguity assertion catches a missed one |
| Provenance | The three hand-off fixtures are hand-authored models; no spawned worker has emitted one | medium | Pre-existing and not closed here. This milestone narrows what a future genuine capture must carry rather than claiming the gap is shut |
