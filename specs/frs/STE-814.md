# The trend reports each run's own quality signals

## Summary

The trend pools its quality signals over a whole group, so no single run can be compared with another.
Each run now carries its own metrics and quality signals.
A value whose tracking switch is off reads as not observable and names that switch.
A value with no data reads as not observable, never as zero.
The pooled group values do not change.

## Requirement

Each `runs_detail` entry of the trend report carries per-run metric and quality-signal values computed from that run alone and gated by the same tracking switches as the group cells.

## Acceptance Criteria

- AC-STE-814.1: Each `runs_detail` entry carries `metrics` (`waste`, `tokens`, `time`) and `signals` (`gate_failure_rate`, `spec_review_gaps_per_fr`, `code_review_concerns_per_100_lines`, `post_merge_fixes`). Each value is computed from that run's own sessions and from the receipts and commits naming its FR, and the entry carries `notes`, a list of strings.
- AC-STE-814.2: A per-run value whose input tracking switch is off (the `INPUT_KEY` table) is `null`, and `notes` holds `<id>: tracking.<key> is off` for each such switch. The per-run computation receives the project's real switches; no switch is hardcoded `true`.
- AC-STE-814.3: A value with no observable input (no receipt of its kind, no gate run, git unreadable, a non-Conventional history) is `null` with a note naming why, never `0`. The `tokens` value is `null` for a run holding an incomplete fork row (STE-812).
- AC-STE-814.4: A session shared by two runs contributes its gate runs and code-review receipts to each run's own values, so per-run values are not additive. The group's pooled `signals` and `metrics` keep counting a session once, and their values on every existing trend fixture are unchanged.
- AC-STE-814.5: `docs/retro-reference.md` describes the per-run values, their switch gating and the shared-session rule.
- AC-STE-814.6: `bun test` from `plugins/dev-process-toolkit` reports 0 failures, and its skip identities equal the trunk baseline by name.

## Technical Design

Refactor `signalValues` in `retro_trend.ts` so that its per-session accumulation runs over a run list of length one for the per-run case, and over the window for the pooled case with the count-once set. `runValues` takes the switch set from `trackingOff`. The note text reuses `offNote`.

## Testing

Trend fixtures with each tracking switch off in turn, a shared session across two runs, a run with no review receipts, and an equality test of the pooled group output before and after on the existing STE-776, STE-784 and STE-796 fixtures.

## Notes

Per-run values are what a later trial compares with a baseline. This FR only reports them.
