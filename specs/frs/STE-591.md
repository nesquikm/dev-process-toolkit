# Sibling work is named by tracker ID, and the orphan remedy knows the sibling

## Summary

A path-shaped link to a sibling repository's FR always fails the traceability check, which resolves every link locally.
The gate and the plan template now say a sibling FR is named by its tracker ID alone.
The orphan remedy for an FR whose plan lives in the sibling stops asking for a second plan.
Pull requests for a spanning milestone carry the release's measured sibling rows.

## Requirement

Probe #23's rule is forced by its shipped regex, which matches every path form; only a bare tracker ID escapes. The rule is written into the probe row and the plan template, scoped to sibling FRs. Probe #27's orphan remedy gains a sibling arm naming the spanning declaration. `/pr` injects one `Spans:` row per sibling from the same front door the release uses.

- AC-STE-591.1: `skills/gate-check/SKILL.md`: the probe #23 row (located by `^23\. \*\*`) states that a SIBLING repository's FR is referenced by tracker ID only, edited in place; probe #26's row stays on line 81 and `tests/m120-ste-444-jira-binding-prose.test.ts` stays green.

## Technical Design

Probe #23's row is three lines above the line-81 pin, so its edit is a byte edit of one line. The remedy arm appends to the `orphan` string in `frontmatter_milestone_not_archived.ts`; its note keeps `orphan`. The `/pr` rows reuse the release's front door, so no second copy of the measurement exists.
