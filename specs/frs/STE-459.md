# Make M121's milestone-scoped test files survive their own archival

## Summary

Archiving this milestone turns the gate red with fourteen failures and raises the skip count from fifteen to eighteen. Six test files written here resolve their milestone plan and their FR files at the live path, with no archive fallback.

The fourteen failures are loud and stop the release. The three assertions that instead go quiet are the worse half: their guards exist to tolerate a checkout that ships no specs, archival is indistinguishable from that, and so the suite reports green while three fewer things are being checked.

The fallback conditional already exists in this repository and predates this milestone by thirteen. Six new files did not adopt it, because it is discoverable only by reading unrelated test files.

## Requirement

Give every M121 test file that reads a milestone-scoped spec artifact the house live-then-archive fallback, so that archiving the milestone changes neither the failure count nor the skip count; and add a meta-test so the next milestone-scoped test file cannot reintroduce the defect silently.

- AC-STE-459.2: Each of the six files resolves its `specs/` artifact with the house conditional `existsSync(active) ? active : archived`, in that shape — the form already shipped at `tests/m108-ste-393-docs-pins.test.ts:99` and `tests/m114-ste-416-linear-checkbox-doc-accuracy.test.ts:203`. No new shared helper is introduced: the repository has settled on a two-line conditional, and a seventh abstraction for six call sites would be one more thing to keep in sync. {#AC-STE-459.2}
- AC-STE-459.3: With this milestone's FRs and plan archived, the full gate reports **zero failures AND a skip count equal to its pre-archive value**. A green gate at a higher skip count does NOT satisfy this criterion — both numbers are the assertion, because fixing only the half that screams is the failure this FR exists to prevent. {#AC-STE-459.3}
- AC-STE-459.4: The three assertions that previously skipped on archival — `m121-ste-455`'s AC-STE-455.5 block and `m121-ste-458`'s two AC-STE-458.1 tests — RUN against the archived artifact rather than skipping. Any assertion that genuinely cannot run carries its reason in the test name rather than a bare `describe.skip`. {#AC-STE-459.4}
- AC-STE-459.5: `m121-ste-458`'s git-history query spans the live AND archived paths, concatenated **archive-first** so newest-first ordering holds across the union and `FR_COMMITS[length - 1]` still resolves to the authorizing commit rather than to the archive commit. {#AC-STE-459.5}

## Technical Design

The six files and what each binds:

| file | artifact bound at the live path | archival behaviour before this FR |
|---|---|---|
| `tests/m121-ste-445-derivation-falsifiability.test.ts` | `specs/plan/M121.md` | 3 hard failures |
| `tests/m121-ste-446-leg-set-authority.test.ts` | `specs/frs/STE-446.md` | 3 hard failures |
| `tests/m121-ste-452-termination-harness.test.ts` | `specs/frs/STE-452.md` | 1 hard failure |
| `tests/m121-ste-457-mode-none-claim-instruction.test.ts` | `specs/frs/STE-457.md` + `specs/plan/M121.md` | 7 hard failures |
| `tests/m121-ste-455-plan-id-equality-correction.test.ts` | `specs/frs/STE-448.md` | 1 silent skip, unlabelled |
| `tests/m121-ste-458-capture-artifact-identity.test.ts` | `specs/frs/STE-458.md` | 2 labelled skips |

**Five of the six take the plain conditional.** The artifact is read as text and the only question is where it lives.

**`m121-ste-458` does not, and a plain conditional there would be a regression rather than a fix.** Its path constant feeds `commitsTouching`, which runs `git log --diff-filter=AM -- <path>`. After the rename, the archived path's history contains exactly one commit — the archive commit itself, an `A` — because `git log` without `--follow` does not cross a rename, and the live path's `D` is excluded by the `AM` filter. So a single-path fallback to the archive path leaves `FR_COMMITS` holding one commit that is not an ancestor of any code commit, `authorizing` filters to empty, and the deliberate non-vacuity assertion `expect(authorizing.length).toBeGreaterThan(0)` turns a silent skip into a hard failure.

The union is therefore required, and its **order is load-bearing**. `FR_COMMITS[FR_COMMITS.length - 1]` is read as the oldest commit — the one that authorized the work — and the second AC-STE-458.1 test asserts it is an ancestor of every code commit. Concatenating live-first would put the archive commit last and assert the archive commit authorized the code, which is false and would fail. Archive-first preserves newest-first across the union: post-archive the archive commit is the newest, and pre-archive the archived path contributes an empty list, so the expression degenerates to today's value by construction rather than by coincidence.

Deliberately NOT used: `--follow`. `specs/plan/M121.md` proves the hazard for the plan side and `plan_identity_mode_conditional` proves it for provenance — content-similarity matching launders one template-shaped artifact into another. The union of two explicit paths has no similarity heuristic in it.

## Testing

The meta-test (AC.6) is the durable half: it globs `tests/m121-*.test.ts`, finds every string literal binding a `specs/frs/` or `specs/plan/` path, and requires the same file to name the corresponding `archive/` path. It fails against the pre-fix tree — that is the measurement, not the intention.

AC.7 is what separates a fix from a quieter skip. For each of the six, the resolved path is asserted to exist and the consuming assertion is asserted to have run: a file whose guard now skips more cleanly satisfies "zero failures" and fails this.

The load-bearing mutation for AC.5 is to swap the concatenation order in `m121-ste-458`. Both orders are green pre-archive and only archive-first is green post-archive, which is the asymmetry proving the order is doing work rather than decorating it.

Full gate green from the plugin root, measured twice — once with the milestone live and once with it archived — with the failure count AND the skip count recorded for both.

## Notes

Found on the milestone's last action, after it had twice been described as finished. That is the honest provenance and it is written here rather than smoothed over: nothing in thirteen FRs of falsifiability work looked at whether the suite survives the archival that every milestone ends with, because the gate is always run against a live tree.

This is the third distinct instance in M121 of an assertion that stops being about its subject while the suite reports green — after the AC-STE-448.9 anchor relocation and the once-occurring-token pin, both recorded at `specs/notes/follow-ups.md` § 0i. Those two were found by mutation inside the milestone. This one was found by performing the archive.
