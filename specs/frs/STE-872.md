# A Bun startup crash in a test child is named, and v3.10.0's small fixture gaps close

## Summary

Bun sometimes crashes at startup and turns a random test red.
The failure looked like a product bug.
Tests now say when a child process was killed by a signal.
The Jira test data gains the request fields and the old answer shape it lacked.
A custom v2 bug type must be confirmed before it is used.

## Requirement

A crashed test child is named as a crash and still fails, the Jira create-metadata fixtures match recorded requests and answers on both surfaces, and a v2 issue type of unknown level is accepted as a bug type only when it is known or declared standard.

## Acceptance Criteria

- AC-STE-872.1: One shared test helper reads a finished `Bun.spawnSync` or `node:child_process` result and, for a signal-killed child, gives an error text naming the signal, the command and that the child did not exit on its own. A child killed by its own timeout is named as a timeout instead. It never retries and never turns a failure into a pass.
- AC-STE-872.2: The shared test runners under `tests/` that start `bun` and return its exit code use that helper, and so does each test file that failed in the two recorded red runs of v3.10.0. An exit code derived from a signal is never 0. A test asserts, over the runner modules' source, that none collapses a null exit code without the helper.
- AC-STE-872.3: A test starts a child that kills itself with SIGTRAP and reads the signal in the helper's text; a child that exits 1 on its own gives no signal text.
- AC-STE-872.4: The create-metadata fixtures hold the recorded request with `requiredFieldsOnly` and `startAt`, for v2, as the documented AC-field read sends it. Every key, site, id and name is invented.
- AC-STE-872.5: A v1 create-metadata answer is recorded by a read-only call and kept as a sanitised fixture with its request. `discover_field.ts` reads it through its stdin front door. Where the recorded envelope differs from `{fields, startAt, total}`, the reader accepts the recorded shape and still refuses a page chain that is not whole.
- AC-STE-872.6: A bug type whose listing row has no numeric `hierarchyLevel` passes when its name is exactly `Bug`, `Task` or `Story`, or when the binding declares `jira_bug_type_standard: true`. Any other name refuses and the refusal names that setting. `subtask: true` and the name Epic in any case refuse even with the setting on. A numeric level decides as today whatever the setting says.
- AC-STE-872.7: `jira_bug_type_standard` is a boolean under `task_tracking.jira` and the legacy `### Jira` sub-section; another value refuses in the NFR-10 shape. The `bug_tracker_type.ts` front door reads it from the binding through an optional project-root argument, and `/spec-write`, `docs/resolver-entry.md` and `adapters/jira.md` show that form.
- AC-STE-872.8: A mutation that drops the known-name check, the setting, or the Epic refusal turns a named test red.
- AC-STE-872.9: `bun test` from `plugins/dev-process-toolkit` reports 0 failures, and its skip identities equal the trunk baseline by name.

## Technical Design

The helper generalises the signal text in `create-front-door-shared.test.ts` into a `tests/_child_result.ts` module that imports only node builtins. The bug-type check gains a `declaredStandard` input; `checkJira` keeps one level rule. The front door's new argument is optional, so existing calls keep working, and without it an unknown level is judged by name alone.

## Testing

Helper unit tests with real killed children, fixture reads through the front door, and bug-type cases for both listing shapes.

## Notes

Bun is not upgraded here: 1.4.3 reds two older tests on main. Every recorded v2 listing lacks a level. Operator choice 2026-11-25: known names pass, custom names need the setting.
