# STE-432: Extract the toolkit-managed predicate and guard probe #18 with it {#STE-432}

## Summary

Probe 18 asserts that a project's CLAUDE.md carries a Docs section. Its only scope check is whether that file exists, so it fires on any project that wrote its own CLAUDE.md — which is most of them, since that file is a Claude Code convention rather than a toolkit one. The severity is error, so it turns the whole gate red on a tree the toolkit never bootstrapped, and its remedy tells the operator to paste toolkit content into a file the toolkit does not own.

Every sibling probe reading the same file already guards on either the setup marker or the declared tracker mode. Fifteen modules read that file; thirteen guard correctly. Probe 18 is the only one that guards on nothing.

The managed-tree question is currently answered by hand in five places, with three different regular expressions for the same heading. This extracts it into one module and routes probe 18 and probe 69 through it.

## Requirement

Probe #18 `claudemd_docs_section` MUST be vacuous on any tree the toolkit does not own, and the managed-tree predicate MUST have exactly one implementation that probe #69 also consumes.

Verified against v2.57.1 at `edd8eaf`:

- **The defect.** `adapters/_shared/src/claudemd_docs_section.ts:37` — `if (!existsSync(claudeMd)) return { violations: [] };` is the only early return before the heading test at `:43`. The module header at `:8` states the false equivalence outright: *"Vacuous when CLAUDE.md is absent (project not toolkit-managed)."*
- **Reproduced.** A `CLAUDE.md` containing only `# Stock Check App` and `## Tech Stack` yields **1 violation** from probe #18, **0** from probe #19, **0** rows from probe #69 — same input file, opposite verdicts.
- **The outlier count.** Of the fifteen modules under `adapters/_shared/src/` that read `CLAUDE.md`, thirteen already guard on the marker (`setup_audit_section_presence.ts:60`, `toolkit_bootstrap_committed.ts:130`, `bun_zero_match_placeholder.ts`, `upgrade_staleness.ts:98`) or on the declared mode (`setup_output_completeness.ts:40-44`, `task_tracking_canonical_keys.ts:68-72`, `task_tracking_workspace_binding_present.ts:82-86`, and five more). Probe #18 is the sole outlier.
- **Five open-coded sites, not four.** The four marker-reading modules above, plus `skills/upgrade/SKILL.md` Step 0 in LLM-evaluated prose. Three divergent `## Docs` regexes coexist: `/^## Docs\s*$/m`, `/^##\s+Docs\b/m`, `/^##\s+Docs\s*$/m`.
- **The constraint that decides the design.** This repo's own `CLAUDE.md` carries **zero** occurrences of the setup marker (`templates/CLAUDE.md.template:1` is the marker, and this file was never written by `/setup`), but does carry `## Task Tracking` at line 107. A marker-only guard would make probe #18 permanently vacuous on the one tree where it currently has teeth.

- AC-STE-432.4: `runClaudeMdDocsSectionProbe` returns exactly one violation for a `CLAUDE.md` carrying a `## Task Tracking` heading and no real `## Docs` heading.
- AC-STE-432.5: Probe #18 ignores the `docs_section` signal — a `CLAUDE.md` whose only managed signal is a `## Docs` heading is treated as unmanaged by probe #18 and yields zero violations.
- AC-STE-432.6: The existing HTML-comment fixture in `tests/gate-check-claudemd-docs-section.test.ts` is amended to also carry a `## Task Tracking` heading, and still asserts exactly one violation.

## Technical Design

**One module, one signal vocabulary, per-probe acceptance policy.** The predicate implementation is shared; the decision about *which signals a given probe accepts* stays visible at each call site:

- Probe #69 Step 0 calls `isToolkitManaged(root)` — behaviour-identical to today.
- Probe #18 calls `isToolkitManaged(root, { ignore: ["docs_section"] })`. Accepting `## Docs` as evidence of managed-ness inside the probe that asserts `## Docs` exists is circular; passing `ignore` makes the carve-out greppable instead of implicit.
- Probes #19 and #22 use `detectManagedSignals(root).includes("setup_marker")`.

**AC-STE-432.9 is a regression fence, not a formality.** Probes #19 and #22 assert invariants only `/setup`'s own write path can create — the `## /setup audit` section and the bootstrap commit. This repo is a managed tree that `/setup` never wrote: `## Task Tracking` is present, `hasDefaultApplicableOutcomes` returns true because `## Docs` is present, and there is no `## /setup audit` heading anywhere in the file. Widening probe #19 to the marker-or-section form would therefore turn this repo's own gate **red**. That is the single most dangerous naive move available here.

**Why `docs_section` is excluded rather than left in.** Leaving it in also satisfies every fixture today — but only by accident: the guard would read the raw file while probe #18's assertion reads the comment-stripped file, so the HTML-comment fixture passes on an asymmetry rather than on intent. A later cleanup that normalized both sides would silently vacate that fixture with no test failure. AC-STE-432.6 makes the fixture explicit instead.

**Shape.** Synchronous, `readFileSync`-based. Probe #69 currently reads via `fs/promises`; calling a sync helper from its async body is behaviour-neutral, and its test suite pins behaviour rather than the read mechanism. The helper never throws — an unreadable file returns `false` — following the STE-394 precedent that a crashed gate is strictly worse than a failed one.

**Guard rails — tests that MUST NOT change:**

- `tests/gate-check-upgrade-staleness.test.ts` — every assertion, unmodified.
- `tests/m111-ste-411-upgrade-hint-pins.test.ts` — the byte-pinned hint literals.
- `tests/gate-check-toolkit-bootstrap-committed.test.ts` and `tests/gate-check-bun-zero-match-placeholder.test.ts`.
- Fixtures (a) through (e) of `tests/gate-check-claudemd-docs-section.test.ts` keep their current expectations. Only fixture (f) is amended, under AC-STE-432.6.

**Deferred residual — recorded so it stays findable.** `skills/upgrade/SKILL.md` Step 0 decides managed-ness in LLM-evaluated prose; the `upgrade_staleness` CLI call it makes serves only the legacy-monolith hint. That is a sixth site, and converting it to a deterministic CLI would honour the deterministic-gates-over-judgment principle. Deliberately out of scope: its prose definition currently matches the helper exactly, so the exposure is drift risk rather than a live defect, and the refusal path it would touch is byte-pinned.

## Notes

The field report that prompted this FR proposed a pure marker guard as the cheapest fix. It is refuted: a marker-only guard breaks two existing fixtures and makes this repo's own regression fence vacuous — while the repo-baseline test at `tests/gate-check-claudemd-docs-section.test.ts:136-148` stays **green**, because it asserts an empty violation list and a vacuous probe satisfies that trivially. AC-STE-432.12 converts that test into a two-sided assertion so the same trap cannot be set again.

The report also claimed the existing suite "only covers the marker-carrying case". The opposite is true: fixtures (a) through (f) contain zero occurrences of the marker, so the marker-carrying case is the one that was never covered. AC-STE-432.3 adds it.

Severity stays **error**. Once the guard lands, every tree probe #18 can fire on is a tree the toolkit wrote or maintains, where a missing `## Docs` section is the toolkit's own defect. Probe #69 is warn-only for a different reason — it reports drift the operator inherited from an older toolkit, which must not block a merge.
