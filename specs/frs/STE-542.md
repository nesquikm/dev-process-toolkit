# Classify, check, and record external links when they are authored

## Summary

Specs cite external resources, and those links rot without anyone noticing. The scanner that walks reference sections drops anything carrying a scheme, so an external link today is not merely unchecked. It is invisible.

Not every link deserves the same treatment. One an implementer must open is load-bearing; a link to a terms page is a courtesy.

Only the author can tell them apart, so the classification is made once, by a human, when the link is added.

## Requirement

Each external link supplied during spec-writing is classified as required for implementation or informational, checked for reachability at that moment, and written into the spec with its verdict and the time of the check. A host that answers with an authorization challenge counts as reachable. A check that cannot run records that it did not run, rather than recording a failure.

## Acceptance Criteria

- AC-STE-542.1: Each external `http` or `https` link supplied during a run is classified one at a time through an ask-tool call, defaulting to informational; the classifications are never batched into one prompt.
- AC-STE-542.2: A required link is written as a list item under `## Design References`; an informational link under a new `## External References` section, created immediately after `## Design References` when absent.
- AC-STE-542.3: `/spec-write` performs the reachability check at authoring time and records the verdict inline in the shape `` - `<url>` — <caption> (checked <ISO8601>: reachable|dead) ``, which round-trips through the scanner that will grade it.
- AC-STE-542.4: Response mapping is exact: `401` and `403` are reachable; DNS resolution failure, connection refused, `404`, `410` and any `5xx` are dead; `2xx` and `3xx` are reachable.
- AC-STE-542.5: `scan_design_references.ts` stops discarding tokens carrying a URL scheme and emits them as their own row kind with no on-disk resolution attempted; every repo-root-relative path row is byte-identical to today.
- AC-STE-542.6: When the check cannot run at all, the link is recorded as unchecked and never as dead, and the run surfaces a capability row saying the check did not run.
- AC-STE-542.7: A run whose specs cite no external link is vacuous — no classification prompt, no request, no record — asserted as a request count of zero.
- AC-STE-542.8: `docs/layout-reference.md`'s closed-set claim — that the three named optional sections are the only ones — is widened to admit `## External References`, and a tripwire asserts the superseded sentence is gone, following the precedent set when `## Summary` widened that same list.

## Technical Design

New `adapters/_shared/src/check_external_link.ts`: pure `classifyLinkVerdict(probe)` returning `reachable | dead | unchecked` per AC.4, plus an `import.meta.main` CLI shim printing one verdict line — modelled on `check_marker_runtime.ts`. `scan_design_references.ts` keeps `scanDesignReferences` byte-identical; the line-51 URL rejection feeds a NEW sibling export `scanExternalReferences(projectRoot)` walking `## Design References` and `## External References`. A URL must never become a `DesignReferenceRow` — probe #61 (`skills/gate-check/SKILL.md:148`) would `existsSync` it and GATE FAILED. Dead-versus-unchecked is decided by one run-level connectivity preflight, never per-URL error codes. `/spec-write` § 0b gains step 6b AND a § 7 map row — two edits against three lines of cap headroom. `docs/layout-reference.md:31` gains a fourth optional section, retiring its "three are the only optional sections" claim. Register `external_link_check_unchecked_offline` in `CANONICAL_CAPABILITY_KEYS` + `KEY_OWNER_SKILL`.

## Testing

**New `adapters/_shared/src/check_external_link.test.ts`** (co-located, following `adapters/_shared/src/design_asset_slug.test.ts`).

- **AC.4** — table-driven over `classifyLinkVerdict`, preflight online: `{status:200}`, `{status:204}`, `{status:301}`, `{status:302}` → `"reachable"`; `{status:401}`, `{status:403}` → `"reachable"`; `{status:404}`, `{status:410}`, `{status:500}`, `{status:503}` → `"dead"`; transport `{code:"ENOTFOUND"}` and `{code:"ECONNREFUSED"}` → `"dead"`. Each row asserted as `expect({input, verdict}).toEqual({input, expected})` so a wrong answer names its own input, plus `expect(CASES.length).toBe(12)` so a deleted row is not a silent pass. **AC.4 must spell out the 401-vs-403 split in words**: `specs/plan/M140.md`'s verify line ("an authorization challenge reads reachable; refusal, absence and server error read dead") is satisfiable by reading "refusal" as either 403 or `ECONNREFUSED`, and the table above picks the second. An AC that does not resolve it leaves this row unfalsifiable-by-review.
- **AC.4 closed union** — `expect(new Set(CASES.map((c) => classifyLinkVerdict(c.input)))).toEqual(new Set(["reachable","dead"]))`. Mapped over the CLASSIFIER's outputs, never over the table's `expected` column — mapping the column asserts the literal against itself.
- **AC.6** — replay the whole AC.4 table with `preflight: "offline"` and assert every row returns `"unchecked"`, the `{status:404}` and `{code:"ENOTFOUND"}` rows explicitly named. The mutation control is the online leg above running the same table and reproducing the AC.4 verdicts: without it a classifier hard-coded to `"unchecked"` passes the offline leg.
