# Best-practices CLI adds and removes entries, and a declared hash is checked

## Summary

Tools that wanted to register a best-practices document had to write the manifest by hand.
The manifest command now has add and remove legs that go through the same checks as the skill.
An entry may also declare the hash its document must have.
A new gate check fails when a document no longer matches its declared hash.
Select refuses such a document, so a stage never reads a changed document as if it were the approved one.

## Requirement

`best_practices_manifest.ts` gains `add` and `remove` CLI legs over the module's own helpers, entries gain an optional `sha256` key, and a gate-check probe fails any entry whose document does not match its declared hash.

## Acceptance Criteria

- AC-STE-879.1: `bun best_practices_manifest.ts add --specs <dir> --name <n> --path <p> [--scope "<globs>"] [--topics "<t1,t2>"] [--notes "<text>"] [--max-bytes <N>] [--sha256 <hex>]` appends the entry through `addEntry` and `writeManifest` and exits 0. A duplicate name, a missing document, or any shape error prints the NFR-10 refusal, exits 2 and leaves the manifest byte-identical.
- AC-STE-879.2: `bun best_practices_manifest.ts remove --specs <dir> --name <n>` removes the entry through `removeEntry` and exits 0. An unknown name prints the NFR-10 refusal, exits 2 and leaves the manifest byte-identical.
- AC-STE-879.3: An entry may declare `sha256: <64 lowercase hex characters>`. The closed schema accepts it and the helpers round-trip it. Any other value is a `BestPracticesManifestShapeError`.
- AC-STE-879.4: A new `/gate-check` probe, at the next free probe number, reports one violation per entry whose declared `sha256` differs from its document's digest, naming the entry, the path, the declared and the actual digest. Entries without the key, and an absent or empty manifest, are vacuous. The probe is registered at every probe-count-pinned site in the same change.
- AC-STE-879.5: `select` prints `refused: <name> sha256 <actual>` in place of the line of a selected entry whose declared `sha256` differs from its document's digest. The other selected entries still print.
- AC-STE-879.6: The `/best-practices` skill's add and edit legs accept `max_bytes` and `sha256`, and its text names the CLI legs as the way for other tools to write the manifest.
- AC-STE-879.7: `bun test` from `plugins/dev-process-toolkit` reports 0 failures, and its skip identities equal the trunk baseline by name.

## Technical Design

The CLI dispatch gains two commands beside `select`, reusing `parseCliFlags`. `add` builds the entry, checks the path with the same existence rule the skill uses, then calls `addEntry` and `writeManifest`. The probe clones the `best_practices_manifest_hygiene` module shape and runner registration, and shares its digest helper with `select`. Depends on the four-column select from STE-878.

## Testing

CLI tests run the module with `Bun.spawn` against fixture manifests in a temp directory and compare the manifest bytes before and after each refusal. Probe tests cover a match, a mismatch, a missing key and an absent manifest.
