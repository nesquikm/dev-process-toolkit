# A timeline reader derives call timing, review rounds and gate runs from the session log

## Summary

The session log already holds a timestamp and an error flag for every tool call.
This adds a reader that turns that log into a timeline of calls, review rounds and gate runs.
It joins the capture rows and the gate outcome records where they exist.
Anything it cannot see is marked as not observable instead of counted as zero.
At session stop it saves the timeline, so the data outlives the log.

## Requirement

New module `adapters/_shared/src/tool_call_timeline.ts`. It reads transcript blocks only through `firstCopies(records, { topLevel: true })` from `templates/hooks/_lib/session.ts` (dynamic import, the `create_idempotency_probe.ts` precedent), so a call written twice is read once (STE-695, STE-696). It classifies Bash calls with the same classifier STE-716 uses; command text is read in memory and never written.

### Output — schema `tool-call-timeline/v1`

- `calls[]`, one per `Bash` or `Skill` `tool_use`: `tool_use_id`, `tool`, `class`, `skill` (the STE-716 rule), `started_at` (the `tool_use` first copy's `at`), `ended_at` (the `at` of the matching `tool_result` first copy, or `null`), `wall_ms`, `is_error` (`true` only when the result's `is_error === true`), `diff` (the commit `pre` capture row's `diff`, else `null`), `duration_ms` and `pairing`. Every time is the epoch ms that `firstCopies` reports; `recordTimestamp` stays private to `session.ts`.
  - `pairing` is `paired` when capture rows hold one `pre` and one `post` for the id (`duration_ms` = post `ts` − pre `ts`), `orphan-pre` or `orphan-post` when only one exists, and `uncaptured` when none does. The first row per (id, event) wins; later ones are counted in `gaps.duplicates`.
  - `exit_code` appears only per D2.
- `rounds[]`, one per Skill call to `dev-process-toolkit:tdd-write-test`, `tdd-implement`, `tdd-refactor`, `tdd-spec-review` or `spec-review-audit`:
  - `status`: from `extractTddResultBlock`/`parseTddResultBlock` (`tdd_result.ts`), `extractTddSpecReviewBlock`/`parseTddSpecReviewBlock` (`tdd_spec_review_result.ts`) or `parseSpecReviewResultBlock` (`spec_review_result.ts`) over the call's `tool_result` text. A tdd block gives its `status`. A spec-review block gives `ok` when `drift_count` is 0 and every traceability row is `done`, else `failed`. A missing or unparseable block gives `unparsed`.
  - `tree_changed`: `true` or `false` from the call's `pre` and `post` capture `tree` digests; `null` with `tree_disposition: "not-observable"` when either is missing or D5 is no.
  - `tokens`: per D3, a number, or `"not-observable"`.
- `gate_runs[]`, one per `kind: "gate"` receipt of the session in the checkout's store (`readSessionReceipts`): `subject`, `ran_at` (its `createdAt`), `outcome` (`pass`/`fail` from the `gate-outcome` receipt whose `evidence.run` equals its digest, else `none`), `wall_ms` (outcome `createdAt` − `ran_at`, else `null`), `key_digest` and `key_stable` (from STE-715, else `null`). With `tracking.gate_outcomes` off, every run reads `outcome: none`, `key_digest: null` and `key_stable: null`, since no outcome or key is written.
- `gaps`: counts of `orphan_pre`, `orphan_post`, `uncaptured` and `duplicates`.

An inline skill's Skill call returns as soon as its body loads, so no `gate-check`, `tdd` or `spec-review` Skill call duration is used as a gate's run time; gate wall time comes only from receipts.

The output's key sets are closed. It carries no command text, `cwd`, path, branch or session id.

### Front door and fold

- CLI: `bun run tool_call_timeline.ts <transcript> <checkout root>` prints the JSON and exits 0; an unreadable transcript is an NFR-10 refusal, exit 1, empty stdout.
- Fold: `templates/hooks/_lib/hooks/session-token-ledger.ts` (SessionEnd and Stop), when `tracking.tool_calls` is true, writes the timeline to `toolCallTimelinePath(root, sessionId)` = `<root>/.dpt/ledger/tool-calls/<sessionId>.timeline.json` (new composer in `dpt_paths.ts`), replacing any earlier copy. The token-stats flag no longer ends the entrypoint early for the fold; the token ledger's own behaviour is unchanged. The fold is fail-open. With both flags off, the hook's exit code, stdout, stderr and written files equal v2.101.4.

## Technical Design

The transcript is the source of truth for when a call started, when it returned and whether it erred; capture rows add only tree digests, diff counts and hook-side durations. Rounds are read from the parent side, the Skill call that starts each fork and the result block it returns, because fork internals may be invisible. Gate time comes from the run and outcome receipts, since an inline skill's call returns at once. Each unobservable field carries a named disposition, so a later rule can skip it rather than grade zero.
