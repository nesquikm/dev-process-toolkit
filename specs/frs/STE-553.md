# One review outcome, one instruction

## Summary

Two passages twenty-four lines apart give opposite instructions for the same condition.

Where the first review pass returns critical findings, one says surface them and stop; the other says fix them, re-run the check, re-enter the loop, and escalate only if a second round still fails.

A reader following the first aborts a run the bounded loop was built to carry. A reader following the second walks through a stop the other calls mandatory. Both are shipped and neither defers.

## Requirement

The critical-finding path carries exactly one shipped instruction. Whichever behaviour is chosen, the other passage is corrected rather than left standing, and the resolution is asserted from both sites so neither can drift back alone.

## Acceptance Criteria

- AC-STE-553.1: Exactly one instruction governs the critical-finding path. The superseded passage is rewritten to agree, not merely left unreferenced.
- AC-STE-553.2: The chosen behaviour is the bounded-loop one — fix, re-run, re-enter, escalate on a second failure — because a halt on the first critical finding defeats the loop the surrounding phase is built around, and the escalation path already exists for the case the loop cannot carry.
- AC-STE-553.3: Both sites are asserted, so correcting one and leaving the other is a failure. A single-sided assertion is what allowed the two to diverge.
- AC-STE-553.4: A tripwire asserts the superseded wording is absent, so it cannot be reintroduced by a later edit that only reads the site it is changing.
- AC-STE-553.5: The edit is net-zero or shorter on `skills/implement/SKILL.md`, which sits at 358 lines against a 358-line cap.
- AC-STE-553.6: Falsifiability — restoring the superseded wording at either site turns the pinning assertion red, asserted at each site independently.

## Technical Design

`skills/implement/SKILL.md:154` and `:178` are the two sites. `:178` carries the behaviour that survives; `:154` is rewritten to match it rather than deleted, since it sits at the point a reader reaches first and silence there would leave the path undescribed.

The pin is a two-sided documentation assertion of the shape probe #66 already uses for a single-file contract: positive literals at both sites plus a tripwire on the retired wording. Two-sided is the whole point — the divergence exists because nothing compared them.

Net-zero on line count is a hard constraint, not a preference: the file has no headroom.

## Testing

Extend the existing `/implement` documentation suite.

- AC.1 / AC.3 — read both sites and assert they describe the same outcome, with the assertion naming each site so a failure says which one drifted.
- AC.2 — assert the surviving text carries the loop's own vocabulary: re-run, second round, escalate. A leg asserting only that the two agree would pass if both had been rewritten to halt.
- AC.4 — a tripwire asserting the retired sentence is absent from the file, matched as a literal so a copy-edit of the replacement does not silently disable it.
- AC.5 — assert the file's line count is at or below the cap, measured the way the enforcing test measures it rather than by `wc -l`, which reports one fewer.
- AC.6 — mutation at each site independently: restore the old wording there and assert the pin reddens, so neither site is pinned only by its sibling.

## Notes

The two passages were almost certainly written at different times for different concerns, and each is defensible alone. What made the contradiction survivable is that nothing in the repository ever read them together — the same absence that let a milestone ship three FRs whose technical designs disagreed about a derivation, one milestone earlier in this same program.
