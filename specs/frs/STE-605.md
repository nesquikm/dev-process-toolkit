# The orphan list offers only this repository's tickets and names who filed the rest

## Summary

When a spec session starts it lists tracker tickets with no local file and offers to import them.
In a shared container that list offered every sibling repository's open tickets, even their milestone containers, with nothing to tell them apart, and a yes rewrote the sibling's ticket.
The listing is now a command that keeps this repository's tickets, drops the siblings', names who filed each unlabelled one, and never offers a container.
The gate check reports unlabelled tickets too.

## Requirement

Measured at HEAD `ac1f3cb`:

- `reconcileTrackerLocal` (`adapters/_shared/src/reconcile_tracker_local.ts:84-111`) lists `provider.listActiveFRs()` minus local bindings, with no owner, label, type or parent filter. `listActiveFRs` has no mapping in either adapter doc (0 hits; control: `listMilestones` is mapped), so its scope is whatever the model improvises. The one observed live emulation was `project = GF AND statusCategory != Done` — no issue-type conjunct, so the sibling's milestone Epics (GF-85, GF-89, GF-92, GF-94) would be offered as FR imports too.
- Two-repo repro (verify-enumeration-writes `v1.ts`, real module, live-shaped data): once BE is bound to GF, its tracker orphans are FE's GF-86 (In Review), GF-91, GF-93 and GF-95; the split control shows none. The effect is symmetric.
- The ask shows only id and title — no owner, no repository — and both repositories use the same key prefix. A yes runs `importFromTracker`, which writes a stray FR file and then syncs, rewrapping the sibling's description. Jira history keeps the old text, so it is recoverable, but it is an outward write to someone else's ticket.
- The ask-first gate exists only in prose: no code references `tracker_orphan_import`, and no test covers it.
- Tickets people file by hand carry no tag and appear in both repositories' lists. Measured: GB-42 was filed with no labels by a contributor with zero commits under `specs/`; 69 of 128 NEX issues created since 2026-06-30 carry no component.

### 1. One classifier

A new `adapters/_shared/src/container_ownership.ts`:

- `normalizeContainerPage(json, adapter)` reads Jira `searchJiraIssuesUsingJql` results or Linear `list_issues` results into tickets `{ key, title, labels, isContainer, project, creator, hasBackLink }`. Required fields: key and title always, plus the issue type on Jira; labels, description (for the back-link column) and creator when shared. Jira names the creator `creator`; Linear's `list_issues` names it `createdBy` in its `fields` enum. A required field missing on any ticket is a refusal naming the field and the key.
- `classifyTicket(ticket, binding)` — the binding read through STE-602, receipts written through its store — returns one of:
  - `container` — a Jira issue of type Epic, or of a hierarchy level above the FR level; never an FR candidate, in every mode;
  - `ours` — carries this repository's `repoTag`;
  - `sibling` — lacks this repository's tag and carries at least one label that is neither a `milestone-` label nor in this repository's `default_labels`: another repository's tag, or the default labels an older sibling client forwards;
  - `unowned` — neither: no label beyond this repository's own default labels and milestone labels. This is what a person filing by hand, and a client too old to tag, both leave behind.

  The back-link line `Source: specs/frs/<key>.md` is NOT ownership evidence: every toolkit version writes it, identically, in every repository, so a classifier keyed on it would file every pre-tagging client's ticket as `sibling` and hide it from the detector. It is reported only as a `toolkit-written` column.
  In an undeclared repository `ours`, `sibling` and `unowned` collapse into today's single candidate class; only `container` is removed.
- `listOrphans(projectRoot, pages)` returns the tickets no local FR binds (through the existing `readLocalFRBindings`), each with class and owner (the creator's display name), and one summary line counting read, ours, sibling (excluded), unowned, containers (excluded) and bound, and saying whether the page set was complete.
- Front door: `bun run adapters/_shared/src/container_ownership.ts list <projectRoot> <page.json>...` prints the table, the summary, and for each offerable ticket the two option labels the ask must use, `Import <KEY>` and `Skip <KEY>` — the write gate accepts only an answer that selected the first. `consent <projectRoot> <key> <page.json>...` re-classifies the same pages and writes an `import` receipt (shared only) for an `ours` or `unowned` key, printing `dpt-receipt: <path>`; it refuses `sibling`, `container`, and any key absent from the pages.

### 2. Reconcile takes the classified tickets

`reconcileTrackerLocal` accepts the classified tickets in place of bare ids when given. Tracker orphans then exclude containers in every mode and siblings in shared mode, and each orphan item carries `ownerClass` and `owner` — present only on this path. The bare-id path through `provider.listActiveFRs()` keeps its current output, so existing exact-shape pins on reconcile items do not move.

### 3. Probe #49 becomes the detector

`runTrackerLocalReconciliationDriftProbe` (`adapters/_shared/src/tracker_local_reconciliation_drift.ts`) takes the same pages as `deps.containerPages` and gains a front door, `bun run adapters/_shared/src/tracker_local_reconciliation_drift.ts <projectRoot> <page.json>...`:

- tracker-orphan rows only for `ours` and `unowned`, each naming class and owner;
- shared only: an `unowned-container-ticket` warning per unowned, non-container ticket, naming key, title and creator — the tickets people and too-old clients leave untagged — and a `bound-ticket-untagged` warning per ticket a local FR here binds whose labels lack this repository's tag, with the remedy of adding the tag so siblings exclude it;
- shared only: a `numeric-milestone-shared` warning per numeric `milestone-M<N>` label carried by tickets of more than one repository, as NEX's `milestone-M8` is on NEX-211 (FE) and NEX-297 (BE). A ticket's repository is this one when it is `ours` or bound by a local FR, and a sibling's tags otherwise (its labels that are neither `milestone-` labels nor this repository's defaults); `unowned` tickets are attributed to no repository. The warning names the label and the keys on each side, and says the bucket mixes repositories. It is a visible warning, never a write: numeric labels are never renamed, migrated or removed. Tracker-keyed `milestone-M_<key>` labels are out of this rule;
- one info row counting siblings excluded and containers excluded;
- named outcomes, never a silent green: no page supplied → a `container-not-read` skip row; an empty, complete page → a `container-empty` info row; an incomplete page set → a `container-partial` warning.

The probe stays read-only: no import, no sync, no receipt. `skills/gate-check/SKILL.md` row 49 (line 128) is rewritten in place to run the front door and list the new rows; the file stays at 356 split-lines and 87 STE tokens.

### 4. Adapter contracts

`adapters/jira.md` and `adapters/linear.md` each gain a `list_active_frs` operation row naming the exact read — Jira JQL `project = <KEY> AND statusCategory != Done` with the required fields, paginated to `isLast: true`; Linear `list_issues(team, project, fields: [id, title, labels, description, createdBy, project, team], limit: 250)` followed by its cursor to `hasNextPage: false` — and stating that the saved pages feed the front doors.

### 5. Importing an unowned ticket claims it

In a shared repository, importing an `unowned` ticket adds this repository's tag in the same outward sync (a read-merge-write of `labels` on both trackers: read the ticket's current labels, write their union with the tag — never a set that drops a label), so the sibling's next listing classifies it `sibling`. A `sibling` or `container` key is never imported.

## Technical Design

One classifier decides ownership from the labels the tracker page already carries: this repository's tag, a label this repository does not forward, or neither. The back-link is not evidence, because every client writes it. The listing, the consent, the probe and the claim-side ownership check all call it, so they cannot disagree. Containers are excluded by type before ownership is considered. The model fetches the page and hands it over as a file, because a command cannot reach the tracker; the command refuses a page lacking the fields ownership needs rather than guessing.

- **Pin moves** (named, and none other):

  - `tests/shared-declaration-setup.test.ts` AC-STE-603.10: the STE-603 ledger leg finds its entry by rationale, not as the head, the same move STE-603 made for STE-602's leg.
- **The pin fell 124 → 122**, measured by the awaited probe and diffed against a checkout of HEAD. The two references on `skills/gate-check/SKILL.md:128`, probe #49's row naming `tracker_local_reconciliation_drift.ts` and `reconcile_tracker_local.ts`, became reachable through the new front door. The FR commit carries `commit: "uncommitted"`, and the next commit records its sha.
- **Probe #74:** `container_ownership.ts`, `import.ts` and `tracker_local_reconciliation_drift.ts` now read CLAUDE.md through `readWorkspaceBinding`. Each gains a recorded `CLAUDEMD_GUARD_EXEMPT` entry, because its applicability is the declared tracker `mode:` and `repo_tag`.
- **The import's ownership context.** The FR names no signature for the claim. `importFromTracker` gains an optional sixth argument, `{ projectRoot, pages }`, carrying the saved container pages. It flows through a new optional `FRSpec.labels`, which `TrackerProvider.sync` forwards only when set. Without the argument the import is byte-identical to before. `docs/spec-write-tracker-mode.md` § Orphan listing orders the pages passed.
- **Stage C / AUDIT fixes:**
  - The import now reads pages as strictly as `list` and `consent` do in a shared repository. Read leniently, a page lacking `labels` read as "no labels", so the claim would have written the tag alone and replaced the ticket's real labels (H1).
  - The numeric-label warning now groups sibling tickets that share ANY foreign label as one repository. It used to key each on its joined label set, so a sibling ticket also carrying a generic label such as `bug` read as a second repository and warned falsely (H2).
  - `adapters/jira.md` and `adapters/linear.md` said labels are never touched on update. Each now names the claim on import as the one exception: the union of the ticket's current labels and the tag, never a set that drops a label.
- **Pass 2 review fixes:**
  - Probe #49 now builds its tickets with the shared-mode strict read at the point it parses. Before, the read was lenient, and a malformed shared page was refused only because `listOrphans` happened to parse it strictly first.
  - The sibling grouping's union-find now compresses paths and names each group once per root, instead of re-filtering every label for every ticket.
  - Both are behaviour-neutral. The suites stay green, and H2 was re-measured red against the rewritten code.
- **Custom trackers:** given container pages, `importFromTracker` refuses a tracker key other than `jira` or `linear` before any write. Container pages and ownership exist only for those two adapters, so for any other adapter ownership cannot be decided, and the import must not proceed as if it had been. Without pages the import is unchanged for every adapter. A Pass 1 review named this refusal as untraced; it is recorded here and tested ("the ownership context is Jira/Linear-only").
- **Advisory (not changed):**
  - `skills/spec-write/SKILL.md` line 26 names the tracker-write hook that refuses an import no consent recorded. That hook is STE-607 in this same milestone and ships in the same release; nothing reads an `import` receipt until then.
  - Probe #49 prints its excluded-count info row whenever pages are supplied, an undeclared repository included. This is info only: AC-STE-605.7's existing fixtures supply no pages, and their rows are unchanged.
