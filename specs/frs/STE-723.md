# The settings file names a closed set of reuse knobs and a probe refuses any other

## Summary

A project can ask its gate to reuse a result already proved on identical input.
The request lives in one optimizations section of the project settings file.
That section accepts only knobs from a fixed list, each set to reuse or run.
Every knob is off unless the project turns it on, and an off knob changes nothing.
A new gate probe fails on any other knob, any other value, or a knob aimed at the review.

## Requirement

### Schema

`specs/settings.yaml` (the M_94e6f7 consolidated settings file) gains an optional top-level `optimizations:` mapping. It is read through the M_94e6f7 settings loader and never re-parsed privately. The loader's closed top-level key set gains `optimizations`, but the loader passes the section through without validating its keys: a bad knob reds this FR's probe and reads as `run`, rather than refusing every settings read. `docs/settings-reference.md` documents `optimizations.gate_commands`, and the M_94e6f7 key-mapping table (AC-STE-706.12) gains a `new` row naming this FR. `/setup` writes no `optimizations:` section.

```yaml
optimizations:
  gate_commands: reuse   # reuse | run   (absent = run)
```

- **Closed knob set** `OPTIMIZATION_KNOBS = ["gate_commands"] as const`. `gate_commands` covers the project's deterministic gate commands (typecheck, lint, test, build) run by `/gate-check` and nothing else.
- **Closed value set** `OPTIMIZATION_VALUES = ["reuse", "run"] as const`. `run` is the default and equals an absent key or an absent section.
- **Refused names** `NEVER_REUSABLE_STEPS`: `code_review`, `review`, `spec_review`, `tdd`, `probes`, `conformance_probes`, `tracker_probes`, `upgrade_staleness`. Each names a step that is an LLM judgement or reads outside the tree (the `/gate-check` `## Code Review` section, the tracker probes, probe #69, the date-epoch probes). A knob with one of these names is refused with its own reason, distinct from an unknown name.
- **One effect only.** The sole effect any knob may have is reuse of a stored deterministic pass, as decided by STE-724. No knob skips a command, lowers a severity, or changes what a run checks. With `gate_commands` anything but `reuse`, `/gate-check` runs exactly as today: no front door, no step receipts (operator ruling R6).
- **No environment override.** No `DPT_*` variable and no `userConfig` field changes a knob's value. The existing `DPT_*` knobs (`DPT_GATE_TIMEOUT_MS`, `DPT_SKIP_FETCH` and the rest) stay where they are and stay out of the settings file. `milestone_scan_fetch`'s precedence chain is untouched.

### Module

A new module `adapters/_shared/src/optimizations_config.ts` exports `OPTIMIZATION_KNOBS`, `OPTIMIZATION_VALUES`, `NEVER_REUSABLE_STEPS`, `readOptimizations(projectRoot)` (returns the effective knob map, every knob `run` when the section is absent or invalid) and `validateOptimizations(raw)` (returns violations). The probe and the STE-724 front door both call `validateOptimizations`; there is no second validator.

The module carries an `import.meta.main` entry with one verb: `bun run optimizations_config.ts knob <root> <knob>` prints the effective value from `readOptimizations`, `reuse` or `run`, and exits 0. A knob name outside `OPTIMIZATION_KNOBS` exits 1 in NFR-10 shape with nothing on stdout. `/gate-check` and `/simplify` read the knob only through this verb.

### Probe

A new `/gate-check` probe `optimizations_reuse_only` at the next free probe number, registered in `skills/gate-check/SKILL.md` as `call \`runOptimizationsReuseOnlyProbe(projectRoot)\` from \`adapters/_shared/src/optimizations_config.ts\``. **Severity: error.** Vacuous when the tree is not toolkit-managed (routed through `isToolkitManaged` in `toolkit_managed.ts`), when the settings file is absent, or when it has no `optimizations:` section. Violation rows use the NFR-10 shape with `specs/settings.yaml:<line> — <reason>`. Reasons: `unknown-knob`, `unknown-value`, `never-reusable`, `not-a-mapping`.

## Technical Design

One small module owns the vocabulary, the reader and the validator. The probe and the reuse front door call the same validator, so their verdicts cannot drift.

The reader fails toward `run`: an absent, malformed or refused section means no reuse anywhere. The refused-name list exists so that an author who writes `code_review: reuse` gets a reason naming why, not a bare unknown key.

The section is read through the M_94e6f7 settings loader. No environment variable takes part, which keeps the knob out of reach of a model-written env block.

## Testing

Unit cases for the reader and validator; a probe test with one positive and one negative fixture per reason; a source grep with a control; mutation controls.

## Notes

Depends on M_94e6f7 for the settings file and loader. Only one knob ships, on purpose. A second knob needs its own FR proving its step is deterministic and in-tree. The key name gate_commands is a recorded milestone decision.
