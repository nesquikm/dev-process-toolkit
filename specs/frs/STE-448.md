# Add the mode:none leg end-to-end to /smoke-test and /conformance-loop

## Summary

Tracker-less is the default configuration for every project this toolkit bootstraps. The setup skill never writes a mode line for it — the absence of the tracking section is what the default means. Yet the conformance loop has only ever driven two legs, both of them tracker-bound, so the most common downstream configuration is the least tested path in the toolkit.

This adds it as a real third leg rather than a degraded one. Tracker-less is not a weaker version of the tracker chain; it exercises a genuinely different set of code paths. Identity is minted locally instead of allocated remotely, the milestone is an opaque token rather than a sequential number, and release is proved by the deletion of a lock file rather than by a ticket transition.

The gate behaves differently too. Roughly eleven probes go vacuous while two others switch into their enforcing arms, so this leg's gate step is a different set of checks rather than a shorter one.

The leg costs essentially no additional wall-clock, because the legs are detached and run concurrently under a single shared poll. It costs tokens, not minutes.

## Requirement

Add `none` as a third conformance leg across both project-local driver skills, with its own artifacts, no tracker surface, and verify-on-disk assertions that only a tracker-less run can make.

The leg must not be a special case bolted beside the other two. Its admission to the basename allow-list and its spawn group derive from `SMOKE_LEGS` per STE-446, not from a third hardcoded literal.

## Technical Design

The leg's artifacts follow the existing tracker-segment convention exactly, which is why STE-423's scoping tests stay green unmodified — they assert templates, not literals.

The MCP-free path is the one genuine branch. Phase 1 step 5 constructs a wrapped MCP config per tracker; the `none` leg skips it entirely, and the spawn omits the corresponding flag rather than passing an empty file. Pre-flights (c) and (d) do not fire for this leg per AC-STE-447.6.

AC.9 is deliberately only half of the lock assertion. An end-state absence check is satisfied vacuously by a lock that was never created, so on its own it cannot distinguish a working release path from a claim that silently no-opped. The other half — proving the lock existed mid-run — is STE-451, and it needs mid-run observation that Phase 4 structurally cannot perform.

The Phase 4 verify rows are prose contracts executed by the driver at run time, so their coverage here is the meta-test asserting the rows exist and name the right paths. Their live exercise is a conformance run.
