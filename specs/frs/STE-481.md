# One active plan file per tracker-less project after /setup then /spec-write

## Summary

Setting up a tracker-less project scaffolds a plan file named by sequence, and the first specification run mints a second plan file named by identity, right beside it. The project now carries two active plans under two naming schemes, and the documentation that describes the naming says the scheme is chosen by mode — which cannot be true when both are present at once.

## Requirement

A tracker-less project ends up with one active plan file. Either the scaffolded plan is consumed by the mint step or it is not scaffolded on that path; whichever is chosen, the shipped prose calling the filename mode-dependent is made true rather than left describing a state the code cannot produce.

## Acceptance Criteria

- AC-STE-481.1: After `/setup` followed by `/spec-write` in `mode: none`, `specs/plan/` contains exactly one active (non-archived) plan file.
- AC-STE-481.2: The surviving file is the minted `M_<short-ULID>` form and carries the `id:` frontmatter key probe #73 requires in this mode.
- AC-STE-481.3: The shipped prose describing the plan filename as mode-dependent is true as written, or corrected to describe what now happens; no surface claims a state the code cannot produce.
- AC-STE-481.4: Probe #73's `kind: scaffolding` exemption is narrowed or retired in step with the change, so it no longer papers over a duplicate.
- AC-STE-481.5: A test drives setup-then-spec-write under `mode: none` and fails when a second active plan file appears.

## Technical Design

Measured: `/setup` scaffolds `specs/plan/M1.md` with `kind: scaffolding`, and `/spec-write` mints `specs/plan/M_JQMS6C.md` beside it. Nothing fails today because probe #73 exempts the scaffolding plan — but the exemption is what hides the duplicate, and Phase 4's own row states the filename "is mode-dependent: `plan/M1.md` in tracker mode, `plan/M_<TAIL>.md` on the tracker-less path", which this leg falsifies by having both.

Preferred direction is consuming the scaffold at mint time (rename in place, carrying the minted `id:`), since it preserves any content `/setup` seeded. Not scaffolding at all under `mode: none` is the simpler alternative and acceptable if the seeded content proves to be pure boilerplate.

## Testing

Integration test over setup-then-spec-write in `mode: none` asserting exactly one active plan; mutation restoring the double-write must go red. Probe #73 fixtures updated for the narrowed exemption. `bun test` full root.
