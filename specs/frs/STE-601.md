# A commit behind a wrapper, keyword or nested shell is still a commit

## Summary

The commit guards see a commit only when the first word is literally git and the subcommand is literally commit.
A wrapper, a full path, a nested shell, an if block, an alias, or a merge or cherry-pick that writes a commit all pass in silence.
Every such shape now gets a stated verdict: recognised, refused with its reason, or out of scope with a visible notice.
Replaying real session traffic proves the change refuses nothing it should not.

## Requirement

STE-597 taught both pre-commit hooks to find the repository a commit writes to, for the bare, directory-change-prefixed, `-C`, subshell and heredoc shapes. It did not widen what counts as a commit. At HEAD (`ac1f3cb`, v2.86.0):

- `parseGit` returns null unless the segment's first token is literally `git` (`adapters/_shared/src/commit_target_repo.ts:443-444`).
- `scanCommand` splits only on `&&`, `||`, `;`, `|`, newline and parentheses (`:318-330`). A single `&`, a `{`, and the reserved words `then`/`else`/`do` stay glued to the git words.
- Only the `commit` subcommand is considered (`:551-552`), and nothing documents that as a decision. `git merge`, `cherry-pick`, `revert`, `am` and `commit-tree` write commit objects the gates never see, and a git alias (`git ci`) is never expanded.
- STE-601 (adopted here) lists further live shapes that still run the real git binary: `\git`, `\git -C`, `command git`, `env git`, `GIT_DIR=… git`, and a backtick substitution holding an operator.

Measured on the installed 2.86.0 hooks (skeptic repro `verify-hooks/drive.ts`, rows C05-C15, two scratch git checkouts, no evidence in the transcript): `env X=1 git -C BE commit`, `HUSKY=0 …`, `GIT_AUTHOR_NAME=me …`, `command git …`, `time git …`, `/usr/bin/git …`, `bash -c "git -C BE commit"`, `cd BE && if true; then git commit; fi`, `{ git -C BE commit; }` and `sleep 0 & git -C BE commit` all return `isCommit=false`. Both commit hooks then exit 0 with no stderr, while the bare control (`git -C BE commit`) is refused by both. The shape is live traffic, not a lab curiosity. A spec-time scan of 85,948 distinct Bash commands across 3,842 transcript files on the operator's machine (2026-09-18) found 43 distinct `command git … commit` commands. The skeptic counted 34 of them in this repository's own sessions, several of them real commits here. `tests/commit-target-repo.test.ts` (1138 lines) has no case for any of these shapes, so they are neither handled nor pinned out of scope.

The fix has two halves. First, extract the command reading that `commit_target_repo.ts` does today (quote-aware scanning, heredoc skipping, substitution handling, subshell scoping and the `cd` walk) into one shared recogniser, so that STE-613 and STE-615 read commands through the same code instead of growing a second parser. Second, give every shape that can carry a commit an explicit verdict from a closed vocabulary:

- **Recognised.** The commit is found, and its target is resolved exactly as the unwrapped command would be (or named unresolvable by the STE-597 rules, when a word cannot be expanded).
- **Unplaced.** A literal commit is present, but it runs through a wrapper whose count or directory the recogniser cannot model. This yields `isCommit: true`, `repoRoot: null`, and an `unresolved` reason naming the wrapper. It also yields an additive `candidateRoots: string[]`: the checkout of the directory the wrapper itself runs in (when that directory is literal), plus the checkout of every literal directory word inside the wrapped words that follows `-C`, `--chdir`, `-D`, `cd` or `pushd`. An unplaced commit therefore never hides a literal target: `sudo git -C <B> commit` and `cd <B> && xargs git commit` both carry `<B>` as a candidate. The existing STE-597 legs then apply: the /tdd hook emits its advisory, and the gate-check hook demands evidence. STE-614 then turns an admitted unplaced commit into an operator-visible advisory, so the row is refused-with-reason or admitted out loud, never allowed in silence.
- **Out of scope.** Not a commit for these gates. Each such row is pinned by a test and listed with its reason in the hooks manual. A shape that is silently unhandled is the defect.

Shape table (the decision for each row is binding):

| Shape | Verdict |
|---|---|
| leading `NAME=value` assignments, one or more, quoted values included | recognised |
| `env` with `-i`, `-`, `-0`, `-v`, `-u NAME`, `--unset=NAME` and `NAME=value` operands | recognised |
| `env -C DIR` / `--chdir=DIR` / `--chdir DIR` | recognised; DIR is a directory change for the wrapped command only |
| `env -S` / `--split-string` | unplaced |
| `command` and `command -p` | recognised |
| `command -v` / `command -V`, `type git`, `which git`, `hash git` | out of scope: lookup, not execution |
| `exec`, `nohup`, `time` (`-p`), `nice` (`-n N`, `-N`), `timeout` (its options, then a duration) | recognised |
| `!` pipeline negation | recognised |
| an argv0 whose final path segment is exactly `git` (`/usr/bin/git`, `/opt/homebrew/bin/git`, `./git`) | recognised; `gitk`, `git2` and `legit` are not git |
| a single `&` and `\|&` | segment separators, like `;` |
| `{ …; }` brace group | recognised; a brace group does NOT scope the directory, while a parenthesised subshell still does |
| `if`/`then`/`elif`/`else`/`fi`, `while`/`until`/`do`/`done`, the header of a `for NAME in …;` loop | recognised; reserved words are stripped and conditions are commands that run |
| a function definition body (`f() { git commit; }`, `function f { … }`) | recognised as if it runs: conservative, measured in the replay |
| a commit inside a `case` arm | unplaced ("a case arm") |
| `sh`/`bash`/`zsh`/`dash`/`ksh` with options (combined `-lc`/`-ec`/`-xc` included) and `-c STRING` | recognised; STRING is read recursively, starting in the running directory |
| `eval STRING` | recognised, read recursively like `-c` |
| `-c "$CMD"` or `eval "$CMD"`, where the whole string is one unexpanded word | out of scope: no literal commit exists in the command |
| `$(…)` and backtick command substitutions | recognised; the commands inside run in the running directory, and heredocs inside them are still skipped |
| `xargs`, `find -exec`/`-execdir`/`-ok`, `parallel`, `watch`, `sudo` wrapping a git commit | unplaced |
| `bash FILE`, `./FILE`, `source FILE`, `. FILE` | out of scope: file contents are not read |
| `ssh HOST 'git commit'` | out of scope: not a commit in any local checkout |
| a quoted or backslash-escaped argv0 (`\git`, `"git"`, `'git'`) | recognised; quote removal runs before the argv0 match |
| a `GIT_DIR=` or `GIT_WORK_TREE=` binding, as a prefix, an `env` operand or an in-command `export` | recognised as a commit; target unplaced ("GIT_DIR"), with the literal value's checkout in `candidateRoots`, matching STE-597's `--git-dir` rule |
| a backtick substitution holding an operator (`` echo `cd DIR && git commit` ``) | recognised; the operator splits inside the substitution, which scopes its own directory |
| `git merge` (not `--ff-only`, `--squash`, `--no-commit`, `--abort`, `--quit`); `git cherry-pick` and `git revert` (not `-n`, `--no-commit`, `--abort`, `--quit`, `--skip`); `git am` (not `--abort`, `--quit`, `--show-current-patch`); `git commit-tree` | recognised: each can write a commit object. The gate-check hook demands evidence as for `commit`; the /tdd hook classifies the staged set for the `--continue` forms and otherwise exits 1 with a `Reminder:` naming the subcommand, since the index does not show what it commits |
| `git pull`, `git rebase` (not `--abort`, `--quit`), `git stash` (bare, `push`, `save`), writing `git notes` forms | out of scope for the gates, never silent: the gate-check hook exits 1 with a `Reminder:` naming the subcommand and the command proceeds; `git stash list`, `git stash show` and `git notes list` get no notice |
| a git alias (`git ci`) | resolved before classifying: `-c alias.NAME=VALUE` on the command, else `git config --get alias.NAME` run in the target checkout. A plain value replaces the alias word; a `!` value is a shell command read recursively from the checkout's top level; an alias that cannot be read (no target, git not runnable) is unplaced ("git alias") |

**The /tdd hook's Reminders become visible.** Its three advisory legs exit 0 today, and the exit-code contract in `docs/hooks-reference.md` shows no stderr on exit 0, so each is a silent allow: the unresolved target (AC-STE-597.4), `git` that cannot be run in the target (AC-STE-597.4, finding B) and the unknown stack (STE-548). Each now exits 1 with its `Reminder:` text unchanged: non-blocking, shown to the operator, the command proceeds. The pins that assert exit 0 on these legs, in `tests/hook-modules-pre-commit-tdd-orchestrator.test.ts`, `templates/hooks/__tests__/pre-commit-tdd-orchestrator.test.ts` and `tests/m142-ste-548-unrecognised-layout.test.ts`, are amended to exit 1 in place and listed in this FR's implementation notes. The sentence in `docs/hooks-reference.md` saying advisory hooks exit 0 is corrected: the commit gates' Reminders exit 1.

Recursion into nested shells, `eval`, substitutions and alias expansions is bounded at depth 8. Deeper nesting is unplaced ("nesting deeper than 8"), never a crash and never a silent `isCommit: false`.

Two STE-597 round-2 pins in `tests/commit-target-repo.test.ts` are amended by this FR, and the amendment is named here rather than slipped in. They are "`echo $(git commit)` is NOT a commit" and "CONTROL — a QUOTED substitution that merely mentions a commit is not a commit". Both commands run `git commit` under bash and zsh: a substitution executes whether or not it sits in double quotes. The pins recorded the old splitter's behaviour, not shell semantics. Each is replaced by a clause that asserts the commit, paired with a scratch-repo demonstration that the command really creates a commit.

## Acceptance Criteria

- AC-STE-601.1: `adapters/_shared/src/shell_invocations.ts` exports the shared recogniser. Given a command, a session directory and an injected checkout-root lookup, it returns every simple command the shell would run, in order, each with its argv after wrapper stripping, the directory it runs in (literal, or named as an unexpanded word under the STE-597 rules) and its wrapper chain. `commit_target_repo.ts` declares none of `scanCommand`, `tokenize`, `readHeredocOperator`, `skipHeredocBodies`, `readSubstitution` or `applyCd`, and imports its command reading from the shared module. `resolveCommitTarget` and `resolveCommitTargetFromPayload` keep their exported signatures, and every `CommitTarget` field present at HEAD keeps its name, type and meaning; this milestone only adds fields (`candidateRoots`, `subcommand` and `advisory` here, `repoRoots` in STE-614). Every clause of `tests/commit-target-repo.test.ts` passes unedited, except the two amendments named in AC.6.
- AC-STE-601.2: Every "recognised" prefix row of the shape table (assignments, `env` with its listed options, `command`, `command -p`, `exec`, `nohup`, `time`, `time -p`, `nice`, `timeout`, `!`) placed before `git -C <B> commit` yields `isCommit: true` with the same `repoRoot` and `shape` as the unwrapped command. The prefixes also compose: `env X=1 time command git -C <B> commit` resolves to `<B>`. `env -C <B> git commit` resolves to `<B>`, and the directory change does not leak into a later segment. Paired controls: each prefix before `git status` gives `isCommit: false`. `command -v git`, `type git` and `which git` give `isCommit: false`.
- AC-STE-601.3: An argv0 whose final path segment is exactly `git` is git. `/usr/bin/git commit`, `/opt/homebrew/bin/git -C <B> commit` and `./git commit` are recognised. `gitk`, `/usr/bin/git2 commit` and `legit commit` are not.
- AC-STE-601.4: A single `&` and `|&` separate segments. Reserved words (`if`, `then`, `elif`, `else`, `fi`, `while`, `until`, `do`, `done`, a `for … in …;` header) and brace groups hide no commit: `cd <B> && if true; then git commit; fi` and `{ git -C <B> commit; }` resolve to `<B>`. Scope is exact in both directions. `{ cd <B>; }; git commit` resolves to `<B>`, because a brace group is not a scope. `(cd <B>); git commit` resolves to the session's checkout, which is the STE-597 behaviour, unchanged. A function body is recognised as if run. A commit inside a `case` arm is unplaced, with `unresolved` naming "a case arm".
- AC-STE-601.5: Nested shells. `bash -c "git -C <B> commit"`, `zsh -lc 'git -C <B> commit'`, `cd <B> && sh -c 'git commit'` and `eval 'git -C <B> commit'` resolve to `<B>`. `bash -c 'cd <B> && git commit'; git commit` is two commits in two checkouts and yields the existing "more than one repository" `unresolved`. A `-c` string that carries no commit gives `isCommit: false`. `bash -c "$CMD"`, `eval "$CMD"`, `bash f.sh`, `source f.sh` and `. f.sh` give `isCommit: false`, each pinned as out of scope. A literal commit nested nine levels deep is unplaced ("nesting deeper than 8") and neither throws nor answers `isCommit: false`.
- AC-STE-601.6: Substitutions. `x=$(git -C <B> commit -m y)`, `echo $(git commit)` and `echo "$(git commit)"` are commits in the running directory. The commit-message idiom `git commit -m "$(cat <<'EOF'` … `EOF` `)"`, with a heredoc body carrying unbalanced parentheses, both quote characters and the words `git commit`, resolves as exactly one commit in the running directory. A heredoc inside a substitution that only mentions a commit (`gh pr create --body "$(cat <<'EOF'` … git commit … `EOF` `)"`) is not a commit. The two STE-597 pins named in the Requirement are replaced, not deleted, and a scratch-repo test runs each replaced command under `bash` and `zsh` and observes a new commit object. The STE-597 rule that an unexpanded value in a git global option leaves the target unresolvable is unchanged, and its clauses pass unedited.
- AC-STE-601.7: Unplaced rows. `xargs … git commit`, `find . -exec git commit …`, `parallel … git commit`, `watch git commit`, `sudo git commit` and `env -S 'git commit'` yield `isCommit: true`, `repoRoot: null`, and an `unresolved` naming the wrapper. `candidateRoots` is graded in both directions: `sudo git -C <B> commit`, `cd <B> && xargs git commit` and `find . -exec git -C <B> commit \;` each list `<B>`; `sudo git commit` run from checkout A lists A only; `find . -execdir git commit \;` and `xargs -I{} git -C {} commit` list only the running directory's checkout and never a word they cannot expand. Every other resolver answer carries `candidateRoots: []`, and the `CommitTarget` fields that existed at HEAD keep their values on every existing clause. Driven through the shipped hook wrappers, the /tdd hook exits 1 (never 0, which the harness would not show) with a `Reminder:` naming that wrapper, and the gate-check hook exits 2 with no evidence and lets the command proceed (any exit other than 2) with evidence. Controls: `xargs git status`, `find . -name '*.md'` and `sudo ls` give `isCommit: false`.
- AC-STE-601.8: Commit-producing subcommands. `git merge --no-ff x`, `git merge x`, `git merge --continue`, `git cherry-pick x`, `git revert x`, `git am p.mbox`, `git commit-tree t -m m` and each with `-C <B>` give `isCommit: true`, `subcommand` naming it, and the same target as `git -C <B> commit`. Driven through the wrappers from checkout A with no evidence, each `-C <B>` form exits 2 from the gate-check hook (red on HEAD, where C15 `git merge --no-ff` exited 0); with B's evidence it proceeds. The /tdd hook exits 1 with a `Reminder:` naming the subcommand for `git merge x`, and classifies the staged set for `git merge --continue`. Permit twins, each `isCommit: false` and exit 0 with empty stderr from both hooks: `git merge --ff-only x`, `git merge --abort`, `git merge --squash x`, `git cherry-pick -n x`, `git revert --no-commit x`, `git am --abort`, `git status`, `git log`.
- AC-STE-601.9: Advisory rows and the remaining out-of-scope rows. `git pull`, `git rebase main`, `git stash`, `git stash push` and `git notes add -m x` give `isCommit: false` and an `advisory` naming the subcommand; through the wrappers the gate-check hook exits 1 with a `Reminder:` naming it, and the command proceeds (never exit 0 with empty stderr, never exit 2). Permit twins with empty stderr and exit 0: `git stash list`, `git stash show`, `git notes list`, `git rebase --abort`. `ssh h 'git commit'` gives `isCommit: false` under a test naming the row.
- AC-STE-601.10: Aliases are resolved before classifying. In checkout B configured with `alias.ci=commit`, `git -C <B> ci` resolves as a commit in B; `git -c alias.ci=commit ci` resolves without reading config; `alias.mc=merge --no-ff` makes `git -C <B> mc x` a commit; `alias.pc='!git commit'` is read recursively and resolves to B. Permit twins: `alias.st=status` makes `git -C <B> st` not a commit, and an undefined alias word is not a commit. `git -C "$R" ci`, whose checkout cannot be read, is unplaced naming "git alias". A self-referencing alias chain stops at depth 8, unplaced, never a hang.
- AC-STE-601.11: STE-601's shapes each have a row and a test. `\git commit`, `\git -C <B> commit` and `"git" -C <B> commit` resolve like the unescaped command. `command git -C <B> commit` and `env git -C <B> commit` resolve to `<B>` (AC.2). `GIT_DIR=<B>/.git git commit`, `env GIT_DIR=<B>/.git git commit` and `export GIT_DIR=<B>/.git; git commit` are commits with `repoRoot: null`, `unresolved` naming GIT_DIR and `candidateRoots` holding `<B>`; with FE-only evidence the gate-check hook exits 2 naming B. `` echo `cd <B> && git commit` `` and `` x=`git -C <B> commit -m y` && echo ok `` resolve to `<B>`; `` echo `cd <B>` && git commit `` resolves to the session's checkout. Controls: `\git status`, `GIT_DIR=<B>/.git git status` and `` echo `git status && git log` `` give `isCommit: false`.
- AC-STE-601.12: `docs/hooks-reference.md` gains one "Recognised command shapes" table carrying every row of the shape table, each with a runnable example command and its verdict. A test parses that table out of the markdown file and runs every example through `resolveCommitTarget`, asserting the stated verdict. It asserts at least 27 rows, one per row of this FR's shape table, so an empty or unparsed table is a named failure and never a green pass. - AC-STE-601.13: End to end, on two git checkouts built on `makeSpanFixture`, with the shipped `templates/hooks/process/*.sh` wrappers driven the way the harness drives them (`CLAUDE_PLUGIN_ROOT` set, JSON on stdin, cwd = checkout A, checkout B staging an FR file, a source file and its test). ## Technical Design

Split `commit_target_repo.ts` along the seam STE-597's own implementation notes named: `shell_invocations.ts` owns the grammar (quotes, heredocs, substitutions, scopes, wrappers, reserved words, recursion), and `commit_target_repo.ts` keeps only the commit question over the invocation stream. The directory model moves over unchanged, and STE-613 widens it. Wrapper stripping is a table of prefix words with their value-taking options, so every added row is data plus one pinned test; git subcommand options are a second such table. Aliases are read through an injected config lookup run in the target checkout, like the checkout-root lookup. Unplaced wrappers reuse the existing unresolved leg, so neither hook gains a new exit path. The manual's shape table is graded by running it.

## Testing

Extend `tests/commit-target-repo.test.ts` with one describe block per shape-table group. Each recognised row is paired with a non-commit control that uses the same wrapper. A new `tests/shell-invocations.test.ts` covers the invocation stream directly: order, directory, wrapper chain and depth bound. Hook-level pairs run through the bash wrappers on two `makeSpanFixture` checkouts initialised with `git init`. Alias legs configure real aliases in the fixture checkouts; subcommand legs pair each commit-producing form with its non-committing twin. The two named pin amendments carry a scratch-repo execution check under both shells, run as `bash <file>` and under `zsh`. The replay helper is run by hand, and its numbers land in this FR.
