# An inline phase does not close with a terminal report

## Summary

Eleven skills each close with one status block, mandated as the last thing in the report with nothing permitted after it.

Under a fork that is harmless: ending the turn returns control. Inline it ends the whole run. Two blocks in one report is separately refused, so a turn cannot span two phases.

Suppressing it inline costs little. The probe grading capability tokens reads authoring files, not reports.

## Requirement

A stage running as an inline step of an orchestrated run does not close with a terminal report block, and continues to the next step in the same turn. Run standalone, the same stage closes exactly as it does today. The orchestrator's own report carries what the operator needs to see.

## Acceptance Criteria

- AC-STE-550.1: A stage invoked with the driven signal emits no `stage-status-block` fence and proceeds to the next step within the same turn.
- AC-STE-550.2: The same stage invoked without the signal emits exactly one fence, positioned and bounded exactly as today. Both halves are asserted on the same stage, since either alone proves nothing about the distinction.
- AC-STE-550.3: The adoption scanner continues to require a documented closed fence in every adopting `SKILL.md`. Suppression is a runtime behaviour of a driven invocation, never a removal of the authoring contract, and the scanner's verdict on the tree is unchanged.
- AC-STE-550.4: `closing_summary_capability_keys` is unaffected, demonstrated rather than asserted: it is run against a tree whose rendered reports carry no tokens at all and reports the same verdict, because its subject is the authoring files.
- AC-STE-550.5: The one-fence-per-report refusal is untouched. A report carrying two fences is still refused, so this criterion cannot be satisfied by relaxing the count rule.
- AC-STE-550.6: A driven `/deliver` run reaches Phase 3 from Phase 1 without an operator turn in between, asserted end to end rather than per stage — the per-stage legs above cannot show that the composition works.
- AC-STE-550.7: Falsifiability — restoring the fence on the driven path makes the end-to-end leg stop at Phase 1 again.

## Technical Design

The suppression is conditioned on STE-549's signal and lives in each adopting stage's closing-summary clause, which already names its own condition ("closes with exactly one … as the LAST thing in its report"). The clause gains a driven branch; the standalone branch is left byte-identical.

Nothing in `adapters/_shared/src/stage_block_adoption.ts` changes. Its scanner grades authoring surfaces and must keep requiring the documented fence, and its report grader keeps refusing `fences.length !== 1` at `:756` — a driven report simply carries zero fences, which is not the case that rule polices.

`docs/stage-status-block.md` gains the composition rule that is currently absent: rule 4's "last thing" holds for a report, and a driven inline phase produces no report of its own.

## Testing

New `tests/m143-ste-550-inline-no-terminal-block.test.ts`.

- AC.1 / AC.2 — the same stage rendered twice, driven and standalone, asserting zero fences and exactly one. The pair is the assertion.
- AC.3 — run `scanStageBlockAdoption` over the tree and assert its verdict is unchanged from the pre-change baseline, so the authoring contract is demonstrably untouched.
- AC.4 — run the capability-keys probe against a fixture whose rendered output contains no tokens and assert it still passes, which shows by execution that its subject is the authoring file. Include a control that mutates the authoring file and reddens it, or the leg proves only that the probe is inert.
- AC.5 — a two-fence report is still refused, asserted directly against the shipped grader.
- AC.6 — the end-to-end leg. Drive Phase 1 and assert the run reaches Phase 3's spawn point with no operator turn between. This is the only leg that observes the defect the milestone exists to fix; the others observe its parts.
- AC.7 — mutation: restore the fence on the driven path and assert AC.6's leg fails at Phase 1.

## Notes

The reason the test-driven flow never had this problem is the fork boundary, not better prose — its children carry the identical terminal instruction. That is why the fix is scoped to the inline path: the rule is correct wherever ending a turn returns control, and wrong only where it ends the run.
