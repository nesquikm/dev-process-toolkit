# Build the N-leg termination harness with executed bash fences

## Summary

The termination check decides whether a conformance run is finished and whether it succeeded. It is written as a shell snippet in the driver skill that counts high-severity lines across the per-leg findings files, and it currently assumes exactly two of them.

Generalizing that to a variable number of legs is the kind of change that needs real coverage rather than a prose assertion, because a prose grep passes happily against text describing a guard the adjacent snippet does not implement. This repository has shipped that defect more than once, and the flag this harness attaches to is itself an example of claimed-but-absent machinery.

The snippet is genuinely executable, so it can be extracted from the skill and run against synthetic inputs. That precedent already exists here for a different guard and is the model to copy exactly.

One case needs a decision rather than a test. A leg whose findings file is missing entirely currently fails closed only by accident, through a shell usage error rather than by design. A leg that produced no findings file did not run, and no findings must never reconcile with no evidence.

## Requirement

Build a fixture-backed harness for the termination probes, generalized to N legs, that EXECUTES the extracted shell fences rather than inspecting the prose around them.

Scope is the termination probes only. Extracting the aggregation pass and the cross-leg dedup into callable code is a genuine architectural change that would dominate this milestone and displace the tracker-less coverage work; it is explicitly out of scope and recorded as a follow-up.

## Acceptance Criteria

- AC-STE-452.1: The `green` fence is extracted from the driver skill's prose and EXECUTED via `Bun.spawnSync(["bash","-c",script])` against synthetic per-leg findings files. No assertion in this FR is a prose grep. {#AC-STE-452.1}
- AC-STE-452.2: A slice-sanity test asserts the extracted fence still resolves and still carries its anchors, so a prose edit cannot silently reduce the extraction to an empty string and leave the executed assertions vacuous. {#AC-STE-452.2}
- AC-STE-452.3: The harness covers and asserts N=1, N=2 and N=3; all-green; all-red; and asymmetric, meaning at least one green leg alongside at least one red leg. {#AC-STE-452.3}
- AC-STE-452.4: A missing per-leg findings file aborts the iteration and is asserted NOT to report green. {#AC-STE-452.4}
- AC-STE-452.5: The absent-file semantic is written into the fence explicitly rather than inherited from shell behavior. {#AC-STE-452.5}
- AC-STE-452.6: The `no-progress` probe is covered by the same executed-fence discipline as the `green` probe. {#AC-STE-452.6}
- AC-STE-452.7: **A reduced `--legs` run reaches a verdict, and the question of which leg set the termination surfaces count is answered rather than inherited.** Every leg-counting surface downstream of pre-flight (0) MUST count the SELECTED leg set, not the registered one. This FR MUST record its outcome in its `## Implementation notes` as exactly one of two literal tokens: `reduced_run_reaches_verdict` or `reduced_run_still_aborts`. The second form MUST be followed on the same line by the surface that still aborts and the reason it was not adapted. A probe asserts exactly one of the two tokens is present. Either decision is acceptable; completing this FR without the question having been put is not. {#AC-STE-452.7}
- AC-STE-452.8: **The AC.7 outcome is proven by execution, not by inspection.** A test EXECUTES the adapted surfaces against a synthetic proper subset of `SMOKE_LEGS` — at minimum a single-leg selection — with per-leg artifacts present for the selected legs and ABSENT for the unselected ones, and asserts the run reaches a reported verdict rather than aborting. **This test must FAIL if a reduced run aborts, and must FAIL if a reduced run reports `green` while a selected leg's findings file is missing.** Both halves are required: an implementation that reaches a verdict by ignoring absent files would satisfy the first and violate AC.4. {#AC-STE-452.8}

## Technical Design

The model is `plugins/dev-process-toolkit/tests/driver-gate-fail-open-guards.test.ts`, which pulls every shell fence body from a skill, selects the one it wants by an anchor string, and runs it under bash against synthetic files. Its slice-sanity test is the guard against the extraction silently matching nothing, and is why AC.2 is a separate criterion rather than an implementation detail.

AC.5 is the substantive behavioral change. Today, a missing findings file makes the counting command fail with an empty result, so the comparison that follows is a shell usage error whose non-zero status happens to skip the success branch. The run therefore does not report green, but only by accident — nothing in the snippet expresses the intent, and any refactor could silently invert it. The fence must test for the file's existence and treat absence as an abort with its own message.

The asymmetric case in AC.3 is the one most likely to expose a generalization bug, because a naive N-leg rewrite that folds the per-leg counts with the wrong operator passes both the all-green and all-red cases.

### AC.7 and AC.8 — the defect STE-447 introduced and this FR is obliged to close

**This is not speculative scope. It is a measured defect, shipped knowingly on this branch because STE-452 lands in the same release.** STE-447 added the `--legs` selector; it did not adapt any surface that counts legs. Evidence, executed during STE-447's implementation and again by its AUDIT stage — see that FR's `## Implementation notes` § Audit findings and `specs/notes/follow-ups.md` § 0a:

- With only `linear.rc` present, the rc-collection fence exits 1 with
  `/conformance-loop: Phase A subprocess failed (linear=0, jira=1, none=1). Aborting.`
- That gate fires **before** aggregation and **before** the capture-only short-circuit, so a reduced run yields no report and no verdict in either mode. It never reaches the `green` probe at all.
- The diagnostic additionally misleads: it names a subprocess failure when no subprocess was ever spawned for the unselected legs.

**So `--legs` currently parses correctly, guards emptiness correctly, and then dies at the first gate that counts legs.** It fails closed, which is the right direction — no vacuous green is reachable through it — but it is not a working reduced run, and shipping the milestone with the selector unusable for any proper subset would leave M121 having built an opt-out nobody can use.

**Four surfaces count legs off the registered set** and each needs the selection. Ordered by which fires first:

1. **rc collection** — start here; it is what actually aborts.
2. The **`green`** termination probe — the surface AC.1–AC.5 already address.
3. The **leg-completeness check**, which verifies each leg's grandchild log set.
4. **Aggregation**, which reads one per-leg findings file per registered leg.

The common requirement is that `SELECTED_LEGS`, resolved by pre-flight (0) in `.claude/skills/conformance-loop/SKILL.md`, must be visible to all four. For each surface the rule is the same and is what makes AC.8's two halves non-negotiable: an absent artifact for a **selected** leg stays an abort (AC.4); an absent artifact for an **unselected** leg is a no-op. Those two cases are indistinguishable today precisely because none of the four surfaces can see the selection.

**Why AC.7 is shaped as a forced two-token decision.** It is modelled on AC-STE-446.6, which used the same construction for the roster-guard scope question and worked: it made an inherited question impossible to complete the FR without answering. Adapting all four surfaces may prove larger than this FR should carry, and `reduced_run_still_aborts` is a legitimate outcome — but only if it is chosen, named and justified in the implementation notes, rather than arrived at by not looking. A note in a predecessor's follow-ups file is not a forcing function; an AC whose audit cannot return `missing_acs: []` while the defect is live, is.

## Testing

New test file following the fail-open-guards precedent. Every assertion executes; none greps.

The harness's own falsifiability: break the fence deliberately, in a way that would make a zero-leg or missing-file run report green, and confirm the harness reports red.

Full gate green from the plugin root.
