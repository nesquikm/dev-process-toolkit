# A bug's regression test is proved red before the fix, and /debug proves it without a commit

## Summary

An external contribution makes a bug fix prove its test.
Each bug test must fail before the fix and pass on it.
The audits mark a bug test that cannot run before the fix as partial.
The implement report counts a bug case without that proof as unproved.
The debug skill gains a path for a reported bug.
One step there asked for an unapproved commit; it now proves the test in a throwaway copy of the tree.

## Requirement

A bug's regression test is fixed only when it is shown RED on the code before the fix and GREEN on the fix. `/tdd`, the two spec-review audits and `/debug` say so and enforce it (external PR #137). No step of that proof asks the agent to make a commit the operator has not approved (Core Principle 4).

## Acceptance Criteria

- AC-STE-817.1: For a `kind: bug` FR, the `/tdd` test-writer proves each bug case's test RED on the code before the fix and takes its tree snapshot only after a bug-case RED; the implementer proves the fix load-bearing by undoing it from Stage RED's tree and reporting the outcome (`skills/tdd-write-test/SKILL.md`, `skills/tdd-implement/SKILL.md` and their agents).
- AC-STE-817.2: On a bug FR, the `/tdd` spec-review audit and the `/spec-review` audit classify as `partial` a bug-case test that asserts only the fix's new code ran, or a `Regression:` test off its named path or name, and never add `missing` (`skills/tdd-spec-review/SKILL.md`, `skills/spec-review-audit/SKILL.md`). `/implement` step 14 counts a bug AC without a red-before proof as unproved (`docs/implement-reference.md`). The `/tdd` halt report names `--resume-at audit` beside the re-run clause for a false-RED test-writer halt (`adapters/_shared/src/tdd_halt_report.ts`).
- AC-STE-817.3: `skills/debug/SKILL.md` carries `## A reported bug`: a reported bug is fixed only when a test is RED at its assertion before the fix and GREEN on it, and a bug FR's fix goes through `/implement <FR-id>`.
- AC-STE-817.4: The `/debug` "fix made before its test" path never tells the agent to commit or stash. For a fix that is not committed yet: `<dir>` is a fresh directory outside the working tree from `mktemp -d`; `git worktree add --detach <dir> HEAD`, and stop if `add` fails. In `<dir>` it copies in every path `git status --porcelain --untracked-files=all` lists that is neither the fix nor the test (the other uncommitted work, deletions and renames applied, parent directories created), installs or links dependencies and regenerates, then copies the test in and runs it (RED at its assertion). It then copies in the fix's paths, regenerates, and runs it again (GREEN). A file holding both the fix and other uncommitted work cannot be split: it says so and asks the operator to commit or set aside the other work first. The other uncommitted paths copied in are named in the change description. Whatever the outcome, it finishes with `git worktree remove --force <dir>`. The steps of the path for a committed fix are unchanged.
- AC-STE-817.5: `tests/bug-regression-proof-contract.test.ts` pins the AC-STE-817.4 wording and pins that `skills/debug/SKILL.md` no longer carries the sentence "commit a fix that is not committed yet".
- AC-STE-817.6: `bun test` from `plugins/dev-process-toolkit` reports 0 failures, and its skip identities equal the trunk baseline by name.

## Technical Design

The PR's four commits land as written, with the author rewritten to the contributor's GitHub noreply address. Our change is one bullet in the `/debug` SKILL plus the pins that read it. HEAD lacks both the fix and any other uncommitted work, so that work goes into the worktree first and RED then isolates the fix. Paths come from `git status --porcelain --untracked-files=all`, so a new directory is listed file by file.

## Testing

Update the `/debug` pins in the bug-regression contract test to the new wording, slice each path on its own, pin the step order, and forbid commit and stash on the new path. The PR's own suites stay green.
