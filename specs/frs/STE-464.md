# /deliver pipeline orchestrator: inline Socratic phases + spawned visible ceremony chain

## Summary

One command takes a feature from an idea to a merged-ready pull request. The design conversation and spec writing stay in the invoking session with the human; the mechanical chain — implement, ship, pull request — runs in a fresh, visible spawned agent per milestone that the human can watch and take over. Every approval a stage raises is relayed to the human, never fabricated. If the spawning plugin is missing, the command halts with install instructions rather than degrading to invisible background agents.

## Requirement

A new user-invocable `/dev-process-toolkit:deliver` skill: inline `/brainstorm` + `/spec-write`, then one fresh visible agent-toolkit worker per milestone running `/implement M<N>` → `/ship-milestone M<N>` → `/pr` serially, with fenced stage hand-offs, bounded retries, deterministic halts, operator-relayed approval gates, `merge_policy`-routed PR closure, and a hard headless-refusal contract. Consumes STE-463's `readOrchestrationConfig`.

## Acceptance Criteria

- AC-STE-464.1: New user-invocable skill `skills/deliver/SKILL.md`; every probe-#57-pinned count surface updated (user-invocable 16→17, skills 24→25, README + CLAUDE.md).
- AC-STE-464.2: Phases 1–2 (`/brainstorm`, `/spec-write`) run inline in the invoking session with their Socratic contracts untouched; `/deliver` never proxies or batches their questions.
- AC-STE-464.3: Pre-flight: when the `agent-toolkit:spawn-agent` skill is unavailable, halt with an NFR-10-shape message carrying verbatim install instructions; never substitute the built-in Agent/Task tool — a visible session is the contract.
- AC-STE-464.4: Phase 3 spawns one fresh visible worker per milestone, serially; the worker runs `/implement M<N>` → `/ship-milestone M<N>` → `/pr` in-session; the kickoff task text carries the effort keyword from `readOrchestrationConfig().defaultEffort`.
- AC-STE-464.5: Stage hand-offs: each stage reports a single fenced `deliver-stage-result` block (banner, fixed section order, line cap, `- (none found)` fallback); one scoped retry on shape violation, second violation ⇒ deterministic halt naming the stage (STE-225/STE-296 bounds).
- AC-STE-464.6: Worker approval gates (commit / release / PR / tracker prompts) are relayed to the operator via AskUserQuestion and the answer forwarded by keystroke; `/deliver` never injects the auto-approve marker into worker prompts and never fabricates an approval.
- AC-STE-464.7: Post-PR behavior follows `merge_policy`: `offer` ⇒ ask the operator; `auto` ⇒ merge only after the PR is mergeable and checks pass, then re-run the project gate on merged main before the next milestone; `never` ⇒ stop at the open PR.
- AC-STE-464.8: Headless refusal: non-tty stdin ⇒ canonical refusal carrying the machine-readable refused marker (AC-STE-404.5 shape); no marker carve-out — `/deliver` is interactive by design.
- AC-STE-464.9: Meta-test pins: stage-block banner, refusal literal, and install-instructions literal grep-pinned; NFR-1 line caps green on all touched SKILLs; flow detail lives in new `docs/deliver-reference.md` keeping the SKILL lean.
- AC-STE-464.10: Smoke coverage: a project-local fixture asserts the headless refusal (a `claude -p` child invoking `/deliver` yields the refusal marker, not silent scaffolding); `SMOKE_LEGS` untouched; the fixture is mutation-verified.

## Technical Design

Orchestration mechanics delegate at runtime to the agent-toolkit spawn-agent skill (host detection, ledger, watcher, occupant checks are its contract, not duplicated prose). The SKILL carries the stage contract + gates; `docs/deliver-reference.md` carries the narrative. Serial agent-per-milestone topology per the 2026-08-15 operator decision (parallel milestones collide on probe-count pins + release files). The pre-flight probes skill availability via the plugin registry (installed-plugins listing), not via filesystem guesses.

## Testing
