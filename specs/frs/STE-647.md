# A shared floor moves only when asked, and probe #25 remedies hold true

## Summary

Re-running a shared declaration from a newer client silently raised the version floor every sibling repository must meet.
A shared re-run now keeps the floor unless a validated floor is passed, and prints one line saying what happened to it and which manifest the running version came from.
The binding probe's remedies stop asserting a false cause for a foreign ticket file, and following them never raises the floor.

## Requirement

A `--shared` re-run keeps an existing floor unless `--floor <X.Y.Z>` is passed. `--floor` is validated. Every `--shared` run prints one line that states the floor change and the manifest the running version was read from, which makes an unpublished working-tree source visible.

Probe #25's remedies stop asserting a false cause:
- A key-prefix violation says the ticket is read by key.
- It gives each route with its condition, including removing an untracked leftover file.
- It names the repoint command through `${CLAUDE_PLUGIN_ROOT}`.
- The paragraph remedy for a declared sub-section re-renders without `--shared`, so following it never raises the floor.

Covers B-7 (medium) and B-6 (medium). **Amends STE-603's floor contract** (AC-STE-603.2) per operator ruling R1: a `--shared` re-run no longer raises min_dpt_version to the running version; it keeps the existing floor, and only `--floor` moves it.

## Acceptance Criteria

- AC-STE-647.1: Re-running `--shared <tag>` from a newer client leaves min_dpt_version unchanged and prints a `kept at` line naming the running version.
- AC-STE-647.2: `--floor <v>` together with `--shared` sets min_dpt_version to v and re-renders the stop paragraph, and nothing else in the file changes.
- AC-STE-647.3: `--floor` above the running version, below 2.87.0, not strict X.Y.Z, or without `--shared` exits 1 with the file byte-identical.
- AC-STE-647.4: An existing non-strict floor without `--floor` still refuses, and the remedy names `--floor <X.Y.Z>` instead of a hand edit.
- AC-STE-647.5: Every run with `--shared` prints exactly one line beginning `min_dpt_version` that states the old and new floor (or "kept") and the manifest path the running version came from. A run without `--shared` prints no such line.
- AC-STE-647.6: Every key-prefix remedy says the file's ticket stays in the foreign project and is read by key, and names the untracked-leftover route with its condition: if `git status` shows `??`, move the file out of this checkout.
- AC-STE-647.7: No probe #25 remedy contains `was changed without the repoint command`.
- AC-STE-647.8: Every key-prefix remedy names `${CLAUDE_PLUGIN_ROOT}/adapters/_shared/src/repoint_tracker_binding.ts`, and no probe #25 remedy outside buildMessage's pinned text contains `plugins/dev-process-toolkit/adapters/`.
- AC-STE-647.9: For a declared sub-section, the paragraph remedy names the writer through `${CLAUDE_PLUGIN_ROOT}` with the bound project and without `--shared`, and running it under a newer client leaves min_dpt_version unchanged.
- AC-STE-647.10: Probe #25's verdicts (violation count and reasons) are unchanged for every existing fixture; only the remedy text differs.

## Technical Design

In the writer, TrackerSubsectionOptions gains `floor` and the CLI gains `--floor`, accepted only with `--shared` and validated as strict X.Y.Z between FIRST_GATED_DPT_VERSION and the running version; an explicit lower floor is printed as a lowering. The summary line prints on every shared run. The published-version check (design part 4) is skipped. In the probe module, the fixed key-prefix remedy becomes the conditioned text with no git subprocess, the repoint and writer names move to the plugin-root form, and the paragraph remedy fills in the bound project with no shared flag; buildMessage stays untouched.
