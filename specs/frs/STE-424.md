# STE-424: Detect mode-none short-ULID collisions across the archive boundary {#STE-424}

## Summary

In tracker-less mode every identifier the toolkit resolves against is the same six-character tail of a minted unique id. The feature-record filename, its archive path, the acceptance-criterion prefix, the milestone token and the plan filename all derive from one slice, so the long id is write-only and buys no operational uniqueness. The effective key is thirty bits.

The randomness design is sound and must not be touched. The slice sits wholly inside the random region and can never reach the timestamp, the generator draws from a cryptographic source, and the alphabet divides the byte range exactly so there is no modulo bias. This is a governance defect, not an entropy defect.

What is actually wrong is that the two collision guards disagree. The milestone side probes both the active and archived trees and retries. The feature-record side mints raw, with no predicate and no retry at all. And the archive blindness is held open by a passing test that asserts a new record whose tail matches an archived one resolves without complaint.

The worst path is silent from end to end: the identity gate probe compares each file against itself, so two plans deriving the same token sit green side by side, one active and one archived, until something much later moves a file onto an occupied name.

## Requirement

Two distinct minted identities that derive the same short tail MUST be detected loudly, across the active and archived trees together, on both the plan and the feature-record surfaces. Feature-record minting MUST gain the same existence predicate and retry the milestone minter already has.

Verified against `4b25d07` by the parallel audit:

- One slice, five production call sites: `ac_prefix.ts:68`, `local_provider.ts:40`, `local_provider.ts:206`, `tracker_provider.ts:356`, `milestone_token.ts:119`.
- Asymmetric guards: `mint_milestone_id.ts:56-61` probes `specs/plan/` **and** `specs/plan/archive/` and throws after 3 attempts; `local_provider.ts:72-74` returns raw `mintIdImpl()` with no predicate and no retry.
- The archive hole is pinned open by `ac_prefix.test.ts:174-204` (*"scan ignores archive/ subdirectory"*), which asserts a deliberate tail reuse against an archived record resolves undefined.
- Worst silent path: `plan_identity_mode_conditional.ts:280` compares `milestoneIdFromUlid(scan.value)` against the file's own basename — per-file self-consistency. The walk at `:190-205` keeps no cross-file state, so two plans sharing a tail each validate against themselves and the gate stays green.

Keyspace is 32^6 = 2^30. Birthday thresholds: 0.1% at 1,467 ids, 1% at 4,647, 10% at 15,043, 50% at 38,582. The probability is not the problem; the silence is.

**Explicitly out of scope — do not implement.** Widening the slice and changing the random source are both wrong: the entropy is fine and widening would break every shipped filename, prefix, token, branch name and asset folder in every consumer project. Adding command-line entry points to the minter modules is **also** out of scope: prose invocation is the house pattern here (only 4 of 143 non-test shared modules carry one, and the sibling allocator has none), so their absence is not a defect. No acceptance criterion below proposes either.

## Acceptance Criteria

- AC-STE-424.1: The plan walk that the milestone-identity probe already performs gains a cross-file duplicate-basename check spanning `specs/plan/` and `specs/plan/archive/` together; two plans deriving the same token fail the gate loudly instead of passing.
- AC-STE-424.2: The equivalent cross-file duplicate-tail check covers `specs/frs/` and `specs/frs/archive/` together.
- AC-STE-424.3: Feature-record minting routes through the collision-guarded minter with a **synchronous** existence predicate covering the active and archived trees, so a collision is retried rather than silently accepted.
- AC-STE-424.4: `ac_prefix.test.ts:174-204` is inverted to assert the archive **is** scanned. This is a deliberate reversal of a currently-green test, not a regression — the test presently enforces the defect.
- AC-STE-424.5: The two prose over-claims are corrected: `skills/spec-write/SKILL.md:178` ("collision-guarded by construction") and `specs/frs/archive/STE-417.md:18` ("cannot collide by construction") are restated as detection within one working tree, which is what two existence checks provide.
- AC-STE-424.6: A fixture reproduces the worst silent path — an active plan and an archived plan deriving the same token — and asserts the gate now fails on it.

## Technical Design

Roughly twenty-five lines, no data migration and no identifier-format change.

The plan-side check goes into the walk that already recurses over both directories: accumulate a map from derived basename to the ids that produced it during the existing loop, and raise when any entry holds more than one. The feature-record side gets the same treatment on its own walk.

The minting fix mirrors the milestone minter exactly: a synchronous predicate is required, because the collision-retry helper documents that an asynchronous one would fall through the retry silently. The existing asynchronous scan can remain as a belt-and-braces layer.

Sequencing matters for AC-STE-424.4: invert the test in the same commit as the behavior change, and say so in the message, so the TDD audit does not read a deliberately-flipped assertion as a regression it should repair.

## Testing

- Unit coverage for both cross-file duplicate checks, each with a passing case and a colliding case.
- A seeded-mint test forcing a first-mint collision against an archived record, asserting the retry produces a distinct tail and the archived file is byte-unchanged.
- The inverted archive-scan test per AC-STE-424.4.
- A fixture per AC-STE-424.6 with an active and an archived plan sharing a token.
