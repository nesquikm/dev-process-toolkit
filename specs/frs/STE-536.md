# Authoring surfaces state the budgets, from a single source

## Summary

The caps land in the scanner, but the surfaces that guide authoring state no budget, so a writer discovers the number by turning the gate red. This states each budget where the writing happens: the summary limit, the technical design limit, the notes limit, and the plan narrative limit. It also adds the anti-decoration rule the budgets exist to enforce.

## Requirement

Every authoring surface that guides FR or plan prose states the applicable budget and carries the anti-decoration rule. Budgets are stated once and read from one place.

## Acceptance Criteria

- AC-STE-536.1: The surface that guides FR authoring states all three FR budgets, in the section each applies to. A budget stated only in the scanner is invisible to the person doing the writing.
- AC-STE-536.2: The plan template at `templates/spec-templates/plan.md.template` states the plan narrative budget beside the subsection guidance, and names the three structural kinds that are exempt, so an author knows a checklist is not measured before writing one.
- AC-STE-536.3: The anti-decoration rule is stated: no aphorisms, and no restating a point in a second register. The rule is stated where the prose is authored, not only in a document about the rule.
- AC-STE-536.4: Budgets are SINGLE-SOURCED. The number a surface states and the number the scanner enforces come from one definition, and a test fails when they diverge. The NFR-1 skill-length cap is written as three different numbers — 351 in `specs/requirements.md`, 354 and 358 across test files — and has drifted unnoticed; this AC is what prevents the new budgets from repeating it.
- AC-STE-536.5: Skill files stay under the NFR-1 line cap. `spec-write`, `setup` and `implement` sit at 357 of 358, so this FR's prose lands through an extraction to `docs/` rather than by growing a skill file. The test asserts the cap holds for every file this FR touches.
- AC-STE-536.6: A budget changed in the scanner but not at the authoring surface fails a test, and so does the reverse. Both directions are asserted, because a single-direction check passes whenever the unchecked side is the one that drifted.

## Technical Design

Single-sourcing is what AC-STE-536.4 buys, and the cheapest form is for the scanner module to export its constants and the surfaces to state numbers that a test reads back from that export. The alternative, generating the prose, would put a build step between the author and the guidance.

The extraction in AC-STE-536.5 follows the shipped precedent set by `docs/deliver-reference.md`: the operating rules stay in the skill, the reference detail moves to `docs/`, and the skill points at it.

The anti-decoration rule is guidance rather than a scanned rule. No probe can tell an aphorism from a load-bearing sentence, and a rule that tried would fire on the specifications it was meant to improve.

## Testing

AC-STE-536.6 is tested in both directions with two separate mutations, since one assertion cannot distinguish which side moved.

The cap assertion in AC-STE-536.5 runs over the actual files this FR edits, read from the diff rather than from a hand-maintained list.

## Notes

The anti-decoration rule is the one part of this milestone nothing enforces. That is deliberate, and it is also the part most likely to drift.
