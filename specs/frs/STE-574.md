# The dogfood grades only the subject its milestone owns

## Summary

An archived plan that has not yet shipped is legitimate transient state between the archival commit and the release commit. One live-tree assert grades the whole report flat, so that window reds the entire test run and the ship cannot clear a gate it must clear to ship.

Give each violation a typed kind, and let that assert exclude the one kind this milestone does not own.

Detection does not move. Only the instant of grading does.

## Requirement

The plan/ship coherence violation record carries a typed kind, and the live-tree assert that grades the whole report excludes the one kind that is legitimate transient state during a release. Every path that detects unshipped ship debt keeps detecting it.

## Acceptance Criteria

- AC-STE-574.1: `PlanShipCoherenceViolation` carries a `kind` field typed as a closed union of exactly `"unshipped_debt" | "corrupt_stamp" | "surface_disagreement"`. All four of the probe's violation push sites set it — the unstamped-and-unparked site as `unshipped_debt`, the malformed-stamp and no-matching-heading sites as `corrupt_stamp`, and the release-surface-agreement site as `surface_disagreement`. The last of those is a raw object literal rather than a call to the shared factory, so a change that only touches the factory fails this clause.
- AC-STE-574.2: No byte of any violation's `reason`, `note`, `message` or severity changes. Two sibling suites pin that text, and the assertion is that they pass unchanged rather than that they were not edited.
- AC-STE-574.3: The live-tree dogfood in `tests/m141-ste-546-surface-agreement.test.ts` grades the report through a predicate that excludes `kind === "unshipped_debt"`, and on a temp root reconstructing the archive-then-ship window that predicate selects nothing. This fails before the change: no such predicate exists, and the flat assert reds.
- AC-STE-574.4: On that same temp root the probe itself still reports at least one row whose `kind` is `"unshipped_debt"`. Detection is unmoved. A change applied to the probe instead of the test fails this clause.
- AC-STE-574.5: Mutation arm, and it is mandatory. A corrupt-stamp fixture and a surface-disagreement fixture both survive the predicate — each yields at least one graded row. A predicate degenerated to one that selects nothing fails here while passing AC-STE-574.3 and AC-STE-574.4.
- AC-STE-574.6: Removal arm. With a genuine corrupt stamp present on the temp root, the graded set is non-empty and the assert reds.
- AC-STE-574.7: Both surviving detection paths are confirmed by test, not by prose. Probe #63 is still registered at severity `error` in `skills/gate-check/SKILL.md`, and `skills/ship-milestone/SKILL.md` still directs its bare no-arg form at `specs/plan/archive/` for this same predicate.
- AC-STE-574.8: The sibling filter in `tests/gate-check-plan-ship-coherence.test.ts` migrates from the `reason` substring to `kind === "corrupt_stamp"`, and the migration is proved behaviour-preserving: on a fixture carrying all three kinds, the two selections return the same rows.

## Technical Design

The probe module gains a `PlanShipCoherenceViolationKind` union and a `kind` field on the violation record. `makeViolation` takes the kind as a parameter. The release-surface-agreement site builds its record inline rather than through that factory, so it needs its own edit — it is the one a factory-only change misses.

Nothing else about the record changes. Two suites pin `reason` text, and `resume_classifier.ts` is a shipped consumer that reads `message` only, so an additive field is safe there.

The grading move lives in the tests, never in the probe. Probe #63 keeps flagging unshipped debt at severity error, and the release skill keeps scanning the archive for it. This FR confirms both rather than assuming them.

## Testing

The mutation arm is the load-bearing one. A predicate that selected nothing at all would satisfy the excludes-it arm and the detection-unmoved arm while silently deleting the whole check; only a fixture that must survive the predicate catches that.

Every arm runs against a temp root that reconstructs the window — archived plan, no stamp, not parked, newest changelog heading one release behind — rather than against the live tree, whose state changes underneath the suite as the milestone ships.

## Notes

This is a reduction in automatic pressure, recorded as such rather than dressed up. Today an archived-never-shipped plan reds every test run, crudely but automatically. After this change both surviving detectors are operator-invoked. That is the correct design and it is not a free lunch.

## Recorded anomaly

Recorded as fact, without speculation, because the artefacts cannot settle it and the operator has decided not to investigate.

Measured, not recited. For each of the ten releases from v2.76.0 through v2.80.5, the tree immediately before the release commit carries exactly one archived plan that is neither stamped nor parked — the condition probe #63 reports as unshipped debt, one row each, ten for ten. The flat live-tree assert that reds on such a row is present in the suite at all ten of those trees. The CHANGELOG entries for those releases each record `0 failures`.

`/ship-milestone` pre-flight #3 measures once, before any write, and refuses on a non-zero failure count. Executed as documented, it could not have produced those ten release commits.

The artefacts cannot distinguish "the gate ran out of documented order" from "a refusal was overridden", because stamping the plan does not change the test total either way. That is the whole of what is known.

This FR removes the symptom, not the cause. After it lands, the evidence stops announcing itself.
