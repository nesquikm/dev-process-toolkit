# /setup --template flow: analyze-and-ask reuse selection via dispatch child skill

## Summary

With the inventory in hand, setup can bootstrap a new project from a template the way an experienced engineer would: show what the template offers, ask what to keep, adapt names, preview the result, and land it in the single bootstrap commit. The flow lives in a dispatch child so the main setup instructions stay within their size budget, and it refuses cleanly when no operator is present — reuse selection has no safe default.

## Requirement

A `--template <path>` flag on `/setup` dispatching to a new `setup-template` child skill (`user-invocable: false`, model-invocable — the STE-395 menu-exile precedent): analyzer run → categorized table → Socratic per-category selection (per-entry for manifests) → copy/adapt with rewritten names → unified diff preview → files ride the normal single bootstrap commit (STE-109 porcelain pre-flight widened to the selected set). Whole-project mode backs up a non-empty destination first (STE-392).

## Technical Design

Dispatch-child architecture is forced by the cap: `skills/setup/SKILL.md` has one line of headroom, so the flag line must be surgical and the flow lives in `skills/setup-template/SKILL.md`. The child is Socratic (probe #43 auto-scopes it) and delegates all analysis to the STE-468 module. The `skills/` STE-token ceiling is at 246/246 — offset any new tracker-ID tokens.
