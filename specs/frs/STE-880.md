# /tdd runs from tests the project already has

## Summary

Some projects already have the tests for a feature, such as conformance cases copied from a specs repository.
The TDD run always wrote a second set of tests first.
A new option names the existing test files instead.
The run then checks that those tests fail, and builds the code to make them pass.
The implement command passes the option through to the TDD run.

## Requirement

`/tdd <FR-id> --tests-provided <path...>` replaces the test-writer stage with a RED check of the named existing test files, then runs GREEN, REFACTOR and AUDIT as usual; `/implement` accepts the same flag and passes it through.

## Acceptance Criteria

- AC-STE-880.1: `/tdd <FR-id> --tests-provided <path...>` takes one or more paths. A path that does not exist, or lies outside the repository, refuses in the NFR-10 shape before the receipt is recorded and before any fork is dispatched.
- AC-STE-880.2: At Stage RED no test-writer fork is dispatched. The orchestrator runs the named files with the project's test command and requires at least one failing test. When every named test passes, the run halts with a named failure mode and no implementer fork is dispatched.
- AC-STE-880.3: GREEN runs once per AC as today, with the named files as the failing-test command; REFACTOR and AUDIT are unchanged. The AUDIT retry round may still dispatch the test-writer, scoped to the ACs the audit reports missing.
- AC-STE-880.4: `--tests-provided` combined with `--resume-at` is accepted, and Stage RED is skipped as on any resume.
- AC-STE-880.5: `/implement` accepts `--tests-provided <path...>` and Phase 2 passes it to `/dev-process-toolkit:tdd`, as it passes `--resume-at`. Both argument hints name the flag. `skills/implement/SKILL.md` does not grow past its line cap.
- AC-STE-880.6: The success report and the halt report say the tests were provided rather than written, and name the files.
- AC-STE-880.7: `bun test` from `plugins/dev-process-toolkit` reports 0 failures, and its skip identities equal the trunk baseline by name.

## Technical Design

Follow the `--resume-at` precedent: parse the flag in the orchestrator's inputs, check the paths before the receipt, and route Stage RED to an orchestrator-run RED check instead of the test-writer fork. The RED check reuses the failing-test command shape the implementer already receives. `/implement` names the flag in the Phase 2 step 8 pass-through sentence, replacing words rather than adding a line.

## Testing

Contract tests over the `/tdd` and `/implement` skill texts: the flag in both argument hints, the path refusal before the receipt, no test-writer dispatch at Stage RED, and the halt when every provided test passes.
