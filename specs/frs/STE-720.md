# Bug report payloads hide home paths, session ids and branch names

## Summary

A bug report today removes secrets before upload, but not the details that identify a person or project.
This adds an opt-in second pass for home folder paths, session ids and branch names.
Home paths become a tilde, session ids become short aliases, and branch names become a short hash.
With the setting off, the default, a report is byte-identical to today's.
A report seeded from a retrospective always runs the pass.

## Requirement

Operator rule and amendment 3, 2026-11-04: existing payloads do not change by default, so the pass is opt-in for them. The new `--from-retro` path of STE-721 is new behaviour, so the pass is mandatory there.

### The switch and its boundary

`specs/settings.yaml` gains a top-level `report_issue:` section with one key, `identifier_redaction`, closed key set `{enabled}`. The loader's closed top-level key set (AC-STE-706.2) gains `report_issue`. It is read through `loadProjectSection(projectRoot, "report_issue")`. An absent key or section, `enabled: false`, a legacy tree, a tree with no settings file and any loader refusal all mean off. No legacy home carries it, and neither `/setup` nor any migration writes it. It enters the AC-STE-706.12 table as a `new` row naming this FR, and `docs/settings-reference.md` documents it.

| Path | Identifier pass | Payload |
|---|---|---|
| `/report-issue`, switch off (the default) | not run | byte-identical to v3.0.0: seven summary rows, `across 7 pattern(s)` |
| `/report-issue`, switch on | runs | ten summary rows, `across 10 pattern(s)` |
| `/report-issue --from-retro` (STE-721) | always runs; the switch is not read | ten summary rows |

### The pass

New module `adapters/_shared/src/scrub_identifiers.ts`, pure and free of I/O like `scrub_secrets.ts`:

- `IDENTIFIER_PATTERNS`: exactly three keys, in this order: `home_path`, `session_id`, `branch_name`.
- Aliases come from `createAliasMap()` and `aliasFor` in `session_aliases.ts` (STE-719), the one shared session aliaser. The pass defines no numbering of its own. One map serves a whole report, shared by every file of it, so one session id gets one alias in every file.
- `scrubIdentifiers(text, ctx)` with `ctx = { home, branches, aliases }`, returning `{ scrubbed, matches }` in the `ScrubResult` shape, zero counts included.

Rules:

- `home_path`: the literal `ctx.home`, and any `/Users/<segment>` or `/home/<segment>` prefix, become `~`. Only the prefix is rewritten, so `/Users/<segment>/x/y` becomes `~/x/y`.
- `home_path` also covers Claude project-folder slugs. `cwdToSlug` (`find_current_session.ts`) turns `/Users/<name>/repo` into `-Users-<name>-repo`, so a path under `~/.claude/projects/` still names the user after the prefix rule. The literal `cwdToSlug(ctx.home)` becomes `-~` first, which handles a name holding a dot or dash. Then any remaining `-Users-<segment>` or `-home-<segment>` followed by `-` or `/` becomes `-~`, with `<segment>` one run of letters and digits. Both count under `home_path`.
- `session_id`: every UUID-shaped token (8-4-4-4-12 hex, any case) becomes `s<N>`, numbered by first appearance across the report. A UUID that is not a session id is aliased too; over-redaction is accepted.
- `branch_name`: each name in `ctx.branches` becomes `branch-<first 8 hex of sha256(name)>`, matched as a whole token, and also after a remote prefix such as `origin/`, which is kept. `ctx.branches` is every local and remote-tracking branch, from `git for-each-ref --format='%(refname:lstrip=2)' refs/heads refs/remotes` with the remote name stripped. It also holds every `gitBranch` or `git_branch` value in the files being scrubbed. So a branch named inside a command or a commit message is found even when it is not checked out. The names `main`, `master`, `develop`, `trunk` and `HEAD` are never rewritten.
- Idempotent: a second pass over scrubbed text changes nothing and counts zero.

### The payload front door

New module `adapters/_shared/src/report_issue_payload.ts` with `scrubPayloadDir(dir, ctx)` and an `if (import.meta.main)` front door `bun run report_issue_payload.ts <workdir> <projectRoot> [--from-retro]`.

- Without `--from-retro` it reads the switch first. When the switch is off it exits 0 with empty stdout and stderr and touches no file.
- Otherwise it runs `scrubIdentifiers` over every file in the working directory, with one alias map for the whole run. It appends the three identifier rows to `metadata.json` `redaction_summary`, after the seven secret rows.

The per-file `scrubSecrets` prose of `/report-issue` § 4 to § 6 stays as it is, in every mode. The skill calls this front door once, after every file is written and secret-scrubbed and before the preview gate. The closing summary's redaction row counts the rows in `redaction_summary`, so it reads `across 7 pattern(s)` when the pass did not run and `across 10 pattern(s)` when it did.

Call placement (R4-6, for operator review). The supervisor ruled that a default run issues no extra tool call, keyed on an output an existing call already prints. `/report-issue` has no such call. Before the preview it runs only git commands, file reads and model-written library calls (§ 4). Its one toolkit command, `check_marker_runtime.ts`, runs after the preview and not at all under `--dry-run`. So without `--from-retro`, the front door call is the one default-path call this milestone adds. It prints nothing and writes nothing when the switch is off. Two other shapes would remove it, and both need the operator: a command-line flag in place of the settings key, which amendment 3 did not choose, or a pass run after the preview, which would publish bytes the operator never saw. Under `--from-retro` the call is keyed on that flag, so no default run makes it. Every sentence of the skill that names the front door carries its condition.

### Coverage

When it runs, the pass covers every payload file: `report.md` (which embeds `git log -10 --oneline`, `git status --porcelain`, the settings bodies and the skill list), `metadata.json`, `transcript.jsonl` when included, and any file a later FR adds.

## Technical Design

A second pure pass beside `scrubSecrets`, never folded into it, so the secret patterns, their prose and their tests stay untouched. It runs after the secret scrub, so a token that is both is counted as a secret.

The front door moves the identifier scrub into code, which lets a subprocess test prove it. It reads the switch first, so a default report is today's report.

Branch hashing uses `createHash("sha256")` from `node:crypto`, as `tracker_receipts.ts` does. The default-branch list stays fixed because those names carry no identity.

## Testing

Unit cases per rule, an alias-sharing case, idempotence, a subprocess privacy test with the switch on and under the retro flag, a default byte-identity case and switch rows.
