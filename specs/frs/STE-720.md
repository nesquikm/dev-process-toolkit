# Bug report payloads hide home paths, session ids and branch names

## Summary

A bug report today removes secrets before upload, but not the details that identify a person or project.
Home folder paths, session ids and branch names reach the shared report unchanged.
This adds a second pass that rewrites home paths to a tilde and replaces session ids with short aliases.
Branch names are replaced by a short hash.
A test fails if a home path or a session id reaches any report file.

## Requirement

### The pass

New module `adapters/_shared/src/scrub_identifiers.ts`, pure and free of I/O like `scrub_secrets.ts`:

- `IDENTIFIER_PATTERNS`: exactly three keys, in this order: `home_path`, `session_id`, `branch_name`.
- Aliases come from `createAliasMap()` and `aliasFor` in `session_aliases.ts` (STE-719), the one shared session aliaser. The pass defines no numbering of its own. One map serves a whole report, shared by every file of it, so one session id gets one alias in every file.
- `scrubIdentifiers(text, ctx)` with `ctx = { home, branches, aliases }`, returning `{ scrubbed, matches }` in the `ScrubResult` shape, zero counts included.

Rules:

- `home_path`: the literal `ctx.home`, and any `/Users/<segment>` or `/home/<segment>` prefix, become `~`. Only the prefix is rewritten, so `/Users/<segment>/x/y` becomes `~/x/y`.
- `session_id`: every UUID-shaped token (8-4-4-4-12 hex, any case) becomes `s<N>`, numbered by first appearance across the report. A UUID that is not a session id is aliased too; over-redaction is accepted.
- `branch_name`: each name in `ctx.branches` becomes `branch-<first 8 hex of sha256(name)>`, matched as a whole token, and also after a remote prefix such as `origin/`, which is kept. `ctx.branches` is the current branch from `git rev-parse --abbrev-ref HEAD` plus every `gitBranch` or `git_branch` value in the files being scrubbed. The names `main`, `master`, `develop`, `trunk` and `HEAD` are never rewritten.
- Idempotent: a second pass over scrubbed text changes nothing and counts zero.

### The payload front door

New module `adapters/_shared/src/report_issue_payload.ts` with `scrubPayloadDir(dir, ctx)` and an `if (import.meta.main)` front door `bun run report_issue_payload.ts <workdir>`. It runs `scrubSecrets` and then `scrubIdentifiers` over every file in the working directory, with one alias map for the whole run, and writes the combined per-pattern counts into `metadata.json` `redaction_summary` (ten rows: seven secret, three identifier). `/report-issue` § 4 to § 6 call this front door once, after every file is written and before the preview gate, in place of per-file scrub prose.

### Coverage

The pass covers every payload file: `report.md` (which embeds `git log -10 --oneline`, `git status --porcelain`, the settings bodies and the skill list), `metadata.json`, `transcript.jsonl` when included, and any file a later FR adds. The closing summary's redaction row counts across both passes (`across 10 pattern(s)`).

## Technical Design

A second pure pass beside `scrubSecrets`, never folded into it, so the secret patterns and their tests stay untouched. Secrets run first, so a token that is both is counted as a secret. The front door moves the scrub from prose into code, which is what lets a subprocess test prove the guarantee. Branch hashing uses `createHash("sha256")` from `node:crypto`, as `tracker_receipts.ts` does; the default-branch list stays fixed because those names carry no identity and appear in ordinary prose.

## Testing

Unit cases per rule, an alias-sharing case, idempotence, and one subprocess privacy test over a seeded working directory with a ten-row summary check.
