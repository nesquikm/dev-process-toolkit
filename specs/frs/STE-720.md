# Bug report payloads hide home paths, session ids and branch names

## Summary

A bug report today removes secrets before upload, but not the details that identify a person or project.
A per-run flag adds a second pass for home folder paths, session ids and branch names.
Home paths become a tilde, session ids become short aliases, and branch names become a short hash.
Without the flag, the default, a report is byte-identical to today's.
A report seeded from a retrospective always runs the pass.

## Requirement

Operator rule and amendment 3, 2026-11-04: existing payloads do not change by default, so the pass is opt-in for them. The new `--from-retro` path of STE-721 is new behaviour, so the pass is mandatory there.

Operator ruling at the v3.0.0 rebase (supersedes the R4-6 call-placement question): the opt-in is a per-run command-line flag, not a settings key. `/report-issue` has no existing call before its preview that could print a marker line, so a settings switch would cost every default run one extra call. A flag costs none: a run without it never reaches the new code.

### The flag and its boundary

`skills/report-issue/SKILL.md` gains the flag `--redact-identifiers`, and its `argument-hint` becomes `'[--full] [--dry-run] [--redact-identifiers]'`. The flag is read off the command line, as `--full` and `--dry-run` are. No settings key exists for it: `specs/settings.yaml` gains no `report_issue:` section, `NEW_KEYS` and the loader's closed key sets are unchanged by this FR, and the AC-STE-706.12 table gains no row for it. The archived AC-STE-706.12 prose lists `report_issue.identifier_redaction` among the later `new` rows; this ruling drops that row (Amended by AC-STE-720.14). The marker lives in the archived AC itself: `specs/frs/archive/STE-706.md` AC-STE-706.12 gains, appended at the end of its line and no other byte changed, the clause `` *(Amended by AC-STE-720.14 (v3.2.0): `report_issue.identifier_redaction` is dropped from the later `new` rows; identifier redaction is the per-run `--redact-identifiers` flag, not a settings key.)* ``.

| Path | Identifier pass | Payload |
|---|---|---|
| `/report-issue` with neither flag (the default) | not run; the front door is never called | byte-identical to v3.0.0: seven summary rows, `across 7 pattern(s)` |
| `/report-issue --redact-identifiers` | runs | ten summary rows, `across 10 pattern(s)` |
| `/report-issue --from-retro` (STE-721) | always runs, with or without `--redact-identifiers` | ten summary rows |

### The pass

New module `adapters/_shared/src/scrub_identifiers.ts`, pure and free of I/O like `scrub_secrets.ts`:

- `IDENTIFIER_PATTERNS`: exactly three keys, in this order: `home_path`, `session_id`, `branch_name`.
- Aliases come from `createAliasMap()` and `aliasFor` in `session_aliases.ts` (STE-719), the one shared session aliaser. The pass defines no numbering of its own. One map serves a whole report, shared by every file of it, so one session id gets one alias in every file.
- `scrubIdentifiers(text, ctx)` with `ctx = { home, branches, aliases }`, returning `{ scrubbed, matches }` in the `ScrubResult` shape, zero counts included.

Rules:

- `home_path`: the literal `ctx.home`, and any `/Users/<segment>` or `/home/<segment>` prefix, become `~`. Only the prefix is rewritten, so `/Users/<segment>/x/y` becomes `~/x/y`.
- `home_path` also covers Claude project-folder slugs. `cwdToSlug` (`find_current_session.ts`) turns `/Users/<name>/repo` into `-Users-<name>-repo`, so a path under `~/.claude/projects/` still names the user after the prefix rule. The literal `cwdToSlug(ctx.home)` becomes `-~` first, which handles a name holding a dot or dash. Then any remaining `-Users-<segment>` or `-home-<segment>` followed by `-` or `/` becomes `-~`, with `<segment>` one run of letters and digits. Both count under `home_path`. Accepted residual: with no `ctx.home`, a user name holding a dot or dash slugs as `-Users-first-last-…`, and the segment rule rewrites only `-Users-first`, leaving `-~-last-…`. `report_issue_payload.ts` passes `os.homedir()` as `ctx.home`, so the literal slug rule covers the reporting user's own name; the residual reaches only another user's dotted name, or a direct call with no home.
- `session_id`: every UUID-shaped token (8-4-4-4-12 hex, any case) becomes `s<N>`, numbered by first appearance across the report. A UUID that is not a session id is aliased too; over-redaction is accepted.
- `branch_name`: each name in `ctx.branches` becomes `branch-<first 8 hex of sha256(name)>`, matched as a whole token, and also after a remote prefix such as `origin/`, which is kept. `ctx.branches` is every local and remote-tracking branch, from `git for-each-ref --format='%(refname:lstrip=2)' refs/heads refs/remotes` with the remote name stripped. It also holds every `gitBranch` or `git_branch` value in the files being scrubbed. So a branch named inside a command or a commit message is found even when it is not checked out. The names `main`, `master`, `develop`, `trunk` and `HEAD` are never rewritten.
- Idempotent: a second pass over scrubbed text changes nothing and counts zero.

### The payload front door

New module `adapters/_shared/src/report_issue_payload.ts` with `scrubPayloadDir(dir, ctx)` and an `if (import.meta.main)` front door `bun run report_issue_payload.ts <workdir> <projectRoot> (--redact-identifiers | --from-retro)`.

- It needs a mode flag, `--redact-identifiers` or `--from-retro`; given both, it runs as `--from-retro`. With neither, it refuses in NFR-10 shape, exits 1, prints nothing on stdout and touches no file. The skill never calls it that way.
- It reads no setting. It runs `scrubIdentifiers` over every file in the working directory, with one alias map for the whole run. It appends the three identifier rows to `metadata.json` `redaction_summary`, after the seven secret rows.

The per-file `scrubSecrets` prose of `/report-issue` § 4 to § 6 stays as it is, in every mode. When one of the two flags is given, the skill calls this front door once, after every file is written and secret-scrubbed and before the preview gate. The closing summary's redaction row counts the rows in `redaction_summary`, so it reads `across 7 pattern(s)` when the pass did not run and `across 10 pattern(s)` when it did.

Call placement. The skill issues the front-door call only when its invocation carries `--redact-identifiers` or `--from-retro`, and passes that flag through. A run with neither flag issues no new call and reads no new file, so its tool calls equal v3.0.0's. Every sentence of the skill that names the front door also names one of the two flags.

### Coverage

When it runs, the pass covers every payload file: `report.md` (which embeds `git log -10 --oneline`, `git status --porcelain`, the settings bodies and the skill list), `metadata.json`, `transcript.jsonl` when included, and any file a later FR adds.

## Technical Design

A second pure pass beside `scrubSecrets`, never folded into it, so the secret patterns, their prose and their tests stay untouched. It runs after the secret scrub, so a token that is both is counted as a secret.

The front door moves the identifier scrub into code, which lets a subprocess test prove it. Only the two flags reach it, so a default report is today's report, with no extra call.

Branch hashing uses `createHash("sha256")` from `node:crypto`, as `tracker_receipts.ts` does. The default-branch list stays fixed because those names carry no identity.

## Testing

Unit cases per rule, an alias-sharing case, idempotence, a subprocess privacy test under each flag, a no-flag refusal and byte-identity case, and a no-settings-key row.
