# The runner's live-checkout pin goes red between the archive and the release commit

## Summary

A test requires every probe to pass on this checkout.
Between the archive and the release, one probe rightly fails.
So the release checks refused, and two releases needed workarounds.
The test now ignores only that one expected failure.
The probe itself stays as strict as before.

## Requirement

### Steps to reproduce

1. On a clean trunk, archive a finished milestone with `/spec-archive` and commit.
2. Run the full suite, as the `/ship-milestone` test gate does.

### Expected

The suite is green: an archived plan that is not yet released is legitimate until the release commit.

### Actual

Three tests fail, because probe #63 reports the plan and the live-checkout test expects `74/74`.

## Acceptance Criteria

- AC-STE-847.1: Regression: `tests/m_e8850b-ste-847-archive-window.test.ts › an archived unshipped plan is the only failure the live-checkout grade ignores` fails before the fix and passes after it.
- AC-STE-847.2: The live-checkout grade accepts a run where every probe passes, and a run where the only failing row is probe #63 and every violation it reports is `unshipped_debt`. It uses the `gradedViolations` predicate of `tests/_plan_ship_grading.ts` and keeps no copy of it.
- AC-STE-847.3: It rejects a run with another failing row, a #63 row with any other violation kind beside or without the debt, a #63 row that failed by throwing, and a run with a missing or extra row. Each case is a test on a fixture tree or a fixture table.
- AC-STE-847.4: Outside the window the summary is still pinned to `74/74`.
- AC-STE-847.5: A named test copies this checkout's specs to a temporary tree in the archived, unshipped state and shows that every live-checkout test that grades probe #63 accepts it, the nested at-risk suites included. The state is built by the shipped archive code.
- AC-STE-847.6: Probe #63, its severity, its `/gate-check` text and `/ship-milestone` are unchanged, and the STE-574 and STE-690 suites pass unmodified.
- AC-STE-847.7: A mutation that ignores all of #63, or that ignores any single failing row, turns a named test red.
- AC-STE-847.8: `bun test` from `plugins/dev-process-toolkit` reports 0 failures on the archived, unshipped tree of this milestone, before its release edits, and its skip identities equal the trunk baseline by name.

## Technical Design

### Root cause

The pin in `m_d1e7b1-ste-756-gate-probe-runner.test.ts` grades the runner's summary flat, so it includes the one transient violation that STE-574 removed from the older dogfood.

The runner's rows carry counts and no kinds, so the grade runs `runPlanShipCoherenceProbe` itself for the kinds and the runner for the rows. The grading function lives beside `gradedViolations`.

## Testing

Fixture tables for each verdict, one temporary tree for the window, and the mutation legs above.
