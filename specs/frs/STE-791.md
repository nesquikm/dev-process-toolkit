# The gate receipt counts under one narrow cd form, and spec deletions get the spec-only pass

## Summary

The commit gate counts a gate receipt only from a standalone call.
Drivers often change directory first, and the gate then ignores the call.
The gate now accepts one more shape, with the receipt call last.
Every other compound shape is still refused.
A commit that only deletes spec files now gets the spec-only pass.
The smoke skill documents the receipt steps its driver needs.

## Requirement

`announcesGateReceipt` accepts the single compound form `cd <literal dir> && bun <literal gate_receipt.ts path> <args>`, the spec-only commit pass covers spec deletions, and the smoke skill documents the driver's gate evidence for every commit it makes.

## Acceptance Criteria

- AC-STE-791.1: `announcesGateReceipt` accepts `cd <dir> && bun [run] <path> <gate-skill> <args>` when the receipt call is the last segment, `<dir>` is a literal directory with no option, and `<path>` resolves, relative to `<dir>` when not absolute, to the front door's own file.
- AC-STE-791.2: It still rejects, with one negative test for each: any segment after the receipt call (`;`, `&&`, `||`, a pipe, `; echo $?`); anything before the `cd`; a `$VAR`, `${…}`, `$(…)` or backtick in the directory or the path; a `cd` with an option; and a script with the same basename at another path.
- AC-STE-791.3: `runsGateOutcome` and every other reader of `bunInvocation` are unchanged, and a test pins that the outcome verb under the `cd` form is still not recognised.
- AC-STE-791.4: `docs/hooks-reference.md` documents the one accepted `cd` form, says that variable paths are unsupported, and shows the standalone form instead.
- AC-STE-791.5: `git add <paths> && git commit` and `git rm <paths> && git commit` get the spec-only pass when every named path is a spec path inside the checkout, including a path whose file was deleted, and the staged set plus the named paths is spec-only. A staged spec-deletion-only set under a plain `git commit` passes, pinned by a test.
- AC-STE-791.6: A deletion of a path outside the spec set, named alone or beside spec paths, gets no pass.
- AC-STE-791.7: The smoke-test skill's Phase 1 and Phase 2 steps document the driver's gate evidence: a `/gate-check` run and a standalone receipt call per checkout before the scaffold commit and before the post-setup merge. Phase 9 gets a written setup recipe whose commits satisfy the gate and never set `core.hooksPath`.
- AC-STE-791.8: `bun test` from `plugins/dev-process-toolkit` reports 0 failures, and its skip identities equal the baseline by name.

## Technical Design

A wrapper in `gate_receipt.ts` strips one literal `cd <dir> &&` prefix through the `shell_invocations.ts` tokeniser, refuses on any expansion, and hands the rest to `bunInvocation` with the directory as the resolution base. The deletion pass changes `isSpecOnlyAfterAdding` to accept a named path that is absent on disk when it is tracked, and adds `git rm` to the add-then-commit reader.

## Testing

Recogniser tests for the accepted form and each rejected shape. Hook tests for the deletion pass in both directions.

## Notes

Recogniser widening is narrow by ruling: a compound records the last segment's exit code. Supersedes STE-750 (archived). Also closes STE-834. Conformance 2026-11-17 F7 and F17.
