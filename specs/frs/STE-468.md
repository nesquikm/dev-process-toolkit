# Template-source analyzer: categorized reuse inventory module

## Summary

Bootstrapping a new project from an existing one starts with knowing what the existing one contains. This adds an analyzer that inventories a template project into reuse categories — process configuration, curated manifests, project scaffolding, and source patterns — plus a whole-project signal, without mutating anything. The selection interview and the copying are a separate concern; this module only answers what is reusable here.

## Requirement

`analyzeTemplateSource(sourceRoot)` in `adapters/_shared/src/template_source_analyzer.ts`: filesystem-only, never mutates, returns a typed categorized inventory consumed by `/setup`'s template flow (STE-469). STE-391's detect() discipline (read-only, deterministic) is the shape authority.

## Acceptance Criteria

- AC-STE-468.1: New module exports `analyzeTemplateSource(sourceRoot)` returning a typed inventory with the four categories — `processConfig` (CLAUDE.md, .claude/settings.json, .mcp.json, git-hook templates), `manifests` (specs/deps.yaml + specs/best-practices.yaml with per-entry rows), `scaffolding` (known build/CI/lint configs by name detection), `sourcePatterns` (top-level source trees, listing only) — plus a `wholeProjectCandidate` flag; pure file reads, zero mutation.
- AC-STE-468.2: A missing or non-directory `sourceRoot` refuses in NFR-10 canonical shape; a non-git source directory is legal (any directory can be a template) and the result records `isGitRepo`.
- AC-STE-468.3: Manifest rows are parsed through the existing deps/best-practices manifest modules (never re-parsed ad hoc); malformed manifests surface as category-level warnings in the inventory, not silent drops and not hard failures of the whole analysis.
- AC-STE-468.4: Test file covers all four categories, the whole-project flag, the refusal, the non-git case, and the malformed-manifest warning path; each classifier mutation-verified.

## Technical Design

STE-391's `detect(projectRoot)` discipline: synchronous filesystem walk, no git, no network, no mutation. Manifest parsing delegates to `deps_manifest.ts` and `best_practices_manifest.ts` (single source of truth per manifest; the twin-parity lesson). Category classifiers are exported consts so STE-469 and tests share the vocabulary.

## Testing

`bun test`; fixture template trees under the test's temp dirs (all four categories, malformed-manifest, non-git); mutation-verify each classifier.

## Notes

- Precedents: STE-391 (analyze→preview→apply registry shape), STE-301/STE-465 (manifest module delegation).
- Scope bound (deliberate): template source is a local path; a git-URL fetch step is a follow-up candidate, not in scope.
- Consumer: STE-469.
