# A spawn script cannot be fed to bash through stdin, and every spawn is counted

## Summary

The runaway started when a script that launches background children was fed to bash through standard input, and bash kept re-running its own launches.
A repository hook now refuses that shape before anything starts, and the skills tell the driver to run such scripts from a file.
Every spawn block also counts its live children straight away and aborts when the count differs from the number it launched.

## Requirement

A PreToolUse hook on Bash, registered in the tracked `.claude/settings.json` (never the plugin's `hooks/hooks.json`, so consumer projects are unaffected), refuses with exit 2 and an NFR-10 message any command in which `bash`, `sh` or `zsh` reads a script from stdin (heredoc, here-string, pipe or `<` redirect) when that script backgrounds a process (`&` other than `&&`, `&>` and `>&`, or `nohup`, `setsid`, `disown`) or its text is not in the command itself (a `<` redirect, or a pipe from a file or another command). A `claude -p` prompt heredoc (STE-185, STE-226) and `bash <file>` stay allowed. `/conformance-loop` Phase A and every `/smoke-test` spawn site tell the driver to write the fence to a file and run `bash <file>`, and every spawn fence ends with a live-child count that aborts through the per-leg teardown when it differs from the number launched.

## Acceptance Criteria

- AC-STE-595.1: The 2026-09-11 Phase A command, the `bash <<'OUTER'` call captured verbatim from the kept transcript into a fixture, is refused with exit 2, and stderr carries the NFR-10 `Refusing:`, `Remedy:` and `Context: mode=hook, …` lines naming the run-from-a-file remedy.
- AC-STE-595.2: Refused: `bash <<EOF`, `bash <<'EOF'` and `bash <<-EOF` with a backgrounding body, `sh -s <<EOF`, `zsh <<EOF`, `… | bash` and `… | sh` with a backgrounding body, `bash < fence.sh`, `cat fence.sh | bash`, and `bash <<< "cmd &"`. Allowed: `claude -p … <<'PROMPT_EOF' … &` (the sanctioned spawn), `bash /path/fence.sh`, `bash -c 'a && b'`, a heredoc into bash with no backgrounding (the two pre-flight `bash <<'EOF'` calls from the same transcript), and `cmd1 && cmd2`.
- AC-STE-595.3: Empty or unparseable stdin fails open (exit 0); the hook reads nothing beyond its stdin payload.
- AC-STE-595.4: `.claude/settings.json` registers the hook under `PreToolUse` with matcher `Bash`; `spawn_pattern_allowlist` and every settings probe stay green, and both the tracked allow-list and the `/smoke-test` scaffold grant the file-run command the fences now use.
- AC-STE-595.5: `/conformance-loop` Phase A and each `/smoke-test` spawn site state the run-from-a-file rule, and a meta-test pins the rule at every site.
- AC-STE-595.6: Every spawn fence ends with a live-child count (recorded pids answering `kill -0`, each passing a `ps -p <pid> -o comm=` identity check) compared with the number launched, placed where an earlier abort cannot skip it; a mismatch aborts through the per-leg abort teardown.
- AC-STE-595.7: The actual Phase A fence, extracted and run from a file with `claude` stubbed, launches exactly one child per selected leg and its count line reports that number; the same fence fed to bash through stdin is refused by the hook before any stub runs, so its pidfiles are absent.
- AC-STE-595.8: Runtime, verified at the next live run (ships `[~]` until then): in a live session the hook blocks a stdin-fed spawn fence before any process starts.

## Technical Design

A pure detector module in the shared adapters finds a shell consumer reading stdin and scans the fed body for backgrounding, ignoring `&&`, `&>` and `>&`; a body it cannot see counts as unsafe. A hook entry reuses `parseHookPayload` behind a two-line shell shim, exits 2 with byte-stable NFR-10 lines, and is registered repo-level. The golden fixture is the command text from transcript 9c766729 at 2026-09-10T20:41:53Z. The child count reuses the pidfiles each fence already writes.

## Testing

Table-driven detector tests over the refused and allowed shapes plus the golden fixture; hook-entry tests through `Bun.spawn({ stdin })` for exit 2, exit 0 and fail-open; a settings-probe regression; the extracted Phase A fence run from a file with stubs; meta-tests pinning the rule and the count at every spawn site.

## Notes

The sanctioned child spawn itself feeds its prompt through a heredoc, so the hook keys on bash, sh or zsh as the stdin consumer, never on a heredoc plus an ampersand alone.
