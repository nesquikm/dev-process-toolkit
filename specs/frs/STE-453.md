# Narrow --dry-run prose to what ships and generalize the report shape to N legs

## Summary

The conformance driver documents a dry-run mode that returns canned per-leg findings by reading from a fixture directory. That directory does not exist anywhere in the repository, and the test named as its coverage never imports any code, never spawns anything, and asserts among other things that the skill mentions the test file's own name.

So the flag is a claim rather than a mechanism. The previous FR builds a real harness for the termination probes specifically; this one narrows the surrounding prose to describe exactly that and nothing more.

The honesty requirement is the substance here, not a tidying pass. Whatever remains uncovered after the harness lands — the aggregation pass, the cross-leg dedup, the report shape — must be named as prose-only in the skill body and in its rules, rather than left implied to be tested. An overstated claim of coverage is worse than an acknowledged gap, because it stops anyone from looking.

The report shape also carries a pairwise assumption in its own right, describing coverage as a two-element tracker list and its dedup as a walk from one named tracker to another.

## Requirement

Narrow the dry-run documentation to describe exactly what ships, name every remaining prose-only surface as such, and generalize the aggregated report past its two-leg assumption.

The measured state: the fixture directory the skill describes is absent from the repository, and `plugins/dev-process-toolkit/tests/conformance-loop-dry-run.test.ts` is 81 lines carrying no executable coverage of the mechanism it is named for.

## Acceptance Criteria

- AC-STE-453.1: The `--dry-run` prose in the conformance-loop skill describes only what ships. No claim of a fixture directory broader than what exists on disk survives anywhere in the skill. {#AC-STE-453.1}
- AC-STE-453.2: The aggregation pass, the cross-leg dedup and the report shape are explicitly named as prose-only — model judgment rather than algorithms — in both the skill body and its `## Rules` section. {#AC-STE-453.2}
- AC-STE-453.3: `tests/conformance-loop-dry-run.test.ts` no longer asserts that the skill cites the test file's own name, and carries the STE-452 executed-fence assertions instead. {#AC-STE-453.3}
- AC-STE-453.4: The aggregated report emits an N-way `legs:` list in place of the pairwise `tracker-coverage:` field. {#AC-STE-453.4}
- AC-STE-453.5: The dedup prose describes a registry-order walk scanning all later legs rather than a walk from one named tracker to another, and is explicitly labeled model judgment. {#AC-STE-453.5}

## Technical Design

AC.3 removes a self-referential assertion. A test asserting that the skill mentions the test's own filename is circular in the same way this milestone's other findings are circular: it cannot fail for any reason connected to the behavior it purports to cover.

AC.4 is a rename with a shape change, and the closing-summary columns derive from the leg set per STE-446, so the report's leg list should derive the same way rather than being restated.

AC.5 keeps the dedup as model judgment deliberately. Making it an algorithm is out of scope for this milestone; what is in scope is that the prose no longer implies otherwise and no longer hardcodes two named trackers into its description of the walk.

## Testing

Assertions on the narrowed prose, plus the rewritten dry-run test carrying the executed-fence coverage from STE-452.

The check that AC.1 and AC.2 actually landed is that a reader can no longer find a coverage claim in the skill that is not backed by an executing test. That is checkable by enumerating the skill's coverage claims and pairing each with its test.

Full gate green from the plugin root.
