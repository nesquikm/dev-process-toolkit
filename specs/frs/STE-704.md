# A ticket create is decided from the searches the session actually ran

## Summary

Before a new ticket is created, a command decides from saved search pages whether it already exists.
Those pages are files the agent writes, and nothing ties them to the search the command printed.
A page from a narrower search, or one with rows removed, can authorise a duplicate create.
This fix lets the command read the search calls and their answers straight from the session log.
It accepts only calls whose arguments match the printed search exactly.

## Requirement

### Steps to reproduce

1. In a project bound to Linear, run `create_idempotency_probe.ts query <root>` and note the printed arguments.
2. Save an empty first page from a `list_issues` call that also passed a `query` title filter, or that dropped the row matching the title.
3. Run `create_idempotency_probe.ts decide <root> <page.json> --title <t> --attempt fast`.

### Expected

The decision refuses: the page was not produced by the printed search.

### Actual

It prints `create` with reason `proven-absent`, because the saved file carries no record of the arguments it came from.

## Acceptance Criteria

- AC-STE-704.1: Regression: `tests/m_9261c7-STE-704-decide-from-transcript.test.ts › a page from a narrowed search never authorises a create` fails before the fix and passes after it.
- AC-STE-704.2: `decide` accepts `--from-transcript <transcript_path> <tool_use_id>...` in place of page files. It reads each named search call and its tool result from the transcript through the shared session reader, in the order given, as the page chain. Page files passed together with the flag are refused, and no file page is read.
- AC-STE-704.3: Each named call must be a `list_issues` call (Linear) or `searchJiraIssuesUsingJql` call (Jira) whose input equals exactly the object `query` printed, plus the page cursor after the first page, plus `cloudId` on Jira. Any other key, or any changed value, refuses with reason `page-violates-query` and never yields `create`.
- AC-STE-704.4: A named id with no call in the transcript, no tool result, or an error result refuses. The chain, conjunct and cap rules apply to transcript pages exactly as to file pages.
- AC-STE-704.5: Pinning cases, each through the spawned command: an extra `query` argument with an empty result refuses; a changed label with an empty result refuses; exact arguments with an empty, complete listing print `create` with reason `proven-absent`; a shared-mode page carrying a row with another repository's tag refuses with `page-violates-query`.
- AC-STE-704.6: `adapters/linear.md` and `adapters/jira.md` § `upsert_ticket_metadata`, and the `/spec-write` § 0b step that orders the query and decide sequence, order the transcript form, naming the transcript path from the hook payload and the search calls' tool_use ids.
- AC-STE-704.7: Removing the exact-input comparison, or letting page files ride beside the flag, turns at least one named test red.
- AC-STE-704.8: `bun test` from `plugins/dev-process-toolkit` reports 0 failures, and its skip identities equal the trunk baseline by name.

## Technical Design

### Root cause

`decide` grades saved page files against the printed conjuncts, but only on fields the rows carry. A narrowed or trimmed page that stays consistent with them reads as a complete miss.

The fix sources pages from the transcript, where each call's input sits beside its result. The command rebuilds the printed query from the same binding, compares inputs, then hands the results to the existing chain reader.

## Testing

Synthetic transcripts with fake ids, run through the spawned command, one case per pinning row, plus mutation controls.
