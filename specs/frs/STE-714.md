# A measurement spike records what tool-call hooks and the session log can see

## Summary

Tool-call capture depends on facts nobody has measured yet.
It is unknown which fields a hook receives, and whether calls inside a forked skill fire hooks.
It is also unknown whether a fork's token use reaches the main session log.
This spike records real hook payloads and answers each question in a committed findings note.
A fixed decision rule then sets what the later capture work records.

## Requirement

The capture design for this milestone rests on six unmeasured claims, the sixth being whether a project-local settings hook fires at all. The repo holds no captured PreToolUse or PostToolUse payload for `Skill`, and none at all for PostToolUse: `hooks/hooks.json` registers no PostToolUse entry today. `HookPayload` in `templates/hooks/_lib/session.ts` declares `tool_use_id` but nothing about a tool response, an exit code, `agent_id` or `agent_type`. The only fork measurement on record (memory and STE-641) found that a running `context: fork` skill leaves no `isSidechain` records, no `agent-*.jsonl` and no child process, and STE-641 deferred the subagent `transcript_path` "until measured". The token ledger (`token_usage.ts` `parseTranscriptTokenUsage`) reads only the main `transcript_path`.

This FR measures before anything is built. It ships no hook, no adapter code and no change to `hooks/hooks.json`.

### Method

1. One recording hook is registered twice, for PreToolUse and PostToolUse, matcher `Bash|Skill`. The first copy goes in the measurement checkout's **project-local** `.claude/settings.local.json`, by absolute path. The second goes in a throwaway local plugin loaded with `claude --plugin-dir <dir>`, whose `hooks/hooks.json` uses the toolkit's inline `"${CLAUDE_PLUGIN_ROOT}"/...sh` command form. Neither touches the toolkit's own `hooks/hooks.json`, so the installed plugin cache version does not matter. Each copy tags its lines with its registration (`local` or `plugin`). It appends its raw stdin, its own wall-clock (`Date.now()`), `process.cwd()` and `CLAUDE_PROJECT_DIR` to a file outside any repository, then exits 0. D1 and D6 rest on the `local` copy, because the capture hook is registered in that scope only (STE-716, supervisor ruling 2026-11-04). The `plugin` copy is kept for comparison.
2. The operator runs every case interactively, at the keyboard, on the installed Claude Code, whose version is recorded:
   - a Bash call that exits 0, one that exits 1, one the operator interrupts, and one blocked by another PreToolUse hook's `exit 2` (a `git commit` with no gate run);
   - an inline `Skill` call (`/dev-process-toolkit:gate-check`) and a forked one (`/dev-process-toolkit:tdd` on a one-AC fixture FR, which forks `tdd-write-test`, `tdd-implement`, `tdd-refactor`, `tdd-spec-review`), plus `/dev-process-toolkit:spec-review` (forks `spec-review-audit`).
3. A no-op Bun hook (`bun run` of a file that reads stdin and exits) is timed 30 times on the measurement machine.
4. After the last case, both registrations are removed: the recorder entry leaves the project-local settings file and the throwaway plugin directory is deleted.

### Deliverables

- `specs/notes/ste-714-hook-payload-measurement.md`: Claude Code version, date, the recorder's source in one fenced block, the answers below, and the decision table.
- `plugins/dev-process-toolkit/tests/fixtures/hook-payloads/`: one scrubbed payload JSON per observed (event, tool, case), plus a matching scrubbed transcript slice for the forked `/tdd` run.

The scrub table, printed in the note and applied by one scrub pass to every committed payload and transcript slice:

- every session id (`session_id`, `sessionId`) becomes `00000000-0000-4000-8000-0000000000NN`;
- every record `uuid` and `parentUuid` becomes `00000000-0000-4000-8000-0000001000NN`, numbered by first appearance;
- every `tool_use_id` becomes `toolu_SYNTH_NN`;
- every absolute path, `cwd` and `transcript_path` included, becomes `/synthetic/repo/...`;
- every Claude project-folder slug (`-Users-<name>-...` or `-home-<name>-...`, the `cwdToSlug` form) becomes `-synthetic-repo`;
- every branch name, `gitBranch` included, becomes `synthetic-branch`.

The same pass scrubs the gate transcript slices STE-715 commits under `tests/fixtures/m_7bc805-gate-slices/`.

| Row | Question | If yes | If no |
|---|---|---|---|

- AC-STE-714.3: For the exit-1, interrupted and hook-blocked Bash cases, the note states whether PostToolUse fired and which field, if any, carries an exit code or an error flag, quoting the scrubbed value.
- AC-STE-714.4: The note states whether `tool_use_id` is present on both events and equal for one call, and whether a forked Skill call's PostToolUse fired after its fork's last internal call (the recorder's wall-clocks are quoted).
- AC-STE-714.5: For the `/tdd` and `/spec-review` runs, the note states, per registration, how many recorder events came from calls made inside a fork (zero is a valid answer, stated as zero), and for each such event the values of `agent_id`, `agent_type` and `transcript_path` relative to the parent's (scrubbed).
- AC-STE-714.6: The note states whether usage-bearing assistant records produced inside a fork appear in the main transcript, with their count and their `attributionSkill` values from the committed transcript slice.
- AC-STE-714.7: The note records, per case, the offset in ms between the recorder's wall-clock and the transcript record timestamp of the matching `tool_use` (Pre) and `tool_result` (Post), and the p50 and p95 of the 30 no-op Bun hook runs.
- AC-STE-714.8: The note ends with the decision table rows D1-D6, each answered yes or no from a quoted measurement, and names which branch every later FR of M_7bc805 implements. A later FR whose ACs follow the other branch is a spec defect to fix before its /implement.
- AC-STE-714.9: `tests/m_7bc805-ste-714-synthetic-ids.test.ts › committed measurement files carry synthetic identifiers only` passes. No scanned file contains `/Users/`, `/home/`, a project-folder slug starting `-Users-` or `-home-`, an email address, a `gitBranch` value other than `synthetic-branch`, or a UUID outside the two synthetic blocks of the scrub table. - AC-STE-714.10: The FR ships no behaviour: `git diff --name-only` from the milestone base to the FR's commit names no path under `plugins/dev-process-toolkit/hooks/`, `plugins/dev-process-toolkit/templates/hooks/`, `plugins/dev-process-toolkit/adapters/` or `plugins/dev-process-toolkit/skills/`. Paths outside `specs/` are limited to the fixture directory and the AC.9 test.
- AC-STE-714.11: The note states that the operator ran every live case at the keyboard, and that both registrations were removed after the last case. It quotes the project-local settings hooks block with no recorder entry, and states that the throwaway plugin directory no longer exists.
- AC-STE-714.12: Removing the `/Users/` pattern, the slug pattern or the UUID rule from the scan, or, once STE-715 lands, dropping its slice directory from `SCRUBBED_FIXTURE_DIRS`, turns at least one AC.9 control red.
- AC-STE-714.13: `bun test` from `plugins/dev-process-toolkit` reports 0 failures and skip identities equal the trunk baseline by name.
- AC-STE-714.14: For each registration the note states the recorded `process.cwd()` and `CLAUDE_PROJECT_DIR` (scrubbed), and whether each equals the checkout root. It also states whether a `local` entry added while a session runs fires before the session restarts. D6 quotes these values.

## Technical Design

The recorder is a 20-line Bun script kept in the note, not shipped. Payloads are copied into fixtures through one scrub pass whose substitution table the note prints, so a reader can check nothing real survived. The scan test reads every committed byte under the fixture directory plus the note, using a UUID regex and an allow pattern for the synthetic block. Decision rows quote the measurement they rest on, so a later FR's branch can be checked against evidence rather than memory.

## Testing

One scan test with a planted-path control. The measurement itself is graded by reading the note against AC.1 to AC.8 and AC.11.

## Notes

The operator runs the live cases at the keyboard, since an agent cannot interrupt its own call. The project-local recorder is removed afterwards, so no maintainer session keeps recording. Shape follows the STE-693 measurement note.
