# The spawn allow-list probe grades only repositories that spawn children

## Summary

The gate fails every project the setup command creates, because one probe demands a permission the setup template never writes.
That permission only matters where the smoke-test scaffold spawns child sessions.
The probe now grades the settings file only where that scaffold exists.
Elsewhere it reports why it skipped.
This repository still has the scaffold, so it is still graded.

## Requirement

The spawn-pattern allow-list probe grades a project's settings file only when the project carries the smoke-test spawn scaffold, and is vacuous with a stated reason otherwise.

## Acceptance Criteria

- AC-STE-735.1: `runSpawnPatternAllowlistProbe` scans `.claude/settings.json` only when `.claude/skills/smoke-test/SKILL.md` exists at the project root; otherwise its report is vacuous, with a note naming the missing scaffold as the reason.
- AC-STE-735.2: With the scaffold present, every verdict is the same as at v3.3.0, malformed settings included.
- AC-STE-735.3: The module header and line 149 of `skills/gate-check/SKILL.md` say the probe is scoped to the scaffold, edited in place without raising the line cap.
- AC-STE-735.4: Twins: a project with a settings file lacking the pattern and no scaffold is vacuous; the same project with the scaffold fails. Removing the scaffold condition turns a named test red.

## Technical Design

One existence check moves ahead of the settings scan. The setup template is unchanged, so no consumer is handed a wider permission.

## Testing

Temporary project roots with and without the scaffold; the existing probe suite.

## Notes

Adding the permission to the setup template was rejected: it would let every consumer spawn child sessions.
