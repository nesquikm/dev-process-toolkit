# The skills that demand a fresh gate say when a proven reuse counts as fresh

## Summary

Three skill texts tell the model never to trust an earlier gate result.
Simplify already skips its gate re-run on an unchanged tree after a clean gate.
With the reuse knob off, that skip is unchanged.
With it on, the skip asks the reuse front door, not an old log.
The implement and gate-check texts now say a proven reuse is fresh and nothing else is.
The docs name this as the house reuse shape, beside the skip baseline.

## Requirement

### /simplify (STE-196 carve-out)

`skills/simplify/SKILL.md` step 4 ends today with "Consult the most recent `/implement` or `/gate-check` log for the active gate stamp." That sentence stays byte for byte, and one knob branch follows it (operator ruling R6). The branch is keyed on the log that sentence already reads, so an off knob costs no tool call (supervisor ruling 2026-11-04, for operator review). When that `/gate-check` run's receipt call printed `reuse: on` (STE-724), precondition 2 of `## When this is a no-op {#when-this-is-a-no-op}` holds only when `bun run "${CLAUDE_PLUGIN_ROOT}/adapters/_shared/src/gate_reuse.ts" verdict "<root>"` prints `clean`. Otherwise the log read decides, as today. Every sentence of the file that names `gate_reuse.ts` also names `reuse: on`, and the file never names the `knob` verb.

The new `verdict` verb of the STE-724 front door prints `clean` only when all of these hold: the knob's effective value is `reuse`, which needs `tracking.gate_outcomes` on (STE-723), and the section is valid; this session's latest announced `gate-check` run receipt is referenced by an M_7bc805 `gate-outcome` receipt with `decision: pass` and `key_stable: true`; that run recorded at least one `gate-step`; and every `gate-step` of that run is an announced pass whose stored key deep-equals the live key. Every announcement is vouched for by the STE-724 provenance rule: the run receipt by `announcesGateReceipt`, the outcome by `runsGateOutcome` and each step by `announcesGateStep`. The live key takes `command_sha256` from the stored step, since the gate commands live in tracked files that HEAD plus a clean tree already pin. Otherwise it prints `rerun`, including when `CLAUDE_CODE_SESSION_ID` is unset, and `/simplify` runs the gate. The verb runs no command and writes nothing.

The `## When this is a no-op` rationale sentence "or the prior gate stamp is dirty" becomes "or the prior gate stamp is dirty (with the reuse knob on: or the verdict prints `rerun`)". The heading, its anchor and precondition 1 are unchanged.

### /implement

`skills/implement/SKILL.md` Phase 3 step i ("re-run the full gate fresh, cite actual numbers ... Never claim clean from memory.") gains one clause: a command the gate reports as `(reused)` by the front door counts as fresh because its key was recomputed on the spot, and its numbers are the stored run's. `docs/implement-reference.md` line "After any fix, always re-run the full gate check..." gains the same clause. After any fix the tree differs, so the key differs and the command runs; the clause says so.

### /gate-check

Three `skills/gate-check/SKILL.md` lines would contradict a reused command, so each gains the same exception:

- `## Rules` "Do NOT report GATE PASSED without running commands fresh this session" becomes: fresh this session, or reused by the front door under the live key, which still writes the receipt and still runs the code review.
- `## Rules` "Do NOT skip any step — run all commands AND the code review" keeps its wording and adds: a command the front door reports as `(reused)` counts as run; the code review is never reused.
- `## Reporting` "Run each command fresh and read the result" adds: or read the front door's `dpt-reuse:` line, which cites the stored run's numbers.

The `## Red Flags` and `### Rationalization Prevention` rows are unchanged.

## Technical Design

The simplify skip already exists and is correct, per STE-196. With the knob off, nothing about it changes.

With the knob on, only its evidence changes: a deterministic verdict replaces a model reading a log.

The verdict verb reuses the decision function of the run verb with execution removed. One function decides both, so they cannot disagree.

The implement and gate-check lines keep their intent. They now name the one case where an unrun command counts as fresh.
