# The tracker write gate reads a call written twice as one call

## Summary

Claude Code can write one tool call twice in the session log.
The commit gates read both copies as one call.
The tracker write gate has its own reader, and it counts each copy.
So one decision can authorise two creates, and one create can spend two receipts.
This fix moves every reader onto one shared rule.

## Requirement

### Steps to reproduce

1. In a repository that declares a shared tracker container, build a session transcript with one Bash call running the create-decision front door (id `toolu_syn_decide_01`), and its result announcing one create receipt.
2. Write that result record twice, the second copy without a timestamp, as Claude Code can.
3. Add a create tool call for the decided ticket, then a second create call of the same ticket shape, and run `pre-tracker-write-gate` against the second create.

### Expected

The second create is refused: the one receipt was spent by the first create.

### Actual

The second create is permitted. The reader records the one receipt twice, so one copy is spent and the other still authorises a create.

## Acceptance Criteria

- AC-STE-696.1: Regression: `tests/m_46b121-STE-696-tracker-gate-duplicate-tool-use.test.ts › a decide result written twice authorises one create` fails before the fix and passes after it.
- AC-STE-696.2: The session library exports one helper that applies the STE-695 rule: tool_use records that share a non-empty id are one call at the earliest line, with the timestamp of the first copy that carries a parseable one; id-less records are never merged; tool_results are graded once per tool_use_id and the first copy decides.
- AC-STE-696.3: `scanSkillCalls` uses the helper for Skill calls, mint calls and mint results, and the STE-695 suite stays green unchanged.
- AC-STE-696.4: `scanSkillCalls` grades a Skill call's tool_result once per id: an `is_error` copy that follows a non-error result for the same id no longer retires the call, and an `is_error` first result still does.
- AC-STE-696.5: The tracker gate's announcement scan uses the helper: a deciding command's result written twice yields one announcement, and a duplicated deciding call is one call.
- AC-STE-696.6: The tracker gate's create walks use the helper: a create written twice is one create at its first line, so it spends one receipt, and the prior-create grading orders it by its first copy, not its last.
- AC-STE-696.7: Each duplicate permits or refuses the same way in both orders (timed copy first, untimed copy first), and the refusal twin differs only in the defect: two distinct ids still count as two calls.
- AC-STE-696.8: Removing the collapse from the announcement scan, from either create walk, merging id-less records, keeping the latest copy instead of the earliest, or grading a second Skill result each reddens at least one named test.
- AC-STE-696.9: The tracker gate keeps no private copy of the rule: it contains no per-id first-copy bookkeeping of its own, and the session library still reads the transcript file exactly once.
- AC-STE-696.10: `bun test` from `plugins/dev-process-toolkit` reports 0 failures, and its skip identities equal the trunk baseline by name.

## Technical Design

### Root cause

STE-695 put the merge-by-id rule inline in `scanSkillCalls`. The tracker gate's `scanAnnouncements`, `createsBefore` and `priorCreates` walk the same records with no merge, and `priorCreates` overwrites its map entry so the last copy wins.

The fix extracts the rule into one exported helper over parsed transcript records that yields first copies only, each with its earliest line and first stamp. All four readers iterate that view.

## Testing

Synthetic transcripts with fake ids and temporary repositories drive the gate through its shipped hook entry point. Each duplicate runs in both orders, with a twin that differs only in the defect, plus mutation controls.
