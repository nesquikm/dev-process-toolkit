# Phase 9 artifacts must carry the tracker segment and stay out of the toolkit repo

## Summary

Phase nine writes its evidence files named only by fixture and date. Three runs on the same day therefore write the same filenames and overwrite one another, and this run proved it: the neighbouring fixture class, which does include the run's tracker name, kept all three runs' files, while phase nine kept exactly one set. Two runs' evidence was destroyed. Worse, the files land inside the real toolkit repository, untracked and not ignored, so a run leaves committable debris that would trip the next run's own clean-tree check.

## Requirement

Phase 9's artifact paths carry the resolved `<tracker>` segment, matching the rule STE-423 already decided for every per-run artifact path. The write target is contained so a run does not dirty the toolkit's own working tree.

## Acceptance Criteria

- AC-STE-487.1: Every Phase 9 artifact path includes the resolved `<tracker>` segment; three concurrent runs on one date produce three disjoint file sets with none overwritten.
- AC-STE-487.2: Phase 9 artifacts do not leave the toolkit working tree dirty — they are written outside the repository, or covered by a committed ignore rule.
- AC-STE-487.3: A check enumerates every per-run artifact path in both harness SKILLs and fails on any that omits the tracker segment, so the STE-423 rule is enforced rather than restated.
- AC-STE-487.4: The six tracked fixture files already in `tests/fixtures/capability-rows/` at HEAD are untouched.
- AC-STE-487.5: STE-483's harness proves the collision check fails when the segment is removed from a path.

## Technical Design

The A/B control sits inside the same run's teardown listing, which is why this is measured rather than inferred. Phase 9 persists `tests/fixtures/capability-rows/<fixture-name>-<YYYY-MM-DD>.log`; group 8a persists `tests/fixtures/nested-spawn/8a-<tracker>-<YYYY-MM-DD>.log`. All three legs ran concurrently on 2026-08-16 — the documented-safe parallel mode. Group 8a's three files all survived; Phase 9 kept exactly one set of five, all stamped 22:21, the finishing time of whichever leg wrote last. The difference between the surviving three and the destroyed two is precisely the tracker segment.

Two further confirmations from the same listing. The convention already existed and Phase 9 regressed from it: the same directory's tracked files from the previous run are `spec-write-jira-2026-07-27.log` and `spec-write-linear-2026-07-27.log`, segmented. And the write target is the toolkit repo rather than the guarded test project — eight artifacts landed untracked with `git check-ignore` returning no match, leaving roughly two megabytes of committable junk in the real repository.

AC-STE-487.3 generalises: STE-423's claim was that every path a leg writes, globs, or reaps carries the segment. That claim was asserted, not enforced, and Phase 9 falsified it. An enumerating check converts the claim into a gate.

## Testing

Three-leg concurrent-write simulation asserting disjoint file sets. Clean-tree assertion after a simulated Phase 9 run. Path-enumeration check with a mutation removing a segment, which must go red. `bun test` full root.
