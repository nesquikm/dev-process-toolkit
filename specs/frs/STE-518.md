# The worker's remote-control name is derived, never typed

## Summary

A spawned ceremony worker has no name today. The orchestrator hands the spawning skill the kickoff text and the milestone identity and nothing else, so every worker launches under whatever name the spawner defaults to. On a machine where session names are global, that makes the sessions indistinguishable from each other and from the operator's own.

This gives the worker a name derived from what the run already knows: the repository it is working in, and the unit of work it is delivering. Both halves matter. The repository half separates two repos delivering the same milestone number; the identity half separates two FR-scoped runs under one milestone, which is a real shipped path and not a hypothetical one.

The name has to satisfy the spawning skill's own grammar, which is narrower than it looks and caps the whole name at thirty-two characters. What happens when a name does not fit is defined here rather than left to whoever hits it first, because a silent truncation that collides blocks a spawn outright.

## Requirement

One function derives the worker's name from the repository and the resolved unit of work, always within the spawning skill's name grammar, with a defined and deterministic behaviour when the name cannot fit.

## Acceptance Criteria

- AC-STE-518.1: A milestone-scoped run renders the repository segment joined to the milestone segment — a repository named `dev-process-toolkit` delivering `M134` yields `dev-process-toolkit-m134`.
- AC-STE-518.2: An FR-scoped run renders the FR as the identity segment — the same repository delivering `STE-515` yields `dev-process-toolkit-ste-515`. This is asserted as its own case; a test exercising only the milestone form does not satisfy it, because the FR-scoped collision is what selected this name shape.
- AC-STE-518.3: The identity segment comes from the routing object the argument resolution already returns — the FR when the run carries one, the milestone otherwise — and is never re-derived by re-parsing the raw argument. Mutation-verified: changing the routing's FR field changes the returned name.
- AC-STE-518.4: Every name the function returns matches the spawning skill's grammar: a leading lowercase letter followed by at most thirty-one further characters drawn from lowercase letters, digits, underscore and hyphen.
- AC-STE-518.5: A name that fits renders in full — no segment shortened and no character dropped. Asserted against both shapes above, which measure twenty-four and twenty-seven characters against the thirty-two cap.
- AC-STE-518.6: A name that would exceed the cap shortens the REPOSITORY segment only, deterministically, keeping its leading characters, until the whole name fits. The identity segment is byte-identical to its unshortened form.
- AC-STE-518.7: When no repository segment of one character or more makes the name fit, the function refuses in the canonical refusal shape, naming both segments and their lengths. It never returns a name whose identity segment was truncated.
- AC-STE-518.8: AC.6 and AC.7 are both exercised with repository names long enough to trigger them, and the fitting case is asserted alongside each. A one-sided assertion would pass forever on this repository, where both real shapes fit today.
- AC-STE-518.9: A composed name that would not begin with a lowercase letter after sanitizing refuses rather than returning a name outside the grammar.
- AC-STE-518.10: The derivation imports nothing from the branch-proposal module. That module's template selector returns the ticket-keyed template for a full numeric milestone token, so a reader reusing it here would inherit a measured wrong answer.

## Technical Design

The function takes the repository root and the resolved identity and returns one string or refuses. Keeping the identity a parameter rather than a routing object is what lets both callers reuse it: the resume path passes the identity its routing already carries, and the fresh path passes the milestone the spec-writing phase has just produced, which no routing object knows about.

Sanitizing lowercases and folds runs of characters outside the grammar to a single hyphen, then strips leading and trailing hyphens from each segment before joining.

The overflow rule is asymmetric on purpose. The identity segment is the discriminator that motivated the name shape, so truncating it would silently reintroduce the collision the shape exists to prevent — and a collision is not cosmetic here: the spawning skill refuses to launch when a live session already holds the name, so a collision blocks a spawn. The repository segment carries no such load, so it is the half that gives way, and when giving way is not enough the function refuses rather than returning something that fits but means the wrong thing.

AC.10 records a live caller trap rather than a style preference. `canonicalBranchTemplate` in `adapters/_shared/src/branch_proposal.ts` tests for bare digits and then for an epic token; a full numeric token such as `M133` matches neither and falls through to the ticket-keyed template, while the module's own comment describes that input as supported. The derivation here needs a different alphabet and a different cap, so it shares no code with it, and saying so keeps a later reader from "reusing" into the trap.

## Testing

Both real shapes are fixtures and both are asserted to render in full. The overflow path gets a repository name long enough to force shortening, asserted to keep the identity byte-identical, and a second long enough that no shortening suffices, asserted to refuse. The grammar is asserted over every returned name rather than spot-checked.

The routing-reuse criterion is mutation-verified: the returned name has to move when the routing's FR field moves, which a re-derivation from the raw argument would not do.

## Notes

The thirty-two character cap is the spawning skill's constraint on agent names, inherited from one of its hosts rather than from the CLI, and it applies on every host. Headroom against this repository's own two shapes is five characters and seven characters respectively.
