# /spec-write branch-gate-on-main must commit the FR and emit its own capability rows

## Summary

Invoked on the trunk branch with approval pre-granted, spec-write creates the branch and the tracker items, then stops short: the specification files are staged but never committed, and the run closes with a different skill's report instead of its own. A run that creates real tracker state and a branch but silently drops the commit looks exactly like success to anything reading its output. That is the shape of a defect that hides.

## Requirement

On the branch-gate-on-main path, `/spec-write` completes its commit and emits its own closing summary carrying the capability rows the contract requires. A staged-but-uncommitted end state remains reachable only through the two documented paths — the marker-absent non-tty refusal and the interactive decline — each of which emits its own literal token.

## Acceptance Criteria

- AC-STE-478.1: Invoked from trunk with the auto-approve marker present, `/spec-write` creates the branch, writes the FR and plan files, and commits them; `git log <trunk>..HEAD` returns ≥ 1 and `git status` reports no staged spec files.
- AC-STE-478.2: The run's closing output is `/spec-write`'s own summary block (FR table + spec-file table + open-questions block), never another skill's report.
- AC-STE-478.3: The run emits `branch_gate_default_applied` and `spec_write_commit_default_applied` as literal backticked tokens in assistant text; a raw-log-only occurrence does not satisfy this (STE-421 scoping).
- AC-STE-478.4: The only paths ending staged-but-uncommitted are the marker-absent non-tty refusal and the interactive `n` decline; each emits its documented literal token and neither creates tracker state without saying so.
- AC-STE-478.5: A regression test drives the trunk-invocation path end-to-end and fails when the commit step is skipped or the closing summary is replaced by another skill's.

## Technical Design

Measured on the jira leg's Phase 9 `branch-on-main` fixture: invoked from `master` with the marker, branch `feat/m_dst_74-…` auto-created, Jira Epic DST-74 and Task DST-75 created, then `git log master..HEAD` = 0 with `A specs/frs/DST-75.md` still staged, and the closing output a Gate Check Report. All four relevant capability tokens absent from assistant text; raw counts were injected-SKILL-body only.

The contrast is what makes this evidence rather than inference: the canonical Phase 2 `/spec-write` emitted all three rows, as did the `branch-off-trunk` and `draft-commit` fixtures in the same run. So the defect is specific to the trunk-invocation control path, between branch creation and the § 7a commit.

## Testing

End-to-end regression over the trunk-invocation path asserting a commit lands and the summary is spec-write's own. Token assertions scoped to assistant text. `bun test` full root.
