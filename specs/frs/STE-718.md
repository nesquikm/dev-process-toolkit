# The out-of-scope list stops ruling out what the toolkit ships

## Summary

The requirements list three things as out of scope that the toolkit ships or is about to ship.
Multi-agent runs have shipped for many releases, and this milestone adds a retrospective command.
Those two lines are struck, each with a dated note naming what replaced it.
The fast-track line is narrowed, not struck, with a note saying why nothing here skips a gate.
The bundled-hooks line is left alone, because the capture milestone supersedes it first.

## Requirement

`specs/requirements.md` § 5 Out of Scope opens with three lines this milestone still contradicts. Spec review grades an FR against that section, so a stale line reds the milestone that ships the new command. Each line changes as follows; the original wording stays visible, struck through, so the history survives.

| Line today | After this FR |
|---|---|
| `- No new slash commands (depth over breadth)` | `- ~~No new slash commands (depth over breadth)~~ — superseded in v3.2.0 (M_d1b4b7, 2026-11-04 ruling): /retro (STE-719) ships as the 20th user-invocable command. Any later command needs its own note here.` |
| `- No fast-track workflow skipping ceremony` | Kept, not struck, with the note `— still in force (v3.2.0, M_d1b4b7): /retro reads the record and changes a setting only on explicit approval (STE-728), and M_fd9a03 reuse, only when its knob is on, shortens a gate run that really happens; neither skips a gate, a review or an approval.` |
| `- No multi-agent orchestration` | `- ~~No multi-agent orchestration~~ — superseded in v3.2.0 (M_d1b4b7): /tdd forks four subagents (STE-225) and /deliver drives spawned workers (STE-464); /retro grades only what their parent session can see.` |

No other line of § 5 changes. The tracker-integration and parallel-safe-layout sub-lists are untouched.
