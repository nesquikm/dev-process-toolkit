# Give the tracker-less claim step an instruction shaped like its siblings, and verify the artifact

## Summary

The claim step's sibling instructions each name a module path and a call form. Its tracker half points at a runbook. Its tracker-less half names neither — it states a fact about a class rather than instructing anyone to do anything.

On the run that surfaced this, the tracker leg claimed correctly and the tracker-less leg never claimed at all. The difference is not the code, which is implemented and unit tested. The difference is that one leg had something followable to follow.

The verification that would have caught it already exists as a Phase 1 exit self check with a hard refusal and a go back and claim remedy. Tracker-less mode was carved out of it on a rationale that is true of the tracker assertion and false of the lock artifact — the sentinel really is vacuous, but the lock file and its commit are not.

So this is not new machinery. It is an existing house mechanism whose exemption was generalized one surface too far.

## Requirement

Give the tracker-less half of the claim step the same instruction shape as its siblings, replace the Phase 1 exit exemption with a tracker-less arm that verifies the lock artifact, and correct the release proof definition so the shipped prose and the shipped behaviour agree.

## Technical Design

The sibling shape is `call form` FROM `module path`, closing with a documentation pointer. The tracker-less half currently has none of the three. Matching it needs the constructor, the call, its three way return contract, and the artifact the call produces — the lock file plus the commit that makes it durable.

The Phase 1 exit arm is the same shape the tracker arm already uses: read the artifact back, assert it is what the claim should have produced, refuse in the canonical shape naming observed against expected. The tracker arm reads the ticket; the tracker-less arm reads the lock file and the commit. The exemption being replaced is not deleted from history, it is superseded with the reason recorded.

Two budgets bound the whole change and neither has slack to spare. The line budget has room for a short rewrite and not for a long one. The token ceiling has NO room at all, so the new prose must name no internal identifier. If the instruction cannot be made followable inside both, that is the halt condition rather than a trimming exercise.

The release proof correction is prose only. No code changes, so the predecessor criterion pinning the release implementation stays satisfied by construction.

## Testing

The drift pins assert the sibling shape textually — a module path and a call form present in the tracker-less half — plus both caps, so a future edit that reintroduces the asymmetry or overruns a budget goes red.

Both caps are asserted with their own measurements rather than inherited numbers, because a ceiling that another branch has consumed is a ceiling that reads as headroom.

What CANNOT be tested here is the thing the FR exists to change. A drift pin proves the prose says the right thing; nothing offline proves a child obeys it. The detection FR is what makes that observable, which is why it lands first.

Full gate green from the plugin root.

## Notes

Depends on STE-456, and the dependency is load bearing rather than a preference about ordering: the detection is this FR's ONLY falsifier.

**The honest boundary of this fix:** no offline test can prove a `claude -p` child FOLLOWS the improved prose; only the next conformance run shows that, which is why the detection ships first.

The tracker-less lock has never promised cross tree prevention and this FR does not add such a promise. The existing statements that collision is detected within one working tree and never prevented across trees remain exactly true. What the claim actually buys is single tree and real: the resume path after an abort, a durable witness that makes release provable, and a merge time conflict when two branches meet.

Retiring the lock instead was considered and rejected. It would strand a fixture group that shipped in this same milestone, rewrite five documentation surfaces, and give up a guard that works in the only place it ever claimed to work.

Build order: this FR lands THIRD and LAST.
