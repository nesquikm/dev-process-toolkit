# The /video skill

## Summary

A new command takes a developer from a feature to a finished explainer video, in their own session.
Setup writes the video settings and names the key to add, without ever asking for the key.
A run asks about audience and tone, checks every technical claim against the code, and drafts a script with shots.
Nothing is voiced or recorded before the script is approved, and the final cut is reviewed.
Re-running a video reuses everything unchanged.

## Requirement

- **Setup.** `/video init` asks for the TTS provider, the recorder and the music source, one question at a time, writes `config.yaml`, a default `style.yaml` and `scenarios/`, ensures the ignore lines, and names the key variable to put in `.dpt/.env`. It never asks for or writes a key.
- **Run.** `/video <slug>` checks readiness, asks the brief (feature, audience, length, demo or technical depth, tone and humor) one question at a time, researches the code and records each technical claim with its source location, and writes `script.md` with a shot list.
- **Script gate.** The pipeline front door refuses every stage after the script unless an approval record matches the current script's hash.
- **Then.** Voice, recording, music, edit list, render and QA run through the cached stages; the developer reviews the final cut and either approves it or sends it back to the script or the edit.
- **Surfaces.** Every skill-count pin and the README surface include the new skill.

## Technical Design

A thin skill over two front doors: init and the stage pipeline. The pipeline front door composes the readiness check, the cache, the providers, the recorders and the renderer, and owns the script-hash approval record in the work dir. Research and script writing stay in the session, with claims cited to code.

## Testing

Front-door tests in temp projects with injected providers and recorders; skill-text pins for step order and the one-question rule; the existing count tests updated.

## Notes
