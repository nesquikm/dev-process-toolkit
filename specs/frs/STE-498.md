# /deliver enters a resumed milestone at the phase its state allows

## Summary

Work arrives mid-pipeline routinely: specs written in an earlier session, or written by someone else, reviewed and merged; a milestone half-implemented and abandoned; a milestone fully built that needs only the ship ceremony. The orchestrator can be entered only at its first phase, so none of those states can be asked for.

The most common resume state is the worst one. A freshly merged spec-only pull request lands with its requirements flagged for technical review, and the implement skill hard-refuses a whole milestone in that state — so naive entry at the ceremony phase is guaranteed to bounce, and the operator discovers the spec-writing passes they needed only by reading the refusal. Every input the routing needs is already computed by an existing helper or probe.

## Requirement

A resumed milestone is classified from what is on disk, entered at the phase that state allows, and the classification is shown to the operator before anything is spawned.

## Acceptance Criteria

- AC-STE-498.1: A resumed milestone is classified into the states that change the entry point: FRs awaiting technical review, ready to implement, partly implemented, ship-ready, already shipped, and parked.
- AC-STE-498.2: The classifier reads only files already on disk and mutates nothing — no spec write, no tracker write.
- AC-STE-498.3: Classification reuses the existing helpers and probes (`plan_task_state`, `active_plan_ship_ready`, `plan_ship_coherence`, `needs_technical_review_consistency`) rather than re-deriving their logic.
- AC-STE-498.4: A milestone with FRs awaiting technical review runs those `/spec-write` passes inline in the invoking session, never in a spawned worker, so the Socratic contract is preserved.
- AC-STE-498.5: A ship-ready milestone enters at `/ship-milestone`, skipping `/implement`.
- AC-STE-498.6: A shipped or parked milestone refuses cleanly, with the parked reason surfaced when there is one.
- AC-STE-498.7: The classified state and the exact chain the orchestrator intends to run are rendered to the operator, who confirms, edits, or aborts before any worker is spawned and before any tracker claim is made.
- AC-STE-498.8: Aborting at that gate leaves no side effects.
- AC-STE-498.9: Resume runs one milestone per invocation; the serial worker topology is unchanged.

## Technical Design

Every classifier input already exists and was verified present: `adapters/_shared/src/plan_task_state.ts`, `adapters/_shared/src/active_plan_ship_ready.ts` (probe 75, which also ships a runnable CLI entry), `adapters/_shared/src/plan_ship_coherence.ts` (probe 63), and `adapters/_shared/src/needs_technical_review_consistency.ts` (probe 40). AC.3 therefore constrains this FR to assembly rather than new machinery — re-deriving any of that logic would create a second source of truth for a classification the gate already computes.

The ship-ready row pays twice: probe 75 exists solely to tell the operator a milestone is ship-ready, and today acting on it means reading a gate report and hand-running the ceremony.

AC.4 is a hard constraint inherited from the orchestrator's existing contract, not a preference: `/spec-write` is Socratic, and `/deliver` already forbids proxying Socratic questions, so the partial spec-writing leg must run inline exactly as the normal spec-writing phase does. Pushing it into a worker would violate a contract this milestone is otherwise repairing.

AC.7 makes the classifier's verdict auditable before any side effect, so a misclassification costs a keystroke rather than a worker session and a tracker claim. AC.8 pairs with it — the abort must be genuinely free.

Explicitly out of scope, per the source request: multi-milestone resume, any change to the three ceremony skills (all three are already individually resumable), and deciding which FRs need re-specing beyond the existing flag.

## Testing

Classifier coverage for each state, driven from on-disk fixtures. Read-only property asserted by checking that no spec or tracker mutation occurs on any classification path, mutation-verified so a write would go RED. Reuse asserted against the named helpers rather than re-implemented logic. Inline-not-worker placement of the partial spec-writing leg asserted directly. Abort path asserted to leave no side effects. `bun test` full root.
