# The release writer writes every surface it claims to write

## Summary

Two release surfaces are declared as maintained and are maintained by nothing.

The codename never reaches the regex writer. It substitutes the version alone, and the arm dispatching to it drops a codename the options object has always carried.

The requirements file has no writer at all: its latest-release line names no entry in the release-files block, so the root-hygiene probe reds every release commit until a human amends it.

## Requirement

Every surface the `## Release Files` block declares is rewritten by the writer, and every surface a release must leave current is declared in that block. A field the ceremony can compute is never left for a human to remember.

## Acceptance Criteria

- AC-STE-554.1: `bumpRegex` renders a `{codename}` placeholder from a codename it is given, the way it already renders `{version}`. Measured at HEAD before the change: `bumpFile` with `{codename}` in the template and `codename: "Ceremony"` in the options wrote the six literal characters `{codename}` to the string — the placeholder is not merely unfilled, it survives onto disk.
- AC-STE-554.2: `bumpFile`'s regex arm forwards `opts.codename`. Asserted through `bumpFile`, not only through `bumpRegex`: the defect is in the arm, and a test that reached the helper directly would have passed for the defect's whole life.
- AC-STE-554.3: A template naming `{codename}` when no codename was supplied REFUSES, naming the placeholder and the path. Writing the literal placeholder is the failure mode measured above; falling back to the old version-only substitution would reproduce it silently.
- AC-STE-554.4: A `replace` template that names no `{codename}` produces byte-identical output whether or not a codename is supplied. Every consumer template that predates this change is therefore untouched.
- AC-STE-554.5: This repository's `## Release Files` block carries an entry for `specs/requirements.md`, `kind: regex`, whose pattern captures the version AND the codename of the `Latest shipped release:` line, and whose template rewrites both.
- AC-STE-554.6: A release run rewrites that line unaided. Asserted end-to-end over a fixture tree: run the writer's command-line door, then run `findVersionFreshnessDrift` over the result and assert `[]` — the probe passes on a tree no hand touched. Asserting the rewrite alone would pass on a line the probe still rejects.
- AC-STE-554.7: The README entry's pattern captures the codename too, so the `codename` row of `release_surface_agreement` can no longer fire after a bump. Asserted over a fixture: bump, then grade, then assert no `codename` violation. The milestone and the paragraph after it remain hand-written prose and are out of this criterion's scope — stated here so the criterion is not read as a claim the whole banner is now machine-maintained.
- AC-STE-554.8: `skills/ship-milestone/SKILL.md` names the requirements surface. Measured at HEAD: the string `requirements` appears zero times in that file, so a reader following the skill could not learn the surface exists.
- AC-STE-554.9: `skills/ship-milestone/SKILL.md` stays within the NFR-1 per-skill line cap. Measured at HEAD: 284 lines by `split("\n").length` against a cap of 358, so the budget is not the binding constraint here — the number is recorded so a later reader does not have to re-measure to know that.
- AC-STE-554.10: Falsifiability — each of AC.1, AC.2, AC.3 and AC.5 is mutation-tested: revert the single line that satisfies it and assert exactly that criterion's leg reds while its siblings stay green.

## Technical Design

The regex writer gains a codename argument and a second placeholder, and refuses when a template names that placeholder with nothing to fill it. The dispatching arm forwards the codename it already holds.

The release-files block gains an entry for the requirements file, and the README entry gains a codename capture. Both are data, not code: the writer already walks whatever the block declares, which is exactly why a missing entry was invisible.

The checklist prose telling an operator to update the requirements line by hand becomes false the moment that entry lands, so it is rewritten in the same change.

## Testing

A new suite beside the shipped release-writer tests. The end-to-end legs (AC.6, AC.7) build a fixture tree in a temp dir, run the writer's command-line door as a subprocess the way the ceremony does, and then run the real probe over the result — never a re-implementation of it.

## Notes

The codename fix does not retire the `release_surface_agreement` hand-edit entirely: the README banner also names a milestone and a paragraph, and both stay human-authored. What it retires is the codename half, which is the field that went stale on every release since the entry was written.
