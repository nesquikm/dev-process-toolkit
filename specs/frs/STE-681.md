# Probe 88 grades each bug section where it belongs

## Summary

The bug FR check accepts a bug section under any heading.
It also accepts a regression criterion that holds only a TODO marker.
Import leaves a root cause from the ticket under the requirement section.
This fix grades each section under its own parent and rejects a TODO regression criterion.
Import moves a supplied root cause under the technical design section, and the schema lists the bug kind key.

## Requirement

### Steps to reproduce

1. Write an active bug FR whose Steps to reproduce subsection sits under `## Technical Design` instead of `## Requirement`, and whose only regression criterion reads `Regression: TODO — name the test`.
2. Run `bun run plugins/dev-process-toolkit/adapters/_shared/src/bug_fr_shape.ts <projectRoot>`.
3. Import a Jira Bug whose description carries a filled Root cause subsection.

### Expected

Step 2 reports one violation for the misplaced subsection and one for the TODO regression criterion. Step 3 writes the Root cause under `## Technical Design`.

### Actual

Step 2 exits 0 with no violation. Step 3 leaves the Root cause under `## Requirement`, where the documented bug body does not put it.

## Acceptance Criteria

- AC-STE-681.1: Regression: `tests/m_0cac80-ste-681-bug-shape-placement.test.ts › a Steps to reproduce subsection under Technical Design is reported` fails before the fix and passes after it.
- AC-STE-681.2: Probe #88 reports a violation naming the section it found when `### Steps to reproduce`, `### Expected` or `### Actual` sits under any `##` section other than `## Requirement`, or `### Root cause` sits under any `##` section other than `## Technical Design`; a subsection present only in the wrong place is reported as misplaced, not missing.
- AC-STE-681.3: An AC whose body is `Regression:` followed by nothing or only a TODO marker does not satisfy the regression piece, so the TODO criterion import appends keeps a freshly imported bug FR red on that piece.
- AC-STE-681.4: `importFromTracker` moves a ticket-supplied `### Root cause` subsection (heading and body, up to the next heading) out of the description and under `## Technical Design`; an imported Jira Bug whose ticket supplies all four subsections and a filled `Regression:` AC passes probe #88.
- AC-STE-681.5: `docs/resolver-entry.md` § Bug FR body and `skills/spec-write/SKILL.md` say a supplied Root cause is written under `## Technical Design`, also under `--no-tech` where it sits beside the needs-technical-review placeholder; `specs/technical-spec.md` Schema Q lists `kind` as an optional key whose only value is `bug`.
- AC-STE-681.6: Removing each new check, or the import move, reddens at least one test.
- AC-STE-681.7: `bun test` from `plugins/dev-process-toolkit` reports 0 failures, and its skip identities equal the trunk baseline by name.

## Technical Design

### Root cause

`gradeBugFr` in `bug_fr_shape.ts` finds each `###` subsection by title across the whole file, so its `##` parent is never read. The regression check tests only that an AC body starts with `Regression:`. `renderFRFile` in `import.ts` keeps the description verbatim under `## Requirement`, so a supplied Root cause stays there.

The fix looks each subsection up inside its parent's top section and reports a misplaced one on its own; it treats an empty or TODO-only regression body as absent; and import splits a supplied Root cause out of the description.

## Testing

Probe fixtures per misplaced subsection and per TODO regression form; an import fixture with all four subsections supplied.
