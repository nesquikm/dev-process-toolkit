# Skills learn the tracker mode from one command, never from a missing heading

## Summary

Seven skills decide the tracker mode by reading CLAUDE.md themselves, following written steps.
Those steps treat a missing heading as no tracker at all.
After settings move, such a skill would quietly drop its tracker and work locally.
This change replaces the written steps with one command that runs the settings loader.
A failing command stops the skill, and a missing heading never means no tracker.

## Requirement

The Schema L probe in `docs/patterns.md` § Tracker Mode Probe is a prose procedure: read CLAUDE.md, `grep -c '^## Task Tracking$'`, and treat zero as `mode: none`. Seven skills run it by reference: `/setup`, `/spec-write`, `/implement`, `/gate-check`, `/pr`, `/spec-review` and `/spec-archive`. On a tree whose settings live in `specs/settings.yaml`, that procedure answers `none` for a tracker-mode project.

The replacement is the loader's front door from STE-706:

```
bun run "${CLAUDE_PLUGIN_ROOT}/adapters/_shared/src/project_settings.ts" mode "<projectRoot>"
```

It prints `mode: <value>` and `source: <settings|legacy|none>`. Each of the seven skills runs it at entry, before any side effect, and branches on the printed `mode:`. A non-zero exit stops the skill and surfaces the NFR-10 message; the skill never falls back to `mode: none` on a failed or skipped run.

`skills/gate-check/SKILL.md` is frozen by AC-STE-618.8, and the operator pre-granted one `KICKOFF` re-base per milestone. So this FR leaves that file byte-identical. Its gate-check probe step lands in the single gate-check edit commit of STE-713, which also adds the gate-check rows of this FR's tests.

`mode: none` keeps its meaning: it is canonical when the settings file has no `task_tracking` section, or when a legacy tree has no `## Task Tracking` heading. Only the front door decides which case applies.

Prose that restates the old probe is rewritten to name the front door: `docs/patterns.md` (the pattern, its canonical probe block and the key table), `docs/setup-reference.md`, `docs/setup-tracker-mode.md`, `docs/tracker-adapters.md`, and the "Do NOT paste a literal heading" comment in `templates/CLAUDE.md.template`. This FR deletes that comment's sentence quoting the grep, because the scan below covers `templates/` and this FR lands before STE-710 removes the rest of the block.

The adapter docs read binding values in prose too: `adapters/linear.md`, `adapters/jira.md` and `adapters/_template.md` source `team`, `project`, `default_labels` and `jira_issue_type` from the `### Linear` / `### Jira` sub-section "in CLAUDE.md". Each such read is rewritten to run `project_settings.ts get task_tracking <projectRoot>` and take the adapter's sub-map from its JSON.

## Technical Design

The front door already exists from the loader FR, so this change is prose plus a scan. Each skill's probe step becomes one command and one rule about its exit.

The pattern doc is rewritten around the command, keeping the mode table and the canonical none form.

The scan forbids the old procedure's literal strings across skills, docs and templates. A restored copy anywhere fails the suite.

## Testing

Per-skill clause rows, a forbidden-string scan with a control, front-door spawns for the defect case and each refusal, and a timing bound.

## Notes

Origin: the consolidation-blast finding that a code-side fallback cannot reach a probe written as prose. NFR-2's absence rule is amended in the docs FR. The gate-check probe step waits for the docs FR, under the operator's one re-base per milestone.
