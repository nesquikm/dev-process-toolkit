# The release writer fails loudly rather than silently

## Summary

Three failure modes in the release writer, each measured by executing the module.

The optional flag guards a missing file only. Once the file exists, a pattern that stops matching aborts the whole release — and this repository's own README entry is that shape.

The changelog inserter has no duplicate guard: a second identical run doubles the file and reports success both times.

The regex writer bumps only the first occurrence, and expands a template instead of writing it out.

## Requirement

The release writer never reports success over work it did not do. A skip is named, a duplicate is refused, every occurrence the pattern matches is rewritten, and a user's template reaches disk as the characters they wrote.

## Acceptance Criteria

- AC-STE-555.1: An `optional: true` entry whose file exists but whose pattern does not match is SKIPPED with a named reason. The run completes, every other entry is written, and the exit code is zero. Measured at HEAD: the same fixture printed `Refusing: to rewrite the release files — bumpRegex: pattern did not match` at rc=1 with the JSON manifest left unwritten.
- AC-STE-555.2: A NON-optional entry whose pattern does not match still refuses, still exits non-zero, and still leaves nothing on disk. The skip is a property of `optional`, never of the miss.
- AC-STE-555.3: `--dry-run` reports the same skip, in the same shape as the skips already reported, so the preview and the write agree about what will not be rewritten. A preview that showed a rewrite the run then skips is the same lie in the other direction.
- AC-STE-555.4: `bumpChangelog` refuses to insert a version whose section the CHANGELOG already carries. The refusal names the version.
- AC-STE-555.5: The double-run fixture exits zero on the first run and non-zero on the second, and the CHANGELOG carries exactly one `## [X.Y.Z]` section afterwards. Asserted by counting sections on disk, not by reading the exit code alone — the exit code is what was already wrong.
- AC-STE-555.6: The second run writes nothing at all. The refusal envelope's `nothing was written.` clause is asserted against the tree, not against its own text: every release file is byte-compared to its pre-run content.
- AC-STE-555.7: `bumpRegex` rewrites EVERY occurrence the pattern matches. A two-occurrence fixture leaves neither behind. Measured at HEAD: the second occurrence survived untouched while the writer reported success.
- AC-STE-555.8: The `replace` template is written LITERALLY. A template containing `$&`, `$1`, `` $` ``, `$'` and `$$` lands as exactly those characters. Measured at HEAD: `[$&] v{version}` produced `[v1.0.0] v2.0.0` — the engine expanded the matched text inline.
- AC-STE-555.9: The no-match detection is unaffected by the flag change. A global regex carries `lastIndex` between calls, and a detection that ran `exec` on the same instance the rewrite then reuses would report a spurious miss on the second call. Asserted by calling `bumpRegex` twice with the same arguments and getting the same answer both times.
- AC-STE-555.10: Falsifiability — each of AC.1, AC.4, AC.7 and AC.8 is mutation-tested: revert the single change that satisfies it and assert that criterion's leg reds while its siblings stay green. AC.2's leg is the isolation half of AC.1's: it must FAIL if the skip is made unconditional, not merely pass while the skip is correct.

## Technical Design

A named error class for the pattern miss, thrown by the regex writer and nothing else, so the command-line door can recognise it precisely rather than matching on message text. The door's per-entry loop skips when the entry is optional and rethrows otherwise, reading the same declaration the missing-file branch reads.

A duplicate-section guard at the top of the changelog inserter, before any insertion is computed — the existing content is what makes the answer knowable, and that function is the only one holding it.

The regex writer builds its pattern with the global flag and rewrites through a replacer function. A function replacement is the only form the engine does not scan for dollar patterns.

## Testing

Fixture trees under a temp dir, driven through the command-line door as subprocesses — the same door `/ship-milestone` runs. The double-run leg (AC.5, AC.6) runs the door twice with identical argv and grades the tree between runs, because the defect is precisely that both runs looked identical from outside.

## Notes

Skipping a non-matching optional entry does not make a broken README silent: the surface-agreement guard grades the banner after the bump and aborts the ceremony on disagreement. The skip removes an abort that punished the wrong surface; the surface itself is still graded.
