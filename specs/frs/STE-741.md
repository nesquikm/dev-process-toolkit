# A spec edit committed with add&&commit gets the spec-only pass

## Summary

A spec-only commit needs no gate run.
The commit hook checks the staged files before the command runs.
When one command adds the spec files and then commits them, nothing is staged yet.
So the hook refuses a commit that would be spec-only.
The fix grades the files the add will stage as well.
It does this only when the add names plain spec file paths.

## Requirement

`pre-commit-gate-check` gives the spec-only pass to `git add <paths> && git commit …` when every named path is a spec path and, after the add, the staged set is spec-only and the tracked working tree matches the index.

## Acceptance Criteria

- AC-STE-741.1: A Bash command of the form `git add <p1> [<p2> …] && git commit -m <msg>` (or `-F -` with a heredoc), where every `<p>` is a literal existing file path satisfying `isSpecPath`, takes the spec-only pass when the current staged set plus those paths is spec-only and every unstaged tracked change is inside those paths.
- AC-STE-741.2: The add half never qualifies with `-A`, `--all`, `-u`, `.`, a directory, a glob, or a path that is not a spec path; such a command is graded exactly as today.
- AC-STE-741.3: A tracked change outside the added paths keeps the commit off the spec-only pass, so no code can ride into the commit ungraded.
- AC-STE-741.4: `docs/hooks-reference.md` documents the combined form in the spec-only pass section.
- AC-STE-741.5: `bun test` from `plugins/dev-process-toolkit` reports 0 failures, and its skip identities equal the trunk baseline by name.

## Technical Design

The hook's command recogniser already splits the chain. A new reader extracts the add segment preceding the commit, keeping its literal path arguments only. A helper in the archive-only module then computes the prospective staged set and the unstaged diff outside those paths, using git name-only listings without renames.

## Testing

Hook tests drive the hook with payloads over a temp repo: spec-only add-and-commit passes, a code path refuses, each forbidden add form refuses, and a dirty code file refuses.

## Notes

The receipt-recognition half (a receipt call under a cd compound or a shell variable) is split out to its own backlog ticket. Conformance runs on 2026-11-12 and 2026-11-14.
