# The pull-request gate finds the repository a request is opened from

## Summary

The pull-request guard acts only when a command begins with the exact words gh pr create.
Change directory first, use a subshell, name the repository with a flag or an environment variable, or chain the request after a push, and the guard never looks.
It now finds pull-request creation through the same recogniser the commit guards use, works out which local checkout the request is opened from, and asks that checkout for its review evidence.

## Requirement

`templates/hooks/_lib/hooks/pre-pr-spec-review.ts:15-18` exits 0 unless the raw command matches `/^gh pr create\b/`. That line is byte-identical in 2.83.0, 2.85.0, 2.86.0 and HEAD. STE-597 recorded it as a known gap it left out of scope (`specs/frs/archive/STE-597.md`, Implementation notes). Measured on the installed 2.86.0 hook (skeptic repro `verify-hooks/drive.ts`, session rooted in FE, no spec-review in the transcript): the bare `gh pr create` is refused (P00). These all exit 0 before any evidence is looked at: `cd BE && gh pr create` (P01), `(cd BE; gh pr create)` (P02), `gh -R org/be pr create` (P03), `GH_REPO=org/be gh pr create` (P04), `git push -u origin b && gh pr create` (P05) and the newline-chained push-then-create (P07). Live traffic did exactly this. FE session `3ca0ab95` was refused on a bare FE `gh pr create` at 1-based line 983. At line 1016 it opened BE's PR #62 with `cd …/glacy-app-be && gh pr create`, with no refusal. FE session `80bbcf8c` (line 1071) did the same with no spec-review in the session at all. A rough spec-time regex scan of 85,948 distinct Bash commands found 140 that mention `gh … pr create`, and 64 that start with it. Some of the rest are heredoc or echo mentions, which is why the replay hand-classifies them. `skills/pr/SKILL.md:41` and `docs/honored-contracts.md:54` say the hook refuses "the `gh pr create` Bash call", which overstates what it does.

**Decision: recognition.** PR creation is read through the shared recogniser (STE-601, STE-613), so every wrapper, separator, nested-shell, substitution and directory row of its shape table applies unchanged. An invocation is PR creation when its argv0's final path segment is exactly `gh` and, after gh's flags (`-R`/`--repo` with a value, in either spelling, before `pr` or after `create`), its words are `pr create` or `pr new` (gh's built-in alias for create, measured on gh 2.95.0: its help lists `gh pr new` under ALIASES). `url=$(gh pr create …)` is creation, and so are `--dry-run` and `--web`, conservatively. `gh pr create --help` and `-h` are not creation: HEAD's anchored regex refuses them, measured during this review, and the new resolver must not. These are not PR creation, and each is pinned and listed in the hooks manual: `gh pr list`, `gh pr view`, `gh pr edit`, `gh pr merge` and `gh pr checkout`; `gh api …/pulls` with any method; `hub pull-request`; `git push -o merge_request.create`; `gh pr create` inside a script file; a user-defined `gh alias` (expanding it needs the user's gh config); and an opaque `bash -c "$X"`. A heredoc body that mentions `gh pr create` is not creation.

**Decision: the target.** A new module, `adapters/_shared/src/pr_target_repo.ts`, exports `resolvePrTargetFromPayload(payload)`. It returns the same `CommitTarget`-shaped verdict, with `isPr` in place of `isCommit`, `repoRoot`, `repoRoots` and `unresolved`. The local checkout is the checkout root of the directory the invocation runs in. A repository slug comes from `-R`/`--repo` (which takes precedence), or from `GH_REPO` set as a prefix assignment, as an `env` operand, or by an in-command `export`, or failing all of those from `GH_REPO` in the hook process's own environment, which the Bash tool's shell inherits from the same launch. When a slug is given, it must match a remote of that checkout. The remotes are read with `git remote -v` run in that checkout. Matching accepts https and ssh URL forms, an optional `.git` suffix and an optional `HOST/` prefix, and is case-insensitive.

- A slug that no remote matches is a known-foreign target, and the hook refuses it with exit 2 even when evidence is present. The refusal names the slug and the checkout, and the remedy names opening the request from that repository's own checkout. Evidence in one checkout cannot vouch for a request into another repository.
- An unexpanded slug, or a `git remote` that cannot be run, is unresolved. An unexpandable directory is unresolved too.

**Decision: the evidence.** The hook calls `requireSkillToolUse("dev-process-toolkit:spec-review", …)` with the target, and the rule from STE-614 applies without change. A toolkit-managed checkout needs a non-error Skill call plus a spec-review receipt in that checkout. An unmanaged checkout needs the transcript leg alone. Several checkouts need evidence in each. An unresolved target is evaluated against the session's own checkout and every candidate root the recogniser reports, and on success the hook exits 1 with a `Reminder:`, the operator-visible channel. The hook entry point carries no filesystem read of its own, which keeps the guard-family pin in `tests/hook-session-lib.test.ts` green. The /pr skill's own step 5 shape, a bare `gh pr create` in the session's own checkout, keeps working exactly as today once /spec-review has run for that checkout.

## Technical Design

`pr_target_repo.ts` consumes the shared recogniser's invocation stream, exactly as `commit_target_repo.ts` does. It adds only the gh argv grammar and the slug-to-remote match, and it runs `git remote -v` through the same spawn-and-report pattern the /tdd hook uses, so a spawn failure is a named verdict, never a throw. The hook entry point becomes a thin caller: parse the payload, resolve the target, and demand evidence with the target. The anchored regex is deleted, not kept as a fast path.

## Testing

A new `tests/pr-target-repo.test.ts` covers recognition and target rows with real remotes on real `git init` checkouts. Hook-level pairs run through the bash wrapper, where every forbid row has a permit sibling. The replay helper supplies the real-traffic numbers.
