# The trend and its upgrade step read their inputs honestly

## Summary

A review of the 3.6.0 trend found seven ways it misreads its inputs.
Review signals read zero when no review was recorded.
A session shared by several runs is counted once per run.
Some skipped notes name one switch where two are needed.
Fixes that cite an AC or touch a renamed file are misread.
Groups never sort, and the upgrade step passes a broken priority.

## Requirement

Every number `/retro --trend` prints comes from recorded input, counted once, and every skipped cell names each tracking key it needs. The `retro-priority-default` step refuses a broken `retro.priority` instead of passing it.

## Acceptance Criteria

- AC-STE-784.1: Groups sort worst first by the newer-half change of the first-ranked metric; when that change is null for both groups compared, the next ranked metric decides, and so on. `docs/retro-reference.md` says waste reads skipped until TDD rounds record whether they changed a file.
- AC-STE-784.2: With `tracking.review_findings` on, `spec_review_gaps_per_fr` reads `skipped: not observable` when the window holds no spec-review receipt, and `code_review_concerns_per_100_lines` reads it when the window holds no code-review receipt. Neither reads 0.
- AC-STE-784.3: In one group's window, a session that several runs share counts its gate runs once, and each `review-findings` receipt counts once, so five runs in one session with one code-review receipt of 2 concerns over 96 lines read about 2.08, not 10.42.
- AC-STE-784.4: `time` and `gate_failure_rate` need both `tracking.gate_outcomes` and `tracking.tool_calls`; with either off the cell reads `skipped: not observable` and names every key that is off.
- AC-STE-784.5: A fix commit whose message cites `AC-<FR id>.<n>` names that FR, so it is not counted as a post-merge fix of it.
- AC-STE-784.6: A rename in a `Refs:` commit (`dir/{a.ts => b.ts}` or `a.ts => b.ts`) records the new and the old path, so a later fix that touches either is matched.
- AC-STE-784.7: `retro-priority-default` reports a present `retro.priority` that is null or fails the loader's check as broken: detect applies with evidence naming the file, and apply returns a `Refusing:` summary that writes nothing. A throw from the settings writer also becomes a `Refusing:` summary, with the file unchanged.
- AC-STE-784.8: `bun test` from `plugins/dev-process-toolkit` reports 0 failures, and its skip identities equal the trunk baseline by name.

## Technical Design

Changes are local to `retro_trend.ts` and the migration entry. The sort compares the priority list in order and stops at the first metric where the two deltas are not both null. `signalValues` keeps a per-window set of seen sessions and receipt keys (session plus receipt file), and counts each receipt reviewer kind it saw, so an empty kind reads null. `INPUT_KEY` maps each cell to a list of keys. `namesId` accepts an optional `AC-` prefix before the id. The numstat parser expands brace and arrow renames into both paths. The migration validates a present priority with `checkRetroPriority` and wraps the writer.

## Testing

Extend the three M_4daa6e test files with fixture cases per AC: a shared-session window, a window without receipts, a switch-off matrix, the AC-citing fix commit, a git repo with a rename, and the two broken settings shapes. Each AC gets a defect check.
