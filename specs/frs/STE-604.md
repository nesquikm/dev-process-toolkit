# Creating a ticket in a shared container is decided by code on Jira and Linear

## Summary

Before creating a ticket the toolkit checks whether an earlier run already made it, but that check was prose the model followed, so another repository's same-titled ticket could be adopted.
The check is now a command that reads the ownership label itself, confirms the tracker answered the question asked, and records its decision.
New tickets are created already inside their milestone, so a retry after a timeout finds its own ticket.
Linear gets the same check.

## Requirement

Measured at HEAD `ac1f3cb`:

- The live create decision is prose in `adapters/jira.md` and `adapters/linear.md` § `upsert_ticket_metadata`. `runCreateIdempotencyProbe` in `adapters/_shared/src/create_idempotency_probe.ts` has no production caller, and `jira.md` says outright that nothing grades whether the prose and the code agree. The prose normalizer (trim, collapse whitespace) and the code's (also dashes, NBSP, heading anchors) disagree, so which near-identical titles are adopted depends on which one the model applies.
- With no tag in a shared container, a title equal after normalization under the same container is REUSED, and the reuse writes nothing, so the adoption is silent until `/implement` claims the sibling's ticket. Repro (verify-fr-adoption `adopt.ts`, real module, conjunct-honouring in-memory Jira): shared Epic, no tag → reused, zero creates; control, separate Epics → created.
- The JQL carries no issue-type conjunct, and the title is interpolated raw: a title containing a double quote produced a live 400 ("Expecting either 'OR' or 'AND'").
- `createJiraIssue` sets no parent (the parent is written by the later attach), so the retry probe's `parent =` conjunct can never see the ticket its own timed-out create made. Repro `unparented.ts`: own unparented ticket, probe with the parent conjunct → created again; control, probe without it → reused; control, ticket already parented → reused. A numeric container's `labels = "milestone-M<N>"` conjunct misses the same way, because that label is also written after create.
- With a tag declared, a tracker that honours its own filter never returns a differently-tagged ticket, so the foreign-repo-tag stop cannot fire. Its test (the STE-579 suite, `recorder()` at lines 142-155) passes only because the recorder ignores its search parameters and returns a `glacy-be` ticket to a search filtered on `glacy-fe`.
- Linear has no pre-create probe. Its retry probe orders a `projectMilestone` filter that `mcp__linear__list_issues` does not accept (the schema has no such input and sets `additionalProperties: false`), cites a "documented cap" that `linear.md` never defines, and claims the module implements the Linear build (the module mentions Linear zero times). On an uncapped retry miss with a tag declared the module CREATES where both prose files say refuse.

### 1. The query command

`bun run adapters/_shared/src/create_idempotency_probe.ts query <projectRoot> --title <t> [--parent <EpicKey> | --milestone-label <label> | --linear-milestone <id>]`:

- reads the binding itself through STE-602 — the model never supplies the tag — and refuses on a malformed declaration or a failed version floor, then runs `assertRepoTagForwarded`;
- Jira: prints `project = <KEY> AND <container> AND issuetype != Epic [AND labels = "<tag>"] AND summary ~ "\"<title>\""`, with `\` and `"` in the title escaped, and the field list the page must carry (`summary, labels, issuetype, parent, project`);
- Linear: prints the `list_issues` arguments `{ team, project, [label: <tag>], fields: [title, labels, projectMilestone, project, team], limit: 250 }` — never `query`, never a `projectMilestone` input.

### 2. The decide command

`bun run adapters/_shared/src/create_idempotency_probe.ts decide <projectRoot> <page.json>... --title <t> [container flags] --attempt <fast|retry-1|retry-2|retry-3>` reads the saved page or pages (Jira search results; Linear `list_issues` results in cursor order) and prints one JSON line `{ outcome, key?, reason?, capability?, createPayload? }`:

- `refused` / `page-violates-query` when any candidate fails a conjunct the query carried — project, container, issue type, and the tag when shared; the Linear milestone is checked here, client-side. This replaces the dead foreign-tag branch: a differently-tagged candidate on a filtered page means the search that produced the page was not the one `query` printed.
- `reused` when a candidate matches under the one normalizer, `normalizeTitleForCompare`.
- `refused` / `page-cap` when nothing matched and the last page reports `isLast: false` (Jira) or `hasNextPage: true` (Linear).
- On `retry-3` with an uncapped miss: `refused` / `retry-miss-shared` when shared; `create` with the `tracker_idempotency_uncertain` warning when undeclared — today's prose, now also the code's.
- A missing, unreadable or non-JSON page file, or a candidate lacking a field a conjunct needs, is a refusal — never read as "no match". An empty page that reports itself complete is the named outcome `proven-absent`, followed by `create`.

Every refusal carries `capability: "tracker_idempotency_uncertain"`. No capability key is registered: the canonical set stays at 47.

### 3. The create carries its container

`createPayload` for Jira sets the parent to the Epic key for an Epic-keyed milestone and adds the `milestone-<M-token>` label for a grandfathered numeric one; for Linear it sets `milestone`. Its labels are the forwarded `default_labels`, tag included. The later attach finds the parent already set and stays the no-op its idempotency pre-check already defines. This is what lets a timed-out create's own retry find its ticket. In this milestone the session supplies the container flag from the plan's milestone binding; from M_685ff6 on, the `key=` line of the attach-target front door (STE-611) is the one source of `--parent`, and the write gate then requires the create's parent to equal that key.

### 4. Receipts

In a shared repository, `create` writes a `create` receipt holding `createPayload`, and `reused` writes a `reuse` receipt naming the key; both print `dpt-receipt: <absolute path>`. An undeclared repository gets the decision and no file: its working tree stays byte-identical. A `create` receipt is single-use: the write gate lets it authorise one create call, whatever that call's result, so a retry after a timeout must re-run `decide --attempt retry-<N>`. Live evidence (finding LJ-2, skeptic-corrected) says the GF-90/GF-91 pair was an improvised second create, not an index-lag miss; single-use receipts refuse that shape as well.

### 5. One decision, two surfaces

`runCreateIdempotencyProbe` keeps its exported shape and gains `attempt`, so the TypeScript API and the command make the same decision on every input.

### 6. Prose

- `adapters/jira.md` and `adapters/linear.md` § `upsert_ticket_metadata` order `query`, then the search, then `decide`, then the create with `createPayload`, on the fast path and on each retry attempt. The "reference implementation … nothing grades the agreement" paragraphs are deleted, because the prose now runs the code. `linear.md` gains the shared-mode fast path and defines its cap as `hasNextPage: true` after cursor pagination.
- `skills/spec-write/SKILL.md` line 109 is rewritten in place. It names the command by its adapter section and carries no module path (pinned). It keeps the six step-4 tokens its sibling suite grades — `Provider.sync(spec)`, `1s + 2s + 4s`, three attempts, `JQL`, Gateway-Timeout, single-shot / fast path — and the one `MUST emit` directive for `tracker_idempotency_uncertain`. The file stays at 358 split-lines with 54 STE tokens, and line 111 still opens the milestone-attachment paragraph.

### 7. The test that graded a tracker that does not exist

The STE-579 suite's recorder honours its search parameters: it drops candidates that fail project, container or tag. The foreign-tag case is re-expressed as an explicitly named conjunct-ignoring fake and asserts `page-violates-query`. These are the only pins of that suite that move, and each move says why.

A title containing both `"` and `\` produces a phrase that unescapes to the original title. A declared but unforwarded tag refuses with `RepoTagBindingError`; a failed floor refuses. The Linear arguments never contain `query` or `projectMilestone`. Relocated: given a worktree root whose CLAUDE.md declares a different tag from the main checkout's, `query` uses the worktree's tag and `decide` writes its receipt under the worktree root.
- AC-STE-604.2: `decide` forbids, over a two-repo fixture (FE declares `glacy-fe`, BE declares `glacy-be`, one Jira project, one shared Epic): BE's decision over a page carrying FE's same-titled ticket tagged `glacy-fe` is `page-violates-query` with zero creates; the same ticket untagged is refused the same way; a same-titled Epic on the page is refused by the issue-type conjunct.

## Technical Design

The query and the decision become two subcommands of the module that already owns the normalizer, so there is one join rule. The query is built from the binding, never from arguments the model supplies. The decision validates the page against the query before joining; that one check replaces the foreign-tag branch a filtering tracker made unreachable, and it catches a model that searched for something else. Creating inside the container closes the window in which a ticket exists outside it. Receipts record what was decided so the write guard can compare the create call against it.
