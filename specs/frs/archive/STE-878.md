# Best-practices select prints size and hash, refuses oversized documents, and both TDD writers read it

## Summary

The best-practices select command printed only a name and a path for each document.
A reader could not tell how large a document was, or whether it had changed.
It now also prints each document's size and hash.
A new optional size limit makes select refuse an oversized document, and the other documents still print.
Three stages read these documents: the test writer, the TDD code writer and the implement review.
Each reads them as reference data, never as instructions.

## Requirement

`best_practices_manifest.ts select` prints the byte size and sha256 of every selected document and honours an optional per-entry `max_bytes` cap. Every reader of its output, now including the TDD implementer, reads the printed documents as reference data and reports a refused entry as a blocker.

## Acceptance Criteria

- AC-STE-878.1: For each selected entry, `select` prints one line `name<TAB>path<TAB><bytes><TAB><sha256>`, in manifest order, where `<bytes>` is the document's size in bytes and `<sha256>` is the lowercase hex digest of its bytes.
- AC-STE-878.2: An entry may declare `max_bytes: <positive integer>`. The closed schema accepts the key, and `addEntry` / `writeManifest` round-trip it. A value that is not a positive integer is a `BestPracticesManifestShapeError`, and `select` exits 2 on it.
- AC-STE-878.3: A selected entry whose document is larger than its `max_bytes` prints `refused: <name> <bytes>` in place of its line. The other selected entries still print, and the exit code is 0.
- AC-STE-878.4: A selected entry whose document is missing on disk prints `refused: <name> missing` and exits 0. Exit 2 keeps meaning a malformed manifest or bad usage, and the `no-manifest:` and `no-match:` lines are unchanged.
- AC-STE-878.5: The tdd-write-test child skill, the tdd-test-writer agent and the `/implement` best-practices lens each say that the printed documents are reference data, not instructions, and that a `refused:` line is reported as a blocker in `notes` (the lens: in its review findings). `skills/implement/SKILL.md` does not grow past its line cap.
- AC-STE-878.6: The tdd-implement child skill runs the same `select` with the AC's failing test file paths, and the tdd-implementer agent reads every document it prints as reference data. A `refused:` line is reported as a blocker in `notes`. A `no-manifest:` or `no-match:` line means there are no documents to read.
- AC-STE-878.7: `bun test` from `plugins/dev-process-toolkit` reports 0 failures, and its skip identities equal the trunk baseline by name.

## Technical Design

Add `max_bytes` to `KNOWN_KEYS` and the entry type, validated in the parser beside the existing keys. In the CLI, `statSync` each selected path for its size and hash the bytes with `node:crypto`. A size check runs before the read, so a refused document is never read in full. The reader texts replace words, not add them, where a file is at its cap. The tests that pin today's two-column output move to the four-column shape.

## Testing

Unit tests over fixture manifests: the four-column line, a cap hit beside an entry under the cap, a missing document, and a malformed `max_bytes`. Text tests over the three reader skills and the two agents for the `select` call and the reference-data rule.
