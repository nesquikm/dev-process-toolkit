# The planning repository can edit its Epic's text with consent, and a fetched ticket proves ownership

## Summary

The write gate refuses every edit to a milestone Epic, even from the repository that planned it.
A new checked command proves that this repository's committed plan binds the Epic.
After one consent answer from the operator, the description and title may change.
Every other Epic write stays refused.
The gate also reads ownership from a ticket fetched in this session.
No agent has to hand-build a ticket file any more.

## Requirement

In a repository that declares a shared tracker container, the repository that planned a milestone can edit its Jira Epic's description and summary after explicit operator consent, and a ticket this session fetched can be written once its fetched answer proves ownership. Every other refusal stays as it is.

## Technical Design

### Root cause

`ticket_ownership.ts` refuses a container whatever binds it, and the gate grants ownership only through a tracked FR, a create in the session, or a receipt. A tracked plan never counts, so no supported path edits an owned Epic. A non-Epic ticket needs a receipt built from a ticket file that no script can fetch, because only the MCP tools reach the tracker.

### Fix

Mirror `epic_close.ts`: a new `epic-edit` receipt on the existing trust path, plus the exact consent label rule the join decisions use. The gate reads the get-ticket tool_result straight from the transcript and runs the shipped ownership decision on it in-process.

## Testing

Synthetic transcripts, recorded payloads and temporary git repositories with fake keys only, driven through the shipped hook entry point; one twin per condition and a mutation battery over hook and grader.
