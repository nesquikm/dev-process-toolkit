# STE-414: Non-tty smoke-test driver hard gate against leg-stranding (fire-and-exit + discretionary prose-pause) {#STE-414}

## Summary

During a two-leg conformance run, both smoke-test legs finished quickly but never ran the canonical chain and left tracker data behind, because each leg was a nested headless session the driver mistook for an interactive one.
One leg spawned a setup grandchild and then ended its turn to wait for a completion notification that a headless session never delivers, aborting the grandchild mid-stream.
The other leg paused mid-run to ask the operator a free-form rate-limit question and ended its turn, which is silently ignored when no human is on the line, leaving its tracker project orphaned.
This work turns the driver's headless-context detection into a hard gate rather than an advisory note, forbids every background-wait and turn-yield path when standard input is not a terminal, resolves any mid-run judgment call deterministically from the auto-approve marker, and makes a driver about to end its turn with an unfinished chain or a live grandchild abort loudly and tear down its tracker project and test directory instead of exiting quietly as success.

## Requirement

Origin: 2026-07-24 `/conformance-loop` run (capture-only, plugin v2.55.0). `/conformance-loop` spawned the two `/smoke-test` legs as nested `claude -p` sessions. BOTH legs exited rc=0 in ~8 min WITHOUT running the canonical chain (a false green — rc=0 is not proof the chain ran), and BOTH left orphaned data because Phase 5 teardown never ran. Two distinct manifestations:

1. **Jira leg — F3 fire-and-exit RECURRENCE.** The driver spawned `/setup` as a background task, then ended its turn narrating "the harness will re-invoke me when it exits — this is the sanctioned wait in an interactive parent (background completion *does* notify here, unlike a nested claude -p driver)." It WAS a nested `claude -p` driver, so no completion notification arrived; when the leg process ended it aborted its own `/setup` grandchild mid-stream (`[Request interrupted by user]`, terminal_reason: aborted_streaming). This is the exact F3 failure the STE-355 / STE-357 / STE-365 apparatus targets, recurring despite the STE-365 SMOKE-CTX probe.

2. **Linear leg — discretionary prose-pause under the auto-approve marker.** The driver completed pre-flights + Phase 1 setup (created the Linear project), then PAUSED and asked the operator a 3-option prose question about a seven-day rate-limit warning ("Options: 1 Proceed / 2 Abort cleanly / 3 Reduced run … Which would you like?") and ended its turn. Under `claude -p` (non-tty) a prose-ask-then-end-turn is a silent no-op: the leg exited rc=0, no chain, and left the Linear project orphaned.

**Root cause.** The STE-365 SMOKE-CTX context probe is an ADVISORY banner (`[ -t 0 ]` → prose) the LLM driver can and did rationalize around (the Jira leg narrated itself as "an interactive parent" while headless). And the Linear leg's mid-run discretionary "should I proceed?" decision is a code path the existing anti-F3 apparatus (STE-355 bounded poll / STE-357 final-message self-check / STE-365 probe) does not cover at all — a new pause-and-ask escape hatch that strands the leg under non-tty.

**Fix target.** The project-local harness skills `.claude/skills/smoke-test/SKILL.md` (primary) and `.claude/skills/conformance-loop/SKILL.md` (parity) — NOT the shipped plugin. Follows the harness-hardening precedent of M95 / M96 / M98 (driver-side milestones that shipped as plugin releases with a CHANGELOG entry).

## Technical Design

**Fix target:** project-local harness skills only. No shipped-plugin behavior changes; no new numbered `/gate-check` probe (the fix is SKILL prose + a doc-conformance meta-test, matching the M98 / STE-365 shape).

**`.claude/skills/smoke-test/SKILL.md`:**

- `#### Phase-2-entry context probe — SMOKE-CTX (STE-365)` (~line 322). Upgrade the advisory banner to a hard-gate clause. The banner's headless branch already prints the prohibitions as prose; add that the `[ -t 0 ]` result is the SOLE determinant of headless vs interactive, that a `SMOKE-CTX: headless` classification is BINDING for the rest of the run, and that any self-narration to the contrary — specifically the phrase "interactive parent," the exact 2026-07-24 Jira-leg rationalization — is forbidden and does not re-open any background-wait or turn-yield path. The driver may not proceed on an "interactive" self-classification when stdin is non-tty.
- `#### Phase 2 child-spawn discipline` FORBIDDEN callout (STE-365.2). Extend the existing co-located ⛔ FORBIDDEN paragraph so its forbidden set names, together in one paragraph: `run_in_background`, the `Monitor` tool, background-task completion waits, ending the turn to await a completion notification, AND the "interactive parent" self-classification — with the bounded `kill -0` poll-until-exit loop as the only sanctioned wait. The STE-365.3 drift guard (detached spawn + pidfile + bounded poll snippet) is untouched.
- New `#### Discretionary-halt guard (STE-414)` subsection, co-located immediately after the SMOKE-CTX probe. Contract: under a `SMOKE-CTX: headless` classification, any mid-run judgment call the driver would otherwise resolve by asking the operator — a rate-limit / seven-day-usage warning, a cost pause, a reduced-run choice, or any new decision the auto-approve marker could not pre-authorize — MUST resolve deterministically. Marker present in the invoking prompt body ⇒ proceed with the full run; marker absent ⇒ abort-with-full-teardown (run Phase 5 teardown, then exit non-zero). There is NO prose-ask-then-end-turn path under non-tty: ending the turn on an operator question is a silent no-op that strands the leg. (The Phase 0 pre-approval `[y/n]` gate is unaffected — it fires before the run and is already marker/refusal-routed.)
- `**Final-message self-check (STE-357).**` (~line 429). Strengthen from "resume the bounded poll loop" into a hard abort-with-teardown: before emitting any final message, a driver that finds an incomplete grandchild chain (canonical chain not run to completion) OR any live pidfile MUST loudly abort AND run Phase 5 teardown — it must NEVER exit rc=0 silently with an unfinished chain or a live grandchild. Retire the `[~]` runtime-deferred posture into this byte-checkable contract clause.
- `### Phase 5 — Teardown` (~line 1077). Referenced as the single abort target by all three abort paths above. Teardown is tracker-branched: Linear archives the per-run project; Jira transitions the `dpt-smoke`-labelled items to Done; both `rm -rf` the test directory. No abort path may skip it.

**`.claude/skills/conformance-loop/SKILL.md`:** mirror the hard-gate clause + discretionary-halt guard + end-of-turn abort-with-teardown into the Phase A / Phase B driver surface (this driver is itself a non-tty session spawning legs), extending the STE-365.4 parity callout at the Phase A leg-spawn site.

**Meta-test:** `tests/m112-ste-414-nontty-hard-gate.test.ts`, mirroring `tests/m98-ste-365-fire-and-exit-guard.test.ts` — computes `repoRoot` as `join(import.meta.dir, "..", "..", "..")`, reads both harness SKILLs via `.claude/skills/{smoke-test,conformance-loop}/SKILL.md`, `describe.skip` when a SKILL is absent (dogfood-only surface; a plugin-only checkout has neither file), and byte-pins each contract clause with section-scoped slices + paragraph-proximity predicates.

## Implementation notes

**Spec deviation 1 — `underspecified` (self-contradiction, found at REFACTOR).** The rewritten final-message clause stated an unconditional "MUST loudly abort AND run Phase 5 teardown on either trigger" and then immediately offered "if the chain is still runnable, resume the bounded poll loop" — a rationalizing driver could quote either half, which is the exact escape-hatch shape this FR exists to close. Deleting the resume branch was not viable (`smoke-driver-m96-wait-discipline.test.ts` pins `/resume/` in that paragraph, and resuming a healthy in-flight poll is behaviourally correct). Resolved by making precedence explicit: resume is available only while the chain can be finished in the same turn and implies no final message is emitted; once finishing is off the table, abort-with-teardown is the only move.

**Spec deviation 2 — `underspecified` (rc=0 loophole, found at AUDIT).** The abort branch was defined as loud (`emit SMOKE-ABORT: <trigger>`) but stated **no exit code**, while the prohibition read "never exit rc=0 **silently**". A driver could rationalize: "I emitted SMOKE-ABORT and ran teardown, so this is not a silent rc=0 exit" → end turn → `claude -p` returns rc=0 → parent reads a false green. The asymmetry read as deliberate because the discretionary-halt guard's marker-absent branch already says "then exit non-zero". Closed with an explicit non-zero-exit mandate plus an unqualified restatement carrying no adverb to argue over. This is why AUDIT scored AC.4 Partial on intent; it is now Done.

**Spec deviation 3 — `underspecified` (unachievable invariant, found at AUDIT).** Both drivers assert "There is no third branch in which the turn ends while a pidfile still answers `kill -0`". That was **false on the abort branch the same paragraph sanctions**: Phase 5 Teardown contains zero pid handling, so aborting archived the tracker project and `rm -rf`'d the test dir while leaving the grandchild live. A rule its own sanctioned branch violates is precisely the prose an LLM resolves in its own favour. Closed by adding a reap so the invariant is true rather than aspirational.

**Spec deviation 4 — `underspecified` (destructive-ordering race, found at Phase 3 code review).** The reap was sequenced **after** the teardown actions, so `rm -rf` of the test directory and archive/close of the tracker project ran while a live grandchild could still be writing to both. Reordered: reap first, teardown only once the reap is done — in both drivers and in both self-check fences' operator-visible echo strings.

**Spec deviation 5 — `underspecified` (PID-reuse TOCTOU, found at Phase 3 code review round 2).** The reap sends a **real** signal to a PID whose liveness was confirmed by `kill -0` moments earlier; a PID recycled in that window would terminate an unrelated process on the operator's machine. The pre-existing "Residual risk — PID reuse" paragraph framed reuse as uniformly benign, which is true for the polling loop but false for a destructive step. Closed with a `ps -p <pid> -o comm=` identity check before signalling, and by scoping the benign framing to the poll.

## Advisory notes

- The `SMOKE-ABORT:` / `LOOP-ABORT:` markers this FR mandates have **no reader** anywhere in the repo. `/conformance-loop`'s leg-completeness check still detects the fire-and-exit shape by prose judgement rather than by grepping `^SMOKE-ABORT:` in the leg log. Wiring it would make the loud abort byte-checkable end-to-end — the same advisory-to-deterministic escalation this FR applies elsewhere.
- Trigger (1) of the hardened self-check, "an incomplete grandchild chain", has no deterministic detector on the leg side; the co-located fence only tests pidfile liveness, so chain completion stays LLM-judged. The leg could assert its own six-log set the way `/conformance-loop` asserts it from outside.
- `smoke-driver-m96-wait-discipline.test.ts` still greps the contiguous literal `never end the turn`, which this FR softened to "never end the turn **quietly**". The guard passes but now pins a qualified prohibition while reading like an absolute one; consider re-pinning it on the new absolute ("There is no third branch").
