# A default=forbidden decision authorises no write until it is answered

## Summary

For a shared title join, or a Linear create over a possibly capped listing, the milestone decision door prints a forbidden default.
The hook still permitted every write that decision named, so an agent could act on a decision the door refused to default.
The door now prints the exact consent options, and the hook permits those writes only after a human answers one, after the decision.
Unattended runs therefore stop there and wait, by design.

## Requirement

The milestone decision front door prints `default=forbidden` for a shared title join and for a possibly capped Linear create. When it does, it also prints and records the consent options.

- The hook then permits the writes that decision would authorise only after a harness-recorded AskUserQuestion answer, given after the decision's announcement, names that key or title and is exactly "Join `<KEY>`" or "Create `<title>`". Those writes are a labels-only join edit, an FR create attached through the decision, and a container create.
- A decision printed with `default=allowed` permits as at HEAD. So does a later allowed key join of the same key.
- /deliver and auto-mode runs therefore stop at a forbidden default and wait for a human. This is intended: `skills/spec-write/SKILL.md` already withholds the default.

Covers A4 (F3b; medium). Amends AC-STE-608.6, AC-STE-608.10 and LIN-7 (STE-608.md:53, :57, :132). Builds on the transcript wait and the prior-create scan of the two previous FRs.

## Acceptance Criteria

- AC-STE-643.1: A labels-only editJiraIssue on an Epic whose latest join decision printed `default=forbidden` exits 2, unless an AskUserQuestion naming that key was answered exactly "Join `<KEY>`" after the decision's announcement. An Epic this session created itself needs no join consent (it is its own), but its labels write is still a read-merge that must keep every listed label (review round 2, B1R2-1).
- AC-STE-643.2: An FR create whose attach-target provenance is a `default=forbidden` join decision exits 2 without that answer and exits 0 with it.
- AC-STE-643.3: A Linear milestone create decided with `default=forbidden` (possibly capped) exits 2 unless "Create `<title>`" was answered after the decision.
- AC-STE-643.4: An answer of "Skip …", an answer recorded before the decision's announcement, or an errored or denied AskUserQuestion authorises nothing.
- AC-STE-643.5: A decision printed with `default=allowed` permits exactly as at HEAD with no answer, including a key join that follows a forbidden title join of the same key.
- AC-STE-643.6: The front door prints an `options=` line if and only if it prints `default=forbidden`, and records the same labels in the receipt's evidence.
- AC-STE-643.7: A forbidden title join still supersedes an earlier create decision for its title, so the Epic create stays refused.
- AC-STE-643.8: The live grader reports an ungated-write for a labels-only write, or a milestone create, that relied on an unanswered forbidden decision; a labels write to an Epic the run created itself is exempt from the consent half only, as in the hook.

## Technical Design

The decision front door, when its default is forbidden, prints and records an options line with the two consent labels. The hook carries the forbidden flag on each milestone decision and computes the consent label itself from act, key and title, never from recorded evidence. Consent is satisfied only by a harness-recorded question answer that names the key or title, offers the label, is exactly the label, and sits after the decision's announcement. Three gates enforce it: attach-target provenance, the joined-labels edit, and the milestone create. The live grader mirrors the check.

## Implementation notes

- the grader's local namesKey boundary regex differs from the hook's (it excludes '_' and a trailing -<digit>); introduced by this FR's grader twin — low practical risk for ordinary question text; the two modules cannot share code across the hook/grader boundary
- evidence.default values other than 'forbidden' read as allowed rather than failing closed — milestone-decision receipts are written only by resolve_milestone_identity.ts (always 'forbidden' or 'allowed') and count only when that module announced them with a digest the file still matches
- the grader reads consent answers from result text only; the hook prefers toolUseResult.answers — bundles keep only the result text; both agree on every recorded shape
- provenanceUnproven parses the receipt JSON twice — cleanup only; the second parse follows a successful first

## Design detail

- **Front door.** `adapters/_shared/src/resolve_milestone_identity.ts` (~:719-761; `forbidden` computed at ~:245 and ~:711-716): after the `default=` line, print `options=<JSON>` and record `evidence.options`. A title join gets ["Join `<KEY>`", "Skip `<KEY>`"]; a capped create gets ["Create `<title>`", "Skip `<title>`"].
- **Hook: carrying the field.** MilestoneDecision (~:1507-1520) gains `forbidden`, and milestoneDecisions (~:1544-1555) keeps it.
- **Hook: the consent test.** Compute the consent label in the hook from act, key and title. `answeredAfter(parsed, label, line)` is satisfied only by an AskUserQuestion whose input names the key or title, whose options include the label, and whose harness-recorded answer (selectedAnswers, ~:1339) is exactly the label, at a line after the decision's announcement.
- **Hook: where it is enforced.** provenanceUnproven gets `parsed`; before the unchanged row w line `if (act === "join") return null;`, a separate statement sets why = NOT_CONSENTED, and gateAttachTarget gains a refusal naming the receipt and the required answer. gateJoinedLabels (~:1728-1742) refuses when the latest join for the key is forbidden and unanswered; a later allowed join still governs. gateMilestoneCreate permits only on `matching.some((d) => !d.spent && (!d.forbidden || answeredAfter(parsed, consentLabel(d), d.line)))`.
- **Grader.** Mirror the check in `adapters/_shared/src/shared_tracker_live_grader.ts`: the join acceptance (~:2418-2419) and the milestone-create acceptance (~:2383-2390).
