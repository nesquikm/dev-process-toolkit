# One probe runner prints a fixed row per probe, and the fixtures grade that row

## Summary

The gate check has no shipped runner for its numbered probes.
Each run scripts its own probe calls, and one run skipped thirteen of them.
The smoke fixtures then grade the words the model chose, and those words change every run.
A shipped runner now calls every probe that needs only the project root.
It prints one fixed row per probe and the summary line.
The fixtures grade those rows instead of the prose around them.

## Requirement

`/gate-check` runs every project-root-only probe through one shipped runner with a fixed, documented row grammar, and smoke fixtures 3c, 9a, 9b, 2a and 2c grade probe rows in that grammar instead of rendered prose.

## Acceptance Criteria

- AC-STE-756.1: A new module `adapters/_shared/src/gate_probe_runner.ts` with an `import.meta.main` entry, run as `bun gate_probe_runner.ts <projectRoot>`, calls the existing exported function of every probe whose `/gate-check` registration calls it with `projectRoot` as its only argument. It adds no probe semantics: each row comes from that function's own return value.
- AC-STE-756.2: The row grammar is defined once, in `adapters/_shared/src/gate_probe_rows.ts` (`renderProbeRow` and `parseProbeRows`): `probe #<N> <probe-id>: <verdict> (<count>)`, where `<verdict>` is one of `pass`, `notes`, `fail`, `vacuous` and `<count>` is the probe's violation count. The runner prints one row per probe in registration order, then the summary line `conformance-probes pass: <P>/<T> [<active> active, <vacuous> vacuous]`.
- AC-STE-756.3: The verdict is derived, never chosen. Zero violations gives `pass`, or `vacuous` when the probe's report says it was vacuous, unless the report carries a non-empty `notes` or `warnings` list: then it gives `notes (<n>)`, counting those entries, and never `pass` or `fail`. This holds for a vacuous report too, except for a probe whose runner entry declares that its notes explain its own vacuity (#62), which stays `vacuous`. A per-violation severity other than `error`, `warning` or `note` gives `fail`. Violations give `notes` when the probe's severity is warning or note, and `fail` when it is error. A report that carries its own `severity` field decides with that field, and violations that carry their own severity decide by row: any `error` row gives `fail`, otherwise `notes`. The declared severity table equals each registration's `Severity:` text, pinned by a test.
- AC-STE-756.4: A probe that throws renders `probe #<N> <probe-id>: fail (error: <one-line message>)`, and the runner continues with the next probe. The runner exits 1 when any row is `fail`, else 0.
- AC-STE-756.5: A test reads the numbered registrations in `skills/gate-check/SKILL.md` and asserts that the runner's probe set equals the set of registrations whose call takes `projectRoot` as its only argument, read from the call shape `fn(projectRoot)` wherever it appears in the registration and not from the verb before it. Each entry's function is the one its registration names, with a named allowlist for the #61 and #67 wrappers. A registration added later without a runner entry fails the suite and names the probe.
- AC-STE-756.6: `skills/gate-check/SKILL.md` documents the row grammar once and tells the model to run the runner and quote its rows verbatim. Probes the runner does not call (tracker and MCP probes such as #8, #14 and #26, and the prose-defined probes) are rendered by the model in the same grammar.
- AC-STE-756.7: `capability_row_assert.ts` gains a `probe-row <capture> <N> <verdict>…` expectation. For a probe the runner calls, it reads rows only from the `tool_result` of a Bash call whose command runs `gate_probe_runner.ts`. For any other probe, it reads rows in the same grammar from the assistant text. It exits 0 when probe #N's parsed verdict is one of the listed verdicts, and it never matches free prose.
- AC-STE-756.8: Smoke fixtures 3c (#37 `notes`), 9a (#13 `fail`), 9b (#73 `fail`), their controls (`pass` or `vacuous`), and 2a and 2c (#26) assert with `probe-row`. The literal wording arms (`NOTES`, `GATE PASSED WITH NOTES`, `error-severity`) are removed from those clauses.
- AC-STE-756.9: Falsifiability tests on committed capture fixtures: a capture whose runner row gives #37 `notes` passes 3c whatever the prose says (`NOTE`, `Warning`, `note #37`); a capture whose #37 row is `pass` fails; a capture that says `NOTES` in prose but carries no runner row fails.
- AC-STE-756.10: Probe #81 (`module_reachability`) stays green. If the runner's imports move its pinned count, the pin is lowered in the same change with the reason stated.
- AC-STE-756.11: `bun test` from `plugins/dev-process-toolkit` reports 0 failures, and its skip identities equal the baseline by name.

## Technical Design

`gate_probe_rows.ts` holds the grammar, the regex and the verdict rule. `gate_probe_runner.ts` holds a table of `{ n, id, severity, run }` entries, one per project-root-only registration, imported statically so probe #81 sees the edges. Reports are normalised by a small adapter that reads `violations`, `vacuous` and `severity`. The completeness test parses the SKILL registration lines with the same pattern the review used.

## Testing

Unit tests for the grammar, the verdict rule and the throw path. A completeness test against the SKILL registry. Capture fixtures for `probe-row` in both directions.
