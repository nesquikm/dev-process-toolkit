# Ship-ready milestone nudge: active-plan gate probe + /implement close offer

## Summary

Milestones whose feature work is finished can quietly linger unshipped. The existing gate probe only catches an unshipped milestone after its plan is archived, and the existing ship offer only fires on milestone-scoped implement runs. This change closes the pre-archive gap: the gate now names every active milestone whose features are all done but which was never closed and shipped, and implement runs that archive the last remaining feature of a milestone now offer the close ceremony on the spot. The nag is advisory and the ceremony stays human-approved end to end.

## Requirement

Extend ship-milestone encouragement to the pre-archive state. A single shared predicate decides "ship-ready" (active plan, zero active FRs bound, at least one archived FR bound); the gate renders it as a warning note, and `/implement`'s FR-form runs consume the same predicate to offer the close ceremony when the last FR of a milestone archives. No auto-chaining; decline paths print the exact commands.

## Technical Design

Single-predicate reuse is the load-bearing choice — the probe and `/implement` consume one exported function, so the two surfaces cannot drift (the M116 producer/consumer-asymmetry lesson). The probe follows the STE-369 module shape (violations/notes arrays, NFR-10 canonical message shape, `note` as `<file>:<line> — <reason>`); FR-to-milestone binding is read from FR frontmatter `milestone:` tokens across `specs/frs/*.md` (active) and `specs/frs/archive/*.md` (archived), reusing the frontmatter reader idiom (CRLF/BOM-normalized). Prose pinning follows the STE-370 meta-test pattern (grep pins + negative assertions). The `/implement` offer generalizes the STE-75 M-form end-of-loop offer to per-FR-archival detection; both offers route through the same predicate output so a run that is both M-form and last-FR emits exactly one offer.
