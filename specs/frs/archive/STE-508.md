# The test-count parser reports skipped tests

## Summary

The parser that reads a test run reports a total, failures and errors. It has no concept of a skipped test, so every consumer downstream is structurally unable to distinguish a suite that passed from a suite that mostly did not run. That is the first missing piece of knowing whether anything is actually green.

## Requirement

The parser reports skipped counts per stack.

## Acceptance Criteria

- AC-STE-508.1: `TestCount` gains a `skipped` field.
- AC-STE-508.2: Each of the bun, pytest and flutter branches parses its own skip counter.
- AC-STE-508.3: Skip parsing uses last-match anchoring on the summary line, so per-file counters cannot shadow the total — the same defect class already fixed once for pass and fail.
- AC-STE-508.4: A runner emitting no skip counter reports zero skipped, and that is distinguishable from a parse failure.
- AC-STE-508.5: The unknown-stack fallback is unchanged.
- AC-STE-508.6: Existing three-field consumers are unaffected.

## Technical Design

`adapters/_shared/src/test_count_parser.ts` models `{ total, failures, errors }` and dispatches on `bun | pytest | flutter | unknown`. Adding `skipped` is a fourth field on that shape and one extractor per stack branch.

AC.3 is the criterion that stops this FR reintroducing a bug the file already carries a fix for. STE-323's comment in that module records it: Bun "emits per-file `N pass` / `N fail` counters BEFORE the summary block in multi-file runs, so a `.exec()` first-match captures the first per-file count rather than the total", and the fix was last-match via `matchAll`. A skip extractor written with `.exec()` would land the exact same defect in a new field, and the existing `lastCountedMatch` helper is hoisted precisely so a new counter can share it.

AC.4 matters because zero-skipped and could-not-parse must not collapse into the same value. STE-509's ratchet compares against a baseline, and a parse failure silently read as zero is a fail-open — the guard shape this milestone exists to prevent. The parse-failure path already has its own `{ ok: false, reason }` shape; the skip field must not route around it.

AC.6 is the compatibility clause. The shipped consumer is `/ship-milestone`'s CHANGELOG closing line, which reads three fields; adding a fourth must not change what it renders.

## Testing

Per-stack fixtures with real runner output carrying skipped tests, asserting the parsed count. AC.3 asserted with multi-file output where a per-file skip counter precedes the summary — the first-match implementation must go RED on that fixture, which is the mutation that proves the clause is about the right subject. Zero-skip output asserted to yield zero, and unparseable output asserted to yield the parse-failure shape rather than zero. Unknown-stack fallback and the existing three-field consumer both asserted unchanged. `bun test` full root.

## Notes

The module's own history is the specification for AC.3: the anchoring bug was found once, in this file, for the counters that already existed. A new counter written the naive way reproduces it.

## Implementation notes

- flutter skip regex was unanchored — a `~<digits>` fragment in trailing stderr won last-match over the real counter (a true `~2` parsed as 3); anchored to the progress-line shape in a scoped RED->GREEN round. Same defect class AC.3 guards, one layer out.
- `parseFlutter`'s FAILURE extractor is still first-match `.exec` while the new skip extractor on the same progress line is last-match anchored. Pre-existing and pinned by AC-STE-323.5; the anchoring lesson applies to it too. Follow-up FR, not a scope grab.
- `total`'s relation to skips differs per stack — bun's `Ran N` includes them, pytest and flutter exclude them. No AC covers it; left as-is because folding either way would change /ship-milestone's CHANGELOG closing line, which AC.6 requires byte-identical.
- `docs/ship-milestone-reference.md` carries a second verbatim copy of the closing-line template that AC.6's pins never read.
