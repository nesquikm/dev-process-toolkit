# The legs-selector spawn test keeps its stub legs alive until the fence counts them

## Summary

A test runs the smoke-loop spawn block with fake child programs.
The fakes exit at once, so each leg ends within milliseconds.
The spawn block then counts its live legs, finds none, and cleans up.
The test reads no leg records and fails on a fast machine.
Trunk has two red tests from this race.
The fix keeps each fake leg alive until the count has run.

## Requirement

### Steps to reproduce

1. On trunk, from the plugin directory, run `bun test tests/m121-ste-447-legs-selector.test.ts`.
2. Run the Phase A spawn fence of `.claude/skills/conformance-loop/SKILL.md` under `bash -c` with `claude` and `bun` stubbed by scripts that exit 0 at once, and `SELECTED_LEGS="linear jira none"`.

### Expected

Both legs-selector tests pass. The fence prints `launched=3 live=3`, writes a pidfile for every selected leg and keeps it.

### Actual

`REACHABILITY ANCHOR: the full selection opens a log and a pidfile for every leg` and `a two-leg selection spawns exactly those two` fail with pids `[]`. The fence prints `launched=3 live=0`, takes its abort branch and deletes every pidfile, in 3 of 3 runs.

Observed on 2026-11-04: clean trunk ran 20168 pass, 16 skip, 2 fail, and both fails are these two tests.

## Acceptance Criteria

- AC-STE-727.1: Regression: `tests/m121-ste-447-legs-selector.test.ts › REACHABILITY ANCHOR: the full selection opens a log and a pidfile for every leg` and `› a two-leg selection spawns exactly those two` fail on trunk on the measuring machine and pass after the fix.
- AC-STE-727.2: The test's `claude` stub stays alive until the test releases it, and the test releases it only after the fence has printed its `launched=` count line. The stub exits by itself after a bounded wait of at most 10 s, so a fence that aborts before the release cannot hang the suite.
- AC-STE-727.3: Every `runSpawnFence` case asserts that the fence printed `launched=<k> live=<k>` for its own selection size `<k>`, so a stub that dies early fails with the count line named rather than as an empty pidfile list.
- AC-STE-727.4: The fence and its live-count are unchanged: the milestone diff does not touch `.claude/skills/conformance-loop/SKILL.md`.
- AC-STE-727.5: Mutation control: making the stub exit at once again (no release gate) turns the AC .1 tests red on the measuring machine, with the AC .3 count assertion naming `live=0`.
- AC-STE-727.6: `bun test` from `plugins/dev-process-toolkit` reports 0 failures, and its skip identities equal the trunk baseline by name.

## Technical Design

### Root cause

The fence counts live legs right after the last launch, then aborts and deletes every pidfile when fewer are alive than were launched. Real legs run for minutes, so the count is sound. The test's stubs exit at once, so every leg is gone before the count. Its `ps` calls cost tens of milliseconds, and a machine change made the race lose every time.

The fix is in the test only. The `claude` stub polls for a release file with a bounded wait. The test script touches that file after the fence returns and before `wait`.

## Testing

Run the legs-selector file before and after the change, plus the mutation control. The full suite then proves no other test moved.
