# A two-root fixture, and a written acceptance of the smoke-leg gap

## Summary

Cross-repository behaviour has no shared test shape, so each consumer would invent its own two-directory setup and test the same thing three ways.
One fixture now builds two real repository roots with plans and bound work.
A five-state test proves each state gives a different answer.
No conformance leg drives two roots; the plan records that gap in writing, with the command that measures what closing it would cost.

## Requirement

A shared test helper must build two real roots, a falsifiable five-state test must run over the ship-ready predicate on them, and the milestone plan must carry a dated, re-derivable written acceptance that no smoke leg covers cross-repository behaviour.

## Technical Design

The helper sits beside the other shared test helpers as a leading-underscore module, so it is never collected as a suite. Two `mkdtempSync` roots each get `specs/plan/` and `specs/frs/archive/`; `planA` and `planB` write tracker-mode plans with no `id:` key. Real directories matter because `defaultRepoProbe().locate` requires `existsSync` and `isDirectory`. Teardown runs both `rmSync` calls in a `finally`. Every root comparison goes through `realpathSync`, since macOS `mkdtempSync` returns a `/var/…` path that resolves to `/private/var/…`. The acceptance test reads the plan from both the live and the archive path, so archiving the milestone cannot red it.

## Implementation notes

- Deviation from RED→GREEN, recorded rather than halted: every AC was GREEN on arrival (26/26). The brief deliberately built the two-root fixture inside STE-583 as its first consumer, STE-584 shipped the ship-ready logic it grades, and the plan's `### Accepted gaps` section pre-dated this suite — so this FR's deliverable is a set of pins, and no test could fail first. Formally that is TDD failure mode A (false RED); here it is the honest result of that sequencing.
- What stands in for RED — proof each pin can fail: AC.2 asserts the states DIFFER (busy ≠ clear, unlocatable notes ≠ clear notes, undeclared ≠ busy), with "undeclared" built on a tree whose sibling is busy so the declaration is the only difference; it deliberately does not assert five distinct answers, because clear and undeclared rightly agree. AC.4, AC.6/AC.7 and AC.8 each carry in-file negative controls that red the checker on a mutated input.
- Known: AC.4's `>= 3` count includes this very suite (STE-583, STE-584, STE-587); a "defined in exactly one file" check and a count-of-2 negative control keep it falsifiable.
- Known, unpinned by design: the plan's stated `grep -rlE` output (33 files, measured at v2.81.0) now prints 34, because this suite itself matches the roster. No test pins the number — which is why the brief forbade pinning it.
- Drift, corrected at archive: the plan's verify line said each state's answer differs from its neighbour's, and this AC's lead-in says five states give five answers. Both overclaim — a clear sibling and an undeclared one rightly give the same answer. The suite asserts the three differences that exist; the plan line now says so.
- Advisory, open (audit): the fixture's own unhappy paths are unpinned — cleanup continuing to the second root when removing the first throws, and the factory removing the first root when creating the second fails. The one-definition check matches only a `function` declaration, so a `const` duplicate would slip past it.
