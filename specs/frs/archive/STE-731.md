# Lock commits carry only the lock

## Summary

A lock claim or release commits every file that happens to be staged, not just the lock.
A refused feature commit followed by a release therefore lands feature code under a lock subject, with no gate.
Archiving a spec in a tracker-less project commits the staged move early, on trunk.
Each lock commit now carries only the lock files, and anything else staged stays staged.
Archiving releases the lock only after the archive commit.

## Requirement

The three local lock commits (claim, release, stale-lock cleanup) record exactly their own lock paths and leave every other staged change staged and unchanged; spec archival releases locks only after its archive commit.

## Acceptance Criteria

- AC-STE-731.1: `LocalProvider.claimLock`, `releaseLock` and `cleanupStaleLocks` each create a commit whose changed paths (`git diff-tree --no-commit-id --name-only -r HEAD`) are exactly that call's lock paths, whatever else is staged when it runs.
- AC-STE-731.2: Every path staged before the call that is not one of its lock paths is still staged afterwards, with the same index blob and mode, and appears in no commit the call created. This holds for an added, a modified, a deleted and a renamed foreign path.
- AC-STE-731.3: A lock commit that git or a hook rejects rolls back only the lock paths, as today; foreign staged paths stay staged and unchanged, and the call still throws.
- AC-STE-731.4: A new `adapters/_shared/src/lock.ts` front door runs `claim <projectRoot> <id> <branch>` and `release <projectRoot> <id>` through `LocalProvider`, prints the new commit's sha, and refuses any other argv in the NFR-10 shape. `docs/implement-reference.md` names it as the tracker-less lock route instead of a hand-written `git rm` and `git commit`.
- AC-STE-731.5: `/spec-archive`'s single-FR and milestone procedures order the branch gate, then the single archive commit, then each `Provider.releaseLock`; no lock is released before the archive commit. The edit lands in place in `skills/spec-archive/SKILL.md` and a test pins the order.
- AC-STE-731.6: Twin tests drive each of the three methods once with a foreign staged file and once without; they differ only in that file, and only the twin with the foreign file proves AC .1 and .2 on it.
- AC-STE-731.7: Removing the path limit from any one of the three commits turns at least one named test red.
- AC-STE-731.8: Existing lock suites stay green except for named amendments carrying `Amended by` markers.

## Technical Design

All three commits gain `--only -- <lockPath…>`, so git commits only those paths from the index and keeps the rest staged. The rollback arms already restore only lock paths. The new CLI is a thin wrapper around the provider, so skills stop hand-rolling lock commits. The archive skill's step list moves the release after the commit.

## Testing

Temporary git repositories with fake ids, foreign files staged in four shapes, assertions read from git plumbing; a pin over the archive skill's step order; mutation rows over the three pathspecs.

## Notes

Origin: a field report where a refused feature commit was swept into the lock release. Tracker mode is unaffected: there the release is a ticket transition, not a commit.
