# The tracker gate reads the target of every graph link

## Summary

A graph link joins a Jira ticket to another item.
The write gate checked the other item only for two known link types.
A link of an unknown type could name a ticket of another repository.
Such a link is now refused in a shared project.
Links to goals, projects and web pages still work.

## Requirement

In a repository that declares a shared Jira target, every graph link is either of a relationship type the gate can place or refused.

## Acceptance Criteria

- AC-STE-870.1: In a declared container, `addTeamworkGraphContext` whose `relationshipType` is unknown, missing, empty, not a string, or a known type in another case or with surrounding space is refused through the `.sh` wrapper, even when the object side is owned. The refusal names the type and lists the known types.
- AC-STE-870.2: The two item-to-item types check both sides exactly as today: an owned pair permits, and a pair with no owned side or an unresolvable side refuses.
- AC-STE-870.3: The three known types whose target is not a Jira item (remote link, Atlassian project, Atlassian goal) permit with an owned object side whatever the target's text, and refuse with an unowned one.
- AC-STE-870.4: The v2 `addGraphContext` keeps every verdict it has in v3.10.0, direct and wrapped.
- AC-STE-870.5: The live grader gives the hook's verdict on each payload above, and one shared constant holds the known types: the hook, the grader and the translator carry no second copy.
- AC-STE-870.6: With no declared target the hook exits 0 with no stdout and no stderr for the same payloads.
- AC-STE-870.7: Removing the unknown-type refusal from the hook, or from the grader, turns at least one named test red.
- AC-STE-870.8: `bun test` from `plugins/dev-process-toolkit` reports 0 failures, and its skip identities equal the trunk baseline by name.

## Technical Design

The relationship types move to `atlassian_call.ts` as two exported sets: item targets and other targets. The translator marks `relationshipType` as unplaced on a v1 call whose type is in neither set, the route v2 already uses, so the hook and the grader refuse it through the unplaced path they share. If the hook bundle cannot import the module, follow the import path v3.10.0 uses for the translator.

## Testing

Permit and refuse legs through the `.sh` wrapper, grader twins on the same records, and existing STE-649 suites pass unmodified.

## Notes

Known gap recorded in STE-649; found again by the M_b054b1 review. Any future relationship type is refused until it is listed.

## Implementation notes

- A v2 addGraphContext with a real non-item type is refused with the text 'is not a known type' and lists only the two item types — Verdict unchanged from v3.10.0 (AC-STE-870.4); only the refusal text now names the types the tool accepts
