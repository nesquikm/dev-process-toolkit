# Probe #30 grades the bootstrap commit, not a merge that quotes it

## Summary

The bootstrap commit check found its commit by searching the whole commit message.
A merge commit whose body quotes the bootstrap subject is newer than the real commit.
The check then graded the merge and failed a correct project.
It now grades only a commit whose own subject is the bootstrap subject.
Merge commits are never graded.

## Requirement

Probe #30 grades the most recent non-merge commit whose subject starts with the bootstrap prefix, and never a commit that matches the prefix only in its body.

## Acceptance Criteria

- AC-STE-873.1: The probe selects the most recent non-merge commit whose subject starts with `chore: bootstrap dev-process-toolkit`. A commit whose subject does not start with the prefix is never graded, whatever its body says.
- AC-STE-873.2: Regression: in a fixture repository holding a canonical bootstrap commit and a newer merge commit whose body is the line `chore: bootstrap dev-process-toolkit`, the probe reports zero violations. On the code before the fix it reports the merge's subject.
- AC-STE-873.3: A repository whose only match for the prefix is in a commit body is vacuous: zero violations.
- AC-STE-873.4: Unchanged: a non-canonical bootstrap subject, such as one with a parenthesised suffix, still fails; the `Toolkit:` footer rules and the ship-date carve-out still apply to the selected commit.
- AC-STE-873.5: `bun test` from `plugins/dev-process-toolkit` reports 0 failures, and its skip identities equal the trunk baseline by name.

## Technical Design

Root cause: `gitLog` in `setup_bootstrap_commit_subject.ts` runs `git log -n 1 --grep=…`, and `--grep` matches every line of the message, so the newest body match wins. The fix adds `--no-merges`, drops `-n 1`, and selects the first record whose `%s` starts with the prefix. Records stay NUL-separated, with a record separator so bodies cannot run together. The rest of the probe reads the selected record unchanged.

## Testing

Real git fixtures in a temp directory: a bootstrap commit, then a `git merge --no-ff` whose message body carries the prefix; a body-only repository; and the existing suffix and footer cases.

## Notes

From a v3.11.0 consumer report: the consumer worked around it with an empty commit that re-records the subject.

## Implementation notes

- A raw 0x1e byte inside a commit body splits that commit's record, so a malformed Toolkit: line after the byte is not graded — no crash and no wrong selection; git messages carrying a record-separator byte are not a shape any bootstrap commit has
- The gate-check skill's probe #30 entry still says the probe scans the most recent bootstrap commit, without the non-merge and subject-only rules — four suites freeze that file line by line; admitting the edit is its own change and is listed as a follow-up
