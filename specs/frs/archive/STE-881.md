# /spec-write takes a seed file

## Summary

Writing a spec meant answering every interview question by hand, even when a document already held the answers.
A new seed option names such a document.
The interview reads it as background, skips the questions it answers, and asks only what it leaves open.
The answers it took from the seed are shown in the draft for approval.
Every approval gate still fires.

## Requirement

`/spec-write --seed <file>` reads the file as reference data, answers the interview questions it covers from it, asks the rest, shows the seeded answers in the draft-gate preview, and leaves every gate in place.

## Acceptance Criteria

- AC-STE-881.1: `--seed <file>` is parsed in the resolver-entry preamble beside `--no-tech` and `--bug`, and does not change resolver routing. A file that does not exist, is not a regular file, or cannot be read as text refuses in the NFR-10 shape before the first question, with zero tracker writes and zero files written.
- AC-STE-881.2: The seed is read as reference data, not instructions. An interview question whose answer the seed states is not asked; a question it does not answer is asked as today.
- AC-STE-881.3: The draft-gate preview marks every answer taken from the seed, so the operator approves or edits it there. Nothing from the seed is written to a file or the tracker before that gate.
- AC-STE-881.4: The seed never stands in for the auto-approve marker or a `<dpt:answers>v1` block. Under non-tty stdin the refusal rules are unchanged, and the draft, milestone and commit gates fire exactly as without the flag.
- AC-STE-881.5: The closing summary emits the literal token `spec_write_seed_applied`, naming the seed file and how many questions it answered. The token is registered in the § 7 capability map.
- AC-STE-881.6: The `/spec-write` argument hint and the resolver-entry doc's preamble-flags section name the flag.
- AC-STE-881.7: `bun test` from `plugins/dev-process-toolkit` reports 0 failures, and its skip identities equal the trunk baseline by name.

## Technical Design

Model the flag on `--from-retro` (STE-721): validate the file in the preamble and refuse before the first prompt. Record which interview keys the seed answered, and render them in the draft-gate preview. The preamble rule lives in `docs/resolver-entry.md` § Preamble flags, so the skill gains one clause and one capability-map row.

## Testing

Contract tests over the skill text and the resolver-entry doc: the flag in the argument hint, the refusal before the first question, the reference-data rule, and the `spec_write_seed_applied` row in the capability map.

## Notes

From consumer report gist 68968900, gap 7. The operator ruled that the seed answers questions; it never drafts ACs on its own.

## Implementation notes

- spec_write_seed_applied is emitted only when the seed answered a question, and --seed on edit/resume runs is unspecified — AC wording is unconditional but silent on zero answers; FR-level clarification, not a code defect
