# Recorder contract with footage and command recorders

## Summary

Every demo clip arrives in one shape: a video file plus a list of named moments.
Projects with their own footage map each shot to a committed clip.
Projects with an unusual app plug in any program that records a shot and writes those two files.
A checker confirms each clip before the edit uses it.
The contract is written down so a project can build its own recorder without reading toolkit code.

## Requirement

- **Contract.** A recorder receives a shot `{ id, scenario, durationHint }` and must produce `clips/<id>.mp4` and `markers/<id>.json` (`[{ name, t }]`) in the video's work dir.
- **Validation.** The clip must be ffprobe-readable with a video stream; markers must be non-decreasing and within the clip's duration.
- **Footage.** `recorder.kind: footage` maps shot ids to files under `.dpt/video/footage/` and transcodes each to the clip shape; markers come from the mapping, or default to empty.
- **Command.** `recorder.kind: command` runs `recorder.command` (an argv list) from the project root with `DPT_VIDEO_SHOT`, `DPT_VIDEO_SCENARIO`, `DPT_VIDEO_OUT_CLIP` and `DPT_VIDEO_OUT_MARKERS` set.
- **Per-shot override.** A shot may name its own recorder kind, overriding the project default.
- **Documentation.** `docs/video-recorders.md` states the contract and a minimal command recorder.

## Acceptance Criteria

- AC-STE-666.1: `validateRecording` accepts a fixture clip with markers, and refuses, naming the shot, a missing clip, a clip with no video stream, decreasing markers, and a marker past the clip's duration.
- AC-STE-666.2: The footage recorder transcodes the mapped file to `clips/<id>.mp4` and writes its markers; a shot with no mapping, or a mapping to a missing file, refuses naming the shot and the path.
- AC-STE-666.3: The command recorder runs the configured argv with cwd at the project root and the four environment variables set to the shot's values, asserted by a fixture command that echoes them into its output files.
- AC-STE-666.4: A command that exits non-zero, or exits zero without producing a valid recording, refuses naming the shot and quoting the last 20 lines of its stderr.
- AC-STE-666.5: A shot declaring `recorder: footage` in a project whose default is `command` is recorded by the footage recorder, and the others by the command recorder.
- AC-STE-666.6: `docs/video-recorders.md` names every environment variable and output file that AC-STE-666.3 asserts, checked by a test that reads the doc and the recorder's variable list from one exported constant.

## Technical Design

A recorder interface, a dispatcher keyed by kind with per-shot override, a validator using ffprobe through the shared spawner, and the two simplest recorders. The command recorder's variable names are one exported constant that both code and the doc test read.

## Testing

Fixture clips generated with ffmpeg lavfi; a fixture shell command; refusal fixtures per contract rule.

## Notes

Operator decision 2026-10-12: recorders are configured per project, with custom footage and a pluggable recorder.

## Implementation notes

- recordCommand spawns via Bun.spawn with no timeout and bypasses the injectable Runner; a hung recorder blocks the run — left open after the operator-approved third fix round; not an AC failure
- footage mapping file path is joined without containment — a ../ path can escape .dpt/video/footage/ — left open after the operator-approved third fix round; not an AC failure
- recordFootage never validates its transcoded output, so mapped markers past the clip end are written unchecked — left open after the operator-approved third fix round; not an AC failure
- recordShot's fallback refusal for a per-shot ios-sim/android-emu override under another config kind lists only footage/web/command — left open after the operator-approved third fix round; not an AC failure
