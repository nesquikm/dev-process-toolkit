# Bind the capture-equivalence guard to its own run — basename identification lets it compare across runs

## Summary

A committed reproducer is checked against the full capture it was derived from, and the block guards itself by asking whether that capture is present on disk. It finds the capture by basename alone.

The basename is run agnostic. Every conformance run writes exactly the same path, so any later run's capture is accepted as the artifact the fixture was derived from, and the equivalence assertion then compares two unrelated runs.

Observed live on 2026-08-09: the 2026-08-08 run's captures were sitting in the search path, the block treated them as the 2026-07-27 artifact, and three assertions failed against measurements taken from a different run. The gate had been red since the run finished and the failure had nothing to do with the work in flight.

The red is the harmless face of this bug. The dangerous face is the same misidentification reporting GREEN — a mismatched run whose scores happen to agree would satisfy every assertion while comparing against an artifact the fixture was never derived from, and nothing would ever say so.

## Requirement

Identify the capture by a property intrinsic to the run it came from rather than by its filename, so the equivalence block can never compare a derived fixture against an artifact from a different run — and prove the guard refuses the agreeing case, not merely the differing one.

## Technical Design

The failure is in how the artifact is found, not in what the block asserts. The search walks a directory list and takes the first path whose basename matches, and the basename encodes the leg and the skill but not the run. Two runs produce byte-different captures at identical paths.

Binding by an intrinsic property is sounder than binding by a renamed file, which only relocates a name that still is not unique.

**A fingerprint of the original was the obvious design and it is not available.** The full captures were 200–470 KB, were never committed by design, and no copy survives — every `spec-write-*-2026-07-27.log` on this machine is the small DERIVED fixture, not its source. A fingerprint of an unrecoverable artifact matches nothing forever, so shipping one would make the block skip permanently, which is exactly the vacuity AC.7 forbids. The AC that named it has been amended rather than satisfied by pretending the input exists.

Three intrinsic properties do the work without the original, and all three must hold:

- **Size floor, and it is NOT a new number.** The floor is the derived-fixture ceiling the sibling assertion in the same file already enforces — 32 KB. Reusing that constant is the whole point: a derived fixture can never clear the floor, because the assertion that caps it and the floor that excludes it are the same bound. Two independent magic numbers could drift apart; one cannot.

  **Provenance, measured rather than inherited.** The file's own comment claims the untracked sources "run 200 KB – 470 KB". That is wrong in both directions, measured across the eighteen captures of the 2026-08-08 run: the smallest is 46,057 bytes and the largest is 1,252,763. A floor of 200 KB taken from that comment would reject four genuine captures. The comment is corrected as part of this FR rather than left to mislead the next reader who reaches for a number.

  **Edges, stated so a later tidy-up cannot round them off.** Largest derived fixture 11,715 B; floor 32,768 B; smallest observed real capture 46,057 B. The margin below the floor is 2.8x and above it 1.4x — the upper margin is the tight one, and a genuinely small capture (a truncated or aborted run) can fall under the floor. When it does the candidate is REFUSED and the block skips with a distinct reason; it is never admitted on a guess. Fail-closed is the correct behaviour here: a skipped comparison costs coverage, an admitted wrong artifact costs correctness.

- **Self-compare refusal.** A candidate whose bytes equal the derived fixture's is refused.

  **This is the CANONICAL instance of the agreeing case, not one arbitrary example of it, and the distinction is why it leads.** The comparison scores token occurrences, so a file always scores identically to itself — the agreement is guaranteed by construction rather than arranged by coincidence. Every other agreeing artifact has to be contrived: you must find or build a different run whose scores happen to coincide across every key. This one needs no coincidence at all, and it is reachable by ordinary accident — anyone who copies a fixture to the capture path produces it. It is simultaneously the easiest agreeing input to reach and the most vacuous outcome available, since the assertion then compares a file with itself and reports equivalence while establishing nothing whatsoever. A later reader must not demote it to one case among several; it is the case the others are variations of.
- **Declared run.** An operator pointing the search at a preserved capture must also declare which run it came from, and the declaration must match the run the fixture records. A stray file cannot declare anything, so presence alone can never again qualify.

The first two are intrinsic and need no cooperation. The third is the only one a caller supplies, and it is additive — it can qualify an artifact the other two admit, never override them.

**There is no caller-supplied floor override, and its absence is load-bearing rather than an omission.** An earlier draft exposed one. The objection is not that it had no callers: the floor is the derived-fixture ceiling *because* a fixture can then never clear it, and that argument collapses the moment a caller may pass any number. A guarantee that a caller can widen is not a guarantee. The removal is pinned so it cannot return quietly.

The skip-reason split matters as much as the fingerprint. Collapsing wrong-run into absent would return the block to a permanently quiet state that looks like a clean checkout forever, which is how a guard stops guarding without anyone noticing.

## Testing

The load-bearing test is the agreeing case, because it is the one that would ship silently, and its lead input is the self-comparison described above: the derived fixture planted at the capture path. Under the current code that input reports GREEN while the assertion compares a file with itself. The guard must refuse it on IDENTITY, never on score — refusing it on score would be the same mistake one level down, since its score is correct.

A second agreeing input is also exercised, a distinct artifact contrived to score identically, so the repair is not proven only against the degenerate self-compare it most obviously catches.

Both directions are measured per the house rider: the agreeing input is GREEN under the form being replaced and refused under the form shipped. Without the first half the mutation cannot distinguish the two implementations.

The 2026-08-08 captures preserved in the operator's scratchpad are a real mismatched-run artifact and are the natural source for the differing case.

Full gate green from the plugin root.

## Notes

Interim already applied, and it is explicitly not the fix: the 2026-08-08 captures were MOVED out of the search path into the operator's scratchpad, preserved byte for byte, which returned the block to its documented artifact-absent skip. Moving the artifact does not repair the identification and the repair stays owed. The captures were deliberately not deleted, because they are the evidence that proves this defect exists.

## Implementation notes

Baseline owned before any edit: **6925 pass / 15 skip / 0 fail**, on a tree made honest by relocating the 2026-08-08 captures. Final: **6955 / 15 / 0**.

### The RED was a module-load failure, and that proved nothing

`Cannot find module` reddens a whole file as ONE error, so no assertion in the new test file had executed when the cycle reported RED. That is a weaker starting position than it looks and it was treated as such: falsifiability was established afterwards by mutation, not inferred from the red.

### Mutation matrix — 11 targeted, 11 accounted for

Nine against the module's decision points, two against the selection guard. Every mutation applied to the real file, asserted-applied by md5 BEFORE the test ran, restored with absolute paths and `cmp`-verified.

| mutation | RED |
|---|---|
| delete the self-compare identity branch | 6 |
| floor boundary `<` → `<=` | 1 |
| delete the size-floor check | 5 |
| delete the run-not-declared check | 4 |
| delete the declared-run mismatch check | 6 |
| swap: declared-run checked before the floor | 1 |
| skipLabel drops the machine reason | 4 |
| floor reads a private literal, not the constant | 1 |
| `runRecordedByFixture` drops its digit boundaries | 1 |
| selection guard accepts several matches | 1 |
| selection becomes positional (`entries[0]`) | 6 |

**The most useful row is the one that nearly didn't happen.** The scripted form of the swap mutation DID NOT APPLY — the pattern missed — and the only reason that was visible is the assert-applied md5 check. Without it the row would have read `0 RED`, and the conclusion drawn would have been "nothing depends on check order", from a mutation that never ran, minutes after adding the assertion whose entire purpose was to cover that case. A mutation that silently no-ops is indistinguishable from a fix that does nothing.

### What the post-completion stages found, after the work was believed done

**AUDIT** returned `missing_acs: []` with three Partials, and one was substantive rather than cosmetic: AC.4's test NAME claimed run-discrimination the code cannot deliver. Nothing intrinsic distinguishes runs and nothing can — the source artifact is gone — so the non-degenerate agreeing artifact is refused on the caller's declaration, and the identical bytes QUALIFY once the declaration matches. That residual is now an ASSERTED test rather than a described limitation, so a future change that makes a misdeclaration harmless turns it RED and forces this note to be rewritten.

It also found the check-order property only half pinned: swapping the floor and the declared run was invisible to all eighteen inputs the suite used, because every below-floor case supplied a matching declaration. The sole discriminator — below-floor AND undeclared — appeared nowhere.

**Pass 1 spec-compliance** flagged two behaviours with no AC behind them, wanting opposite treatments. `sizeFloor` was deleted: not because it lacked callers, but because the floor is the fixture ceiling BECAUSE a fixture can never clear it, and a caller free to pass any number voids that argument. The selection guard was authorized as AC.8 instead, because deleting it would have reintroduced a real defect.

**Pass 1 round 2 caught the FR itself lying.** AC.8 as authored said the guard was "pinned in both directions" — several-matches throws, table reversal stays green. Both claims came from one-off mutations run during REFACTOR: real measurements, ephemeral ones, written into an AC as though they were shipped coverage. Neither branch had a test. The claim was made true rather than softened: the selection moved into the module as a pure function so both branches are reachable, and both are now pinned and mutation-verified.

**Pass 2 code-quality** — never ran until both Pass 1 rounds closed, having been fail-fast skipped twice. It found `sameBytes` deep-copying both sides through `Buffer.from` on every identity check (candidates reach ~1.25 MB), and the subprocess harness re-running the entire subject file six times, leaking scratch dirs from an unrelated probe. Both fixed.

### Recorded, not fixed

The FR's test file restates the subject's `DERIVED` table by hand. A divergence reddens rather than passing silently (the case-count assertion catches it), so it is a second edit site rather than a correctness hole. `DPT_CAPTURE_RUN` is documented nowhere operator-facing; the skip label is its only discovery channel. Three sibling test files carry independent `32 * 1024` literals for a different fixture family, and two repeat the same class of wrong provenance this FR corrected.
