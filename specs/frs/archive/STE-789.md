# The conformance loop refuses a dirty tree before it spawns

## Summary

Each smoke-test leg refuses to run when the toolkit tree has uncommitted files.
The conformance loop did not check this itself.
So it passed its own checks, spawned three legs, and all three died.
One leg also wrote no verdict on that refusal, so its stale verdict was read.
The fix adds the same check to the loop before any spawn.
Every leg now writes a fresh fail verdict when it refuses this way.

## Requirement

`/conformance-loop` refuses a dirty toolkit tree before any spawn, and `/smoke-test` writes a fresh fail verdict artifact when its pre-flight #4 refuses.

## Acceptance Criteria

- AC-STE-789.1: `.claude/skills/conformance-loop/SKILL.md` adds a pre-flight that runs `git status --porcelain` at the toolkit root and refuses in the NFR-10 shape, naming the paths, when the output is not empty. It runs before pre-flight (c) and before any pidfile or log is written.
- AC-STE-789.2: The pre-flight section's refusal-anchor count is updated, and the existing test that recomputes it passes.
- AC-STE-789.3: `.claude/skills/smoke-test/SKILL.md` pre-flight #4 says its refusal writes the leg's verdict artifact with outcome `fail` before exiting, the same way the final-message self-check writes it.
- AC-STE-789.4: `bun test` from `plugins/dev-process-toolkit` reports 0 failures, and its skip identities equal the trunk baseline by name.

## Technical Design

Prose and a fenced probe in the project-local skills. The new pre-flight gets the next free letter, so no existing by-letter reference moves.

## Testing

Doc-conformance tests over both skill texts, plus the existing anchor-count test.

## Notes

Conformance run 2026-11-14, run 1 aborted at pre-flight 4 on six untracked files. These are maintainer-only skills, so consumers see no change.

## Implementation notes

- AC-STE-789.3's outcome assertion is loose: its regex also matches a later `fail` on the same line, so a plant changing the outcome to pass stayed green.
- smoke_verdict.ts emit with no trigger records `declared`, which the loop's rc-64 carve-out admits; safe while pre-flight #4 exits with a code other than 64.
