# STE-422: Pass projectRoot to the Phase 8 assert runner {#STE-422}

## Summary

The helper that judges first-turn behavior takes an optional project root and, when given one, ignores scaffold writes that land outside it. The bundled runner exposes that as a third argument and documents it in its own usage line. The driver's reference snippet calls the runner with two arguments.

Without the argument the helper is deliberately conservative and treats any out-of-project write as a violation. On this run two of the four in-scope skills flipped verdict on that single argument alone: one moved from violation to a structured refusal pass, the other from violation to vacuous.

Because a violation in this phase is specified to hard-fail the whole run, the documented command manufactures run-killing false alarms against skills that behaved correctly. This was recorded once already on an earlier run and the snippet was never updated, so it has now cost two runs.

## Requirement

The documented Phase 8 driver wrapper MUST invoke the assert runner with the project root, so the contract's verdict reflects in-project first-turn behavior rather than side effects inherited from the operator's global configuration.

Verified 2026-07-27 by reading both sides:

- `socratic_first_turn_assert.ts:64` destructures `const [skill, fixturePath, projectRoot] = process.argv.slice(2);` and its usage string at `:6` documents `[projectRoot]`.
- `.claude/skills/smoke-test/SKILL.md:1196` invokes `bun "${ASSERT_RUNNER}" "${SKILL}" "${FIXTURE}"` — two arguments.

Measured verdict flips on the Linear leg:

| skill | without projectRoot | with projectRoot |
|-------|--------------------|------------------|
| `brainstorm` | `violation Write@9` | `ok-refused@10` |
| `report-issue` | `violation Write@19` | `vacuous` |
| `setup` | `violation Edit@19` | `violation Edit@19` |
| `spec-write` | `ok-refused@13` | `ok-refused@13` |

The `setup` row is the control: it stays a violation either way, which is what confirms STE-419 is a genuine defect and not a scoping artifact.

## Acceptance Criteria

- AC-STE-422.1: The Phase 8 reference snippet in the smoke SKILL invokes the assert runner with the resolved test-project path as its third argument.
- AC-STE-422.2: A fixture asserts that `/brainstorm`'s recorded 2026-07-27 transcript scores `ok-refused` under the documented invocation, not `violation`.
- AC-STE-422.3: A fixture asserts that `/setup`'s recorded transcript still scores `violation` under the same invocation — the argument narrows scope without blunting the contract.
- AC-STE-422.4: A meta-test over the smoke SKILL asserts the documented invocation carries three arguments, so the snippet cannot silently regress to two.

## Technical Design

A one-line change to the reference snippet plus the meta-test that pins it. The snippet already has the resolved test-project path in scope as part of the per-tracker path construction, so no new derivation is needed.

The meta-test matters more than the fix: this exact defect was recorded on 2026-07-20 and lost. Pinning the argument count byte-wise is what stops a third occurrence.

## Testing

- Replay both recorded transcripts through the runner with and without the argument, asserting the four verdicts in the table above.
- Meta-test over `.claude/skills/smoke-test/SKILL.md` asserting the runner invocation includes a project-root argument.

## Notes

Interacts with STE-427: children inherit the operator's global instructions, which mandate an out-of-project write at the start of essentially every response. That is what makes the missing argument bite on nearly every Phase 8 child rather than occasionally. Fixing this FR removes the false alarms; STE-427 corrects the containment claim that made them surprising.
