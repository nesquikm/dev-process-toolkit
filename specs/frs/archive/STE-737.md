# API signature extraction finds a TypeScript project in a subfolder and names an unsupported Rust stack

## Summary

The API reference page comes out empty for a TypeScript project in a subfolder.
It is empty for a Rust project too.
Nothing says why the page is empty.
Extraction now finds a TypeScript project one folder down and reads it.
A Rust project gets a warning naming the stack, instead of a silent empty page.
Projects with a TypeScript config at the root work as before.

## Requirement

Signature extraction reads a TypeScript project one directory below the root when the root has none, and reports a Rust project as an unsupported stack by name; root-level projects behave as before.

## Acceptance Criteria

- AC-STE-737.1: When the project root has no `tsconfig.json`, `detectStacks` finds one in an immediate subdirectory, skipping `node_modules` and dot-directories. Extraction runs against that subdirectory, and module paths are reported relative to the project root. Two or more such subdirectories are all read, in name order.
- AC-STE-737.2: A `Cargo.toml` at the root or one level down, with no TypeScript, Dart or Python stack detected, returns `regex-fallback` with zero modules and a warning that names Rust and `Cargo.toml` and says no extractor covers it. `/docs --full` writes each of the extractor's warnings as a comment line under its existing regex-fallback banner; the step is edited in place in `skills/docs/SKILL.md`.
- AC-STE-737.3: A project with a root `tsconfig.json` gets the same strategy, modules and warnings as at v3.3.0.
- AC-STE-737.4: Fixtures cover each case; removing the subdirectory search or the Rust warning turns a named test red.

## Technical Design

Detection gains a one-level directory scan that runs only when the root check misses. The Rust case adds a warning string to the existing fallback.

## Testing

Temporary project trees with root and nested configs and a bare Cargo manifest, through the shipped extractor.

## Notes

Operator ruling 2026-11-10: no rustdoc extractor, because it needs a nightly toolchain.

## Implementation notes

- Advisory (left open): extractor warnings are written into an HTML comment without escaping `-->`; subfolder name order is code-unit order; only the first Cargo.toml is named; symlinked subfolders are followed.
