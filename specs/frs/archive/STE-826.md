# The spec-review audits state only tree facts they checked

## Summary

A spec review said a file had been deleted while the file was still on disk.
The read-only auditor stated a fact it never checked.
Review output is used as evidence, so an invented fact is a real defect.
Both spec auditors now cite the read behind any claim about a file.
The parent skill checks those claims again before it reports them.

## Requirement

The spec-review and TDD spec-review auditors back every file-existence claim with the tool call that observed it, and `/spec-review` re-checks those claims before it reports them.

## Acceptance Criteria

- AC-STE-826.1: `agents/spec-reviewer.md` says that a claim that a file exists, is absent, or was deleted names the Read or Glob call that observed it. A claim with no such call is left out.
- AC-STE-826.2: `agents/tdd-spec-reviewer.md` carries the same rule.
- AC-STE-826.3: `skills/spec-review/SKILL.md` re-checks each file-existence claim in the audit result against the tree before it renders the report. A contradicted claim is dropped, and the report says so in one line.
- AC-STE-826.4: `bun test` from `plugins/dev-process-toolkit` reports 0 failures, and its skip identities equal the baseline by name.

## Technical Design

Prose rules in two agent files and one skill step. The re-check is a Glob per claimed path.

## Testing

Contract tests read the three files.
