# A release refuses while its sibling still holds active work

## Summary

The release ceremony could stamp a two-repository milestone as shipped while the sibling repository still had work in flight.
It now refuses in that case, reading the same predicate that holds the milestone back everywhere else.
An explicit partial flag releases this repository's half now and records that the release was partial.
Every release of such a milestone carries one footer line per sibling, measured from the sibling's own plan and never typed.

## Requirement

`/ship-milestone` gains pre-flight refusal #4, a `--partial` escape that stamps `ship_partial: true` beside the ordinary `shipped_in:` scalar, and a `Spans:` commit footer. The refusal predicate is the ONE sibling predicate, `spanningSiblingState`: a sibling holding active FRs bound to the milestone. It is never "the sibling has not shipped", which would deadlock two repos that each wait for the other.

## Acceptance Criteria

- AC-STE-589.1: `adapters/_shared/src/sibling_release.ts` exports `siblingShipGate({ projectRoot, planBody, milestone, partial })`, which refuses exactly when `spanningSiblingState(...).busy` is non-empty and `partial` is false. The module imports `spanningSiblingState` and does not call `milestoneFrBinding` or walk an FR directory itself.
- AC-STE-589.2: The refusal is the NFR-10 three-line shape: the verdict names the milestone, the sibling, the active count and the FR ids; the Remedy names finishing those FRs and `--partial`; the Context line ends `skill=ship-milestone`.
- AC-STE-589.3: Degrade, never crash: an unlocatable sibling does not refuse, and the front door prints one stderr line per unlocatable sibling saying it was not checked — exit 0, so an all-unlocatable plan is never a silent pass, while a span whose siblings all locate prints no such line; an undeclared plan does not refuse and yields zero footer lines; a malformed declaration refuses with the reader's own refusal text.
- AC-STE-589.4: `--partial` on a plan that declares no `spans_repos:` refuses, since there is no second half to leave pending.
- AC-STE-589.5: Front door. `bun run adapters/_shared/src/sibling_release.ts <projectRoot> <planFile> <milestone> [--partial]` exits 1 with the refusal on stderr and empty stdout when refused, and otherwise exits 0 printing one `Spans: <name>@<value>` line per non-self entry. An unreadable `<planFile>` refuses in the same three-line house shape, exit 1, empty stdout. The test spawns it as a subprocess.
- AC-STE-589.6: The footer is measured: `<name>@v<X.Y.Z>` when the sibling plan, live or archived, carries a well-formed stamp; `<name>@pending` for absent, `null`, `""`, malformed, no plan, or unlocatable. One test rewrites the sibling's on-disk `shipped_in:` and observes `pending` change to the version.
- AC-STE-589.7: `skills/ship-milestone/SKILL.md`: the `## Pre-flight refusals` window holds a `4. **` block that runs the front door, names `--partial` as the only escape and says why the predicate is active FRs; line 4's `argument-hint` carries `[--partial]`; the commit template carries `Spans: <repo>@<version|pending>` between `Release:` and `Refs:`; the Footers bullet names three footers. `tests/ship-milestone-shape.test.ts` is unedited and green.
- AC-STE-589.8: With `--partial`, step 7 writes `shipped_in:` through the unchanged `stampShippedIn` plus `ship_partial: true` through a writer in `adapters/_shared/src/plan_ship_stamp.ts`; a second run is a no-op. Each of `plan_ship_coherence.ts`, `resume_classifier.ts` and `active_plan_ship_ready.ts` keeps its `STAMP_RE` definition byte-identical to main, and no module gains a second stamp-shaped regex. The measure is the definition, not an occurrence count: the sibling leg legitimately reuses the same regex.
- AC-STE-589.9: Not a deadlock. Two roots whose plans declare each other, both with zero active FRs and neither stamped: the gate refuses neither. Sibling busy: it refuses without `--partial` and passes with it. Both halves in one test.
- AC-STE-589.10: A plan stamped by the partial path, with its CHANGELOG heading, yields zero `corrupt_stamp` rows from probe #63, and the milestone-scope resume reads it as `shipped` with an empty chain.
- AC-STE-589.11: `templates/git-hooks/commit-msg.sh` exits 0 on a message whose footer carries `Spans: glacy-app-be@pending` and exits 1 on a 73-character subject.
- AC-STE-589.12: `docs/ship-milestone-reference.md` carries a refusal #4 decision matrix beside the refusal #1 matrix and lists five refusal verdicts; `docs/layout-reference.md` documents `ship_partial:` in the voice of its `--parked` line.
- AC-STE-589.13: `skills/ship-milestone/SKILL.md` measures at most 358 split-lines.

## Technical Design

`sibling_release.ts` gains the gate, the footer renderer and an `import.meta.main` front door, so the skill orders a command rather than a module and the reachability pin cannot rise. The footer reads each sibling plan through STE-588's union reader. `plan_ship_stamp.ts` gains an idempotent `ship_partial` writer beside `stampShippedIn`. Refusal #4 runs in the pre-flight block, before any write, and reads no tracker. The plan path is already in refusal #2's expected set, so the new key needs no second entry.

## Testing

New suite: gate and footer over `makeSpanFixture`, the front door spawned, the hook fixture run through `sh`.

## Notes

Rejected: decorating the `shipped_in:` value. Four modules read or build it, so a decoration would red the coherence probe, demote the resume state, re-arm the ship-ready nudge and trip the double-ship guard.

## Implementation notes

- Two in-place AC amendments, each confirmed at the commit gate by the orchestrating session. AC.5 gained the unreadable-plan clause: the front door refuses in the house three-line shape, exit 1, empty stdout. AC.8 now measures each `STAMP_RE` by its definition rather than by an occurrence count, because the sibling leg legitimately reuses the regex. Both were right in code and incomplete in the spec.

- Accepted, recorded: a refused front-door run returns an empty footer and prints no not-checked line for an unlocatable sibling. AC.3 permits it.
