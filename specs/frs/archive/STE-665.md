# Stage cache, edit list and renderer

## Summary

A video is assembled from an edit list that names clips, voice segments, captions and music.
Cuts can be pinned to a spoken word, so the picture changes on the right line.
The renderer turns that list into one ffmpeg run and refuses effects the project's style bans.
Every stage is cached by its inputs, so fixing one sentence re-voices only that sentence and re-renders.
A quality check then saves a still frame at each punchline for review.

## Requirement

- **Edit list.** `edl.json` (`edl_version: 1`) lists video clips with in and out points, voice segments, captions taken from alignment, music with its level, and named punchline anchors. Unknown fields refuse.
- **Anchor cuts.** A cut may reference `{ segment, word }` and resolves to that word's start time in the alignment.
- **Renderer.** A pure function builds the ffmpeg argument list from the edit list and style; the runner executes it and writes `final.mp4` in the work dir.
- **Banned effects.** An effect listed in `style.banned_effects` refuses before ffmpeg starts.
- **Stage cache.** Each stage's key is a SHA-256 over its inputs and a per-stage version; a manifest in the work dir records keys and outputs, and a stage whose key matches and whose outputs exist is skipped.
- **QA.** ffprobe confirms one video and one audio stream and a duration within 5% of the edit list total; one still per punchline anchor is written to `qa/`.

## Acceptance Criteria

- AC-STE-665.1: `parseEdl` accepts a valid fixture and refuses, naming the field, an unknown field, a clip whose out point precedes its in point, and an `edl_version` other than 1.
- AC-STE-665.2: A cut anchored at `{ segment: 2, word: 5 }` resolves to word 5's `start` in segment 2's alignment plus segment 2's offset; an anchor naming a missing segment or word refuses naming it.
- AC-STE-665.3: `buildFfmpegArgs(edl, style)` is pure: the same inputs give byte-identical argument lists, pinned by snapshot fixtures for a clips-only, a voice + captions and a music-at-level edit list.
- AC-STE-665.4: An edit list requesting `zoompan` refuses before ffmpeg runs when `banned_effects` holds `slow_zoom` or `ken_burns`, asserted by an injected runner that records no call.
- AC-STE-665.5: After one full run, changing the text of segment 2 of 3 re-runs the TTS stage for segment 2 only and the render stage, and skips every other stage, asserted from the manifest and a stage-call recorder.
- AC-STE-665.6: Deleting a cached output file re-runs that stage even though its key matches.
- AC-STE-665.7: When ffmpeg or ffprobe is not on `PATH`, the render refuses in the NFR-10 shape naming the binary and an install remedy, before any stage runs.
- AC-STE-665.8: A real render of a two-second lavfi fixture (test pattern + sine) produces a `final.mp4` that the QA step accepts, and writes one still per punchline anchor into `qa/`; a fixture whose duration differs from the edit list by more than 5% fails QA naming both durations.
- AC-STE-665.9: Mutation-verified: removing the banned-effect check turns AC-STE-665.4 red, and hashing without the segment text turns AC-STE-665.5 red.

## Technical Design

Edit-list schema, anchor resolver, argument builder and cache manifest are pure modules; one runner shells out to ffmpeg and ffprobe through an injected spawner. Banned effects map to filter names in one table. The cache reuses the SHA-256-over-named-inputs approach already used for bundle hashing.

## Testing

Snapshot fixtures for the argument builder; recorder-based cache tests; one real ffmpeg render of a generated fixture, since ffmpeg is a gate-machine prerequisite.

## Notes

Operator style lesson: no slow zooms or Ken Burns, and check the picture at every punchline.
