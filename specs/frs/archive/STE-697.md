# An interactively approved spec commit passes the post-hoc drift probe

## Summary

The gate fails a branch whose newest commit is a spec commit approved by hand.
The drift probe reads only that commit and expects one of two markers.
Only the headless path writes those markers.
Every delivery run sits on such a commit before the build starts.
Now the spec writer records the approval, and the probe accepts it.

## Requirement

### Steps to reproduce

1. In a temporary git repository, commit `chore(specs): write FR STE-900` with a body that says why the FR exists and carries a `Refs: STE-900` footer.
2. Run the `socratic_first_turn_post_hoc_drift` probe against that repository.

### Expected

An approved interactive spec commit passes the probe, and a headless commit with no marker still fails it.

### Actual

The probe reports `socratic_first_turn_post_hoc_drift_violation`. The interactive commit carries no marker because nothing writes one on that path.

## Acceptance Criteria

- AC-STE-697.1: Regression: `tests/m_46b121-STE-697-operator-approved-spec-commit.test.ts › a spec commit carrying the operator-approval marker passes the probe` fails before the fix and passes after it.
- AC-STE-697.2: The probe accepts `spec_write_commit_operator_approved` in the commit body as a third legitimacy marker beside the two default-applied markers.
- AC-STE-697.3: Refusal twin: the same commit with no marker in its body still reports the violation, and the marker in the subject line alone does not count.
- AC-STE-697.4: The /spec-write commit gate writes the line `spec_write_commit_operator_approved` into the spec commit body when the operator answers `y` interactively, and writes it on no other path: not on the default-applied path, not on a decline.
- AC-STE-697.5: The probe's violation message and remedy name all three markers.
- AC-STE-697.6: Removing the third marker from the probe reddens the regression test, and removing the instruction from the /spec-write commit gate reddens a named prose pin.
- AC-STE-697.7: `bun test` from `plugins/dev-process-toolkit` reports 0 failures, and its skip identities equal the trunk baseline by name.

## Technical Design

### Root cause

`inspectCommit` accepts only the two default-applied capability markers or a refusal block. The interactive yes at the /spec-write commit gate writes neither, so the probe cannot tell an approved commit from the headless silent-commit shape it guards.

The fix adds one marker to the accepted list and one instruction at the commit gate's interactive yes branch.

## Testing

Pure-function tests over subject and body pairs, plus one temporary-repository test through the probe entry point. A prose pin covers the commit-gate instruction.

## Notes

Origin: a maintainer follow-up from shipping v2.101.1. Like the existing markers, the new one is text the model writes, so it is as strong as they are and no stronger.
