# Offer to commit the house video style and tooling

## Summary

A project's video style and recording tooling only help a team when they are committed.
Today nothing tells the developer that these files are still uncommitted after a video is made.
After the developer approves the final cut, the video skill now lists those files and offers to commit them.
The default answer is no, and the offer never pushes.
A warning-only gate check also reports the same uncommitted files.

## Requirement

- **Lister.** A pure function lists every untracked, modified, renamed or deleted path under `.dpt/video/`, except `.dpt/video/work/`. It never lists `.dpt/.env` or any path outside `.dpt/video/`.
- **Front door.** A command prints the list. With a commit flag it stages exactly the listed paths and commits them. It never pushes.
  - A staged path under `.dpt/video/`, other than `.dpt/video/work/`, is never outside the list. The old side of a rename inside `.dpt/video/` belongs in the same commit.
  - When git fails, or the commit itself fails, the front door refuses in NFR-10 shape and unstages whatever it staged.
- **Skill.** /video step 12 runs the lister after the final-cut approval and asks once, default No.
- **Probe.** A warning-only /gate-check probe reports the same paths in a video-configured project. When git cannot list them, it returns one note naming the failure instead of rows.

## Acceptance Criteria

- AC-STE-673.1: `listUncommittedVideoTooling(porcelain)` in `adapters/_shared/src/video/commit_nudge.ts` takes `git status --porcelain=v1 -z --untracked-files=all` output and returns the sorted paths under `.dpt/video/` that are untracked, modified, renamed (new path) or deleted; fixtures prove it excludes `.dpt/video/work/**`, `.dpt/.env`, and every path outside `.dpt/video/`.
- AC-STE-673.2: `bun run adapters/_shared/src/video_commit_nudge.ts <projectRoot>` prints `nothing to commit` or one path per line, exits 0, and changes nothing in the index or the tree (asserted by comparing `git status` before and after in a temp repository).
- AC-STE-673.3: With `--commit`, the front door stages exactly the listed paths (deletions included) and creates one commit with subject `chore(video): commit the house style and tooling`; a temp-repository test asserts the commit's file list equals the lister's output, `.dpt/.env` and `.dpt/video/work/` stay untracked, and no push or remote command runs.
- AC-STE-673.4: With `--commit`, when the index already holds staged changes outside the list, the front door refuses in NFR-10 shape, naming those paths, and creates no commit.
- AC-STE-673.5: `skills/video/SKILL.md` step 12 orders: after an approved final cut, run the front door; when it lists paths, ask once (default No) naming them; on yes, run it with `--commit`; on no, move on; never push. A skill-text test pins the order, the default and the never-push rule.
- AC-STE-673.6: A /gate-check probe `video_tooling_uncommitted`, registered at the next free probe number with every probe count that names the total updated, reports each listed path at warning severity and never yields GATE FAILED; it is vacuous when `.dpt/video/config.yaml` is absent, and clean when the list is empty.
- AC-STE-673.7: Mutation tests: a lister that keeps `.dpt/video/work/` paths, and a probe that reports at error severity, each turn a named test red.
- AC-STE-673.8: `bun test` from `plugins/dev-process-toolkit` reports 0 failures, and its skip identities equal the trunk baseline by name.

## Technical Design

One pure lister, one front door on the `import.meta.main` idiom, both in the video adapter area. The commit path shells out to git with explicit pathspecs, never `-A` over the tree. The probe reuses the lister and follows the warning-only shape of the upgrade-staleness probe. The skill step calls the front door rather than reasoning about git itself.

## Testing

Lister fixtures from recorded porcelain output; temp git repositories for the front door; probe fixtures for vacuous, warning and clean; skill-text pins; mutation tests.

## Notes

Operator request after the first /video run: the house style lived only in one checkout until someone committed it by hand.

## Implementation notes

- `git commit` in the front door commits the whole index; only the staged-outside pre-check guards it — `--only` would split an in-video rename; the pre-check refuses first
- a project root below the git toplevel lists nothing, because porcelain paths are toplevel-relative — toolkit project roots are the checkout root
- if `git restore --staged` fails during rollback, it masks the original commit error — rare; either way the run ends in a refusal
