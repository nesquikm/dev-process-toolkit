# Commit guards classify against the repository the commit writes to

## Summary

A commit guard here decides what to check by looking at the directory its own session happens to sit in, not the one the commit will write to. Commit the same staged files from a worktree while the session is rooted elsewhere and the guard sees nothing and waves it through. It refuses the careful path and permits the careless one, which is the worst shape a guard can have.

## Requirement

Both pre-commit hooks gate on a regex anchored at the start of the raw command string, so a command that changes directory before committing matches neither hook and exits zero in silence. That is a bypass available to anyone who has ever typed a directory change before a commit, with no intent to defeat anything.

Separately, the TDD hook reads staged paths and resolves the stack layout against the hook process's own working directory. That is the session's tree, not the tree the commit writes to. Measured on 2026-09-16: identical staged files, same repository, same branch, opposite verdicts, decided entirely by which directory the calling session happened to be rooted in.

Classify against the repository the commit will actually write to, and say so out loud when that cannot be determined.

## Acceptance Criteria

- AC-STE-597.1: A commit-bearing command is recognised in three shapes — the bare form, a directory-change-prefixed form, and the `-C` form — and each resolves the repository the commit will write to.
- AC-STE-597.2: Staged paths are classified against that resolved repository rather than the hook process's working directory. Given identical staged content, the verdict does not change with the calling session's directory.
- AC-STE-597.3: The sibling gate-check hook recognises the same three command shapes, closing the same bypass. It gains no staged-path classification, because it performs none today and inventing one is out of scope.
- AC-STE-597.4: A commit-bearing command whose target repository cannot be resolved exits zero and emits a canonical reminder naming what could not be determined. It is never a refusal. Scoped to the TDD hook: the gate-check sibling has no repository in its question, so it still refuses for want of its own evidence, and a clause pins that direction.
- AC-STE-597.5: Every clause that asserts the new behaviour is falsifiable against its sibling — it fails on the pre-change bytes, passes on the post-change bytes, and that direction is recorded. Controls, negative guards and no-regression pins are exempt by construction: a control that could go red on the pre-change bytes would not be a control.

## Technical Design

The hook payload already declares the session working directory, typed and parsed, and a sibling hook already consumes it — so the reader exists and only the pre-commit pair ignores it. Parse the command for a leading directory change or a `-C` argument, resolve the target checkout root from there, and run the staged-path query and the layout resolution against it. An unresolvable command reuses the advisory leg this file already carries for an unidentifiable stack: exit zero, name the gap, never refuse.

## Testing

Drive the classifier with staged sets fixed and the calling directory varied, asserting the verdict is unchanged — that pairing is the defect, so it is the pin. Cover all three command shapes plus one unresolvable shape, and assert the advisory fires on the last rather than a refusal. Every clause must also fail on its sibling: a test that cannot go red on the old bytes is not evidence. Extend the two hook-module suites and the classifier suite.

**Caveat 1 — the resolver suite cannot be graded against the true pre-change bytes.**
`adapters/_shared/src/commit_target_repo.ts` did not exist at 85fd645, so the import fails and
the whole file errors out: 28/28 unrunnable. That is red, but it is module-absent red and it is
not per-clause evidence. Each clause was therefore graded against a faithful pre-change-*semantics*
sibling (commit recognised only by `/^git commit\b/`; repo always the caller's own directory;
nothing ever unresolved; `.git` must be a directory, no walk-up). 16 of 28 go red on it.

**Caveat 2 — 20 of the 45 new clauses hold in BOTH directions, and that is the exempt set,
not a shortfall.** Every one is an explicit `CONTROL`, a negative guard (`git status`,
`git log --grep`, `echo git commit`), or a no-regression pin (bare `git commit` still refuses).
None claims to grade the change; their job is to stop the RED clauses passing for the wrong
reason. AC-STE-597.5 originally read "each test added here fails on the pre-change bytes",
which forbade controls in the milestone about controls; it was amended to bind the
behaviour-asserting clauses — the set enumerated above — and to exempt the rest by
construction. The amendment is the operator's, made before this FR shipped.

**Caveat 3 — one clause is vacuously green pre-change.** gate-check's
`CONTROL — all three shapes exit 0 when the /gate-check Skill tool_use IS present` passes on the old
bytes because the `cd` and `-C` shapes are not recognised as commits at all, not because the
evidence was found. Alone it is worth nothing; it is only meaningful paired with the two RED
shape clauses directly above it, which is how it is written.

## Implementation notes

- scanCommand folds four grammars into one loop (quoting, heredocs, paren scoping, operator splitting) — The command-substitution bypass was a direct symptom of that conflation; extracting paren/command-substitution recognition into its own named step is the concrete decomposition.
- git -c key=$(...) commit reports unresolvable although -c names no tree and the target is the session's repo — Deliberately conservative: an unexpanded value in ANY git global option poisons resolution, so the TDD hook advises loudly instead of enforcing for that one shape. A precise rule would scope the poison to repo-naming options only.
- isExemptPlaceholder's two gitOut calls do not check .spawnFailed — A mid-run git failure reads as 'not exempt', requiring MORE evidence rather than less, so it fails safe; but it is inconsistent with the top-level staged-files leg that now emits a Reminder, and it is untested.
- pre-pr-spec-review.ts still gates on /^gh pr create\b/ — the identical anchored-regex bypass this milestone closed in the two pre-commit hooks — Out of STE-597's declared scope, which names the two pre-commit guards only. The third blocking hook keeps the defect: 'cd <dir> && gh pr create' matches neither.
- Two concurrent full bun test runs collide on shared tmp fixture roots — Observed once mid-milestone: three spurious failures that vanished on a solo re-run. Suites are sequential within a file, so this only bites when two gate runs overlap.
