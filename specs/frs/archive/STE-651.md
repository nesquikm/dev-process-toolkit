# Joining a spanning milestone writes only this repository's side

## Summary

Declaring that a milestone spans two repositories used to write into the sibling's checkout too, which an operator could only avoid by discipline.
The declare now writes only the invoking repository's plan, grades the sibling read-only from wherever its plan is found, and prints the one command the sibling's own session runs.
A sibling join names where it found the sibling's plan, and an Epic listing row without a project field is refused with a message naming the missing field.

## Requirement

- **One-sided declare.** The span declare writes only the invoking repository's plan. It refuses a plan file that belongs to another repository, grades the sibling's declaration read-only from any git source, and prints the command the sibling's own session runs.
- **No cross-repo remedies.** No remedy or prose tells a session to write or hand-write both plans, or to check out a branch in the sibling's main worktree.
- **Join reporting.** A `--sibling` join names where the sibling's plan was found, in its gate line and in its receipt.
- **Epic listing refusal.** An Epic listing row with no `fields.project` refuses with a message naming the missing field, and the required field list is documented.

Covers C-SPAN (medium), C-F1 (low) and C-F6 (low). Amends AC-STE-610.1/.2 and the STE-610 Notes.

## Technical Design

verifySpan drops the main-worktree refusal and `siblingPlanInMainWorktree`. declareSpan checks containment after the read with sameRepository, grades the sibling read-only with gradeExistingDeclaration, keeps the one-file drift guard and drops the multi-file rollback. The front door prints the declared/already-declared line, then the sibling line: already named back, or the sibling's own command. sibling_release's remedy becomes act-only (heldRemedy appends the actor). verifyJoinSibling returns `planSource`; withSibling and the receipt carry it. Export `JIRA_EPIC_LISTING_FIELDS`; split the absent-project refusal from keyed-outside.

## Implementation notes

- A plan file that is a hard link into the sibling still passes the containment check (a hard link has no real path to resolve); accepted residual, documented in spans_repos.ts.
- The declare re-resolves and re-checks the plan's real path right before the write and writes to that path; the swap window this closes has no direct test (no injection seam).
- When the sibling's plan exists only on a branch, the printed command says to run it from the checkout holding that branch; run from the sibling's main checkout it cannot find the plan.
