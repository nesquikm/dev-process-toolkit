# The Jira adapter guide, skills and inventory name both Atlassian surfaces

## Summary

The Jira adapter guide and the skills name only the older tools.
They now give both names for every operation.
The tool inventory records both surfaces.
A test fails when the guide names a tool that neither surface has.

## Requirement

Every surface that tells an agent which Atlassian tool to call names the v1 and the v2 call, and the recorded tool inventory holds both surfaces.

## Acceptance Criteria

- AC-STE-869.1: `adapters/jira.md` gives, for each operation it describes, the v1 tool with its inputs and the v2 tool with its inputs, and says to use whichever the session lists. An operation with no direct v2 tool names the execute tool and operation, marked as found through `discover` when no recorded call proves the name.
- AC-STE-869.2: Each read that feeds a deciding command states the fields the command needs and, on v2, `view: "full"`.
- AC-STE-869.3: The setup, spec-write and gate-check skills, `docs/setup-reference.md`, `docs/setup-tracker-mode.md`, `docs/spec-write-tracker-mode.md`, `docs/hooks-reference.md` and this repository's three smoke skills name both surfaces wherever they name a v1-only tool or input, and every skill stays within its line cap.
- AC-STE-869.4: `docs/hooks-reference.md` describes the translator, the execute-tool rule with its fail-closed scope and its non-Jira list, and the plugin-copy note, and its matcher text matches `hooks.json`.
- AC-STE-869.5: `tracker-tool-inventory.json` records both Atlassian surfaces with the source and date of each, and every name in either sits in exactly one of the write, read, ungated and execute sets.
- AC-STE-869.6: A test reads the Atlassian tool names out of `adapters/jira.md` and fails on a name in neither recorded surface, shown by one planted name.
- AC-STE-869.7: `bun test` from `plugins/dev-process-toolkit` reports 0 failures, and its skip identities equal the trunk baseline by name.

## Technical Design

The operations table gains a v2 column. Prose steps that differ, such as the transition and the create, state both inputs on adjacent lines. The inventory keeps its current v1 block and gains a v2 block under its own key, and its consumers read the union. The v2 list comes from the recorded deferred-tool registry.

## Testing

The named-tool test and the inventory partition test, with a planted-name mutation each, plus the existing skill and reference pins.

## Notes

v2 operation names that no recording proves are marked so. The plan heading and codename were composed, not asked.

## Implementation notes

No advisory notes.
