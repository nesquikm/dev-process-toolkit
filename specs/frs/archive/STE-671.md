# Stored video style: music prompt and narration tone

## Summary

A project now stores the feel of its videos in the same style file as its pacing and captions.
One line describes the background music, and one line describes how the narrator should sound.
Every video reads both, so the next video matches the last without anyone retyping the vibe.
The old calm default is replaced by an upbeat one, and the narrator can laugh or sound excited on cue.

## Requirement

- **Two new style keys.** `style.yaml` accepts `music.prompt` and `narration.tone`, both free text capped at 500 characters. The schema stays closed: any other new key still refuses.
- **New defaults.** With no `music.prompt`, the music request uses: "Upbeat, modern instrumental track for a tech product explainer: punchy drums, bright synths, positive energy, steady driving tempo, no vocals." The calm default in `video/music.ts` is removed. `narration.tone` defaults to empty.
- **Music.** The pipeline's music stage sends the stored prompt as the ElevenLabs music request's prompt.
- **Tone.** `/video` reads `narration.tone` as house style for the script and does not ask the tone question when it is set. The script may carry eleven_v4 audio tags such as `[excited]` or `[laughs]`.
- **Tags by provider.** The ElevenLabs adapter sends square-bracket tags untouched; the Google adapter strips them before synthesis.
- **Init and docs.** `video_init` writes both keys into a new `style.yaml`. The style refusal names its file through `videoStylePath`, not a typed literal.

## Acceptance Criteria

- AC-STE-671.1: `parseVideoStyle` accepts `music.prompt` and `narration.tone` as strings of at most 500 characters, refuses a longer value or a non-string naming the key path, and still refuses any other unknown key.
- AC-STE-671.2: An absent `style.yaml`, or one without `music.prompt`, yields the upbeat default prompt quoted in the Requirement, byte-for-byte; `narration.tone` defaults to the empty string. No source file under `adapters/` contains the string "Calm, unobtrusive".
- AC-STE-671.3: With `music.source: elevenlabs`, the music stage's recorded request body has `prompt` equal to the stored `music.prompt` exactly (no prefix or suffix), and equal to the default when none is stored.
- AC-STE-671.4: Segment text `Done [laughs] really [excited] done` reaches the ElevenLabs request with both tags unchanged, and reaches the Google request with both tags removed and no doubled spaces; `[short pause]` keeps its existing handling on both adapters.
- AC-STE-671.5: `video_init` writes `music.prompt` (the default) and `narration.tone` (empty) into a fresh `style.yaml`, and the written file parses back to the defaults.
- AC-STE-671.6: A style refusal message names the style file through `videoStylePath`; a test changes the path helper's output and sees the message follow it.
- AC-STE-671.7: `skills/video/SKILL.md` tells the script step to read `narration.tone` as house style, skips the tone question when it is non-empty, and documents the audio-tag rule; a test pins all three, and the skill stays within the NFR-1 line cap.
- AC-STE-671.8: `docs/video-reference.md` documents both keys, their caps and defaults, and the per-provider tag rule.
- AC-STE-671.9: Mutation-verified: dropping the prompt pass-through turns AC-STE-671.3 red, and stripping tags for ElevenLabs turns AC-STE-671.4 red; each mutation is asserted applied before its test runs.

## Technical Design

Extend the closed style schema and its defaults with the two keys; move the default prompt into the style defaults so music has one source. The pipeline music stage reads the style it already loads and passes the prompt. Tag handling lives in each TTS adapter's text preparation, next to the existing short-pause rule. Skill and reference text change alongside.

## Testing

Schema fixtures for accept, cap and refuse; recorded-request tests for the music stage and both adapters; skill-text pins; mutation battery. No network.

## Notes

Operator decisions 2026-10-12: approach 1 of 3; tone drives script and audio tags; upbeat tech-explainer default prompt.

## Implementation notes

- Google TTS strips any [..] span except the exact `[short pause]`, so literal bracketed narration like [beta] is dropped — the FR specifies Google strips square-bracket tags; ElevenLabs' break rewrite emits the exact lowercase spelling
