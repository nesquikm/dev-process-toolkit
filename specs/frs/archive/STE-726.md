# The token-stats bridge stays off when the session's own brainstorm was shared

## Summary

A spec run can borrow an earlier design session's token stats when it has none of its own.
The borrowing should stop once the run's own session already held a design step.
Today it stops only while that design step is still booked to the current spec.
When one session writes several specs, its design step moves to the shared design bucket.
Each later spec then borrows an unrelated old session.
This fix treats a moved design step as present.

## Requirement

### Steps to reproduce

1. Write a ledger on branch `main` holding three earlier sessions, each with one unclaimed brainstorm row and no spec-write row, and a current session `sess-CUR` holding one brainstorm row and one spec-write row.
2. Call `claimRowsForFR(root, { branch: "main", sessionLineage: ["sess-CUR"], brainstormClaim: <id> })` for `STE-9001`, `STE-9002`, `STE-9003` and `STE-9004`, in that order.

### Expected

No call selects a row from the three earlier sessions, and none of their rows gains a `claimed_by` mark. The current session's rows end in the `design/exploration` bucket.

### Actual

The first call claims the current session's rows. The second demotes them to `design/exploration` and then bridges the newest earlier session into `STE-9002`. The third and fourth bridge the other two. All three foreign claims persist to the ledger.

Observed live on 2026-11-04: one spec run that wrote 20 FRs claimed three brainstorm sessions from July and August for its second, third and fourth FRs.

## Acceptance Criteria

- AC-STE-726.1: Regression: `tests/m_4489fc-ste-726-bridge-shared-session.test.ts › a demoted lineage brainstorm blocks the bridge` fails before the fix and passes after it.
- AC-STE-726.2: `filterRowsForFR` bridges a detached brainstorm only when no row of the FR's session lineage has skill `dev-process-toolkit:brainstorm`, whatever that row's `claimed_by` is: unset, another FR's id, or `design/exploration`. When it does not bridge, no off-lineage row is selected or gains a `claimed_by` mark.
- AC-STE-726.3: A lineage with no brainstorm row is still bridged as today: the existing bridge cases in `token-stats-render.test.ts`, the AC-STE-396.8 cases, `token-stats-claim-persistence.test.ts` and the STE-703 test file stay green unchanged.
- AC-STE-726.4: Replay of the observed run. With the reproduce ledger and 20 sequential claims from one lineage, zero rows from the three earlier sessions are claimed, and every current-session row ends in `design/exploration`.
- AC-STE-726.5: Restoring the selected-rows-only check turns the AC .1 and AC .4 tests red.
- AC-STE-726.6: `bun test` from `plugins/dev-process-toolkit` reports 0 failures, and its skip identities equal the trunk baseline by name.

## Technical Design

### Root cause

The bridge guard asks whether any row selected for this FR is a brainstorm row. A lineage brainstorm row demoted to the design bucket is skipped before selection, so the guard sees none. The lineage then looks brainstorm-less, and the bridge claims the newest unclaimed detached session on the branch, with no age bound.

The fix moves the guard from the selected rows to the lineage: any brainstorm row in the lineage, in any claim state, turns the bridge off.

## Testing

Ledger fixtures in temporary roots: the four-claim reproduce shape, the 20-claim replay and a lineage with no brainstorm row, plus a mutation control.

## Notes

Origin: the 2026-11-04 spec run for M_94e6f7 to M_fd9a03. The three foreign claims were undone by hand from a ledger backup.
