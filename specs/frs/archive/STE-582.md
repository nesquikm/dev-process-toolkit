# A non-scalar target repo declaration is refused, not read as undeclared

## Summary

A plan that lists two repositories under its target repo key today reads as having declared nothing.
Delivery then routes the whole milestone back into the invoking repo with a green chain and never mentions the sibling.
The list is destroyed by the frontmatter parser before the reader ever sees it.
The reader now refuses every non-scalar value in the canonical three-line shape, points at the spanning key instead, and keeps each documented undeclared sentinel undeclared.

## Requirement

The target-repo reader must tell a genuinely absent or sentinel declaration apart from a value the parser turned into a non-string, refuse the latter in the NFR-10 canonical shape without guessing which spelling was written, and the copy of the routing rules that `/deliver` executes must say so.

## Acceptance Criteria

- AC-STE-582.1: `readTargetRepoDeclaration("---\ntarget_repo:\n  - /a\n  - /b\n---\nx")` in `adapters/_shared/src/target_repo.ts` throws a `TargetRepoError` whose message carries `Refusing:`, `Remedy:` and `Context:`, each at the start of its own line.
- AC-STE-582.2: Four undeclared controls each return `{ declared: false, value: null }` and throw nothing: `target_repo: null`, `target_repo: ~`, `target_repo: ""`, and a body carrying no `target_repo:` key at all. A run in which any one of the four throws fails this AC.
- AC-STE-582.3: `target_repo: ../glacy-app-be` returns `{ declared: true, value: "../glacy-app-be" }`, and the same scalar declared under a CRLF source, a lone-CR source and a BOM-prefixed source still reads declared with the same value.
- AC-STE-582.4: The refusal names no single spelling. The messages thrown for a block list, for `target_repo: {}` and for a bare `target_repo:` line are byte-identical, and that one message names all three causes — a block list, an empty map and a bare key.
- AC-STE-582.5: The flow-list path is unmoved. `routeMilestone({ planBody: "---\ntarget_repo: [/a, /b]\n---", invokingRepo: process.cwd() })` still throws a `TargetRepoError` whose message contains `could not be located` and does not contain the new not-a-single-path refusal text.
- AC-STE-582.6: The Remedy names the spanning key: the thrown message contains `spans_repos`, and `grep -c 'spans_repos' adapters/_shared/src/target_repo.ts` returns at least 1.
- AC-STE-582.7: The copy `/deliver` executes says it. In `skills/deliver/SKILL.md`, the undeclared bullet — the line whose bold lead says that no `target_repo:` key, or the `null` sentinel, means the invoking repo — states on that same line that a YAML list under the key is refused and names `spans_repos`, and the file's split-line count is unchanged. In `docs/deliver-reference.md`, the matching undeclared bullet carries the same statement. Neither edited line gains a module path.
- AC-STE-582.8: `bun test tests/m129-ste-495-target-repo.test.ts` passes with zero failures, and the full `bun test` from `plugins/dev-process-toolkit` reports zero failures with the skip count unchanged from the 15 measured at v2.81.0.

## Technical Design

Split the one non-string clause in `readTargetRepoDeclaration` into two arms: `raw === undefined || raw === null` stays undeclared, then any other non-string throws `TargetRepoError` in the Refusing/Remedy/Context shape. The null arm must precede the type test because `typeof null === "object"`; `~` is a string and stays caught by the existing sentinel comparison. `{ lenient: true }` stays. Measured with the shipped parser, the list dies one module earlier:

```
target_repo BLOCK_LIST  → object {}
bare key                → object {}
empty map {}            → object {}
```

So the message enumerates causes instead of naming one. The type union is unchanged, and the refusal never routes through `renderRefusalMessage`.

## Testing

New assertions join the existing target-repo suite. Mutation-check the null arm by moving it below the type test: the `null` control in AC.2 must go red.

## Notes

A stray bare target repo key that routed silently now throws. That is a behaviour change, recorded under Changed rather than Fixed.

## Implementation notes

- Fixed in-flight (post-audit): the refusal's `Refusing:` line first named three spellings as if they were the complete list, but the parser also turns a bare `true`/`false` into a boolean and keeps a nested map's keys, and both reach the same arm. It now says a non-string value was read and names every spelling that produces one; three hardening tests pin the boolean, the nested map and the non-string wording.
- Fixed in-flight: both `/deliver` undeclared bullets omitted the bare-key behaviour change and folded two refusals into "block or flow". A flow list is refused later by the locate step, whose Remedy names no `spans_repos`; both bullets now say so.
- Fixed in-flight: the reader's docstring and the module header still called it purely lenient; both now say it throws on a non-string value.
- Refactor: the new refusal's `Context:` line was aligned to the file's key=value shape (`target_repo=<object>, phase=target-repo-read`), which keeps the three spellings' messages byte-identical.
- Measurement note: one targeted re-run first produced NO test output — zsh does not word-split `$F`, so bun received one filter string and ran nothing. Caught by reading the raw tail instead of trusting a zero-hit grep; re-run via `xargs`.
