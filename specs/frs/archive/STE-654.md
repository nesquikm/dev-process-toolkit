# A tracker FR's title and ticket body round-trip with its FR file

## Summary

A ticket created by the spec writer kept its draft placeholder ids and back-link, because the body was never pushed again once the real key was known.
The spec writer now re-syncs the ticket once after writing the FR file, and the docs explain how an older ticket that still carries placeholders heals.
FR titles that YAML would read differently, such as a bare null or a title with a colon, are now quoted on write and read back exactly.

## Requirement

- **Ticket body.** After /spec-write writes the FR file, it re-syncs the ticket once, as an update of the returned key. The ticket then carries the substituted AC ids and a back-link rendered with the real key. The ac-sync docs explain how a ticket that still carries draft placeholders heals.
- **Titles.** Both FR frontmatter writers quote any title whose YAML reading would differ: indicators, reserved words, number-like strings, and control or separator characters. The reader undoes the writer's escapes, so every title round-trips under the toolkit's parser and under Bun.YAML. Plain titles stay byte-identical.

Covers C-J1 and C-F2 (both low).

## Technical Design

J1: add a fifth Concrete-flow step, Provider.sync(spec) again; with its tracker binding the FR is an update, which sends title and description and leaves labels untouched. Append the step in place on the SKILL.md ticket-create line; jira.md and linear.md get the rendering clause; ac-sync.md one sentence. F2: export and widen escapeYamlScalar (empty, edge whitespace, control/separator/quote/backslash/colon/hash, leading indicator, reserved scalar, number-like), quoting as JSON plus unicode escapes for DEL, C1, U+2028/2029 and BOM. import.ts routes its title through it. The reader's stripQuotes JSON-parses a double-quoted value containing a backslash (raw fallback on throw) and unescapes doubled single quotes.

## Implementation notes

- A lone surrogate is quoted and written as \udXXX: the toolkit reader restores it, a strict YAML reader may reject it.
- The reader's JSON unescape applies to every double-quoted frontmatter value carrying a backslash, not only title; a field that must keep a literal \n belongs in single quotes (documented in frontmatter.ts).
