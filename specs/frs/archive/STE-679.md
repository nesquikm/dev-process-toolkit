# Spec-write files a bug as a bug

## Summary

A bug written with the spec-write skill now says it is a bug.
The FR file records it, and the tracker files it as a bug.
Jira gets a Bug issue, and Linear gets a Bug label.
The body asks how to reproduce the bug and what was expected and seen.
It also asks for the root cause and a test that fails before the fix.
QA authors can file bugs without answering technical questions.

## Requirement

- **Marked.** `--bug` writes `kind: bug` into the FR frontmatter and defaults `changelog_category` to `Fixed`; the author may choose `Security` instead.
- **Shaped.** A bug FR's body asks for reproduction steps, expected and actual results, the root cause, and a regression criterion.
- **Filed as a bug.** The tracker ticket is a Jira issue of the bug type, or a Linear issue carrying the bug label. Both names default to `Bug` and are configurable.
- **Refuses early.** A bug type or label the workspace does not have stops the run before any tracker write or file.
- **QA-friendly.** `--bug --no-tech` asks only the observable questions; the technical sections wait for review.

## Acceptance Criteria

- AC-STE-679.1: `buildFRFrontmatter(spec, binding, { kind: "bug" })` emits `kind: bug` on the line after `changelog_category:`; with no `kind` option no line is emitted; any other value throws in the NFR-10 canonical shape; the frontmatter reader returns `kind: "bug"` for the emitted file; a test pins the key order `tracker → needs_technical_review → created_at → changelog_category → kind`.
- AC-STE-679.2: `/spec-write --bug` is parsed in the resolver-entry preamble beside `--no-tech` and does not change resolver routing; it sets `kind: bug` and defaults `changelog_category` to `Fixed`; `Security` is accepted as an override and any other category is refused at the draft gate; the draft-gate preview shows both values.
- AC-STE-679.3: A bug FR body carries `### Steps to reproduce`, `### Expected` and `### Actual` under `## Requirement`, `### Root cause` under `## Technical Design`, and at least one AC whose body begins `Regression:` and names a test that fails before the fix.
- AC-STE-679.4: Under `--bug --no-tech` the interview fills Steps to reproduce, Expected, Actual and the `Regression:` AC; `## Technical Design` (Root cause included) and `## Testing` carry the needs-technical-review placeholder; `branchTypeFor` is unchanged, and a test pins `{ changelogCategory: "Fixed", noTech: true }` → `chore` and `{ changelogCategory: "Fixed", noTech: false }` → `fix`.
- AC-STE-679.5: `readWorkspaceBinding` parses `jira_bug_issue_type:` from `### Jira` and `linear_bug_label:` from `### Linear`; `resolveBugTrackerType(mode, binding)` returns the override when set, `Bug` otherwise, and `null` for `mode: none`.
- AC-STE-679.6: `create_idempotency_probe.ts decide … --bug` puts `issueType: <resolved>` in the Jira `createPayload` and appends the resolved label to the Linear `labels` (no duplicate when `default_labels` already holds it); without `--bug` the payload is byte-identical to today; in a shared repository the tracker-write hook permits a create that carries that payload.
- AC-STE-679.7: A pure check over a saved listing refuses in the NFR-10 canonical shape, before any tracker write or FR file, when the Jira type is absent (naming `jira_bug_issue_type`), when the Jira type cannot take the milestone Epic as parent (naming the type and the Epic; no label fallback), or when the Linear label is absent or retired (naming `linear_bug_label`).
- AC-STE-679.8: The skill's argument hint shows `[--bug]`; `adapters/jira.md` and `adapters/linear.md` document both keys; `skills/spec-write/SKILL.md` stays under its line cap.
- AC-STE-679.9: `bun test` from `plugins/dev-process-toolkit` reports 0 failures, and its skip identities equal the trunk baseline by name.

## Technical Design

One optional option on the frontmatter builder, read back by the existing reader. A small resolver beside the workspace binding reader returns the bug type or label. The decide front door gains a bug argument that feeds the create payload. A pure availability check runs over the saved issue-type or label listing. Skill prose covers the flag, the body shape and its interplay with the no-tech flag.

## Testing

Unit tests per helper; create-payload fixtures for both trackers; a skill-text pin; the branch-type matrix pin.

## Notes

Design: 2026-10-20 brainstorm, approach #2. Downstream behaviour (fix branch, Fixed changelog section, patch bump) already keys off the changelog category and is reused, not duplicated.

## Implementation notes

- Linear --bug de-duplicates the bug label against default_labels ignoring case — intentional and documented in adapters/linear.md; a test pins default 'bug' + resolved 'Bug' to one label
- runDecideCommand resolves the bug type through a dynamic import of resolveBugTrackerType — follows the file's lazy-import convention; the import runs only on a create outcome
