# Grade release-surface agreement after the bump, not before

## Summary

A detector comparing the release banner against the changelog already exists, is tested against the shipped line, and has no callers at all.

The check that does run fires before the version is bumped, when both surfaces still describe the previous release. They agree by construction, so it cannot fail.

The banner has four fields and one writer, which rewrites one. The rest are hand-corrected so reliably the miss is invisible — but one release shipped under the previous name.

## Requirement

The surface-agreement detector gains an entry point and runs after the version bump, where disagreement is observable. It addresses the changelog entry by version rather than by position. It stays silent on projects carrying no banner, on those whose changelog it cannot parse, and on those that have not run the ship ceremony — the check must not fail a consumer for a surface it never adopted.

## Acceptance Criteria

- AC-STE-546.1: `adapters/_shared/src/release_surface_agreement.ts` carries an `import.meta.main` entry point and at least one production caller, so it is no longer a written-and-tested module wired to nothing.
- AC-STE-546.2: The agreement check runs after the version bump in the ship ceremony. A tree with a deliberately stale banner passes the pre-bump moment and fails the post-bump one — the same tree, both moments asserted, since a check that only ever passes is the defect being fixed.
- AC-STE-546.3: The changelog entry is located by matching the version being released, never by taking the topmost heading, so an entry that is not on top is still found and graded.
- AC-STE-546.4: Vacuity requires all three conditions: the README carries the banner literal, the changelog yields at least one parseable heading, and at least one plan carries a shipped stamp. Any one absent yields zero rows rather than a violation.
- AC-STE-546.5: A banner that is present but disagrees is a violation, and a banner that is absent is not. The two cases are distinguished by the marker, not by whether parsing happened to succeed.
- AC-STE-546.6: The check is registered by extending the existing ship-coherence probe rather than adding a new one, so the probe count and its sixty pinned sites do not move.
- AC-STE-546.7: The probe's documented vacuity contract is updated to match its widened scope, since it previously promised silence on a condition that no longer governs every leg.
- AC-STE-546.8: Falsifiability — reverting the comparison turns a fixture carrying a genuinely stale banner green, asserted by a mutation test.

## Technical Design

`release_surface_agreement.ts` gains an `if (import.meta.main)` door and a production caller. `checkReleaseSurfaceAgreement` is re-pointed from the topmost changelog entry to the entry matching the released version, mirroring the pin `d8787f8` applied to the caps-provenance test for the same reason.

The vacuity predicate becomes a conjunction of three conditions rather than one, because two legs over-fire today: an empty plan set reports a missing shipped stamp, and a non-toolkit changelog format reports a changelog violation before the banner is ever examined. Both would fail consumers who never adopted the surface.

Registration extends probe #63 in `plan_ship_coherence.ts`; a new probe number would move sixty pins across fifteen files.

## Testing

New `tests/m141-ste-546-surface-agreement.test.ts`.

- AC.1 — spawn the entry point and assert it runs; separately assert a non-test importer exists, since a door with no caller is the state being left behind.
- AC.2 — the load-bearing leg. Build one fixture with a stale banner, run the check at the pre-bump state and assert clean, apply the bump, re-run and assert it fires. Both halves on the same fixture: the pre-bump pass is what proves the old placement could not have caught it.
- AC.3 — a changelog whose matching entry sits second; assert it is found, with a control where the topmost entry would have given the opposite verdict.
- AC.4 — three fixtures, each missing exactly one condition, all asserting zero rows; plus one with all three present asserting the check actually ran, so the vacuity legs cannot pass by never running.
- AC.5 — a banner-absent fixture and a banner-present-but-mangled fixture, asserting skip and violation respectively.
- AC.6 — assert the probe count is unchanged and that no new probe id was registered.
- AC.8 — mutation: revert the comparison and assert the stale fixture goes green, then restore and assert it reds again.

## Notes

The pre-bump placement is why this never fired: at that moment both surfaces describe the previous release honestly, so agreement is guaranteed rather than checked. A detector can be correct, tested, and completely inert if it runs where its subject cannot yet differ.

## Implementation notes

- parseChangelogTop is now an exported symbol with test-only callers, and no probe covers dead exports. — Re-pointing the check to version-match lookup is what orphaned it. Kept rather than deleted so its removal is a decision someone makes deliberately.
- probe #63 now walks specs/plan twice — listArchivePlans (archive only) and readPlanTexts inside runReleaseSurfaceAgreement (live plus archive). — Not redundant: the archive-only walk is STE-369's deliberate scope guard, while the agreement check must see live plans because the ceremony stamps the resolved plan, usually still live. One extra directory read per probe run.
