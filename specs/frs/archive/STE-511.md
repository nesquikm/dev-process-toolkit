# /implement carries the same evidence in its own report

## Summary

The hand-off fence only exists when a stage runs underneath the orchestrator. Run the implementation skill on its own and the same guarantee evaporates, which means the guarantee is really a property of one invocation path rather than of the work. The report that skill already prints is the right place to carry the same rows.

## Requirement

A standalone implementation run reports the same evidence, from the same code.

## Acceptance Criteria

- AC-STE-511.1: The step-14 report carries the same gate, drive and e2e rows as the fence.
- AC-STE-511.2: Both rows come from one renderer — there is no second implementation of the same rendering.
- AC-STE-511.3: A standalone run not under the orchestrator is covered by the same guarantee, asserted directly.
- AC-STE-511.4: Counts are machine-derived on this path too.

## Technical Design

`/implement` is invoked directly at least as often as it is invoked as a `/deliver` stage — every single-FR run, every `/implement M<N>` the operator types by hand. Its step-14 report is the surface a human reads before approving the commit, and today it reports gate results in prose with no skip count and no drive evidence.

AC.2 is the criterion that keeps this from becoming a maintenance liability. Two renderers for the same rows drift, and when they drift the two invocation paths disagree about whether the same work was green. One renderer consumed by both the fence and the report is the only shape that cannot produce that disagreement — the same reuse discipline the resume classifier follows in assembling shipped helpers rather than re-deriving them.

AC.3 is asserted directly rather than inferred from AC.1, because "the report carries the rows" and "a standalone run carries the rows" are different claims and only the second is the guarantee.

## Testing

Report coverage asserting the gate, drive and e2e rows are present in the step-14 output. A single-renderer assertion: the fence path and the report path produce the same rows from the same input, compared directly rather than each against a fixture. Standalone-run coverage asserted on its own path. Machine-derivation asserted as in STE-510. `bun test` full root.

## Notes

Without this FR the milestone's guarantee reads as a property of `/deliver`, which is not what was asked for. The operator's request was that the work be provably done, not that one invocation path prove it.
