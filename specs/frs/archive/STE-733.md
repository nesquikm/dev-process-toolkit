# A spec-only commit needs no gate run, and a worker's spec review vouches for the pull request its owner opens

## Summary

A commit of spec files alone is refused unless the session ran the full gate.
A supervisor cannot open a worker's pull request, because the review hook trusts only the opening session.
A spec-only commit now passes the commit gate, as it passes the test-first gate.
The review hook also accepts a receipt from the worker's own review.
That worker's record must show the review run, on the exact commit being opened.
A typed or edited receipt is still refused.

## Requirement

The commit gate permits a commit whose staged paths are all spec files, and the pull-request gate permits opening a branch whose HEAD was reviewed by another session, proven by that session's own transcript; every other refusal stays as it is.

## Acceptance Criteria

- AC-STE-733.1: `pre-commit-gate-check` permits, with no gate-check evidence, a plain `git commit` placed in exactly one checkout whose tracked working tree matches its index and whose every staged path satisfies `isSpecPath`. A staged path outside `SPEC_PATTERNS`, `-a`, a pathspec, `--amend`, or an unplaced commit gets today's rule.
- AC-STE-733.2: An edit to an archived FR's body, such as its Notes, staged alone, commits under AC .1.
- AC-STE-733.3: When the opening session has no spec-review evidence of its own, `pre-pr-spec-review` permits `gh pr create` only when all hold for a receipt R in the target checkout: R is a spec-review gate receipt stored under another session S's receipt store; R parses, and its `evidence.head` equals the checkout HEAD, which equals the remote branch head; S's transcript is the file `<S>.jsonl` found one directory level below the projects root that holds this session's transcript; that transcript holds a `Skill` tool_use of `dev-process-toolkit:spec-review`, followed by a result of the `gate_receipt.ts` front-door run announcing R's path with a digest equal to R's current bytes; and the tracked working tree is clean.
- AC-STE-733.4: The relay refuses: a receipt with no announcement in S's transcript; an announcement whose digest differs from R's bytes; an announcement carried by any tool other than the front-door run (an echo, a Read, a typed line); a transcript with the announcement but no spec-review Skill call before it; an `evidence.head` that differs from HEAD or from the remote head; a missing or unreadable transcript; a transcript path that escapes the projects root; and a dirty tree.
- AC-STE-733.5: The pull-request refusal remedy names the relay route, and `docs/hooks-reference.md` documents both carve-outs and what counts as evidence for each.
- AC-STE-733.6: Permit and forbid legs run through the shipped `.sh` wrappers on synthetic transcripts and receipts; each condition of AC .1 and AC .3 has a twin that differs only in that condition.
- AC-STE-733.7: Removing the spec-path rule, the HEAD equality, the digest check, the front-door rule, the Skill-call rule or the projects-root confinement turns at least one named test red.
- AC-STE-733.8: Every commit and pull request the two hooks refused at v3.3.0 for a reason outside these two carve-outs is still refused; existing hook suites stay green except for named amendments.

## Technical Design

The commit carve-out reuses `isSpecPath` and the archive-only placement checks. The relay reuses the in-session announcement reader, pointed at the owner's transcript, so the trust path stays the same: a receipt counts only if a real front-door run announced it, and its bytes still match.

## Testing

Synthetic transcripts and receipts in temporary git repositories with fake session ids, a fake projects root, and a local bare remote; driven through the shipped hook wrappers; mutation rows over each rule.
