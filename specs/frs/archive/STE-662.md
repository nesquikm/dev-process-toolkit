# Front doors check first and print their counts

## Summary

The skip-baseline capture ran the whole suite before it checked its own preconditions.
An off-trunk or dirty run wasted fifteen minutes and then refused.
The capture now checks first and refuses at once, with the same words.
The gate-capture front door now prints pass, fail and skip totals from its one run.
Three stale test comments and one unnamed sentence rule are also corrected.

## Requirement

- **Check before the expensive work.** `runCapture` evaluates the existing capture preconditions — HEAD equals the trunk sha, and the working tree is clean — before it runs the gate. A failing precondition refuses with the existing STE-527 refusal text, and the gate is never started.
- **The late check stays.** `captureSkipBaseline` still asserts both preconditions after the run, because the tree can change during a long suite (STE-528: the count and the tree it was measured on come from one call). Both call sites use one shared exported function, so the two checks cannot drift.
- **Totals from the same run.** The `gate_capture.ts` front door prints one totals line, read by `parseTestOutput` from the output of the run it already makes. No second run, and the exit codes keep their current meaning.
- **Stale comments.** Three test comments that still describe a five-rule union are corrected to the six-rule union STE-661 shipped.
- **The list-item rule is named.** The sentence splitter starts a sentence at each list item; AC-STE-661.3 did not say so. This FR states and tests it, and leaves the archived FR untouched.

## Acceptance Criteria

- AC-STE-662.1: `skip_baseline.ts` exports the precondition check (today's private `assertCapturable`) under one name, and both `runCapture` (before the gate runs) and `captureSkipBaseline` (after) call that one function; no second copy of either condition exists.
- AC-STE-662.2: In a temp git repo whose HEAD is not the trunk commit, `runCapture` throws the HEAD-mismatch refusal and the gate command is never executed — asserted by a gate command whose execution would leave a marker file, and the marker file is absent.
- AC-STE-662.3: In a temp git repo on the trunk commit with one untracked file, `runCapture` throws the dirty-tree refusal naming that file, and the gate command is never executed (same marker assertion).
- AC-STE-662.4: The refusal text in AC-STE-662.2 and AC-STE-662.3 is byte-identical to the text `captureSkipBaseline` throws for the same state, so the pre-flight changes when the refusal fires, never what it says.
- AC-STE-662.5: `captureSkipBaseline` still refuses when the tree becomes dirty between its precondition check and its write — the existing late-check test stays green unmodified.
- AC-STE-662.6: The `gate_capture.ts` front door prints exactly one line `gate_capture: pass <P>, fail <F>, skip <S>` with numbers from `parseTestOutput` on the same run's output, before the skip names; when the output yields no readable count it prints `gate_capture: totals unreadable — <reason>` instead, and never a guessed number.
- AC-STE-662.7: The front door's exit codes are unchanged: 0 when skips are named or the runner writes no report, 1 when the report is missing or unreadable, and a red gate alone does not change the exit code.
- AC-STE-662.8: The three stale comments (`fr-word-cap-epoch-grandfathering.test.ts`, `scan_fr_summary_altitude.test.ts`, and the test title in `m137-ste-534-fr-word-caps.test.ts`) describe the six-rule union; a grep of `tests/` and `adapters/` for a five-member rule-union description returns zero hits, with a control proving the grep finds a planted five-rule sentence.
- AC-STE-662.9: A test names the list-item rule: `longSentences` starts a sentence at each `- `, `* `, `+ `, `1. ` and `1) ` list item, so two unpunctuated 15-word rows yield zero rows, and the test cites AC-STE-661.3 as the AC it completes.
- AC-STE-662.10: Mutation-verified: making `runCapture` skip the pre-flight call turns AC-STE-662.2 red, and dropping the totals line turns AC-STE-662.6 red; each mutation is asserted to have applied before its test runs.
- AC-STE-662.11: `bun test` from `plugins/dev-process-toolkit` reports 0 failures, and its skip identities equal main's by name.

## Technical Design

Export the existing precondition function from the skip-baseline module and call it from the capture runner before the gate starts. The function keeps its current refusal text, so nothing downstream changes. The capture front door feeds the output it already holds to the shared test-count parser and prints one totals line. Comment fixes and the list-item test are text and test changes only.

## Testing

Temp git repos with a gate command that writes a marker file prove the gate never ran (AC-STE-662.2, AC-STE-662.3). Byte comparison of refusal text against the late check (AC-STE-662.4). Front-door output fixtures for the totals and unreadable lines and the exit codes (AC-STE-662.6, AC-STE-662.7). A grep with a planted control (AC-STE-662.8). Splitter unit test (AC-STE-662.9). Mutation battery (AC-STE-662.10).
