# Every offer of the release asks the sibling gate first

## Summary

Three surfaces offer the release on local state alone, so the repository that finished first was told to ship while its sibling was busy, only for the release to refuse.
The milestone close prompt, the archival exit hint and the no-argument ship offer now ask the same gate before offering.
The resume chain for a milestone whose plan is already archived waited only on live plans; it now waits for the sibling too.

## Requirement

Every path an operator arrives by must reach the refusal's own predicate before offering the ship. Measured before this FR: a milestone-scope resume over an ARCHIVED unstamped spanning plan whose sibling holds an active FR orders `/implement`, `/ship-milestone` and `/pr`, because the sibling wait reads only active plans; the same fixture with the plan LIVE orders nothing, which is what makes this a defect rather than a badly built fixture. A plan is normally archived at ship time, so this is the state the ship path actually runs in. The previous milestone collapsed both resume scopes onto one predicate, but that predicate's input set was still partial: unifying the callers does not help when the thing they share reads half the world.

## Technical Design

`classifyMilestoneResume` already reads the resolved plan's frontmatter from the archive path; for an unstamped, unparked archived plan it reads that body and takes `busy` from `spanningSiblingState`, the predicate both resume scopes and the ship gate share. The three skill edits order the front door and render its refusal; `skills/implement/SKILL.md` is edited in place on its Silent-skip line, since it holds zero headroom.
