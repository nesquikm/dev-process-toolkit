# Chain-continuation prompts are registered so a delegation can reach them

## Summary

The gate registry holds nine entries, three of them the class a standing authorization can reach. No chain-continuation prompt is among them.

Every unregistered gate falls back to the class that always demands a personal answer, so the delegation the pipeline documents reaches none of the prompts that interrupt it.

They meet the registry's own definition of the delegable class word for word: one correct answer, already determined upstream. They are undelegable by omission, not by decision.

## Requirement

Every chain-continuation prompt is registered with the class its behaviour warrants, so an operator who has delegated the mechanical class is not asked again. Registration alters no behaviour without a delegation on the record. No prompt naming an irreversible action can be reclassified this way, and the existing guard remains the authority on that.

## Acceptance Criteria

- AC-STE-552.1: Each chain-continuation prompt carries a registry entry, and `classifyGate` resolves it to the declared class rather than to the unknown-gate fallback.
- AC-STE-552.2: With an active delegation covering the mechanical class, `relayRequired` returns false for each newly registered prompt. Without one it returns true, asserted per prompt so a single entry cannot pass on a sibling's behalf.
- AC-STE-552.3: Registration is inert absent a delegation. The shipped behaviour of an undelegated run is byte-identical and every existing BEHAVIOURAL expectation passes unmodified. Exactly two shipped IDENTITY pins move, both by design and both named here, because AC.6 and AC.8 order them: `tests/m133-ste-515-gate-registration.test.ts`'s registry-length and pre-FR-list equality (AC.6), and `tests/m129-ste-493-gate-class.test.ts`'s guard-id list plus its `merge` isolation sample `merge the open pull request`, which any honest `open_pr` guard also matches, so the sample is retargeted rather than the guard narrowed (AC.8). A third pin moving is a violation of this criterion.
- AC-STE-552.4: The irreversible guard still overrides a declared class. A prompt whose summary names a guarded action resolves irreversible however it is declared, asserted by declaring one mechanical and observing the override.
- AC-STE-552.5: No entry added here names a guarded action, verified by running each new summary through the guard and asserting none matches.
- AC-STE-552.6: The registry's own count assertion is updated in step, so the number of entries is pinned rather than merely grown.
- AC-STE-552.7: Falsifiability — removing any one new entry returns that prompt to the unknown-gate fallback and makes its delegated leg require a relay again, asserted per entry.
- AC-STE-552.8: Opening a pull request is covered by an `IRREVERSIBLE_GUARDS` entry of its own before any ceremony-PR prompt is registered. Measured on this tree 2026-09-04: the five shipped guards are `merge`, `push_to_trunk`, `deploy`, `publish` and `outward_facing`, and `open a pull request`, `open the PR` and `Open a PR for this milestone?` all match NONE of them — `push the branch and open the PR` matches only because it contains the word push. So AC.5's verification passes for a PR prompt today precisely because the gap exists, which makes registering that prompt mechanical enough to render PR-opening relay-free under a delegation. The new guard is asserted the way its five siblings are: drop-one mutation showing it is load-bearing, and a leg asserting a PR prompt declared mechanical resolves irreversible anyway. Adding a guard also widens probe #78 (`delegation_irreversible_exclusion`), whose required phrases are DERIVED from `IRREVERSIBLE_GUARDS[].actionPhrase`: the three shipped delegation carriers — `skills/deliver/SKILL.md`, `skills/gate-check/SKILL.md`, `docs/deliver-reference.md` — must each name the new phrase verbatim in this same change, or the gate reds on a probe this FR never mentions. No ceremony-PR prompt is registered at all, which is what keeps AC.5 honest: AC.8's override leg uses a discarded probe entry, the way AC.4's does.

## Technical Design

New entries in `GATE_REGISTRY` (`adapters/_shared/src/gate_class.ts:195`), beside the existing mechanical block, each declared through the same `gate(id, class, summary)` constructor. The existing `deliver_decision` entry is the model to follow: it documents why it is registered and what registration does *not* change, and warns that a guard hit overrides the declared class.

This costs no `SKILL.md` lines. Gate ids appear in no skill prose, which matters because `skills/implement/SKILL.md` sits at 358 of a 358-line cap and carries three of the prompts.

The fail-closed default is what makes this safe: `relayRequired` at `:494` returns true whenever `delegation?.active !== true`, so a run with no delegation is unchanged whatever the class says. Registration widens what an operator *can* delegate; it delegates nothing by itself.

## Testing

Extend the shipped gate-class suite rather than adding a parallel one, so the new entries are graded by the assertions that already grade the old.

- AC.1 — per prompt, assert `classifyGate` returns the declared class and not `content`. A leg asserting only "not content" would pass on a typo that landed it irreversible.
- AC.2 — per prompt, a paired assertion: `relayRequired(gate, activeDelegation) === false` and `relayRequired(gate, null) === true`. Both halves, per prompt.
- AC.3 — assert the pre-existing expectation count is unchanged, and that an undelegated end-to-end run asks the same questions it asks today.
- AC.4 — declare a probe entry naming a guarded action as mechanical and assert it resolves irreversible anyway, then discard it. This asserts the override still fires rather than trusting that it does.
- AC.5 — run every new summary through the guard and assert no match.
- AC.6 — the count pin moves with the entries, asserted against the registry's length.
- AC.7 — mutation per entry: remove it, assert that prompt's delegated leg reverts to requiring a relay while its siblings do not.
- AC.8 — add the `open_pr` guard, then assert the three unguarded phrasings above now match it and that a ceremony-PR prompt declared mechanical resolves irreversible through the AC.4 override path. Drop the guard and assert both legs revert. The guard's own count pin moves with it, like AC.6's.

## Notes

**The operator's standing rule is that outward gates are never relayable, while local gates are.** Registration must not quietly cross that line, and AC.8 is what stops it.

Registration is the cheapest repair here and the only one touching no prose, worth doing even though it fixes nothing alone. An operator who has said nothing still gets asked everything.
