# New tests prove they can fail for their reason

## Summary

A new test can pass before the code exists and still guard nothing.
The test-driven flow now plants the smallest bug the test should catch and requires the test to go red.
A test that stays green halts the run with its own report and no retry.
This lands an outside contribution on current main.
It also reconciles three freezes that main added after the work began.
It closes the test gaps a review found in the new parsing code.

## Requirement

Land PR #121 on current main with its defect check, its parser fixes and its halt and resume reporting; reconcile it with the three freezes main shipped since the PR was cut, as ruled by the operator; fold in the cleanup test's cache fix; and close every verified test gap and contract drift the rebase review confirmed.

## Acceptance Criteria

- AC-STE-738.1: During GREEN, `/tdd` runs a defect check for each AC: the implementer plants two different smallest bugs in the end state the AC's test reads, requires that test to go RED at its assertion under each, and restores the source unconditionally. A test that stays GREEN under both plants halts the cycle in failure mode `not-load-bearing` on its first occurrence, spends no retry budget, and gets no mode-B retry.
- AC-STE-738.2: Amends AC-STE-732.8 by name. The bun, pytest and flutter parsers read output with SGR codes stripped, pytest reads the last timed summary line, falling back to the last counter line, and flutter counters are anchored to a progress line's elapsed-time stamp. Each re-pinned fixture row in `tests/_m_b2fdc0_ste732_fixture.ts` carries `Amended by AC-STE-738.2`, and the v3.3.0 value stays on record next to it. A corpus output with no counters still refuses with v3.3.0's own reason text, byte for byte, on all three stacks. The STE-732 parser and mutation suites pass.
- AC-STE-738.3: Amends AC-STE-715.18 by name. The `skills/tdd/SKILL.md` freeze is re-based to the file's post-change digest, and the reason is recorded in the test. The neighbour control still rejects any one other changed line.
- AC-STE-738.4: `skills/implement/SKILL.md` is byte-identical to main at 58d211f8. The PR's /implement guidance (the e2e run that executed no test, the shallow-assertion list, the parking rule) lives in `docs/implement-reference.md`, and the AC-STE-722.8 suite passes unamended. *(Amended by AC-STE-738.13 (v3.5.0 fix round): byte-identical but for the three lines AC-STE-738.13 admits.)*
- AC-STE-738.5: The `cli()` helper in `smoke_session_cleanup.test.ts` runs its child with `BUN_RUNTIME_TRANSPILER_CACHE_PATH=0`, so the spawned process writes no bun cache under the synthetic `$HOME`.
- AC-STE-738.6: The bun parser reads a red first suite as red in every summary shape: coloured, Ran-line-only, and two suites. A counter line separated from the summary block by a blank line never reaches the counts.
- AC-STE-738.7: With several summaries in one pytest capture, every counter (passed, failed, errors, skipped) comes from the last timed summary line, falling back to the last counter line when no line is timed. A mixed capture whose first summary is red and whose last is green yields the last line's counts.
- AC-STE-738.8: A flutter progress line stamped `H:MM:SS` is counted like a `MM:SS` line.
- AC-STE-738.9: An end-to-end run with zero passes and at least one failure reads as a red suite, never as a run that executed no test.
- AC-STE-738.10: When a resume point exists, the halt report's Remedy line names that resume command alone: it drops the "re-run /tdd against the FR" clause and the mode list. An implementer halt with no AC names no `--resume-at`. A `not-load-bearing` halt prints its Context line.
- AC-STE-738.11: Two halts resume at `--resume-at audit`: a spec-reviewer halt in any failure mode, and an implementer halt during the audit retry round. ACs that are already GREEN are never re-dispatched.
- AC-STE-738.12: Each fix in AC .5 to .11 has a test, and removing that fix turns the test red. The full serial suite shows 0 failures, and its skip identities match main's baseline by name.
- AC-STE-738.13: Amends AC-STE-722.8 and AC-STE-738.4 by name. /implement accepts --resume-at and passes it to /tdd; every surface that names the resume command names one that parses it. Three `skills/implement/SKILL.md` lines are admitted, each as one exact edit with its own negative control: the argument-hint gains `[--resume-at <AC-id>|refactor|audit]`, Phase 2 step 8 always passes `entry: implement` to `/tdd`, so a first run's halt names `/implement` too, and passes the flag when given, with a pointer to `docs/implement-reference.md` § Defect checks, resuming a halt and parked tests, and step 14 points at the end-to-end `advisories` → `follow_ups` rule. The line count, the line cap and the STE-token count are unchanged.

## Technical Design

The contributor's code and prose land as rebased. The defect check halts only when the test stays GREEN under two different plants. The PR also brings `/implement` resume commands and the `refactor` resume point. The parser conflict keeps main's six-stack switch and its wrong-runner refusal on raw output, and strips SGR codes only for bun, pytest and flutter. The amendments re-pin rows rather than delete them, so the v3.3.0 values stay readable in the tests. The /implement prose moves to the reference doc and SKILL.md returns to main's bytes. The halt-report changes live in `tdd_halt_report.ts` and the SKILL.md resume table.
