# Orchestration config: ## Orchestration CLAUDE.md block + reader helper

## Summary

Orchestrated delivery needs two operator-controlled knobs: how hard spawned workers think, and what happens to a finished pull request. This adds a small optional configuration block to the project instructions file with exactly those two settings, read through one shared helper with loud, well-shaped errors. A missing block simply means the defaults, so existing projects change nothing and no migration is needed. The delivery pipeline consumes the helper; nothing else changes behavior.

## Requirement

A closed-schema `## Orchestration` CLAUDE.md block (`default_effort`, `merge_policy`) with a single reader helper `readOrchestrationConfig(projectRoot)`; absence ≡ defaults (`ultracode`, `offer`); invalid values and unknown keys refuse loudly in the NFR-10 canonical shape. Consumed by `/deliver` (STE-464).

## Acceptance Criteria

- AC-STE-463.1: New module `adapters/_shared/src/orchestration_config.ts` exports `readOrchestrationConfig(projectRoot)` → `{ defaultEffort, mergePolicy }`; absent block, absent heading, or absent CLAUDE.md ⇒ defaults `{ ultracode, offer }`; pure file reads — no git, no network.
- AC-STE-463.2: `default_effort` accepts the closed set `low|medium|high|xhigh|max|ultracode` (default `ultracode`); an invalid value refuses in NFR-10 canonical shape naming the offending line and the legal set — never a silent fallback.
- AC-STE-463.3: `merge_policy` accepts `offer|auto|never` (default `offer`); `auto` is never inferred — only the literal `merge_policy: auto` line enables it; every other state asks.
- AC-STE-463.4: Unknown top-level keys inside the block refuse in NFR-10 canonical shape (closed schema from day one, task-tracking-canonical-keys precedent).
- AC-STE-463.5: Reads are CRLF/BOM-normalized; a Windows-authored CLAUDE.md parses identically.
- AC-STE-463.6: `templates/CLAUDE.md.template` gains a commented `## Orchestration` stub documenting both keys and defaults (STE-167 shape); no /setup interview change; `migration: none` holds (absence ≡ defaults).
- AC-STE-463.7: Test file covers defaults / each key parse / each refusal / CRLF-BOM, with each guard mutation-verified (flip a condition ⇒ red).

## Technical Design

Single reader in `adapters/_shared/src/`, house section-scan idioms (`normalizeFrontmatterSource` sibling), closed enums as exported consts so STE-464 and tests share the same authority. No new probe — the block is optional and self-defaulting; refusals fire at read time in consumers.

## Testing

`bun test` from `plugins/dev-process-toolkit`; new `orchestration_config.test.ts`; mutation-verify each enum guard and the absence-default path.

## Notes

- Precedents: STE-167 (config-block shape, user edits win), STE-321 (closed-schema refusals), the 16-reader CRLF/BOM sweep (2026-07-26).
- Operator decision (2026-08-15): `merge_policy` default is `offer` — automatic merging must never happen unless the literal `auto` value is configured.

## Implementation notes

- `orchestration_config.ts:77-80` rolls a local `normalize()` instead of `normalizeFrontmatterSource`; a CR-only CLAUDE.md silently reads as absent-block (defaults) — safe direction; follow-up candidate.
- `orchestration_config.ts` heading match is byte-exact — `## Orchestration ` (trailing space) reads as absent-block rather than refusing.
- Key regex `^[a-z_]+:` silently skips mixed-case keys (e.g. `Merge_Policy: auto`) — never enables `auto`, but softer than the closed-schema spirit.
