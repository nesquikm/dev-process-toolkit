# Newly introduced skips are red; pre-existing skips are not

## Summary

Demanding zero skipped tests would fail this repository on the day it shipped, and every other repository with a legitimately disabled test. What the operator actually asked for is narrower and more useful: the skips that were already there are fine, and the ones this change introduced are not. That requires remembering the count from before the work started.

## Requirement

A skip count is compared against a baseline captured at the branch point, and only an increase fails.

## Acceptance Criteria

- AC-STE-509.1: A skip baseline is captured at the branch point and stored under `.dpt/` through the shared path module.
- AC-STE-509.2: The delta is current minus baseline; positive fails, zero or negative passes.
- AC-STE-509.3: An absent baseline yields a distinct `unmeasured` outcome that must be surfaced — it is never rendered as a clean pass.
- AC-STE-509.4: The baseline is written at branch creation and never refreshed mid-run.
- AC-STE-509.5: Guards are mutation-verified — a baseline reader stubbed to zero and an inverted delta comparison each go RED.

## Technical Design

The operator's rule, stated verbatim in the design session, is that skips count against a run "only if they already were, not ones this change introduced". That is a ratchet, not a threshold, and it needs one remembered number.

AC.1 puts that number under `.dpt/` through `dpt_paths.ts`, which M104 established as the single source of truth for that layout. The branch point is the right capture moment because it is the last state that is unambiguously not this change's doing.

AC.3 is the fail-open guard and it is the reason this FR is not simply arithmetic. The tempting implementation reads a missing baseline as zero, which makes every pre-existing skip look newly introduced — loud but wrong — or reads it as equal to current, which makes every new skip invisible — quiet and much worse. Neither is acceptable, so absence gets its own outcome that must be surfaced. M129 shipped two Tier-1 guards fail-open; this is the clause written to prevent a third.

AC.4 forbids mid-run refresh. A baseline that updates as the run proceeds always reports a zero delta, which is a guard that cannot fail — the vacuity M127's harness caught six times in its own machinery.

AC.5 names both mutations explicitly rather than leaving the implementer to choose them, because these two are the ones that produce a green guard over a broken predicate.

## Testing

Delta coverage across positive, zero and negative, each asserted to the right verdict. Absent-baseline coverage asserting the `unmeasured` outcome and asserting it is not rendered as a pass — the second half is the one that matters and must be asserted directly. AC.4 asserted by running a capture twice within one run and confirming the baseline did not move. AC.5's two mutations each run and each asserted RED. `bun test` full root.

## Notes

This repository is the motivating case for the ratchet rather than a threshold: a zero-skip rule would have reddened it on the day the rule shipped.

The `unmeasured` outcome is deliberately a third value rather than a boolean. Collapsing it into either pass or fail is the defect the criterion exists to name.

## Implementation notes

- Shipped-but-unconsumed at FR close: STE-510 is the stated consumer. The milestone-level review later found NOTHING was calling `captureSkipBaseline` at all, so the ratchet was permanently unmeasured; closed in the cross-FR hardening commit.
- `.dpt/.gitignore` covered only `ledger/` and `scratch/`, so a real baseline file would have been tracked and committable — a stale baseline from another tree would silently change the verdict. Added to both the shipped constant and this repo's own copy (underspecified backfill; no AC covered it).
- `mutateInRegion` is called with the whole-document region, so its siting protection degrades to whole-document uniqueness. Still throws on absent/ambiguous anchors, so no vacuity — the region argument simply buys nothing at that call site.
- The AC.3 render pin uses `not.toContain('pass')`, which would also reject a legitimate 'bypass'/'passed'. Fragile but currently correct.
