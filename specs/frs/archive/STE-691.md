# A numbered Jira milestone has no children to grade

## Summary

A project can share one Jira space with other projects.
In such a project the release step checks the child issues of the milestone's Epic.
A milestone with a plain number has no Epic, so it has no child list to give.
The release step still asked for that list and refused to go on.
Now it treats such a milestone as having no children and says so.

## Requirement

### Steps to reproduce

1. In a repository bound to a shared Jira container (`repo_tag` set), archive a numeric milestone `M<N>` with one FR.
2. Run `bun run adapters/_shared/src/sibling_release.ts <root> specs/plan/archive/M<N>.md M<N>`.

### Expected

Exit 0, with a stderr line saying the milestone has no tracker container.

### Actual

Exit 1: "M<N> is released from a shared tracker container, so refusal #4 must grade its children", demanding `--children`.

## Acceptance Criteria

- AC-STE-691.1: Regression: `tests/m_7a948e-ste-691-numeric-jira-children.test.ts › a numeric Jira milestone in a shared container passes refusal #4 with no --children` fails before the fix and passes after it.
- AC-STE-691.2: In a repository whose shared binding uses the Jira adapter, `sibling_release.ts` given a numeric `M<N>` milestone and no `--children` exits 0 (when no sibling refuses) and prints `children=none (no container)` on stderr in place of the `children=` count.
- AC-STE-691.3: The same numeric milestone given `--children <file>` is not graded against the listing, and prints the same `children=none (no container)` line.
- AC-STE-691.4: An `M_<epic-key>` milestone under Jira, and every milestone under a Linear shared binding, still refuse without `--children` exactly as before.
- AC-STE-691.5: The `--offer` path prints `children=none (no container)` for a numeric Jira milestone.
- AC-STE-691.6: `skills/ship-milestone/SKILL.md` refusal #4 says `--children` is not required for a numeric milestone under a Jira shared binding.
- AC-STE-691.7: Removing the numeric-Jira branch reddens the regression test.
- AC-STE-691.8: `bun test` from `plugins/dev-process-toolkit` reports 0 failures, and its skip identities equal the trunk baseline by name.

## Technical Design

### Root cause

The front door decides "grade children" from the shared binding alone. STE-523 already routes a numeric token under the Jira `epic` binding to the label path with no parent Epic, so such a milestone has no child listing by construction. The fix classifies the token with `parseMilestoneToken` and skips the grade when it is numeric and the adapter is Jira.

## Testing

Front-door tests with a fixture repository bound to a shared Jira container and a shared Linear one, each with a numeric and a keyed milestone.
