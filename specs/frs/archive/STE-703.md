# The token-stats bridge claims only a brainstorm that wrote no specs of its own

## Summary

A new spec's token stats can borrow the most recent unclaimed design session on the same branch.
That covers a design session that ended before the spec was written in a separate one.
The borrowing today takes any such session, even one that went on to write its own specs.
So a fresh spec run took two earlier sessions' design work as its own.
This fix skips a session that ran the spec-writing step itself.

## Requirement

### Steps to reproduce

1. Write a ledger with two earlier sessions on branch `main`, each holding one brainstorm row and one spec-write row, and a current session holding only a deliver row.
2. Call `claimRowsForFR(root, { branch: "main", sessionLineage: ["sess-CUR"], brainstormClaim: "STE-9001" })`, then again for `STE-9002`.

### Expected

Neither call selects a row from the two earlier sessions, and none of their rows gains a `claimed_by` mark.

### Actual

The first call claims the newer earlier session's brainstorm, and the second claims the older one's. Both marks persist to the ledger.

## Acceptance Criteria

- AC-STE-703.1: Regression: `tests/m_9261c7-STE-703-brainstorm-bridge-foreign.test.ts › a session that wrote its own specs is never bridged` fails before the fix and passes after it.
- AC-STE-703.2: The detached-brainstorm bridge in `claimRowsForFR` excludes every session that has at least one `dev-process-toolkit:spec-write` row in the ledger. No row of an excluded session is selected or gains a `claimed_by` mark.
- AC-STE-703.3: A detached brainstorm session with no spec-write row is still bridged as today: the existing tests in `token-stats-render.test.ts` for the bridge, the AC-STE-396.8 cases and `token-stats-claim-persistence.test.ts` stay green unchanged.
- AC-STE-703.4: When the most recent unclaimed brainstorm session is excluded, an older eligible one is bridged, and the excluded session's rows stay unclaimed.
- AC-STE-703.5: Removing the exclusion turns at least one named test red.
- AC-STE-703.6: `bun test` from `plugins/dev-process-toolkit` reports 0 failures, and its skip identities equal the trunk baseline by name.

## Technical Design

### Root cause

The bridge's candidate filter checks skill, branch, an absent claim and that the session is outside the lineage. It never asks whether the brainstorm already fed specs written in its own session, so a finished session reads as detached whenever its rows are unclaimed.

The fix adds one conjunct to that filter: the session wrote no spec-write row. It matches the verifier's prototype, under which the 43 existing token-stats tests stay green.

## Testing

Ledger fixtures in temporary roots, the verifier's two-foreign-session shape and the eligible-fallback shape, plus a mutation control.

## Notes

Origin: verified M_a5dc12 follow-ups. The last release's spec run hit this live and two foreign claims were undone by hand.

## Implementation notes

- the spec-write exclusion set is built from the whole ledger, any branch — matches the AC wording (a spec-write row in the ledger); a cross-branch spec-write also excludes the session
