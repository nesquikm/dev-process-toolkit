# The smoke harness reaches what each fixture names and stays out of the operator's stores

## Summary

Several smoke fixtures pass or fail without reaching the thing they test.
One reuses a stub that the main chain has already built.
One binds a ticket that does not exist.
One stops at the wrong refusal, and one can never be reached headless.
Smoke children also write into the operator's notes and memory, and later runs inherit that memory.
This change fixes each recipe and keeps children inside the test project.

## Requirement

The smoke-test skill's fixtures 1b, 5b, 2, 3a, 3b, 13a and 14, its Phase 0.5, Phase 4 and child-spawn sections, and `capability_row_assert.ts`'s missing-capture handling are corrected so each fixture exercises its named subject.

## Acceptance Criteria

- AC-STE-824.1: Fixtures 1b and 5b use a stub for a feature that no FR in the chain has written, so the marker-absent `/spec-write` reaches its draft gate.
- AC-STE-824.2: `capability_row_assert.ts` exits 2 with one error line when the capture file is missing, for every expectation, `absent` included.
- AC-STE-824.3: Fixture group 2 binds a real ticket instead of the made-up ticket id. Its stage step creates one fixture ticket per run on the leg's own tracker (team STE, inside the run's own smoke project on Linear, so Phase 5's project-scoped sweep closes it; project DST on Jira), labelled `dpt-smoke` and bound to no milestone or Epic, and teardown closes it through the same label-scoped sweep as 3a and 3b. A failed create aborts group 2 with `fixture ticket not created`, never a made-up id. Sub-fixtures 2a and 2c expect probe #26's row to read `notes`, and 2b expects `fail`, graded through the row grammar; a test pins that the three expectations hold at least two different verdicts.
- AC-STE-824.4: The Phase 4 docs row reads the `docs:` block of `specs/settings.yaml` on a settings-file tree, and the `## Docs` section only on a legacy tree.
- AC-STE-824.5: The 3a and 3b recipes say how a tracker leg creates its tickets, and how teardown closes them.
- AC-STE-824.6: Fixture 13a satisfies `/setup`'s first-turn gate and asserts that the refusal which fired is setup-template's own.
- AC-STE-824.7: Group 14 reports `STE-492 runtime check: N/A (headless)` on a headless leg, and the roster counts it as n/a, not NOT-REACHED.
- AC-STE-824.8: Phase 0.5 deletes the test project's auto-memory directory, and every child prompt carries a preamble saying the child writes nothing outside the test project.
- AC-STE-824.9: The child-spawn section says that `claude … &` inside a shell function needs its heredoc or an explicit stdin redirect on the same line.
- AC-STE-824.10: `bun test` from `plugins/dev-process-toolkit` reports 0 failures, and its skip identities equal the baseline by name.

## Technical Design

Harness text changes in the repo-root smoke-test skill, plus one CLI branch in `capability_row_assert.ts`. Each AC has a contract test that reads the skill text.

## Testing

Contract tests per AC, and a CLI test for the missing capture.
