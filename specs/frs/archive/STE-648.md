# Docs name the in-place install and never an unregistered probe

## Summary

The hooks reference described only a copied install and claimed an update needs no action, which is false for a local-directory marketplace that loads the source tree in place.
It now describes both install shapes and what waits for a restart or a plugin reload.
The gate-check skill and the patterns doc stop calling the branch-gate module a gate-check probe, and the one frozen gate-check line that changes is admitted by name.

## Requirement

- `docs/hooks-reference.md` describes both install shapes:
  - A copied install from a remote marketplace lives under `$CLAUDE_CONFIG_DIR/plugins/cache/…`, and an update needs a restart or /reload-plugins.
  - A local-directory marketplace loads in place: CLAUDE_PLUGIN_ROOT is the source working tree, the running version and floor are read from its plugin.json, script bodies change at their next firing, and hooks.json registrations change only at session start or on /reload-plugins.
- `skills/gate-check/SKILL.md` and `docs/patterns.md` stop calling `commit_producing_skill_branch_gate` a /gate-check probe.

Covers B-8 (low) and B-9 (D-12, low). Per operator ruling R2 the D-12 sentence is corrected without registering the probe, and the AC-STE-618.8 gate-check freeze widens to exactly lines {120, 128}. Retires KNOWN DEFECT D-12 of STE-616: per R4 its bullet gains "Fixed in `STE-648` (v2.92.0)".
