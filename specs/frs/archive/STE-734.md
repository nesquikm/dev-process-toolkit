# A bug found after ship and before merge has a named route

## Summary

When a bug turns up after a milestone has shipped but before its branch merges, no documented route exists.
The gate's only advice is to change the milestone or unarchive the plan.
One project wrote the fix straight into the archive and skipped every check on active specs.
The layout guide now names the route: open a new patch milestone on the same branch.
The gate's remedy points at that route.

## Requirement

The toolkit documents one route for a bug found after a milestone shipped and before it merged, and the archived-milestone refusal names that route.

## Acceptance Criteria

- AC-STE-734.1: `docs/layout-reference.md` gains a section on a bug found after ship and before merge: open a new milestone with `/spec-write --bug` on the same branch, implement it, and ship it as the next patch release. The section says archived FRs and plans stay frozen, and that writing into `specs/frs/archive/` skips every check on active FRs.
- AC-STE-734.2: Probe #27's collision remedy names that route first, ahead of its current two options, and never suggests writing into `specs/frs/archive/`.
- AC-STE-734.3: A test pins the remedy text and the layout section, and removing either one turns it red.
- AC-STE-734.4: Probe #27's verdicts are unchanged on every existing fixture.

## Technical Design

Docs and one remedy string. The probe's detection logic does not change.

## Testing

A pin over the remedy text and the documented route; the existing probe #27 suite.

## Notes

Binding a new FR to a shipped but unmerged milestone was considered and rejected: it would thaw a frozen plan.
