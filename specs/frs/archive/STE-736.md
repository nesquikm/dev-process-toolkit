# Archived plans keep working links, and three messages say what they mean

## Summary

Archiving a milestone breaks its plan's links to its specs.
The links keep the depth of the old folder.
A settings value of "required" is refused without saying that "blocking" is the word for it.
The spec-commit probe never checks a commit that writes several specs at once.
The visual check gives no route when its browser helper refuses a local address.
Each of these gets a small, direct fix.

## Requirement

After archival every relative FR link in an archived plan resolves; the verify-mode refusal and docs name the right value; the spec-commit probe checks plural subjects; and the visual check names a route around a loopback refusal.

## Acceptance Criteria

- AC-STE-736.1: After `/spec-archive` or `/implement` milestone archival moves a plan into `specs/plan/archive/`, every relative link in that plan that targets an FR file resolves to an existing file. Links in active plans and in `specs/requirements.md` keep today's form.
- AC-STE-736.2: An archived plan whose FR link is already broken in the v3.3.0 shape (`../frs/archive/<id>.md` from inside `specs/plan/archive/`) is repaired on its next archival rewrite; a link that resolves today is never changed.
- AC-STE-736.3: `verify_mode: required` is still refused, in both the settings loader and the legacy loader, and the message says to use `blocking` for a check that blocks the commit; `docs/settings-reference.md` says the same. No value is accepted that is refused today.
- AC-STE-736.4: Probe #45 checks a latest commit whose subject starts `chore(specs): write FRs` exactly as it checks `write FR`: with an approval or audit marker in the body it passes, and without one it is flagged.
- AC-STE-736.5: `skills/visual-check/SKILL.md` says that when the browser helper refuses a loopback or private address, the check reaches the dev server through a non-loopback address or through the Chrome browser tools. It is edited in place without raising the line cap.
- AC-STE-736.6: Each of AC .1 to .5 has a test, and removing its fix turns that test red.

## Technical Design

The link rewrite computes each relative link from the file's own folder instead of swapping a fixed string. The other three changes are a message, a regex and a docs line.

## Testing

Temporary spec trees archived through the shipped helpers; loader refusal pins; probe fixtures with singular and plural subjects; a pin over the skill note.

## Notes

Origin: four low-severity items in one field report.

## Implementation notes

- Worker ruling (for operator review): /spec-archive's milestone procedure now moves the plan before the per-FR link rewrites, and its plan-only procedure calls a new `repairArchivedPlanLinks` after the move (audit and review findings against AC-STE-736.1); fragment and query suffixes are kept byte-for-byte.
- Worker ruling (for operator review): the AC-STE-736.6 mutation rows shipped unsited; the implementer filled only their find/replace fields.
- Advisory (left open): 24 archived plans still carry v3.3.0-shape broken links until a later archival rewrite touches them; titled links and backslash paths are not repaired.
- Worker ruling (for operator review): after approval, the full suite's probe #67 dogfood flagged Summary sentences over the 20-word cap; they were split in place with their meaning unchanged, and the ticket synced. AC text is untouched.
