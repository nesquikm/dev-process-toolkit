# Retire fixture assertions that contradict documented runtime behaviour (groups 4, 9a/9b)

## Summary

Two groups assert outcomes the system is documented never to produce. One expects an archive file after an invocation form that the same document twice states does not archive — the document contradicts itself, so the group cannot pass however well the run goes. The other requires a probe's message to appear word for word, while the surrounding tooling reformats every probe message into its own table. Both probes and both invocations behave correctly; only the assertions are wrong.

## Requirement

Each assertion is rewritten to check what the system does, or removed with its reasoning recorded. Where the document contradicts itself, one side wins explicitly and the other is corrected — never left for the next reader to arbitrate. This FR also repairs the group-4 grep that STE-477 retires the literal for.

## Acceptance Criteria

- AC-STE-488.1: The group-4 step-4 archive clause is reconciled with the two passages stating this invocation form does not archive; exactly one account survives in the document and the other is corrected, not merely annotated.
- AC-STE-488.2: Group 4 passes on a healthy run — the other three step-4 clauses, which already passed on both legs, keep passing.
- AC-STE-488.3: Groups 9a and 9b are re-keyed onto what `/gate-check` actually renders, or onto the probe's own output read directly from the module.
- AC-STE-488.4: Both probes' own behaviour is byte-unchanged — nothing in this FR touches the systems under test.
- AC-STE-488.5: The propagation-commit greps at SKILL lines 998 and 1006 are updated to STE-477's new fixed-length subject, so the M126 change does not silently break group 3a.
- AC-STE-488.6: STE-483's harness proves each rewritten assertion fails when its subject genuinely misbehaves.

## Technical Design

Group 4 (F4) is an internal contradiction, and the document states both sides plainly. Step 4 asserts `specs/frs/archive/<id>.md` exists after `/implement <id>`; the Phase 2 step-3 advisory (STE-181) says the driver "intentionally uses the `<feature-id>` form … which silent-skips Phase 5" and that the resulting `status: active` "is correct, not drift"; a third passage says outright "There is no archive commit on this leg." Measured on both legs: implementation commit landed, gate green, ticket Done, archive file correctly absent. The advisory side is right and the assertion is the error.

Groups 9a and 9b (F10) require verbatim probe messages. Both probes fired correctly and drove `GATE FAILED`, but `/gate-check` reformats their output into its own table. Running each module directly confirms the source emits the canonical string, so this is a presentation-layer gap and the assertion is keyed on the wrong surface.

AC-STE-488.5 is the cross-milestone coupling from STE-477. M126 ships first, so by the time this FR is implemented the new subject is already on main.

## Testing

Group 4 and groups 9a/9b run against healthy captures (expect pass) and misbehaving-subject captures (expect fail) via STE-483's harness. Group 3a's propagation grep run against a capture carrying STE-477's new subject. `bun test` full root.
