# Import, backfill and drift leave archived, legacy and sibling work alone

## Summary

Importing a ticket that an archived FR already binds silently minted a second, active copy of it.
Import now refuses any key a local FR binds, active or archived, before it reads the tracker or writes anything.
In a shared repository, reconciliation stops reporting a sibling's milestone as a mismatch, and the milestone-label backfill leaves alone FRs keyed outside the bound project.

## Requirement

- **Import.** importFromTracker refuses a tracker id that a local FR, active or archived, already binds by frontmatter, whatever the filename. It refuses before any tracker read, prompt, file write or sync.
- **Reconcile in a shared repository.** reconcileTrackerLocal treats a tracker milestone that no local FR or plan claims as a sibling's: it goes to `skippedMilestones` and is not reported as a mismatch. A claimed milestone is graded against active and archived plans.
- **Backfill.** backfillMilestoneLabels skips a Jira-bound FR whose key lies outside the bound project and reports it in a new bucket.

Covers C-LEG (medium), C-RECON (low) and C-BACKFILL (low).

## Technical Design

`readLocalFRBindings(specsDir, { includeArchive: true })` returns archive entries as `archive/<name>`; the default stays non-recursive so findDuplicateLocalBindings is unchanged (the next FR reuses the option). importFromTracker scans bindings before ownershipLabels, getMetadata and promptMilestone; both refusals name the file, and the archived-hit refusal also names the reopen route. ReconcileOptions gains `shared?`, used only on the tracker-side direction. Backfill keys its check on the FR's own trackerKey === 'jira', not resolveMilestoneBinding, and adds an `outOfProject` bucket. One in-place rewrite of the SKILL.md section-0.5 line covers import and reconcile.
