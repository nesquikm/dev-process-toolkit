# STE-428: Make /report-issue renderable and reliably covered in Phase 8 {#STE-428}

## Summary

The first-turn phase cannot currently produce a trustworthy verdict for the issue-reporting skill, for two unrelated reasons, and on this run each leg hit a different one.

On one leg the skill behaved exactly right: it assembled the payload, ran its evidence check, scrubbed secrets, declined to publish because pushing a secret gist is an irreversible third-party action, and emitted its refusal capability row. No gist was created. But its output carries none of the canonical refusal marker the stream parser looks for, so the assertion resolves to vacuous — which the runner treats as a failure by design, on the reasonable principle that a skill which did nothing cannot read as compliant. A correct refusal is therefore unrenderable as a pass.

On the other leg the spawn was denied outright by the classifier before the child even started, so that leg produced no fixture at all and the phase silently covered three of four skills. The denial looks nondeterministic rather than structural, since the other leg's equivalent spawn went through.

## Requirement

A correct publish refusal MUST render as a structured pass, and the phase MUST assert that all four in-scope fixtures exist before reporting an aggregate verdict.

Observed 2026-07-27:

- **Linear leg.** `/report-issue` emitted `report_issue_publish_refused` with `refusalReason: "publishing a secret gist is an irreversible push to a third-party service."` and created no gist. Its assistant text contains zero occurrences of `<dpt:requires-input-refused>v1</dpt:requires-input-refused>`; the 2 raw-fixture hits are SKILL prose it had read. `parseStreamJsonTranscript` projects a `refusal` entry only on that marker, a `system/refusal` event, or `stop_reason: "refusal"` — none present — so with `projectRoot` supplied the outcome is `vacuous` and the runner exits non-zero.
- **Jira leg.** The fourth Phase 8 spawn was denied by the auto-mode classifier before the child started. The leg deliberately did not reword to get around the denial. Phase 8 therefore covered 3 of 4 in-scope skills, and the aggregate verdict did not say so.

## Acceptance Criteria

- AC-STE-428.1: When `/report-issue` refuses to publish, its assistant output carries the canonical refusal marker, so the stream parser projects a machine-recognizable refusal rather than `vacuous`.
- AC-STE-428.2: A fixture built from the 2026-07-27 Linear-leg transcript scores `ok-refused` after the change, where it scores `vacuous` before it.
- AC-STE-428.3: Phase 8 asserts all four in-scope fixtures exist before emitting its aggregate verdict, and a run that produced only three reports the missing skill by name instead of an aggregate pass.
- AC-STE-428.4: The phase can exercise `/report-issue` without requiring an irreversible third-party publish — via a dry-run mode, a recorded standing authorization for the smoke context, or an equivalent — so coverage does not depend on classifier variance.

## Technical Design

AC-STE-428.1 is a marker-emission fix at the refusal site: the skill already routes the decision correctly and already emits its capability row, so the gap is that the row is not the token the parser recognizes as a refusal.

AC-STE-428.3 is a counting assertion in the phase's aggregate step — cheap, and it converts a silent coverage loss into a named one.

AC-STE-428.4 is the open design question. A dry-run mode is the cleanest: it exercises everything up to the publish boundary and stops there, which is what the phase actually wants to test. A standing authorization would work but widens what the smoke context is permitted to do outward.

## Testing

- Replay the recorded Linear-leg transcript per AC-STE-428.2, asserting the verdict flips.
- A three-of-four simulation per AC-STE-428.3 asserting the missing skill is named.
- Coverage for the dry-run path per AC-STE-428.4, including that no outward publish occurs.

## Notes

Merges two findings — a marker-emission gap recorded by the Linear leg and an intermittent classifier denial recorded by the Jira leg — because both make the same phase's verdict for the same skill untrustworthy, and fixing only one leaves it untrustworthy.

The intermittency is the part that deserves care: a hard block is honest, whereas a run that silently covers three of four skills reads as full coverage.

**Implementation limitation on AC-STE-428.4 (recorded at implementation, needs confirmation).** The dry-run mechanism ships and performs no outward publish, but the AC's trailing purpose clause — "so coverage does not depend on classifier variance" — is **not** delivered, and the driver prose now says so rather than claiming otherwise. A `--dry-run` spawn is exactly as deniable as the spawn denied on 2026-07-27: the flag makes the run's intent legible at the classification boundary, but nothing forces an allow. What actually removes the silent-failure mode is AC-STE-428.3's four-fixture coverage gate, which converts a denial from "silently covered three of four" into a loud named failure. So the mechanism half of AC.4 is met and the determinism half is met only indirectly, by AC.3. Closing it properly needs a standing authorization for the smoke context — the alternative the AC itself offers — which widens what that context may do outward and was judged to want its own decision rather than being taken here.
