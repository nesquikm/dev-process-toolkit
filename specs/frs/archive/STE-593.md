# A smoke run's session debris is found by identity and removed by exact path

## Summary

A conformance run that looped on 2026-09-11 left almost fifteen hundred dead sessions across ten places on disk.
The hand-built scripts that cleaned it up lived only in a temporary directory that the next reboot erases.
This adds one deterministic cleanup: it assembles a run's sessions from the spawn ledger and from time-window inference, leaves live and kept sessions alone, shows what it would remove, and removes only those files.
Afterwards it checks that nothing it named survived.

## Requirement

A new module in the shared adapters, with a command-line front door, plans and removes the session debris of one `/smoke-test` or `/conformance-loop` run. Its session set is the union of the run's spawn-ledger ids (STE-594) and ids inferred from a time window, minus live sessions and ids passed as kept. It is dry-run by default, removes only exact planned paths re-validated at delete time, and verifies afterwards that nothing it planned survived. It never deletes a live or kept session's files, a run's findings file or approval record, or any `.claude.json` backup.

## Acceptance Criteria

- AC-STE-593.1: The run set is the union of the spawn ledger's session ids for the run and window-inferred ids. Inference admits a session born inside the window whose transcript has entrypoint `sdk-cli` and a first user message invoking `/smoke-test`, or a session with no transcript in any config dir whose only evidence is an empty `session-env` dir, an MCP log whose `cwd` is a run cwd, or a telemetry file whose events are `sdk-cli` and non-interactive. A session registered live (`sessions/<pid>.json` whose pid answers `kill -0`) or passed as kept is never in the set.
- AC-STE-593.2: For the run set the plan lists exactly the paths the set owns in ten stores and nothing else: the transcript and its subdir; the `session-env` dir; `telemetry/1p_failed_events.<sid>.*`; MCP logs whose first `sessionId` is in the set; shell snapshots born in the window that no live process's command line names; `.claude.json.tmp.<pid>.*` orphans no process holds; marketplace `<name>.bak` and `plugins/cache/temp_git_*` orphans that no plugin state file names; cmux registry `.tmp` orphans no process holds; and an empty, unheld `.zcompdump-*.lock` dir. `.claude.json` and every `.claude.json.bak*` are never planned.
- AC-STE-593.3: Without the delete flag the command deletes nothing and prints, per class, the count and bytes a delete would remove; on an unchanged tree a delete removes exactly those counts.
- AC-STE-593.4: The delete path expands no glob. Each removal is an exact planned path re-validated against its rule and a fresh live-session read at delete time; afterwards every planned path is re-listed and any survivor makes the command exit non-zero naming it.
- AC-STE-593.5: Token-ledger rows whose `session_id` is in the set are removed by a compare-and-swap rewrite: every other line is written back byte-for-byte, the file is re-read and compared before the rename, a hook write in between makes it retry, and afterwards zero run rows remain while every other session's rows are unchanged.
- AC-STE-593.6: Given a pre-ledger run's window, manual mode also plans the whole transcript dirs whose cwd slug is a `dpt-test-project-*` path, together with those sessions' `session-env`, telemetry and MCP-log files.
- AC-STE-593.7: The report names what it deliberately leaves: cmux registry rows and workstream lines that name run sessions (never edited while cmux runs), OS crash reports, and the bun install cache.
- AC-STE-593.8: A tandem fixture proves scope: cleaning run A leaves a concurrent run B's files, an interactive session's files, a live session's files, and run A's findings file and approval record untouched.
- AC-STE-593.9: On this machine, a dry run plans the 27 old `dpt-test-project-*` transcript dirs, and the delete then removes them with zero survivors (the operator's release bar).

## Technical Design

One module beside the other smoke adapters: pure per-store planners (a directory listing in, owned paths out), a run-set builder, an executor that removes exact paths and re-lists them, and a front door taking the window, kept ids, config dirs and a delete flag. Store roots come from every config dir in play and from the CLI cache keyed by `cwdToSlug`. The ledger rewrite resolves `ledgerPath` and keeps raw lines, closing the lost-update gap left open since STE-344. The 2026-09-15 prototype and its four-lens verification are the reference behaviour.

## Testing

A synthetic home in a temp dir, populated in all ten stores for run A, a concurrent run B, an interactive session and a live one. Assert the plan, the dry-run output, the exact-path delete, the survivor check, the compare-and-swap retry when a write lands between read and rename, and scope through the tandem fixture. One mutation control per store: a foreign session's file fed to each planner must not be listed.

## Notes

Measured 2026-09-15: 1,129 transcripts against 1,494 session ids, so transcripts alone undercount. Shell snapshots and config temps carry no session id; they are attributed by birth time and liveness only, and the report says so.
