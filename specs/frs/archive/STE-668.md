# Simulator and emulator recorders

## Summary

Mobile projects record demos from a booted iOS simulator or Android emulator.
The project's own driver, such as a UI test, plays the shot while the toolkit records.
Recording stops cleanly so the file is complete, and the driver can mark moments like the web recorder.
Missing tools, no booted device, and Android's three-minute limit each stop the run with a clear remedy.

## Requirement

- **iOS.** `recorder.kind: ios-sim` runs `xcrun simctl io <device> recordVideo --codec h264 <clip>` (device from config, default `booted`), starts the shot's driver command, and stops recording with SIGINT after the driver exits, waiting for the file to finalize.
- **Android.** `recorder.kind: android-emu` runs `adb shell screenrecord` to a device path, starts the driver, stops the recording, and pulls the file into the clip path.
- **Driver.** Each shot names an argv driver command; it receives the same environment variables as the command recorder and may write markers to `DPT_VIDEO_OUT_MARKERS`.
- **Limits and preflight.** Missing `xcrun` or `adb`, or no booted device, refuses before recording; an Android shot whose duration hint exceeds 180 seconds refuses with the limit named.

## Acceptance Criteria

- AC-STE-668.1: With an injected spawner, `ios-sim` issues `xcrun simctl io booted recordVideo --codec h264 <clip>`, then the driver argv, then SIGINT to the recorder after the driver exits, and waits for the recorder process to exit before validating; the order is asserted from the spawner's log.
- AC-STE-668.2: With an injected spawner, `android-emu` issues `adb shell screenrecord <device-path>`, the driver argv, a stop, and `adb pull <device-path> <clip>`, in that order.
- AC-STE-668.3: The driver receives `DPT_VIDEO_SHOT`, `DPT_VIDEO_SCENARIO`, `DPT_VIDEO_OUT_CLIP` and `DPT_VIDEO_OUT_MARKERS`, the same constant the command recorder uses; markers it writes reach the markers file.
- AC-STE-668.4: `xcrun` or `adb` absent from `PATH`, or a device listing with no booted device, refuses before any recording starts, naming the tool or the device check.
- AC-STE-668.5: An `android-emu` shot with `durationHint` over 180 refuses before recording, naming the 180-second screenrecord limit.
- AC-STE-668.6: A driver that exits non-zero still stops the recording, then refuses naming the shot and quoting its stderr tail.

## Technical Design

Two recorders implementing the shared contract, both built on the injected spawner so tests record argv and signals without devices. The driver environment reuses the command recorder's exported variable constant.

## Testing

Injected spawner logs for command order and signals; device-listing fixtures for preflight; no real simulator in the gate.
