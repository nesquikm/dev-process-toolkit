# The PR-title rule states two things that are not true

## Summary

The rule that decides pull-request titles names a release branch to pick the dominant commit from. No such branch has ever existed here. It then claims the title and the squash subject both validate against the commit message hook, which is a local hook that never sees a merge authored on the host.

Both clauses are wrong under any title convention, so correcting them settles nothing about which convention applies. Say what exists instead.

## Requirement

The pull-request title rule describes the branch shape this repository actually uses and states honestly what does and does not enforce the resulting commit subject. The convention itself is unchanged.

## Acceptance Criteria

- AC-STE-576.1: The Title bullet in `skills/pr/SKILL.md` no longer contains the string `on a release branch`. It names the branch's own `chore(release):` commit as the dominant commit when the branch carries one, and the primary feature commit otherwise.
- AC-STE-576.2: The Title bullet no longer claims the PR title and the squash-merge subject both validate against the commit-msg hook. It states the real constraint: squash merging is enabled with the title source set to the commit-or-PR title, so a squash promotes the PR title to a subject on the trunk — and it says plainly that the local hook does not enforce that.
- AC-STE-576.3: Both clauses are asserted through the existing `titleBullet()` reader, which slices the bullet between its shipped anchors, so the assertions are scoped to the bullet rather than to the file. Both fail before the change: the file carries both strings verbatim today.
- AC-STE-576.4: The four existing prose pins on that same bullet still pass unchanged — the derived-from-the-dominant-commit phrase with its curly-apostrophe alternation, the Conventional Commits mention, the word subject, and the no-user-supplied-override clause.
- AC-STE-576.5: No convention is sanctioned or forbidden by this change. The bullet gains no clause blessing or rejecting any non-Conventional-Commits title shape.
- AC-STE-576.6: The edit adds no tracker-ID token to the skill body, which is asserted by the existing pin, and does not touch the skill's frontmatter, whose `argument-hint` is byte-matched against a README cell.

## Technical Design

Two surgical clause replacements inside one bullet. The bullet is not restructured, because four prose pins slice it between fixed anchors and read substrings out of it.

The squash claim is replaced with a statement of the host setting rather than a guess about it: the repository allows squash merging and derives the squash subject from the commit-or-PR title, which is what makes a PR title able to land on the trunk. The local hook runs on commits authored in a checkout; a merge authored on the host never passes through it. Saying so is the correction — the risk being described is real, the mechanism named for it was not.

## Testing

Both assertions are absence assertions over a sliced region, which is the shape most at risk of passing vacuously: a slice that returned nothing would satisfy both. The arm therefore also asserts the slice is non-empty and still carries the four positive pins, so an empty or mis-anchored slice fails rather than reads clean.
