# Give the release-file writer a front door and make the closing line non-optional

## Summary

The module that writes the release files cannot be run. It carries no entry point and nothing outside its tests imports it, so the write step is carried out by hand.

The mandated closing line, stating the test count at release, is therefore typed from memory, and it has been typed wrong three times across one release.

Emitting it from the writer is not enough alone. A guard inside a function nobody calls changes nothing, so the door comes first.

## Requirement

The release-file writer carries a real entry point, and the ceremony's write step orders it rather than describing it. The closing line is rendered by the writer from a count it is given, and the writer refuses to produce the section without one. The count is forwarded from the run that already measured it rather than measured again, because the detector answers differently depending on which directory it is asked about.

## Acceptance Criteria

- AC-STE-545.1: `adapters/_shared/src/release_config.ts` carries an `import.meta.main` entry point that runs, prints a usable result on success, and refuses in the NFR-10 canonical shape on bad input.
- AC-STE-545.2: `skills/ship-milestone/SKILL.md`'s write step reads as an executable order naming that entry point, not as a description of what the module would do.
- AC-STE-545.3: `BumpOptions` carries the release test count, and `bumpChangelog` renders the closing line as the last line of the new section from that value — never from a literal typed into the module.
- AC-STE-545.4: The `changelog` kind refuses when the count is absent, so a section cannot be written without one.
- AC-STE-545.5: Exactly one renderer produces that line. The copy currently living in a test file is promoted into `test_count_parser.ts` and the test consumes the promoted one, so the two cannot drift.
- AC-STE-545.6: The count is forwarded from the gate run the ceremony already performed. A test pins that gate detection against the plugin directory returns nothing, so a re-detection at this point would silently yield an empty count.
- AC-STE-545.7: Landing the entry point flips this module's shipped references from descriptive to ordered without moving probe #81's pinned count, because the module is now reachable.

## Technical Design

`release_config.ts` gains an `if (import.meta.main)` block — the shape probe #81 already accepts — dispatching on the release-file kind and printing the rewritten path. `BumpOptions` (:24) gains `testCount`; `bumpChangelog` (:362) renders it as the final line of `newSection` after the body (:370); the `case "changelog"` guard (:406) refuses without it, alongside the three companions it already demands.

`renderClosingLine` moves out of the M132 skip-parsing test into `test_count_parser.ts`, which already owns the parse half, so render and parse sit together.

The door and the prose rewording land in one commit: reworded prose with no door turns three descriptive references into ordered-and-unreachable ones and reds probe #81.

## Testing

New `tests/m141-ste-545-release-writer-door.test.ts`, plus edits to the module's own suite.

- AC.1 — spawn the entry point as a subprocess: a valid invocation exits zero and prints the path; a malformed one exits non-zero with the canonical refusal. Assert on the process, not on an imported function, or the door itself is untested.
- AC.2 — a line-scoped conformance assertion on the write step, matching the imperative form and failing on the descriptive one it replaces.
- AC.3 / AC.4 — a section rendered with a count ends with the closing line byte-for-byte; the same call with the count omitted refuses. The refusal leg carries a positive control so it cannot pass by refusing everything.
- AC.5 — assert the test imports the promoted renderer rather than declaring its own, and that no second definition of that line exists anywhere in the tree. A zero-hit scan is a claim about the search, so run it for a token known to be present in the same test.
- AC.6 — assert gate detection against the plugin directory returns nothing and against the repository root returns the bun command, which is what makes forwarding necessary rather than stylistic.
- AC.7 — run the reachability probe over the working tree and assert its count is unchanged, with the module now classified reachable.

## Notes

The ordering is the whole design. Shipping the guard without the door was the tempting cut: it would have passed its own tests and changed nothing about the release that motivated it, because the path in use hand-edits the file and never calls the function the guard sits in.

## Implementation notes

- No typechecker exists in the gate — there is no tsconfig.json anywhere in the repo and bun strips types at runtime, so a type error in any adapter module is invisible to `bun test`. — Surfaced while verifying a refactor out-of-band with `bunx tsc --noEmit --strict`. Out of scope; recorded because every type-shaped guarantee this milestone relies on is unenforced by the gate.
- Pre-existing unnarrowed-union type error at test_count_parser.ts:195 — `Property 'count' does not exist on type 'TestCountParseResult'` in the M137 front door. — Confirmed present at HEAD, so it predates M141. Harmless under bun, live under any future typecheck. Left alone rather than widening scope.
- The `--dry-run` refusal parity is STRUCTURAL, not proven: one `dryRun` branch sits after every rewrite is computed so all nine refusal paths share it, but only two are pinned equal by test. — An early `if (dryRun) return`, or a later mode-scoped validation, would slip past both pinned verdicts. The durable fix is to table-drive the refusal matrix through both modes.
- renderUnifiedDiff omits the `\ No newline at end of file` marker — the limitation is recorded in its docstring rather than fixed — and the claim that every release file the door touches is newline-terminated is an operational assumption, not code-enforced, since bumpToml and bumpYaml preserve the source terminator. — Bounded and tested: the diff is human-read under --dry-run and never fed to `patch`, and a test enforces emit-it-or-admit-it. Recorded so the assumption is visible if the renderer is ever reused for patch input.
- docs/ship-milestone-reference.md's post-merge ceremony section never mentions the new step-7 release-surface agreement check, so the ceremony now lives on two surfaces that disagree by omission. — The sibling-surface class this repo has hit repeatedly. Not fixed here because that section is a pinned verbatim mirror of SHIP_CEREMONY_RECIPE and changing it needs its own mirror update.
