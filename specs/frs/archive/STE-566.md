# Instructions that misdirect an author or break a consumer

## Summary

Four findings that cost a wrong action, not a moment's confusion. Two are shipped bugs an audit found rather than a test.

The release ceremony invokes a docs flag pair the docs skill refuses; this repo never notices because its own docs modes are off. The Kotlin release example pins a pattern no real Gradle file can match, and refuses.

One doc tells authors the plugin never forks; seven do. Another tells setup to omit a section a probe demands.

## Requirement

The invocation `/ship-milestone` states is one `/docs` accepts, and the agreement is asserted from both sides rather than restated in two places. The Kotlin example matches a real `gradle.properties` while still failing loudly if it ever stops matching. The author-facing docs describe the delegation and docs-section contracts that ship.

## Acceptance Criteria

- AC-STE-566.1: `/ship-milestone` step 5 states two sequential single-flag invocations — `/docs --commit` first, then `/docs --full` — each with its own non-zero-exit → NFR-10 abort leg. The ordering is the only one under which both invocations do work: `--full` step 6 deletes every `docs/.pending/` fragment as superseded, so a `--full` that ran first would leave `--commit` nothing to merge.
- AC-STE-566.2: Every site in `skills/ship-milestone/SKILL.md` that states the composite form carries the corrected form instead — the frontmatter description (`:3`), the pre-flight expected-modified set (`:69`), the step-5 heading, run instruction, skip log and abort branch, the step-6 diff merge, and the two Rules bullets. Asserted by absence: the literal `/docs --commit --full` does not occur in that file.
- AC-STE-566.3: The agreement is asserted FROM BOTH SIDES by one reader, not by a pair of independent literals. A shared module extracts (a) the set of flags `skills/docs/SKILL.md` documents as mutually exclusive and (b) every `/docs <flags>` invocation form stated in a caller's body, and reports any stated invocation carrying two or more of those flags. The check derives the exclusive set from the `/docs` body rather than hardcoding `--quick/--commit/--full`, so a fourth flag added to `/docs` is covered without anyone remembering this FR.
- AC-STE-566.4: The same reader is run over `skills/ship-milestone/SKILL.md` in the suite and reports zero violations. Falsifiability: restoring `/docs --commit --full` to that body reds the assertion, and the mutation is routed through the throwing `mutate` helper so a pattern that stopped matching is a loud error rather than a green test.
- AC-STE-566.5: The downstream surfaces that repeat the composite string are corrected with it — `README.md`'s `/ship-milestone` table row, `specs/technical-spec.md`, `docs/ship-milestone-reference.md`, `docs/workflow-overview.md` (both the prose and the mermaid node), and the `tests/ship-milestone-shape.test.ts` assertion that pins it. Archived FRs and CHANGELOG history are left alone: they record what shipped at the time.
- AC-STE-566.6: `examples/kotlin/release.yml`'s `gradle.properties` pattern matches a realistic file whose `version=` key is NOT on line one. MEASURED, not reasoned: parsing the shipped file with the real `parseReleaseFiles` and feeding the entry to the real `bumpRegex` bumps `org.gradle.jvmargs=…\nkotlin.code.style=…\nversion=1.2.3` to `1.2.4`, and the retired `^version=` form is measured to throw `RegexPatternMissError` on that same input in the same leg.
- AC-STE-566.7: The entry stays NON-optional. Marking it `optional: true` would convert the miss into a silent skip under the STE-555 contract — a non-bump that reports success — which is a worse failure than the refusal it replaces. Asserted: the parsed `gradle.properties` entry has no truthy `optional`.
- AC-STE-566.8: The caret-pinning assertion in `tests/kotlin-stack-docs-config.test.ts` moves with the pattern rather than being deleted, and the line-one case still bumps — the fix widens what matches, it does not trade one blind spot for another.
- AC-STE-566.9: `kotlin` joins the executable fixture roster in `tests/release-config-fixtures.test.ts`, so the stack is parsed by the real parser alongside the other four rather than being covered only by string assertions.
- AC-STE-566.10: `docs/skill-anatomy.md` § Subagent Execution presents both delegation patterns as shipped — whole-skill `context: fork` paired with `agent:` for the seven fork children, enforced by probes #39/#50/#51/#54, and in-body `Agent`-tool invocation for mid-skill delegation — with a statement of which to pick when. Asserted by absence: the claims that the plugin "does not exercise" the frontmatter, that it is "unexercised in this plugin", and that "No skills in this plugin use this frontmatter" are gone.
- AC-STE-566.11: The count of fork-carrying skills the doc states is DERIVED from the tree, not recited: the assertion counts `skills/*/SKILL.md` files whose frontmatter carries `context: fork` and compares that number to the one the doc states, so an eighth fork child reds the doc rather than silently outdating it.
- AC-STE-566.12: `docs/setup-docs-mode.md` states the shipped write contract — on a decline-both re-ask `/setup` still emits the `## Docs` section with all-false defaults — and qualifies "absent section ≡ all-false" as a READ-side fallback carried by `readDocsConfig`. Asserted against the sibling that already states it correctly (`docs/setup-reference.md`) and against `skills/setup/SKILL.md`, from both sides, so the three cannot drift apart again. The NFR-10 remedy literal quoted in that doc is left byte-identical.

## Technical Design

The docs-invocation agreement gets a reader rather than a second literal. Every defect here is a statement about another file that nothing re-reads, so the fix that matters is the one that reds a test on the next drift.

The reader takes the exclusive flag set from `/docs`'s own body. That is what makes it an agreement check rather than a spelling check.

The Kotlin pattern moves from an anchor to a zero-width lookbehind, which consumes nothing, so the `replace` template and the preceding newline are unchanged. Deleting the `^` outright would also match `kotlin.version=`, which is why the lookbehind.

Optionality is untouched: the loud refusal is the feature, the pattern is the bug.

## Testing

The Kotlin leg executes both the shipped pattern and the retired one against the same realistic fixture in the same test. A test that only exercises the fix cannot tell a fix from a coincidence.

The docs-invocation leg is mutation-tested by writing the composite form back into a copy of the ship-milestone body and asserting the reader reds, so the assertion is proven able to fail on the exact text it was written against.

The absence assertions in `skill-anatomy.md` and `setup-docs-mode.md` are paired with a positive assertion of the replacement text. An absence check alone passes on an empty file.

## Notes

The `/docs` side of the contract is left as it is. Making `/docs` accept the pair would mean a second approval prompt semantics question inside one invocation, and the two-invocation form is what `/ship-milestone` already merges into its single gate.
