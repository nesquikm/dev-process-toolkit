# One translator reads every Atlassian write shape

## Summary

The newer Atlassian tools name some inputs differently.
A shipped Epic could never be closed through them.
One new module turns each call into a standard form.
The write gate and its live grader both read only that form.
The older tools keep working.

## Requirement

Every Atlassian write call, in the v1 or the v2 shape, is translated by one shared module into one canonical call before any rule of the tracker-write gate or the live grader reads it.

## Acceptance Criteria

- AC-STE-865.1: One shared module under `adapters/_shared/src/` maps a direct v1 or v2 Atlassian write call to one canonical call. `pre-tracker-write-gate.ts` and `shared_tracker_live_grader.ts` import it, and a test fails when either file reads `issueTypeName`, `issueType`, `additional_fields`, `transition`, `transitionId` or `transitionName` from a raw Atlassian write input.
- AC-STE-865.2: `isStatusOnlyTransition` is true for exactly one designator, a non-null `transition`, a non-empty string `transitionId` or a non-empty string `transitionName`, beside only `cloudId`, `issueIdOrKey` and `actionSource`. It is false for two designators, for an empty, non-string or missing designator, and for each of `fields`, `update`, `historyMetadata`, `sprintId`, `assignToBacklog`, `boardId` and an unknown key, one negative test each.
- AC-STE-865.3: With an intact `epic-close` receipt for the key announced in the session, the gate permits the close carrying `transitionId` and the close carrying `transitionName`, each through the shipped `.sh` wrapper. The no-receipt, wrong-key and extra-key twins refuse, the v1 `transition: {id}` close still permits, and the live grader gives the same verdict on each.
- AC-STE-865.4: `createJiraIssue` with `issueType` equal to Epic in any case is a milestone-container create in the gate and the live grader, and any other `issueType` is a ticket create. Top-level `labels` count on both surfaces. A call carrying both `issueType` and `issueTypeName` with different types is refused in a declared container.
- AC-STE-865.5: The `additional_fields` of a v2 `editJiraIssue` count as fields in `labelsEnvelope`, the Epic-edit check and every other edit reader, in the hook and the grader. A field named in both blocks, and any of `rankBeforeIssue`, `rankAfterIssue`, `rankCustomFieldId`, `inlineFileId`, `inlineFileCollection` and `inlineFileName`, refuses the Epic-edit and join-label routes.
- AC-STE-865.6: `addOrEditJiraIssueComment` is gated as `addCommentToJiraIssue` is, adding and editing alike, and an `issueIdOrKey` that is a browse URL resolves to its key on every ticket write.
- AC-STE-865.7: The `hooks.json` matcher is generated from the one write list and matches every v2 direct Jira write name under both server spellings, and every v1 name stays matched.
- AC-STE-865.8: Removing any one translated key or designator turns a named test red, shown by a mutation leg per key.
- AC-STE-865.9: `bun test` from `plugins/dev-process-toolkit` reports 0 failures, and its skip identities equal the trunk baseline by name.

## Technical Design

Add `atlassian_call.ts`: a pure function from tool name and input to a canonical tool name, canonical input and a list of keys it could not place. `identifyTrackerCall` and the grader's call reader apply it once at the entry, so the rules keep their v1 vocabulary. The existing `issueTypeName` and `transition` readers stay as they are, downstream of the translator. An unplaced key is kept, so each allowlist still refuses it.

## Testing

New suite on the STE-699 world fixture: permit and refuse twins for each shape through the `.sh` wrapper, the grader on the same transcripts, and the raw-key scan. Inputs use invented keys.
