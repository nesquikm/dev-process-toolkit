# Forked child skills' tokens reach the ledger

## Summary

The TDD and review forks run as separate agents, and their tokens never reach the ledger.
The ledger hook now reads each forked child's own transcript and joins it to the parent's Skill call.
The join relies on files that Claude Code does not document.
So any surprise writes nothing and leaves the parent rows alone.
A child that is still running is marked incomplete, and the trend says its tokens are not yet observable.

## Requirement

The token-ledger capture adds rows for forked child skills, joined to the parent session through the forked-skill marker files and the parent's Skill result, failing open on any shape it does not recognise.

## Acceptance Criteria

- AC-STE-812.1: For a parent transcript at `<dir>/<session>.jsonl`, the hook reads every `<dir>/<session>/subagents/agent-<id>.forked-skill.json` whose `skillName` is a string, whose `agent-<id>.jsonl` exists, and whose `<id>` equals the `toolUseResult.agentId` of a parent transcript line whose `toolUseResult.status` is `"forked"`.
- AC-STE-812.2: Each such child yields rows aggregated per (skill, model, FR) with `skill` = `skillName`, `session_id` = the parent session, and `scope: "fork"`. The FR is the STE-811 attribution of the parent line carrying that `toolUseResult`, and the rows are claimed as STE-811 claims (`claim_source: "run"`) when an FR results.
- AC-STE-812.3: A child whose `agent-<id>.meta.json` is missing or does not hold `finished: true` writes its rows with `complete: false`; otherwise `complete: true`. Parent rows carry neither key.
- AC-STE-812.4: The join fails open. A missing `subagents` directory, an unreadable or malformed marker or transcript file, a status other than `"forked"`, or an agent id with no parent match yields no rows for that child. An unreadable or malformed `meta.json` does not drop the child: its rows are written with `complete: false`, as AC-STE-812.3 marks an unfinished child, because a dropped child would make an incomplete total look complete. The parent rows are byte-equal to what STE-811 writes, nothing is printed, and the hook exits 0. (Amended by the PR #142 review: the meta file left the no-rows list.)
- AC-STE-812.5: A checked-in fixture reproduces the Claude Code layout seen on 2026-11-16 (synthetic ids and paths: marker, marker.json, meta.json and transcript per agent, plus the parent Skill line) and pins the join. One variant per AC-STE-812.4 no-rows case yields no child rows, and the unreadable and malformed `meta.json` variants yield the child's rows with `complete: false`. (Amended by the PR #142 review, with AC-STE-812.4.)
- AC-STE-812.6: The retro rule `cost_per_changed_line` reads only rows without `scope: "fork"`, so its parent-visible value is unchanged by child rows, and its reason text keeps naming its tokens parent-visible. The trend never shows an incomplete or parent-only total silently. Each `runs_detail` entry (STE-813) carries `tokens_scope`: `"incomplete"` when any of its rows has `complete: false`, `"parent-only"` when no ledger row of any of its sessions has `scope: "fork"` (so any forked children of those sessions were never captured, as on every pre-B ledger), else `"parent+fork"`. Its per-run `tokens` value (STE-814) is `null` for an `"incomplete"` run, with the note `tokens: fork tokens incomplete`. A group's `tokens` cell carries the note `includes <n> parent-only and <m> incomplete runs` whenever either count is non-zero.
- AC-STE-812.7: `docs/retro-reference.md` names the child-row source, the fail-open rule, the incomplete marker, and that the source is undocumented upstream.
- AC-STE-812.8: `bun test` from `plugins/dev-process-toolkit` reports 0 failures, and its skip identities equal the trunk baseline by name.

## Technical Design

A new `fork_child_tokens.ts` exports `forkChildRows(transcriptPath, sessionId, attribute)`, where `attribute` maps a parent timestamp to an FR (the STE-811 function). It reuses the token line walk on each child transcript, with every child line's skill forced to the marker's `skillName`. The ledger hook appends its rows after the parent rows, inside its own try block.

## Testing

The pinned fixture directory under `tests/fixtures/`, built from a recorded layout with every id and path replaced, plus generated variants for each fail-open case and an unfinished child.

## Notes

The source is internal to Claude Code and may change without notice. The fixture is what tells us when it does.

## Implementation notes

- a child transcript with only some malformed lines still yields rows from its good lines — parseTranscriptTokenUsage skips line by line; a wholly malformed transcript yields none
- a child's FR is attributed under the marker skillName at the parent Skill-result line's time — the parent line carries no attributionSkill, so the AC wording leaves the skill open
- the orchestrator's own run reads parent+fork when its session holds fork rows — tokens_scope is per session, literal to AC-STE-812.6
- the stale-run token median still pools parent-only totals of incomplete runs — AC-STE-812.6 asks for the note, not a changed median
