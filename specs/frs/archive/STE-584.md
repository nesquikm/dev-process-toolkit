# A spanning milestone waits for its sibling before it reads as ship-ready

## Summary

The moment one repository archives its last local work on a shared milestone, the gate calls the milestone ship-ready.
The close offer fires and the resume classifier routes to the release, though the other repository has not finished.
One predicate feeds all three, so one change fixes all three.
A spanning milestone whose sibling still has active work moves into a waiting bucket the gate shows as a note, and the resume chain orders nothing while it waits.

## Requirement

The active-plan classification must become an exported surface carrying awaiting-sibling and sibling-unlocatable buckets, read through the spanning reader only for a plan that would otherwise be ship-ready; probe 75 renders the new buckets as notes; the resume classifier reads that same single classification and emits no step while a sibling is busy; and the ship-ready CLI stream keeps its shape.

## Technical Design

The new branch sits inside the ship-ready test, in place of the push, so the stamp, parked, template-sentinel and zero-FR exclusions are reached exactly as today. A busy sibling demotes the token into `awaitingSiblings`; an unlocatable one adds a note and keeps the verdict. `resume_classifier` switches its one call to `classifyActivePlans` and returns an empty chain beside the shipped and parked early return. The CLI stream keeps its parsed shape, so the `/implement` offer goes quiet with no reason attached; the reason shows only at `/gate-check`. A malformed declaration on an otherwise ship-ready plan propagates its refusal through all three consumers. `ResumeState` is not widened.

## Testing

Write the resume-chain test first: demotion alone would drop the milestone into partly implemented, which orders the implement step and still appends the ship tail. Trees come from the shared span fixture.

## Notes

The close offer's silence is deliberate, because widening its output would break a parsed contract. Register no new probe to cover the soft window.

## Implementation notes

- Fixed in-flight (post-audit): the ship-ready CLI — the command the `/implement` close offer runs — died with an uncaught `SpansReposError` and a stack trace on a malformed declaration. - Fixed in-flight: the module header and the `shipReadyMilestones` docstring now name the busy-sibling demotion and the unlocatable note.
- Deviation, accepted: `ResumeClassification.awaitingSiblings` is OPTIONAL (absent reads as empty) because hand-built classifications in m129's tests and `continuation_offer`'s chain-shape fixture lack it; `classifyResume` always sets it.
