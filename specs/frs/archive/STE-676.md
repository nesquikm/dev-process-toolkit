# A merge or rebase commit is graded on its own changes

## Summary

The commit hook asks for TDD evidence for every staged test and FR file.
After a merge from main, that list holds tests main already shipped.
So the hook refused the merge and offered only a false proof or a bypass.
Now a file a merge or rebase brought in unchanged is waived, with a visible reminder.
A file changed by hand during conflict resolution still needs evidence.

## Requirement

- **Waiver.** While a merge or a rebase is in progress, a staged test or FR file whose bytes equal the version on the incoming side, or git's own merge result, is dropped from the paths that need evidence. Deletions count when the incoming side also lacks the file.
- **Visible.** A commit that passes only because of the waiver prints one reminder naming each waived file and the commit it matched. The waiver can be forged with a hand-made merge, so it must never be silent.
- **Still graded.** A file edited by hand during resolution keeps the requirement, and the refusal names only those files.
- **Fails closed.** A head that is not a commit, or a git call that fails, gives no waiver.
- **Not covered.** Squash, cherry-pick and revert keep today's behaviour, and the refusal says so.

## Acceptance Criteria

- AC-STE-676.1: With `MERGE_HEAD` present, a plain `git commit` and a `git merge --continue` both drop every tdd-required staged path whose index entry equals that path at any commit listed in `MERGE_HEAD` (octopus heads included); when nothing remains, the hook exits 1 with exactly one `Reminder:` naming each waived path and the head it matched, and the commit proceeds.
- AC-STE-676.2: A tdd-required path that both sides changed and git merged without conflict (index entry equals the `AUTO_MERGE` tree, or a `git merge-tree --write-tree` result when `AUTO_MERGE` is absent) is waived the same way.
- AC-STE-676.3: A path whose staged bytes match no merge head and not git's merge result still requires evidence: the hook exits 2 and the refusal names that path and no waived path. A mixed commit (one waived, one hand-edited) refuses.
- AC-STE-676.4: A path staged as deleted is waived when it is absent at some merge head; a rename on the incoming side is waived at its new path.
- AC-STE-676.5: During a rebase stop (`REBASE_HEAD` present and a rebase directory under `git rev-parse --git-path`), a plain `git commit` applies the same rule against `REBASE_HEAD`.
- AC-STE-676.6: Heads are read through `git rev-parse --git-path` and each line must resolve with `^{commit}`; the waiver works from a linked worktree and from a subdirectory; any head that fails to resolve, or any failed git spawn, disables the waiver for the whole commit and today's refusal stands.
- AC-STE-676.7: With no merge or rebase in progress, the hook's exit code and stderr are unchanged; the existing hook suites pass unedited.
- AC-STE-676.8: `git merge --squash` followed by `git commit`, a cherry-pick and a revert get no waiver, and the refusal remedy names these three as not covered.
- AC-STE-676.9: The staged list is read with `-z`, so a non-ASCII test path is matched; head comparison costs one `git diff --cached --name-only -z` per head, not one spawn per path.
- AC-STE-676.10: The head reader lives in `adapters/_shared/src/`, so the hook still makes no direct file read (the hook-session-lib pin stays green), and the hook keeps exactly one `process.exit(1)`.
- AC-STE-676.11: `docs/hooks-reference.md` documents the waiver, its reminder, the three uncovered operations, and that the waiver is an honesty aid that a hand-made merge can forge.
- AC-STE-676.12: `spec_write_trunk_invocation_path.ts` and `video_commit_nudge.ts` are checked for the merge defect and the result is recorded in this FR's notes; the video nudge's silent merge conclusion is filed as its own ticket, whose key is recorded here.
- AC-STE-676.13: Mutations each redden a named test: removing the waiver (clean merge refuses), removing the hand-edit check (evil merge passes), and removing the reminder (waived commit exits 0).
- AC-STE-676.14: `bun test` from `plugins/dev-process-toolkit` reports 0 failures, and its skip identities equal the trunk baseline by name.

## Technical Design

A shared reader returns the in-progress heads and, per head, the staged paths that differ from it. The hook subtracts paths absent from some head's list, after the placeholder subtraction and before the evidence check. Auto-merged paths compare against the merge result tree. A waived-only commit reaches the existing reminder exit; any remaining path takes today's refusal. Every git failure returns no heads.

## Testing

Temporary git repos through the shipped hook wrapper, with permit and forbid twins per case: clean merge, octopus, auto-merge, conflict taken from main, hand edit, deletion, rename, worktree, subdirectory, rebase, squash, corrupt head and non-ASCII path.

## Notes

Reported in gist 9b9c2f8c against v2.98.0. An attack run confirmed the stash-merge forgery and the auto-merge, deletion and worktree gaps.

Sibling audit: `spec_write_trunk_invocation_path.ts` only reads git state for a summary, so a merge can mislabel it but never pass a commit. `video_commit_nudge.ts --commit` can silently conclude a merge, filed as STE-678.

## Implementation notes

- STE-676: a planted AUTO_MERGE ref (or a hand-made merge commit) defines what counts as git's own result, so it can widen the waiver — inside the documented forgery caveat — the waiver is an honesty aid, never silent (exit 1 Reminder), and the operator ruled out a reachability guard as forgeable
