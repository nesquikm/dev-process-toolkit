# Video offer at /ship-milestone

## Summary

When a release ships a user-facing feature, a project set up for videos is offered an explainer video.
The offer lists the features it would cover and starts the video only on a yes.
Declining, or running without a person present, prints the exact command to run later.
Projects that are not set up for videos never see the offer, and an orchestrated run skips it.

## Requirement

- **When.** After the release commit succeeds, `/ship-milestone` asks once: `Make an explainer video for M<N>? [y/N]`, followed by the milestone's FRs whose changelog category is Added or Changed.
- **Predicate.** `video_offer.ts <projectRoot> <milestone>` prints the proposed slug and those FRs, or nothing; it prints nothing unless `videoReadiness` is ready and at least one such FR exists.
- **Answers.** `y` starts `/video <slug>`; `n`, no answer, or non-interactive stdin prints `Run: /video <slug>`.
- **Driven runs.** The driven-run marker drops the offer, per the continuation-offer rule.
- **One offer.** A run makes at most one video offer, and it never skips or reorders any other ship gate.

## Acceptance Criteria

- AC-STE-670.1: `video_offer.ts` prints `slug=<milestone-slug>` followed by one `fr=<id> <title>` line per Added or Changed FR bound to the milestone, when readiness is ready; it prints nothing and exits 0 when readiness is not ready or no such FR exists.
- AC-STE-670.2: `skills/ship-milestone/SKILL.md` places the offer after the release commit and before the opt-in `/pr` offer, with the prompt `Make an explainer video for M<N>? [y/N]` and the decline line `Run: /video <slug>`, pinned by exact-string tests.
- AC-STE-670.3: A test asserts the offer step is conditioned on non-empty `video_offer.ts` output, so an unconfigured project shows no prompt and no decline line.
- AC-STE-670.4: Under the driven-run marker the offer is omitted, asserted against the continuation-offer module's rule.
- AC-STE-670.5: The slug is derived deterministically from the milestone title (lowercase, kebab-case, at most 40 characters), and `video_offer.ts` reports the same slug on repeated runs.
- AC-STE-670.6: Mutation-verified: making the predicate ignore readiness turns AC-STE-670.1's not-ready case red.

## Technical Design

A predicate front door built on the readiness check and the FR frontmatter reader, plus one offer step in the ship skill, modeled on the existing ship-ready offer and its decline line.

## Testing

Front-door fixtures for ready, not ready, and no user-facing FR; exact-string pins on the skill text; the driven-run rule test.
