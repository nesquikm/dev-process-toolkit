# Web recorder

## Summary

Web projects record demos by driving the real app in Chromium and capturing the screen as it runs.
A short scenario file per shot clicks through the feature and marks the moments the narration refers to.
The browser always starts with the flags that stop macOS from asking for the keychain.
The toolkit uses the project's own Playwright install and says how to add it when it is missing.
Nothing the recording creates is committed.

## Requirement

- **Playwright from the project.** The recorder resolves `playwright` from the project root, not from the toolkit; absent, it refuses with the install commands.
- **Keychain flags.** Chromium launches with `--use-mock-keychain` and `--password-store=basic` on every run.
- **Scenarios.** `.dpt/video/scenarios/<shot>.ts` (or `.js`) default-exports `async (page, mark) => {}`; `mark(name)` records a marker at the current recording time.
- **Capture.** Frames come from the CDP `Page.startScreencast` stream, are acknowledged, and are encoded by ffmpeg with their timestamps into the contract's clip at the style's viewport.
- **Profile.** The browser profile lives in the video's work dir.

## Acceptance Criteria

- AC-STE-667.1: In a fixture project with no resolvable `playwright`, the web recorder refuses in the NFR-10 shape naming the project root and the two install commands (`npm i -D playwright`, `npx playwright install chromium`).
- AC-STE-667.2: Every launch passes `--use-mock-keychain` and `--password-store=basic`, asserted on a fake Playwright module's recorded launch options for two consecutive shots.
- AC-STE-667.3: A scenario calling `mark("open")` and `mark("result")` yields a markers file with those two names in order, with times taken from the frame clock.
- AC-STE-667.4: Screencast frames from a fake CDP session are each acknowledged and fed to the encoder with their timestamps, producing a clip that `validateRecording` accepts.
- AC-STE-667.5: The persistent profile directory is under `videoWorkDir(slug)`, and a scenario that throws ends the recording, closes the browser, and refuses naming the shot and the scenario's error.
- AC-STE-667.6: The viewport comes from `style.layout.viewport`, defaulting to 1280×720.

## Technical Design

A recorder implementing the shared contract. Playwright is loaded by resolving from the project root, injected in tests as a fake module. Screencast frames go to ffmpeg's stdin as images with variable frame timing.

## Testing

Fake Playwright and a fake CDP session; frame fixtures; the contract validator from STE-666.

## Notes
