# A gate probe keeps milestone-name prompts out of the skills

## Summary

A new gate check fails when any skill asks the operator what a milestone or release should be called.
It also fails when an active plan records a codename that breaks the naming rules.
Without it, a later edit could bring a name question back quietly and nothing would notice.

## Requirement

- **Prose arm.** The probe scans the toolkit's skill files for an instruction that prompts the operator for a milestone name, title or codename, using a closed pattern set, and fails naming file and line.
- **Plan arm.** The probe reads every active plan's `codename:` through the shared reader and fails naming the plan and the broken rule; an absent key passes.
- **Registered.** The probe joins gate-check like every other probe, and every count that pins the probe list moves with it.

## Acceptance Criteria

- AC-STE-659.1: Probe `milestone_name_unasked` returns a failure naming file and line for each planted fixture: the retired `Enter milestone codename` prompt block, an `AskUserQuestion` instruction asking for the codename, and one asking for the milestone title; it returns no failure on the current tree.
- AC-STE-659.2: The probe returns a failure naming the plan path and rule for an active plan whose `codename:` fails `validateCodename`, and none for an active plan without the key or with a valid one; archived plans are not read.
- AC-STE-659.3: The probe is registered in `skills/gate-check/SKILL.md` and the probe registry, and every probe-count pin and doc that enumerates probes is updated in the same change.
- AC-STE-659.4: Mutation control: disabling the prose arm turns the AC-STE-659.1 legs red, and disabling the plan arm turns the AC-STE-659.2 legs red.

## Technical Design

New probe module beside the other gate-check probes, reading skill files from the plugin root and plans from the project's `specs/plan/`. The plan arm calls `readPlanCodename` from the codename FR's module. The prose arm matches a closed list of prompt shapes; lines stating that a name is never asked are not matches. Review backfill: a negation clears a shape only within the four words before it, and an `AskUserQuestion` instruction naming the milestone codename, title or name is a fourth shape. "The probe registry" is the numbered list in `skills/gate-check/SKILL.md`; no code registry exists.

## Testing

A fixture-tree test plants each prompt shape and each invalid codename, with clean controls, and runs the mutation legs. The live tree run is asserted green.

## Notes

Depends on STE-657. Raises the probe count; grep tests for count pins before editing prose.

## Implementation notes

- milestone_name_unasked.ts negation window looks only BEFORE a shape; a trailing negation false-positives and a prompt wrapped across two lines is missed — inherent to the line-by-line closed-set design; documented in STE-659 Technical Design
- isQuotedCodenameLine and the probe's violation-line lookup scan the whole file for ^codename:, not only the frontmatter — harmless today (the frontmatter key precedes any body line); follow-up: scope to the frontmatter block
- milestone_name_unasked planArm silently skips a plan whose frontmatter fails to parse — parseFrontmatter rarely throws and malformed frontmatter is graded by other probes; follow-up: report it
