# The trend counts fixes that name the run, and skips what it cannot see

## Summary

The trend report has three faults in two numbers.
The post-merge fix count reads zero when the commits do not follow the commit convention.
The same count measures noise, because any fix to a shared file counts.
Now only fix commits that name the run, after it was archived, count.
The waste metric now names both tracking switches it reads.

## Requirement

`/retro --trend` reports `post_merge_fixes` only when it can observe it, counts only fix commits that name the run, and names every tracking switch the `waste` metric reads.

## Acceptance Criteria

- AC-STE-796.1: `post_merge_fixes` counts a commit when its subject is a Conventional Commits `fix` subject (the `fix` type, an optional scope and an optional `!`, then a colon), its subject or its `Refs:` trailer names the run's id as a whole id (the archive file stem: a tracker id or a short ULID) or cites one of its ACs (`AC-<id>.<n>`), and it is dated after the run's `archived_at` and no more than 14 days after it. A fix that names the run only in its body, names another id (`STE-1` is not named by `STE-10`), or falls outside the window does not count. Touching the run's files no longer matters.
- AC-STE-796.2: A run whose `archived_at` cannot be read as a date makes the group's `post_merge_fixes` unobservable (value `null`), never a smaller number.
- AC-STE-796.3: When fewer than half of the commit subjects dated inside the group's fix windows match the Conventional Commits subject grammar the `commit-msg` hook enforces, `post_merge_fixes` is `null` with the note `skipped: not observable (history is not Conventional Commits)`. A window holding no commit at all keeps an observable `0`.
- AC-STE-796.4: `waste` reads both `tracking.gate_outcomes` and `tracking.tool_calls`: with either switch off, its cell is skipped with a note naming that switch, and with both off the note names both.
- AC-STE-796.5: `docs/retro-reference.md` describes `post_merge_fixes` by the AC-STE-796.1 rule and the AC-STE-796.3 skip, and lists both tracking switches for `waste`.
- AC-STE-796.6: `bun test` from `plugins/dev-process-toolkit` reports 0 failures, and its skip identities equal the trunk baseline by name.

## Technical Design

`archivedFrs` also returns each FR's `archived_at` as epoch ms (or null). `postMergeFixes` reads the subject (first message line) and the `Refs:` trailer values from the `allCommits` records (add the trailer to the log format) and anchors the window on `archived_at`, because a later fix naming the run in `Refs:` moves `lastCommitAt`. A shared `CC_SUBJECT_RE` mirrors the hook grammar; `signalValues` returns the skip note when the share of matching subjects in the pooled windows is under 0.5. `INPUT_KEY.waste` becomes `["gate_outcomes", "tool_calls"]`.

## Testing

Extend the trend fixtures in the existing STE-776 and STE-784 suites: a named fix after archival counts, a body-only mention and a hub-file fix do not, a non-CC history reads skipped, and each tracking switch alone names itself on `waste`. Pinned old tests that encode the file-touch rule are amended with an `Amended by AC-STE-796.1` note.

## Notes

Kickoff of 2026-11-16: the old rule averaged about 6.4 fixes per run, dominated by hub files; the new one is about 0.14.

## Implementation notes

- namesId counts an AC citation (AC-<id>.<n>) as naming the run — inherited from STE-784.5; AC-STE-796.1 now states it
- no fixture uses a short-ULID archive stem as the run id — namesId is id-shape agnostic; every test uses STE-<n>
- merge-commit subjects count toward the Conventional Commits share — intended pooling; a squash-free history with many merges can dilute the share
