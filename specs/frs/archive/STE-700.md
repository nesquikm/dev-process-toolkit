# An archive-only commit or pull request needs no fresh gate or review run

## Summary

Archiving a shipped milestone moves its spec files into the archive folders and stamps them.
The commit gate still demands a full gate run for that change.
The pull request gate still demands a full spec review.
This change lets a commit or a pull request through when every change in it is an archive move.
Any other change still needs both runs.

## Requirement

The commit gate and the pull request gate pass with no gate-check or spec-review evidence when the change set is archive-only, as decided by one shared classifier. Every other change set is graded exactly as today.

## Acceptance Criteria

- AC-STE-700.1: A new module `adapters/_shared/src/archive_only_change.ts` exports a classifier that returns archive-only only when the change set is non-empty and every change is one of: a rename from `specs/frs/<f>.md` to `specs/frs/archive/<f>.md`; a rename from `specs/plan/<p>.md` to `specs/plan/archive/<p>.md`; or a modification of `specs/requirements.md`.
- AC-STE-700.2: Inside a renamed file, the classifier allows only these edits: the frontmatter `status` and `archived_at` values; plan task checkboxes ticked from `- [ ]` to `- [x]`; an appended `## Implementation notes` section; and the token-stats marker block. Any other line added, removed or changed makes the set not archive-only.
- AC-STE-700.3: Inside `specs/requirements.md`, the classifier allows only added lines that are traceability rows beginning `| AC-`. A removed line or any other added line makes the set not archive-only.
- AC-STE-700.4: `pre-commit-gate-check` exits 0 with empty stderr and no gate-check evidence when the staged set is archive-only.
- AC-STE-700.5: `pre-pr-spec-review` exits 0 with no spec-review evidence when the diff between the branch and its merge-base with the pull request's base is archive-only. The base is the `--base` value when given, else the repository's default branch. *(Amended by STE-702 (v2.101.4): the default branch is read from refs/remotes/origin/HEAD, and the pass is withheld when that ref is absent.)*
- AC-STE-700.6: Both gates refuse as today, through the shipped `.sh` wrapper, for each forbid twin: an archive rename staged beside any path outside `specs/`; an edit to an active FR; an archive rename with a body edit outside the allowed set; a file added under an archive folder with no matching delete; a deletion; and a disallowed `specs/requirements.md` edit.
- AC-STE-700.7: The classifier reads git with rename detection on. A move that git reports as a delete plus an add is not archive-only.
- AC-STE-700.8: The spec-path rule now private to `pre-commit-tdd-orchestrator.ts` moves into the shared module, and that hook imports it. No hook keeps a private copy, and the existing STE-295 spec-only suite stays green unchanged.
- AC-STE-700.9: `docs/hooks-reference.md` documents the archive-only pass on both gates and names its allowed-edit set.
- AC-STE-700.10: Removing any allowed-edit rule, the rename-only rule, or either gate's call to the classifier turns at least one named test red.
- AC-STE-700.11: `bun test` from `plugins/dev-process-toolkit` reports 0 failures, and its skip identities equal the trunk baseline by name.

## Technical Design

Both gates resolve their target checkout today and then demand evidence. Each gains one early exit: compute the change set (staged, or branch against merge-base) with rename detection, and pass when the shared classifier says archive-only.

The classifier takes name-status entries and per-file unified diffs, so it is pure and testable without git. A thin reader in the same module shells out to git for the two hooks. The allowed-edit set matches what the archive flow writes today.

## Testing

Pure classifier tables with one permit and one forbid row per rule, plus temporary git repositories driving both hooks through their shipped wrappers. Mutation controls as listed.

## Notes

Origin: a shared-Jira field report against v2.99.1, where an archive-only commit and its pull request were blocked until full runs.

## Implementation notes

- the commit gate's archive-only pass also requires subcommand `commit` and a tracked working tree that matches the index — otherwise git commit -a, --include, --only or a pathspec could pull unstaged source into a commit that skipped the gate
- an Implementation notes block passes only when last (blank lines, a token-stats block or EOF follow) and with no subheading; a complete appended token-stats block also passes — "appended" enforced literally; the whole-block append is what the archive flow writes for an FR that had no block
- the classifier fails closed on an unreadable diff, a binary diff, a hunk-less non-identical rename or requirements edit, and a bare carriage return; paths go to git as literal pathspecs; full context and -M forced — Pass 2 security findings: nothing ungraded may pass
- the PR gate grades the local branch against its merge-base; --head/-H or a --base starting with '-' gets no pass; with no --base the default branch is read from refs/remotes/origin/HEAD only — commits that exist only on the remote branch are not seen; a checkout without origin/HEAD fails closed to the evidence check
- checked against the last 15 archive commits in this repository on 2026-11-02: 10 classify archive-only — the other 5 carry hand-written prose sections, bullets under an existing notes section, or a legacy plan gaining an archived_at key, and correctly fall back to the evidence check
- AC.10 met by a mutation battery on 2026-11-02 — each of the five allowed-edit rules, the rename-only rule (two ways) and each gate's classifier call was removed in turn and turned at least one named test red
