# The manual for the gates is reachable from where an agent looks

## Summary

The hooks have a complete manual. Nothing in the repository links to it, so it is a correct document no reader can find. Every surface that describes the hooks directory names the two harmless capture triggers and omits the three that refuse. The contracts catalog that the manual itself calls its prose layer has no entry for any of them, and the skill that opens pull requests never mentions the review the host will demand first.

## Requirement

Every surface that describes the bundled hooks names the ones that block, the hooks manual is linked from somewhere other than itself, and the honored-contracts catalog carries an entry for each blocking gate.

## Acceptance Criteria

- AC-STE-572.1: `docs/honored-contracts.md` gains one entry per blocking gate, in the catalog's existing four-label shape — Mandate, Violation name, Auditable evidence, Precedent FRs — each naming its precedent FRs.
- AC-STE-572.2: The hooks manual's `## Related references` section links back to the surfaces that now cite it, so the link is bidirectional rather than a one-way pointer that only the manual knows about.
- AC-STE-572.3: Both repository-structure listings that describe the hooks directory — the `README.md` tree and the `CLAUDE.md` tree — name the blocking PreToolUse hooks alongside the SessionEnd and Stop wiring they currently describe alone. Describing only the capture wiring is what rules the blocking ones out.
- AC-STE-572.4: The `README.md` documentation index lists both the hooks manual and the honored-contracts catalog.
- AC-STE-572.5: `docs/workflow-overview.md` names the three gates once in its lifecycle prose, not only in a row two thirds down a sixty-seven-row table.
- AC-STE-572.6: `skills/pr/SKILL.md` and `skills/gate-check/SKILL.md` say at the point of use that the Skill invocation itself is the token the hook reads, and that running the gate commands by hand does not clear it. Both files are measured after the edit with the same counter the length-cap test uses, and asserted at or under the cap read from that test by name rather than restated as a literal.
- AC-STE-572.7: No added line steals a counted token. `publicSurfaceCountDrift` is run over the edited `README.md` and `CLAUDE.md` and reports no violation, and the counts it parses are asserted to be the ones it parsed before this FR.
- AC-STE-572.8: Falsifiability. AC.1 through AC.5 are mutation-tested by removing one gate's mention from each surface in turn, and each mutation is first measured clean against the landed tree, through the throwing `mutate` helper.

## Technical Design

The manual is already right, so nothing is rewritten inside it — the edits are links in and links out. A fourth document would repeat the defect.

AC.7 guards this FR's own blast radius rather than its subject. The count probe is first-match-wins by content scan: the first slash-command count line in `CLAUDE.md`, and line three alone in `README.md`. New prose about skills is exactly the kind of line that can steal one of those tokens, so the probe is run rather than reasoned about.

`skills/gate-check/SKILL.md` has two lines of headroom, and the count is measured with the counter the cap test uses — `wc -l` reports one less and would hide a violation at the boundary.

## Testing

Each surface is asserted separately. A single test asserting "the gates are documented somewhere" would pass on any one of the six surfaces and is the shape this milestone exists to avoid.

The cap assertion reads `SKILL_LINE_CAP` from `tests/skill-nfr-1-length.test.ts` rather than restating the number: a shipped test in this repository was once found pinning a value one off from the cap it named.

## Notes

The precedent FRs for the catalog entries are STE-285 (original design), STE-289 (the bundled-registration reversal), STE-290 (the real transcript-path contract) and STE-291 (exit 1 to exit 2, which made the layer actually block).
