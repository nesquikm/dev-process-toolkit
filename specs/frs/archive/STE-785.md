# An auto-approved spec commit carries its audit token

## Summary

When the approval marker is present, the spec writer commits on its own.
It reports that auto-approval in its closing summary only.
The gate probe for spec commits looks for that token in the commit body.
So every auto-approved spec commit fails the gate.
The next implement run then refuses to commit.
The fix writes the token into the commit body as well.

## Requirement

On the marker-approved path, `/spec-write` writes `spec_write_commit_default_applied` into the commit body as well as the Step 7 summary, so probe #45 passes on that commit.

## Acceptance Criteria

- AC-STE-785.1: `skills/spec-write/SKILL.md` § 7a, on the `PRESENT` branch, tells the run to write the line `spec_write_commit_default_applied` into the commit body as well as the Step 7 summary row; the interactive `y` branch keeps `spec_write_commit_operator_approved`.
- AC-STE-785.2: A commit with subject `chore(specs): write FR STE-1` and the body line `spec_write_commit_default_applied` passes probe #45, and the same commit without that line fails it. A test pins both outcomes against a real git repo.
- AC-STE-785.3: A test reads the shipped SKILL.md and fails if the `PRESENT` branch stops naming the commit body.
- AC-STE-785.4: `bun test` from `plugins/dev-process-toolkit` reports 0 failures, and its skip identities equal the trunk baseline by name.

## Technical Design

Prose change in the § 7a `PRESENT` bullet, mirrored at § 4 where the two gates are summarised. Probe #45 already accepts the token, so no code change is needed there. The skill file sits near its line cap, so the edit extends existing lines rather than adding new ones.

## Testing

A doc-conformance test over the skill text, plus a probe test that builds a two-commit repo and runs the probe on each body shape.

Conformance run 2026-11-14, linear and jira legs. It blocked every unattended spec-write then implement chain.
