# The tracker gate's compound-command note names what made the command compound

## Summary

The tracker gate ignores a receipt when its command was not run on its own.
Its refusal quoted the command but did not say what was wrong with it.
A worker misread the quote and blamed the gate.
The refusal now names the first part that made the command compound, such as a semicolon or a pipe.
Which commands pass does not change.

## Requirement

The pre-tracker-write-gate note about a deciding command run in a non-plain shape names the first construct that made the command non-plain, beside the quoted command.

## Acceptance Criteria

- AC-STE-875.1: The "not a plain invocation" note names the first construct in the rejected command that made it non-plain, beside the quoted command, from a closed set exported by the hook module. The set covers every shape the plain-invocation check rejects, and at least `;`, `&&`, `||`, `|`, a redirection, a subshell or `bash -c` body, and a module path held in a variable.
- AC-STE-875.2: A table test covers each construct in the set with a rejected command whose note names that construct. An extra case puts two constructs in one command, and the note names the one that comes first.
- AC-STE-875.3: Regression: the STE-802 shape (`bun run <module> <args>; echo "exit=$?"`) yields a note naming `;`. On the code before the fix the note names no construct.
- AC-STE-875.4: Unchanged: which commands are accepted, rejected, superseded or counted, the 240-character quote cap, and the refusal's other lines; the existing scan suites pass unmodified.
- AC-STE-875.5: `bun test` from `plugins/dev-process-toolkit` reports 0 failures, and its skip identities equal the trunk baseline by name.

## Technical Design

Root cause: no defect in the quote. Claude Code strips a leading `cd <cwd> &&` before it records a Bash command, so the hook quoted what ran. The gap is the explanation. A pure `nonPlainConstruct(command)` helper beside `rejectedDecidingModules` returns the first construct. `scanAnnouncements` keeps its `rejected` list, and the note renderer asks the helper for the latest entry's construct.

## Testing

A table test of the helper over the closed set, a two-construct case, and a refusal-text test through the hook's note renderer, including the STE-802 command.

## Notes

The live close in STE-802 produced the misread. The worker wrote a cd prefix, and the recorded command had it removed.

## Implementation notes

- AC-STE-875.4 says the existing scan suites pass unmodified, but expectOnlyTodaysNote in m_b054b1-ste-868-foreign-copy.test.ts now also strips the one construct sentence — that helper pinned the old note exactly for five non-plain foreign commands, which AC-STE-875.1 extends; it still fails on any foreign-copy note
- Some rejected shapes are named imprecisely: $((…)) as a command substitution, bash -lc as a first word other than bun, a flag in the module slot as a non-absolute module path — every rejected command is still named from the closed set and never null; the common shapes are exact
- The trailing-blank trim regex nonPlainConstruct shares with trimShellBlanks is quadratic on a long interior run of blanks — the same regex already runs first inside bunInvocation, so the helper adds no new cost class
