# The harness keeps the evidence it gathered

## Summary

The loop driver discards completed, evidence-bearing runs at its final gate, and leaves the tree dirty for the next one.

Its leg-accounting guards count by asking the shell to split an unquoted variable. zsh does not split, so two legs collapse to one and the guard aborts. Measured live at two hours forty minutes.

It fails closed and cannot fake a green, which is why it survived: these fences are tested under the one shell where the bug is invisible.

## Requirement

The leg-accounting guards count legs correctly under every shell that runs them, the tests that certify those fences exercise the shell an agent actually uses, and a completed run leaves the repository as clean as it found it.

## Acceptance Criteria

- AC-STE-565.1: Both accounting guards in `.claude/skills/conformance-loop/SKILL.md` — the RC-collection gate and the green termination probe — count the selection without relying on the shell to split it. MEASURED, not reasoned: the replacement returns 2 for `"linear none"` under `bash`, `zsh` AND `sh`, and the retired form is measured to return 1 under zsh in the same leg, so the assertion names the defect it fixes rather than merely the fix.
- AC-STE-565.2: The count is still zero for an empty selection and one for a single leg, under all three shells, and the empty-selection refusal above each guard is untouched — an empty selection is refused by the guard that already refuses it, never by arithmetic.
- AC-STE-565.3: `tests/m121-ste-452-termination-harness.test.ts` executes its fences under BOTH `bash` and `zsh`. Every existing assertion runs in both shells; a fence that behaves differently between them reds, naming the shell. The runner is parametrized in one place rather than duplicated per test.
- AC-STE-565.4: The dual-shell runner lives in `tests/_fence.ts`, the shared home the fence helpers already occupy, so the next suite that needs it does not open a private copy. `tests/m128-ste-490-rc-verdict-gate.test.ts`, the other suite that executes an accounting fence, uses it too, and its pin on the retired `set --` literal moves to the shipped form rather than being deleted.
- AC-STE-565.5: zsh absence is a SKIP that says so, never a silent pass. On a machine with no `zsh` on `PATH` the dual-shell legs skip with a reason naming the missing shell; they do not quietly degrade to bash-only, which is the shape that produced this finding.
- AC-STE-565.6: `harness_artifact_paths.ts` gains `scanUnignoredRepoArtifacts(...)`, which takes the in-repo per-run artifact path literals it ALREADY extracts from both harness SKILL bodies and reports every one not covered by `.gitignore`. Derived from the existing extraction, so a persist path added tomorrow is covered without anyone remembering this FR.
- AC-STE-565.7: `.gitignore` covers the offending classes, and coverage is asserted by ASKING GIT (`git check-ignore`) rather than by grepping `.gitignore` for a string — a pattern present in the file and not matching the path is the failure mode a grep cannot see. The tracked reproducers that live under these roots stay tracked, asserted in the same leg.
- AC-STE-565.8: A completed run leaves the tree clean, asserted AFTER the capture path is written: over a fixture repository, writing a file at each enumerated persist path leaves `git status --porcelain` empty. This is the end-to-end statement; AC.6 and AC.7 are how it is achieved and neither implies it.
- AC-STE-565.9: Falsifiability — AC.1, AC.3, AC.6 and AC.7 are mutation-tested. Restoring the `set --` form reds AC.1 under zsh and stays green under bash, which is the finding reproduced as a test; removing the zsh leg reds AC.3; dropping a persist path from the extraction reds AC.6; removing a `.gitignore` line reds AC.7 and AC.8. Each mutation is routed through the throwing `mutate` helper so a pattern that stopped matching is a loud error, not a green test.

## Technical Design

The splitting moves OUT of the shell. A word count reads text handed to it, so the answer no longer depends on whether the shell performs field splitting — the only behaviour the guard depended on, and the only one the two shells disagree about.

The membership arms above each guard already compare a quoted expansion, which neither shell splits. Only the count was dependent, which is why the fix is one line per guard rather than a rewrite.

The dual-shell runner is a parameter, not a second copy of each test, and the shell name travels into the failure message.

The ignore check asks git, whose semantics a grep would re-implement badly.

## Testing

The shell legs execute the extracted fences as subprocesses under each shell in turn, because the whole finding is that a fence's behaviour is a property of the interpreter and not of the text.

The retired form is executed too, and asserted to produce the WRONG answer under zsh. A test that only exercises the fix cannot distinguish a fix from a coincidence, and this defect's entire history is a green suite that never ran the failing case.

## Notes

The wider class is recorded rather than closed: fourteen call sites spawn a shell to execute a fence, and this FR converts the two that execute the leg-accounting guards. The rest execute fences this milestone did not measure as shell-dependent, and converting them all is a change of a different size.
