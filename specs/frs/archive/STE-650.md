# The grader mirrors the hook, and the commit and PR gates name a lagging transcript

## Summary

The previous release left the live grader laxer than the hook it grades.
The grader now shares one ownership rule with the hook and mirrors its remaining checks, and both read a consent answer per question.
The commit and pull-request gates stop blaming the evidence window when the transcript has simply not caught up with the receipt, and the deciding-command recogniser and the re-list remedy stop misreading or looping.

## Requirement

- **One ownership rule.** The hook's created-key consent exemption and the grader's ownership test use one predicate, so a key owned only through an FR binding or a reuse, binding or import receipt gets the same verdict from both.
- **The grader mirrors the hook.** It bounds a re-list's future skew as the hook does, checks the joined-labels read-merge, refuses a second create of a settled key, applies the parallel-duplicate rule and forbidden-join consent to ticket creates, and grades against the decision the hook would pick. It re-derives the hook's behaviour digest instead of trusting the bundle's recorded one.
- **Consent is read per question.** A consent counts only when the answer to the question that names the subject and offers the label is exactly that label, in the hook's consent checks and the grader alike.
- **Lag is named as lag.** When the commit or PR gate finds its receipt's tool_use recorded without its result, it waits a bounded time for the result, and if the result still has not landed, it says the transcript has not caught up and to retry unchanged, instead of calling the evidence outside the window.
- **The recogniser and the remedies read what ran.** The deciding-command recogniser counts an absolute bun path, a `bash -c` body and a backslash continuation, and ignores a command that only echoes the invocation. A full 50-row Linear re-list gets the consent remedy, not the re-list remedy.

Carries over M_101065's review items: R2-TWR4-PARTIAL, the two grader partials of AC-STE-644.2 and AC-STE-643.8, the commit and PR flush lag, TWR-2, TWR-3, TWR-5, TWR-6, TWR-7, F2 and AC-STE-642.10, plus the STE-644 text drift ("within 120 s of the gated call"), which the archived STE-644 file annotates as amended to the grading time.

## Acceptance Criteria

- AC-STE-650.1: One exported ownership predicate is called by the hook's created-key exemption and by the grader's ownership test; a source pin proves both call it and neither re-implements it.
- AC-STE-650.2: A Jira labels write after an unanswered forbidden join, on a key owned only through an FR binding, a reuse receipt, a binding receipt or an answered import receipt, is refused by the hook (exit 2) and graded ungated-write by the grader; on a key this session created, the hook exits 0 and the grader reports no finding.
- AC-STE-650.3: The grader does not accept a re-list whose last result is stamped more than 5 s after the create it permits, and accepts one stamped within 5 s.
- AC-STE-650.4: The grader reports ungated-write for a Jira labels write on a joined Epic whose labels value is not the read-merge the join printed, and no finding when it is.
- AC-STE-650.5: The grader reports a finding for a same-ticket create after a settled create of that ticket in the session, for a parallel duplicate create, and for a ticket create that relied on an unanswered forbidden join; each has a control that stays clean.
- AC-STE-650.6: When several unspent decisions match a create, the grader grades against the one the hook permits (the first unspent, consented one), not the first unspent one.
- AC-STE-650.7: hookDemandsRelist re-derives the behaviour digest from the bundle's own per-file hash map; a bundle whose recorded digest disagrees with that map is not trusted as pre-relist.
- AC-STE-650.8: A multi-question AskUserQuestion whose subject-naming question is answered with the exact label counts as consent in both consent checks, even when another question's answer differs; one whose subject-naming question is answered otherwise does not.
- AC-STE-650.9: When the commit or PR gate's receipt tool_use is present and its tool_result is absent, a result that lands within the bounded wait permits (exit 0).
- AC-STE-650.10: When that result never lands, the gate exits 2 with a refusal that says the transcript has not caught up and to retry unchanged, and that does not say outside-window.
- AC-STE-650.11: A receipt that genuinely predates the window, with its result on disk, keeps the HEAD outside-window refusal, and the gate never waits on it.
- AC-STE-650.12: The recogniser behind the "not a plain invocation" note (the receipt's own accepted shape is unchanged) counts `/abs/path/bun run <module> decide …`, `bash -c "bun run <module> decide …"` and a backslash-continued invocation, and does not count `echo "bun run <module> decide …"`.
- AC-STE-650.13: A container create with no answered consent, after a complete re-list of exactly 50 Linear milestones, is refused with the consent remedy (answer Create `<title>`), not a re-list remedy.
- AC-STE-650.14: The STE-644 Requirement's freshness bullet in the archive carries an amendment clause naming the grading time.
- AC-STE-650.15: Every hook refusal this FR adds or changes has a "never lands" leg in which the gated call's own tool_use line is absent at grading time.

## Technical Design

Export the ownership predicate from a module both the hook and the grader import; keep the hook import-light, matching the grader's existing twin comments. The grader's fresh() gains the 5 s future-skew bound; its ownership test gains the labels read-merge check and the settled, parallel and forbidden-join create rules; its decision pick reuses the hook's permitting rule. Replace the per-answer every/some checks with one per-question matcher. The shared gate-receipt reader distinguishes a receipt call without a result from one outside the window, waits a bounded time on the former, and names it. The recogniser splits shell segments, unwraps a bash -c body and joins continuations, ignoring echo arguments.

## Implementation notes

- AC.7 (underspecified→resolved): bundles carry no hook source bytes, so 're-derive the digest' is implemented as recomputing behaviourDigest.digest from its own files map (sha256 over sorted '<sha>  <path>' lines); a disagreement means files[HOOK_SOURCE] is not trusted. AC.1's shared predicate lives in adapters/_shared/src/join_consent_ownership.ts (exemptsJoinConsent).
- HARDENING 1's permit twin (tests/m_2306b6-ste-617-live-grader.test.ts) now creates a DIFFERENT ticket under its second decision (pin move: STE-642's settled rule forbids re-creating the same one); its spent half is now ungated for two reasons (spent receipt AND settled create), so it no longer isolates the spent-receipt property.
- AC.8: consentLines (Import/Adopt consent) now requires the key in the QUESTION text of the ask, not anywhere in its input JSON (options included) — a tightening shared with answeredAfter.
- AC.7 amended: the digest is re-derived from the bundle's per-file hash map, not from source bytes (the bundle carries no hook source bytes). Residual: a forger who swaps the hook-source entry in the map AND recomputes the digest over the swapped map still passes; the recorded bundle has no independent witness of the hook bytes. Closing it needs source bytes (or a signed digest) in the bundle.
- Lag wait scoped to THIS gate's own front-door run via EvidenceTarget.announcesOwnRun (gate_receipt.ts announcesGateReceiptFor); a target without it keeps the pre-STE-650 reading (every pending run). Wait bound is wall-clock (Date.now deadline), not summed sleeps.
- not-vouched dropped from LAG_EXPLAINABLE; a miss carrying a detected tamper (EvidenceMiss.tampered) is never renamed as lag and never waits.
- Multi-root receipt miss: the carried `reason` is now the first root's NON-lag reason when any root has one (a lag rename needs every root's miss to be lag-explainable). No dedicated multi-root leg: the change only narrows the lag rename; residual named.
