# Falsifiability harness for repaired fixture assertions, with halt-on-vacuous

## Summary

Every repair in this milestone changes an assertion that has been passing or failing for the wrong reason. The only way to know a repaired assertion is worth anything is to take away the thing it is supposed to detect and confirm it goes red. This milestone builds that check once, as shared machinery, and records whether it actually works — because a harness that cannot fail is the very defect being fixed, one level up.

## Requirement

A harness that, for each assertion repaired in M127, runs it against a capture with the subject present (expect pass) and against the same capture with the subject removed (expect fail), and records a literal outcome token in the plan. Every other FR in M127 depends on it and lands after it.

## Acceptance Criteria

- AC-STE-483.1: The harness extracts each repaired assertion's shell form from `.claude/skills/smoke-test/SKILL.md` and executes it — never re-derives or paraphrases it — against both a present-subject and an absent-subject capture (STE-456 AC.7 / STE-461 AC.12 method).
- AC-STE-483.2: Each repaired assertion passes on the present-subject capture and fails on the absent-subject capture; either half missing is a harness failure, not a pass (non-vacuity in both directions, STE-421 AC.5).
- AC-STE-483.3: The mutation removes the assertion's actual subject, not a nearby wording — a rewording mutation does not count as evidence (the STE-461 AC.13 erratum, restated as a gate rather than a caution).
- AC-STE-483.4: `specs/plan/M127.md` records exactly one literal token: `harness-fails` (the harness demonstrably fails on absent subjects — proceed) or `harness-vacuous` (HALT the milestone).
- AC-STE-483.5: The harness is re-runnable and its captures ship as repo fixtures, so a later reader reproduces the result without a live conformance run.
- AC-STE-483.6: The harness asserts a marker count rather than mere presence, so a mutation that never applied cannot read as a pass (the M124 lesson).

## Technical Design

STE-445 (M121) is the direct precedent and it earned its keep: widening the leg set with a synthetic fourth leg left the full gate byte-identically green, proving the exported authority was imported by nothing. The same shape applies here — six assertion repairs whose correctness is unverifiable without a mutation pass.

Two traps this harness must avoid, both recorded from prior milestones. First, a perfect pin on the wrong subject is worthless: falsifiability proves an assertion *can* fail, not that it is about the right thing, so each mutation must remove the specific evidence the assertion claims to read. Second, a mutation that silently fails to apply leaves the suite green and reads as a pass, which is why AC-STE-483.6 asserts a count.

## Testing

Self-testing by construction: the harness's own output is the evidence. Meta-test that the harness enumerates every assertion M127 repairs, so a repair added without a mutation check fails the gate. `bun test` from `plugins/dev-process-toolkit`.
