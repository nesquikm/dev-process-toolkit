# The ship-coherence gate grades a milestone's sibling half

## Summary

The ship-coherence gate graded a shipped milestone against this repository alone, so a release covering half of a two-repository milestone looked complete.
It now reads the sibling named in the spanning declaration and reports one new kind of row.
A sibling with no plan for the milestone, or one whose declaration does not name this repository back, fails the gate.
A sibling that has not shipped yet, or cannot be found on this machine, is reported as a note instead.

## Requirement

Probe #63 gains a `sibling_unshipped` violation kind by extension, never a new probe id. The sibling leg runs only on an archived plan whose `shipped_in:` stamp resolves to a CHANGELOG heading and which declares `spans_repos:`. Every row it pushes names the LOCAL plan file, so the resume classifier can still select it.

## Technical Design

A new module, `adapters/_shared/src/sibling_release.ts`, owns the sibling-plan read: it unions the sibling's live and archive plan paths and reads `shipped_in` and `spans_repos` through the shared frontmatter parser, so CRLF and BOM fold once. `plan_ship_coherence.ts` runs the leg after the CHANGELOG check, locates siblings through `resolveSpansRepos`, tests same-repo through `sameRepo`, and routes every push through `makeViolation` with the local plan as `file`. A `SpansReposError` is caught per plan and converted into a row. Unlocatable and unshipped siblings aggregate into one notes row, mirroring `parked milestones:`. `ship_partial: true` is read with the probe's own `scanFrontmatterField`.

## Testing

New suite over `makeSpanFixture` roots; each test writes an archived stamped plan and a matching CHANGELOG heading into root A.
