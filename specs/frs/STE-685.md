# Nested test runs and the gate carry hard time limits

## Summary

Some tests start a whole second test run and wait for it with no time limit.
These runs can nest three levels deep, so one stuck child can hold up the whole gate.
The plain gate also keeps the five second default for each test, and a slow check timed out under load.
This change gives every nested run a time limit and a depth limit.
It also sets a thirty second limit for each test in the gate.

## Requirement

A test that starts a nested `bun test` run waits on it synchronously, so bun cannot time that test out until the child returns. M_0cac80's wedge analysis found about 22 such sites. Some run whole suites, and some re-run their own file under a mutation overlay. None has a timeout, and the chains go up to three levels deep (m_102cfa-ste-672 → m_79b1f6-ste-590 → nested). Every nested `bun test` spawn must go through one shared runner that bounds it in time and depth. The plain gate must apply the per-test timeout already measured to finish a loaded full run (`--timeout 30000`, M_85e846: 380 s, 0 fail).

## Acceptance Criteria

- AC-STE-685.1: A shared test module `tests/_nested_bun_test.ts` exports one runner that spawns `bun test` with a `timeout` (default 300000 ms, overridable per call) and `killSignal: "SIGKILL"`, and returns the exit code, stdout, stderr and a `timedOut` flag; a child that outlives its timeout is killed and reported `timedOut: true`.
- AC-STE-685.2: The runner passes the child an environment depth counter, `DPT_NESTED_BUN_TEST_DEPTH`, one higher than its own; a call made at depth 3 refuses before spawning, with an error naming the depth and the ceiling.
- AC-STE-685.3: A sweep test finds zero nested `bun test` spawns (`spawnSync`/`Bun.spawnSync`/`Bun.spawn` whose argv starts with `bun test` or `process.execPath, "test"`) under `tests/` and `adapters/` outside the runner; a planted direct spawn in a fixture tree is found, as a positive control.
- AC-STE-685.4: `plugins/dev-process-toolkit/bunfig.toml` sets `[test] timeout = 30000`; a fixture test that sleeps 6 s, run from the gate root through the runner, passes, and the same run without the bunfig line fails at the 5000 ms default.
- AC-STE-685.5: The m116-ste-424 probe #73 dogfood test declares its own 30000 ms timeout.
- AC-STE-685.6: Removing the runner's timeout, its SIGKILL signal, or its depth refusal each reddens at least one test.
- AC-STE-685.7: `bun test` from `plugins/dev-process-toolkit` reports 0 failures, and its skip identities equal the trunk baseline by name.

## Technical Design

One helper in `tests/`, beside the other underscore-prefixed test helpers. Every site listed in the M_0cac80 wedge table, and every self-re-running mutation overlay, calls it instead of spawning `bun test` itself. The depth ceiling is 3, the deepest chain that ships today, so no existing chain breaks and nothing can grow past it. The bunfig file sits at the gate root, so nested runs started there inherit it. Runs started in a fixture directory keep their caller's explicit timeout.

## Testing

Unit tests for the runner use a fixture test that sleeps, and a fixture that recurses until refused. The sweep test greps the tree, and a planted direct spawn serves as its control. The bunfig check runs a nested fixture with and without the file.
