# Writes through the generic execute tools are gated

## Summary

The newer Atlassian tools can run any operation by name.
Three generic tools do this, and the write gate never saw their writes.
The gate now reads the wrapped operation as a normal call.
It refuses an operation it does not know where a shared Jira project is declared.
Listed operations outside Jira still pass.

## Requirement

A write sent through `executeWrite` or `executeDestructive` gets the verdict the direct call would get, and an operation the gate cannot place is refused wherever a shared Jira target is declared.

## Acceptance Criteria

- AC-STE-866.1: The `hooks.json` matcher matches `executeWrite`, `executeDestructive` and `executeRead` under both server spellings, and the translator unwraps `{name, inputs, cloudId}` to the named operation's canonical call, with `cloudId` read beside `inputs` or inside it. Two different `cloudId` values are refused in a declared container.
- AC-STE-866.2: A wrapped create, edit, transition, comment, worklog and issue link each gets the direct call's verdict, with one permit leg and one refuse twin per operation, through the `.sh` wrapper. A wrapped operation may use the v1 or the v2 operation name.
- AC-STE-866.3: When the session binds a declared shared Jira target, a wrapped write whose operation name is unknown, missing, empty or not a string, or whose `inputs` is not an object, is refused and the refusal names the operation. With no declared target the hook exits 0 with no stdout and no stderr for the same payloads.
- AC-STE-866.4: A listed non-Jira write operation passes in a declared container. The list is the ungated Confluence and Compass names plus the v2 Confluence names, each entry carries a one-line reason, and no Jira operation is in it.
- AC-STE-866.5: `executeDestructive` naming a Jira operation is always refused in a declared container. A call is graded by its operation and not by its wrapper: a write named under `executeRead` is graded as that write, and a known read named under any wrapper passes.
- AC-STE-866.6: The gate's transcript walk counts a wrapped create as a prior create, as a create that may have made its ticket and as the spend of a receipt, exactly as a direct create. The live grader gives the same verdicts and reports an ungated wrapped write as one.
- AC-STE-866.7: An operation nested in another execute operation is refused in a declared container, never unwrapped twice.
- AC-STE-866.8: `bun test` from `plugins/dev-process-toolkit` reports 0 failures, and its skip identities equal the trunk baseline by name.

## Technical Design

The STE-865 translator gains one unwrapping step and an operation classification: gated write, known read, listed non-Jira write, unknown. `UNGATED_WRITE_TOOLS` and `TRACKER_READ_TOOLS` stay the only lists. An unknown operation carries no container, so it is refused when any declared Jira target is in scope for the call, the scope `main` already computes.

## Testing

Hook tests through the `.sh` wrapper in a declared and an undeclared repository; transcript-walk tests with wrapped creates; grader twins on the same records.

## Notes

The operator chose fail closed on 2026-11-24. A harmless unlisted operation is refused until it is listed with a reason. The wrapper schemas and one wrapped read were recorded; no wrapped write was.
