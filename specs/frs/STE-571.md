# The chains a consumer follows name the gates they will hit

## Summary

A bootstrapped project is handed a workflow chart, and it is a map with the tolls left off. All four chains end at the pull request, none of them names the review step a hook demands first, and the copy the setup skill points readers at is staler still: it drops half the chain and puts the review in the wrong place. An agent following the file it was given walks into a refusal nobody warned it about.

## Requirement

Every workflow chain a consumer is handed names the steps its blocking gates require, and the two shipped copies of that chain agree with each other.

## Acceptance Criteria

- AC-STE-571.1: All four workflow chains in `templates/CLAUDE.md.template` — Bugfix, Feature, Refactor and UI change — name `/spec-review` before `/pr`. Asserted per chain, not once for the block: three of four passing is a fail.
- AC-STE-571.2: The template carries a gate-announcing block naming all three blocking hooks, each with the command that fires it and the Skill invocation it requires, and pointing at the hooks manual. Naming two of the three fails the assertion.
- AC-STE-571.3: The `docs/setup-reference.md` § Step 11 copy of the chains is reconciled with the template, and one of the two is declared canonical in prose so a future editor knows which to change. Asserted by comparing the two chain sets against each other rather than by pinning either one, so a later edit to the canonical side that skips the other still reds.
- AC-STE-571.4: Falsifiability. AC.1, AC.2 and AC.3 are mutation-tested — dropping `/spec-review` from any single chain, naming only two of the three hooks, and reverting either chain copy each red the run — and every mutation is first measured clean against the landed tree, through the throwing `mutate` helper.

## Technical Design

Both surfaces are prose, so the whole design decision is what the test compares against. Pinning the template's chain lines as literals would pass while the second copy drifts, which is the defect that already shipped. So AC.3's reader extracts the ordered skill sequence from each surface and compares the two extractions.

The gate block is placed after the four chains rather than before them: the chains are what a reader scans for, and the block explains what the chains now include.

`skills/setup/SKILL.md` already points at § Step 11 and sits at the NFR-1 cap, so it is not edited. The overflow home is the reference doc, which has no cap.

## Testing

The ordered-token pin at `tests/m84-ste-324-low-polish-bundle.test.ts:336` walks the Feature chain with an at-or-after cursor, so inserting `/spec-review` between `/ship-milestone` and `/pr` is safe and reordering is not. That pin is left alone and this FR's own tests sit beside it.

Every clause is exercised by mutating the landed file, not by reading it twice.

## Notes

The template ships verbatim into every bootstrapped project, so this edit is the one a consumer actually reads. The reference doc is the one this repo's own setup run surfaces.
