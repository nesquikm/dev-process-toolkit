# Best-practices manifest: specs/best-practices.yaml module + day-one hygiene probe

## Summary

Teams accumulate house rules that live in scattered documents nobody checks at review time. This adds a small curated catalog of best-practice documents to the specs tree, read through one module with loud shape errors, and a gate probe that validates the catalog and that every referenced document actually exists — from the first release, not after an incident.

## Requirement

`specs/best-practices.yaml` manifest (git-tracked, empty valid, absent ≡ empty) + `best_practices_manifest.ts` module cloned from the deps-manifest idiom + a day-one error-severity gate-check hygiene probe. Twin of STE-301's deps stack; the STE-373 twin-parity lesson mandates the probe ships in the same FR.

## Acceptance Criteria

- AC-STE-465.1: New module `adapters/_shared/src/best_practices_manifest.ts` (read/write/add/remove/find); entry schema `{name, path, scope?: [globs], topics?: [strings], notes?}`; empty manifest valid; absent file ≡ empty.
- AC-STE-465.2: Malformed manifest ⇒ `BestPracticesManifestShapeError` in NFR-10 canonical shape at read time — never a silent skip or partial parse.
- AC-STE-465.3: Closed schema — unknown entry keys refuse; `path` must be repo-relative (no `../` escape, no absolute paths).
- AC-STE-465.4: New gate probe `best_practices_manifest_hygiene` (severity error): manifest shape valid AND every entry's `path` resolves on disk; vacuous when the manifest is absent; registered in the gate-check SKILL numbered list + every probe-count-pinned site.
- AC-STE-465.5: Probe test file with positive + negative fixtures; each guard mutation-verified (flip a condition ⇒ red).

## Technical Design

Clone the `deps_manifest.ts` idiom verbatim (the fix-the-quiet-half lesson: reuse the existing idiom, do not abstract); shared closed-enum consts exported for STE-466/467. Probe follows the STE-369 module shape and takes the next free number; registering it flips every probe-count-pinned meta-test site in the same commit (the M118 lesson).

## Testing

`bun test` from `plugins/dev-process-toolkit`; new module test + probe test with positive/negative fixtures; mutation-verify each schema guard and the path-resolution check.

## Notes

- Precedents: STE-301 (deps stack), STE-373 (day-one twin parity), STE-369 (probe shape).
- Consumers: STE-466 (management skill), STE-467 (review lens).
- Review-hardening edge cases (Phase 3 round 1, backfilled): adjacent `**` glob segments collapse before regex compilation (backtracking-blowup guard); `name`/`path`/`notes` refuse control characters (single-line values — newline injection would splice manifest lines); `writeManifest` validates every entry via `assertEntryShape` before serializing; absolute-path refusal covers Windows drive-letter (`C:`) and UNC (`\\`) forms, not just POSIX `/`.
