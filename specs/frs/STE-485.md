# Fixture 3c must assert the probe-#37 token and verdict the runtime actually emits

## Summary

This fixture states in bold which spelling of a probe identifier to look for, crediting an earlier correction. The runtime emits the other spelling. The spelling the fixture insists on does appear in the repository — as a module filename, which is not an emission and can never appear in a capture. The same fixture also expects a verdict word the runtime never prints. It is the second time this one fixture has drifted from what the system does.

## Requirement

Both clauses assert what the runtime emits, verified against a real capture rather than against prose. The bold instruction that propagated the wrong spelling is removed, and the correction records how it went wrong so the third round does not happen.

## Acceptance Criteria

- AC-STE-485.1: The probe-identifier clause asserts the hyphenated `cross-cutting-spec-stale-file-refs` the runtime emits; a capture from a genuine probe firing satisfies it.
- AC-STE-485.2: The verdict clause asserts `GATE PASSED WITH NOTES`, the phrase the runtime renders, not the literal `ADVISORY` it does not.
- AC-STE-485.3: Notes record that the underscored occurrences in the repository come from the module path `adapters/_shared/src/cross_cutting_spec_stale_file_refs.ts` — a filename, not an emission — naming the specific reasoning error that produced the wrong correction.
- AC-STE-485.4: STE-483's harness proves both clauses fail when probe #37 does not fire.
- AC-STE-485.5: A check verifies each asserted token against its emitting source, so a fixture cannot assert a token no shipped code emits.

## Technical Design

Measured on two legs, on a capture where probe #37 genuinely fired against a planted stale leaf: the underscored form appears 0 times raw and assistant-scoped alike; the runtime emits the hyphenated probe id. The fixture's bold claim credits STE-421 AC.4, which makes this that AC's own failure mode recurring inverted — a correction applied in the wrong direction.

AC-STE-485.5 is the generalisation and the part that stops recurrence. The failure mode is asserting a token that exists somewhere in the repo but is never emitted; checking the assertion against the emitting source catches that class rather than this instance. The fixture already carries a note about a prior drift on the same surface, so instance-level fixes have demonstrably not held.

## Testing

Both clauses run against a real probe-firing capture (expect pass) and a non-firing capture (expect fail) through STE-483's harness. Token-versus-source check with a fixture asserting a filename-only token, which must fail. `bun test` full root.
