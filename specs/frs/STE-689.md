# A release can close a milestone without a version

## Summary

Some projects let their git tags and CI pick the version number.
In such a project the release step still bumps a version and writes a numbered changelog section.
A downstream team had to revert one release and park the milestone by hand.
This change adds an opt-in setting for that kind of project.
With it, the release step adds the milestone's entries to the unreleased part of the changelog and changes no version.

## Requirement

A project whose git tags and CI workflows own the version cannot run `/ship-milestone`: `release_config.ts` always inserts a `## [X.Y.Z]` CHANGELOG section, and the flow always infers a version, a codename and a `release/v<X.Y.Z>` branch (gist 271417a0, plugin v2.99.1). A new `## Docs` flag, `changelog_unversioned`, makes the ceremony close a milestone with no version: entries land under `## [Unreleased]`, no versioned file is rewritten, and the release commit names no version. A project without the flag behaves exactly as today.

## Acceptance Criteria

- AC-STE-689.1: `readDocsConfig` returns `changelogUnversioned` from a `changelog_unversioned:` line in `## Docs`; an absent key or section reads `false`, and any value other than lowercase `true`/`false` throws `MalformedDocsConfigError` naming the key.
- AC-STE-689.2: The `## Docs` canonical-key set graded by the docs-section probe includes `changelog_unversioned`, so a CLAUDE.md declaring it passes that probe; the CLAUDE.md template and `docs/setup-reference.md` document the key with default `false`.
- AC-STE-689.3: With the flag `true`, `release_config.ts <projectRoot> unreleased --date <YYYY-MM-DD> --body "<body>"` rewrites only the `kind: changelog` entries and reports every other entry as `skipped <path> (changelog_unversioned: true)`, leaving those files byte-identical; `--codename` and `--test-count` are not required.
- AC-STE-689.4: Under the flag, the changelog body is merged into a `## [Unreleased]` section: each FR line goes under its `### <Category>` subsection, an existing subsection is appended to rather than duplicated, and a missing `## [Unreleased]` heading is created directly above the topmost `## [X.Y.Z]` section (or at the end of the preamble when there is none). Every `## [X.Y.Z]` section stays byte-identical.
- AC-STE-689.5: Running the same unreleased write twice with the same body leaves the file unchanged on the second run (no duplicated FR line).
- AC-STE-689.6: The writer refuses in the NFR-10 shape, writing nothing, when the positional version is `unreleased` and the flag is absent or `false`, and when the flag is `true` and the positional version is an `X.Y.Z` number.
- AC-STE-689.7: `--dry-run` under the flag prints the same rewrites and skips as the real run, writes nothing and exits 0.
- AC-STE-689.8: `skills/ship-milestone/SKILL.md` says that under the flag the run skips version inference and codename resolution, still runs the test-gate refusal #3, writes no test-count line, proposes the branch `release/<milestone-lowercase>-unreleased`, stamps `shipped_in: unreleased`, and commits with subject `chore(release): <milestone> unreleased` and footers `Release: unreleased` and `Refs: <milestone>`; `branchNameFor` returns that branch for an unreleased input.
- AC-STE-689.9: With the flag absent, a `release_config.ts` run over this repo's own `## Release Files` block produces output byte-identical to the pre-change writer for the same arguments.
- AC-STE-689.10: Removing the flag check from the writer, or the subsection merge, each reddens at least one test.
- AC-STE-689.11: `bun test` from `plugins/dev-process-toolkit` reports 0 failures, and its skip identities equal the trunk baseline by name.

## Technical Design

`DocsConfig` gains `changelogUnversioned`. The front door accepts the literal `unreleased` in the version slot and routes to a new `bumpChangelogUnreleased(content, body)` beside `bumpChangelog`; the existing `changelog_ci_owned` skip still wins for the changelog entry, and the stamp is unaffected by it. Migration coverage under the flag checks registry presence only, since there is no version to compare `introduced_in` with. `branchNameFor` takes an optional `{ milestone, unreleased }`.

## Testing

Writer tests run fixture repos with and without the flag over a CHANGELOG with and without an Unreleased heading. A golden test pins this repo's own block as unchanged. Docs-config tests add the malformed-value case.
