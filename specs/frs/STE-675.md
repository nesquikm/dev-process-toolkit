# Readiness checks the caption filter; the edit list is documented

## Summary

Captions need a text filter that some ffmpeg builds do not include.
Today the video pipeline finds this out only at the final render, after paid voice and music calls.
The readiness check now looks for the filter whenever captions are on, and names the build that has it.
The video reference also gains a section that documents the edit list file.

## Requirement

- **Readiness.** When the stored style has captions on, readiness asks ffmpeg for its filter list. When the caption filter is missing, it adds one reason with the remedy. When captions are off, there is no check.
- **Remedy text.** The remedy names a build that has the filter. On Homebrew that is ffmpeg-full, which is keg-only, so its bin directory goes first on PATH. The render-time refusal carries the same remedy.
- **Docs.** The video reference documents every field of the edit list, and a test keeps it in step with the parser.

## Acceptance Criteria

- AC-STE-675.1: When the stored style has `captions.enabled: true`, `videoReadiness` runs `ffmpeg -hide_banner -filters` through an injectable runner and adds exactly one reason when `drawtext` is not listed; the reason names `drawtext` and its remedy names `brew install ffmpeg-full` and putting that keg's `bin` first on `PATH`, or turning captions off.
- AC-STE-675.2: With captions off, readiness runs no ffmpeg command (asserted by the injected runner's call log); with captions on and `drawtext` listed, it adds no reason.
- AC-STE-675.3: Because every stage checks readiness first, a missing `drawtext` with captions on refuses the voice stage before any provider call (asserted with an injected fetch that records zero calls).
- AC-STE-675.4: The render-time caption-filter refusal carries the same remedy text as the readiness reason, held in one shared constant; neither still recommends plain `brew install ffmpeg`.
- AC-STE-675.5: `docs/video-reference.md` gains an `edl.json` section documenting `edl_version`, `clips` (`src`, `in`, `out`, `at`, `effects`), `voice` (`segment`, `audio`, `offset`), `captions` (`text`, `start`, `end`), `music` (`src`, `level_db`), `anchors` (`name`, `at`), and the anchor reference form (`segment`, `word`).
- AC-STE-675.6: A test pins that section to the EDL parser: every field the parser accepts is named in the section, and every field the section names is accepted by the parser.
- AC-STE-675.7: `bun test` from `plugins/dev-process-toolkit` reports 0 failures, and its skip identities equal the trunk baseline by name.

## Technical Design

Readiness gains a caption-filter reason that reuses the render module's filter test, behind an injectable runner so tests never need a real ffmpeg. One constant carries the remedy for both readiness and render. The docs section is plain reference prose; the pin test reads the field names from the parser's accepted keys.

## Testing

Readiness fixtures with a fake runner for listed, missing and captions-off; a stage test with a recording fetch; the doc-to-parser pin.

## Notes

The first video run hit the late refusal: Homebrew's plain ffmpeg ships without the text filter, and only ffmpeg-full has it.
