# /implement adds or edits the e2e tests its change needs

## Summary

Tests are written per acceptance criterion, at unit granularity, by an agent that never sees the running system. Nothing in the loop adds or updates an end-to-end test for the behaviour that changed, so the end-to-end suite drifts away from the product one change at a time and the evidence rows above end up reporting on a suite that stopped covering anything.

## Requirement

A change that has end-to-end observable behaviour arrives with its end-to-end tests updated, and the suite is run.

## Acceptance Criteria

- AC-STE-512.1: When `e2e_cmd` is declared, `/implement` adds or edits end-to-end tests covering the change before the gate is declared green.
- AC-STE-512.2: The end-to-end suite is run and its counts reported through the evidence rows.
- AC-STE-512.3: A change with no end-to-end observable surface records that explicitly, rather than silently adding nothing.
- AC-STE-512.4: `e2e_cmd` absent is vacuous and byte-identical to today.
- AC-STE-512.5: Capability tokens distinguish authored, edited, none-needed and suite-red.

## Technical Design

The `/tdd` orchestrator writes tests per AC through a test-writer that is deliberately isolated from the implementation. That isolation is correct for unit tests and is exactly wrong for end-to-end tests, which have to know what the running system exposes. So this work does not belong inside the RED stage; it belongs after the ACs are green and before the gate is declared, alongside the other Phase 4 hooks.

AC.3 is the criterion that keeps the whole thing honest, and it is the quiet half. Most changes to a config parser or a token map have no end-to-end observable surface, and for those the correct output is "none needed" — stated, not inferred from the absence of a diff. A silent skip and a considered decision produce identical trees, and only one of them is a decision. The distinction has to be recorded or the capability degrades into a step everyone assumes ran.

AC.5 makes that distinction machine-readable, which is what lets STE-510's evidence rows report it rather than merely omit it.

AC.4 keeps every project without an `e2e_cmd` on today's behaviour exactly, which is the same gating discipline STE-505 uses for `run_cmd`.

## Testing

Coverage for a change with end-to-end observable behaviour producing an added or edited test before the gate is declared. Coverage for a change with no such surface producing the explicit none-needed record — asserted directly, since this is the path that otherwise reads as a silent skip. Suite-run coverage asserting counts reach the evidence rows. `e2e_cmd` absent asserted byte-identical to today. Capability-token coverage for all four outcomes. `bun test` full root.

## Notes

This is the FR most likely to be quietly under-delivered, because "no e2e test was needed" is always available and never obviously wrong. AC.3 and AC.5 exist to make that claim visible rather than assumed.

Deliberately not in scope: changing what `/tdd`'s test-writer does. The isolation guarantee that makes unit TDD work is left intact.
