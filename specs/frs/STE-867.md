# Atlassian v2 answers are read, and an error inside a success is an error

## Summary

The newer Atlassian tools wrap every answer in one outer object.
The toolkit could not read those answers at all.
A failed write can also come back looking successful.
The one answer reader now handles both cases.
Older answers read exactly as before.

## Requirement

The one tracker-answer reader accepts the Atlassian v2 envelope, and a v2 answer that carries an error is an error to every consumer whatever the call's own error flag says.

## Acceptance Criteria

- AC-STE-867.1: `tracker_answer.ts` accepts `{data: <page>}` and `{data: <item>}` beside the shapes it accepts today. A key beside `data`, an array, a string or a null under `data`, and a nested `data` each still fail closed, one negative test each.
- AC-STE-867.2: A `{data: {error, …}}` answer is a named error from that reader, never an item, a page or an empty page, whatever its other keys.
- AC-STE-867.3: The gate reads a v2 create answer `{data: {id, key}}` as a settled create of that key. An in-band error answer gets the verdict an error result of the same status gets today: a definite 4xx other than 408 proves the call never landed, and any other status, or none, leaves a create that may have made its ticket. So does an in-band error that names a created key or id beside the error, whatever its status.
- AC-STE-867.4: A v2 `getJiraIssue` answer, direct or through `executeRead`, gives ticket provenance exactly as a v1 answer does, and an answer without the fields the ownership verdict needs gives none and the refusal names the missing fields. An in-band error gives none.
- AC-STE-867.5: `create_idempotency_probe.ts decide --from-transcript` accepts v2 searches, direct or through `executeRead`, and every other listing consumer reads v2 pages: the milestone decision, container and ticket ownership, the attach target, Epic close, import, the sibling gate, the bug-type check and the repoint command. One positive test each, through the command form where one exists.
- AC-STE-867.6: A test pins that every v1 fixture under `tests/fixtures/live-shapes/` reads to the same result as before.
- AC-STE-867.7: Each new accepted shape has a sanitised fixture under `tests/fixtures/live-shapes/jira/` that records its provenance and date, and no fixture carries a real key, site, name, address or account id.
- AC-STE-867.8: `bun test` from `plugins/dev-process-toolkit` reports 0 failures, and its skip identities equal the trunk baseline by name.

## Technical Design

`tracker_answer.ts` unwraps one `data` level at its entry and returns an error reason for `data.error`. Readers that parse a result themselves, `createdKeyOf` and the hook's provenance and re-list readers, call it instead. `neverRan` gains the in-band status. Reads through `executeRead` are named by the STE-865 translator.

## Testing

Reader unit tests per shape; hook transcript tests for settled, lost and never-ran v2 creates and for provenance; command tests on saved v2 pages.

## Notes

Measured 2026-11-24: readers refuse `{data}` today. Recorded: reads, searches, edits, a create, transitions and a 4xx transition error returned without the error flag.
