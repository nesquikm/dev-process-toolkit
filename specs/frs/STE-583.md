# A spanning declaration reader, with a front door

## Summary

No plan can say a milestone also lives in a second repository, so nothing can be taught to wait for a sibling.
A new reader parses a spanning declaration, a map from repository name to path, through the shared frontmatter parser.
It refuses each malformed spelling loudly and resolves every entry to a located root and the work bound there.
A command-line entry point makes it runnable, which the reachability ratchet requires before any prose may order it.

## Requirement

A new module must read the `spans_repos:` plan-frontmatter key as a nested map with exactly three arms — undeclared, declared map, malformed and refused — resolve each entry through the shipped repo probe and the shipped FR binding, and expose a front door.

## Acceptance Criteria

- AC-STE-583.1: A nested map at 2-space indentation returns `{ declared: true, entries: [{ name: "glacy-app-fe", declaredPath: "." }, { name: "glacy-app-be", declaredPath: "../glacy-app-be" }] }` with order preserved, and the same body at 4-space indentation, at tab indentation, as a CRLF source and as a BOM-prefixed source each return deep-equal entries.
- AC-STE-583.2: Four undeclared controls — no `spans_repos:` key, `spans_repos: null`, `spans_repos: ~` and `spans_repos: ""` — each return `{ declared: false, entries: null }` and throw nothing. A run in which any one of the four throws fails this AC.
- AC-STE-583.3: The flow list `spans_repos: [a, b]` throws a `SpansReposError` whose message carries `Refusing:`, `Remedy:` and `Context:` at line starts and contains the literal `[a, b]`.
- AC-STE-583.4: A block list throws, and the messages thrown for a block list, for `spans_repos: {}` and for a bare `spans_repos:` line are byte-identical, contain each of the words `block`, `empty` and `bare`, and contain no repository name from the fixture.
- AC-STE-583.5: A block list whose items carry colons (`  - glacy-app-fe: .`) throws a message containing the literal `- glacy-app-fe`, and that message differs from the one in AC.4.
- AC-STE-583.6: An entry with an empty value (`glacy-app-fe:`) throws a message naming `glacy-app-fe`, and an entry whose value is `null` throws a message naming its key.
- AC-STE-583.7: Two real `mkdtempSync` roots A and B, with B holding one active FR bound to the milestone: `resolveSpansRepos({ planBody, milestone, invokingRepo: A })` resolves with `self: true` for the `.` entry, and for B `realpathSync(root) === realpathSync(B)`, `self: false` and `binding.activeFrIds.length === 1`.
- AC-STE-583.8: A declared path that does not exist yields `{ root: null, binding: null }` for that entry, and the call resolves rather than rejects.
- AC-STE-583.9: Each fact keeps one home. `adapters/_shared/src/spans_repos.ts` imports `parseFrontmatter` from `./frontmatter`, `defaultRepoProbe` and `sameRepo` from `./target_repo` (which now exports `sameRepo`), and `milestoneFrBinding` from `./active_plan_ship_ready`; the module contains no `existsSync` call and no `split("\n")`.
- AC-STE-583.10: The front door runs for real: `spawnSync("bun", ["run", MODULE, planFile, "M_GF_78", rootA])` exits 0 and stdout matches `/^glacy-app-fe\s+self/m` and `/^glacy-app-be\s+sibling/m`; the same spawn on an undeclared plan exits 0 with empty stdout.
- AC-STE-583.11: The same spawn with no arguments exits non-zero with empty stdout, and stderr matches `/^Refusing:/m`, `/^Remedy:/m` and `/^Context:/m`; a malformed plan behaves the same way.
- AC-STE-583.12: Documented, never scaffolded: `templates/spec-templates/plan.md.template` names `spans_repos` inside an HTML comment, and no line of the template's frontmatter block begins with `spans_repos:`.
- AC-STE-583.13: No new probe, and the ratchet holds: `grep -cE '^[0-9]+\. \*\*' skills/gate-check/SKILL.md` returns 85; `grep -c 'import.meta.main' adapters/_shared/src/spans_repos.ts` returns at least 1; `await runModuleReachabilityProbe(repoRoot)` reports `orderedUnreachable` equal to the shipped `ORDERED_UNREACHABLE_PIN` with `ok: true`, and this FR does not edit that constant.
- AC-STE-583.14: The full `bun test` from `plugins/dev-process-toolkit` reports zero failures with the skip count unchanged from the 15 measured at v2.81.0.

## Technical Design

Three arms, keyed on `parseFrontmatter(planBody, { lenient: true }).spans_repos`; the undeclared sentinel set is copied from the target-repo reader. Measured, the shipped parser on this key:

```
NESTED_MAP 2-space  → object {"glacy-app-fe":".","glacy-app-be":"../glacy-app-be"}
BLOCK_LIST 2-space  → object {}
bare key            → object {}
empty map {}        → object {}
FLOW_LIST           → string "[., ../glacy-app-be]"
tilde               → string "~"
null                → null
```

A block list dies at the parser's no-colon skip, indistinguishable from an empty map or a bare key — the same silent-degradation class the target-repo refusal closes — so all three refuse with one message. No second raw-line scan. Roots come from `defaultRepoProbe().locate`; an unlocatable sibling is a runtime fact, never a throw.

## Testing

A new suite. Its two-root cases build their trees with the shared span fixture, created here as its first consumer and graded by the fixture FR. Each malformed arm is also asserted to fail on its sibling spelling.

Nothing hard-grades a malformed map between this release and the next milestone, because probe 75 is warning-only. That soft window is accepted, not patched with a new probe.
