# The sibling release gate refuses whenever it cannot prove the sibling is idle

## Summary

One repository could release a shared milestone while its sibling still had work, whenever that work sat on another branch or worktree, had not started, or the sibling could not be found.
The gate read each of those as idle, with the footer a finished sibling gets.
It now reads the sibling's whole repository and refuses unless the sibling is provably idle.
Every place that offers a release says why it is held.

## Requirement

Measured at HEAD ac1f3cb with real git repositories and worktrees (findings SF-1, SF-2, SF-3, SF-5, SF-6, RS-5, RS-6, RS-13, LIN-2, and the skeptics' notes on the `/deliver` message and the close offer):

- A sibling is located by `existsSync` plus `isDirectory` on the declared path, resolved against the invoking checkout (`target_repo.ts:240-252`). A wrong existing directory locates. From a nested `.claude/worktrees/*` checkout the relative path is unlocatable.
- Busy means active FR files bound to the token in that one working tree (`active_plan_ship_ready.ts:197-199`). Work on an unmerged branch or in a second worktree reads as idle. So does a sibling with no plan and no FRs, or an open plan with no FR files.
- An unlocatable sibling ships: refusal #4 exits 0 with one stderr line, probe #75 keeps the milestone ship-ready, the `/implement` close-offer CLI prints the token with nothing on stderr, and the resume classifier consumes only `.busy`.
- Two containers cannot share a token, so a span declared across two tracker projects reads the busy sibling as idle.
- Self versus sibling is a string compare of resolved paths (`target_repo.ts:272-274`), so worktrees and symlinks misclassify. Post-ship probe #63 then raises a false "does not name this repo back" error from a sibling-directory worktree.
- The live `/deliver` milestone resume of a held span refuses with "the delivery decision record carries no `chain` field", which names the wrong cause. `dispatchResume` claims and spawns with an empty chain; it has no live caller today, but nothing stops one.

Old clients keep the fail-open gate: this is local release code, so a repository on an older plugin releases as before, and the release version of this FR is the floor the plan tells shared repositories to declare.

Required behaviour: one executed classification of each declared sibling into a closed set of states, read from the sibling's git state rather than one working tree. Only `idle` releases without `--partial`. Every surface that offers or plans a release reports the state that holds it.

States: `idle`, `busy`, `not-started`, `no-plan`, `unlocatable`, `not-a-repository`, `not-toolkit-managed`, `different-container`, `unreadable`. A located sibling is `idle` only when it is a git repository, is toolkit-managed, binds the same tracker project as this repository (tracker modes), holds a plan for the milestone, has at least one FR bound to the milestone, and has no active one.

## Acceptance Criteria

- AC-STE-609.1: `sameRepository(a, b)` is exported from `adapters/_shared/src/target_repo.ts`. It compares the realpaths of each path's `git rev-parse --git-common-dir`, and falls back to realpath equality when either path is outside a git work tree. `resolveSpansRepos` uses it for the self flag, and `plan_ship_coherence.ts` uses it for the names-back check. Two worktrees of one repository compare equal. A symlinked path to a checkout compares equal. Two separate clones compare unequal. A path that does not exist compares unequal to everything and never throws. `sameRepo` and `routeMilestone` are byte-unchanged (control: a `target_repo:` naming a worktree of the invoking repository routes exactly as on HEAD).
- AC-STE-609.2: A relative `spans_repos` path resolves against the invoking repository's main worktree root, the first entry of `git worktree list --porcelain`, not against the invoking checkout. A bare common directory has no main worktree; there the invoking checkout is used, as on HEAD, and that fallback is asserted. One plan locates the same sibling root from the primary checkout, from a sibling-directory worktree and from a nested `.claude/worktrees/<name>` checkout; all three are asserted, and the nested case is red on HEAD. Absolute and `~` paths resolve as on HEAD. An invoking root outside any git work tree resolves as on HEAD.
- AC-STE-609.3: Exactly one entry names the invoking repository. A declaration in which zero entries, or two or more, resolve to the invoking repository (by `sameRepository`) is refused in NFR-10 shape, naming each entry and what it resolved to, by every reader of the declaration. Pasting one repository's declaration verbatim into its sibling, so that both entries resolve to self, is refused from both roots; on HEAD it passes with an empty footer.
- AC-STE-609.4: The sibling is read from git, not from one working tree. The classifier reads the FR files and the plan bound to the milestone from every worktree's working tree (`git worktree list`), every local branch and every remote-tracking ref of the sibling, without fetching. An FR id is active when some source holds it under `specs/frs/` bound to the milestone and no source holds it under `specs/frs/archive/` bound to it. The refusal names each active id with the source it came from. Legs asserted: active only on an unmerged branch that is not checked out ⇒ `busy` (red on HEAD); active only in a second worktree ⇒ `busy` (red on HEAD); active on a stale branch but archived on the trunk ⇒ not busy (the squash-merged permit leg). A git command that fails while reading the sibling ⇒ `unreadable`, never `idle`.
- AC-STE-609.5: Only `idle` passes. Refusal #4 (`siblingShipGate` and its front door) refuses without `--partial` for each non-idle state: exit 1, an NFR-10 refusal naming the milestone, the sibling, its state and a state-specific remedy that also names `--partial`, and empty stdout. `different-container` is decided by `readWorkspaceBinding` on both roots and is not applicable under `mode: none`; a sibling whose declaration that reader refuses is `unreadable` and carries the reader's text. With `--partial` every state passes, the milestone is stamped `ship_partial: true` as today, and the footer is measured as today. Controls: an idle sibling passes with its measured footer; two idle repositories that declare each other both pass, so no deadlock. A declared path naming an existing unrelated directory (the measured `../docs` case) refuses as `not-a-repository` or `not-toolkit-managed`. One fixture per state, each non-idle state red on HEAD except working-tree `busy`, which is a no-regression pin.
- AC-STE-609.6: One classification, every surface. `spanningSiblingState` is the single home of the state set: refusal #4, probe #75, the close-offer CLI and both resume scopes read it, and none classifies on its own. Probe #75 excludes every non-idle spanning plan from `ship-ready milestones` and renders it as `awaiting-sibling milestones: <token> (<sibling>: <state>)`; an unlocatable sibling keeps its `sibling-unlocatable milestones` row name but is no longer ship-ready. The close-offer CLI (`active_plan_ship_ready.ts` run as a command) keeps stdout as ship-ready tokens only, writes one `held: <token> (<sibling>: <state>)` line per held spanning milestone to stderr, and exits 0. The milestone-scope and FR-scope resume classifications treat every non-idle state as awaiting. The unlocatable fixture is red on HEAD at each surface, where it reads ship-ready.
- AC-STE-609.7: `/deliver` names the cause. `bun run adapters/_shared/src/deliver_decision.ts <milestone>` for a milestone-scope resume whose sibling is held exits 1 with an NFR-10 verdict naming the sibling and its state and a remedy naming `--partial`. The "carries no `chain` field" text never appears for this cause (red on HEAD). An FR-scope record whose chain stops at `/pr` because the sibling is held prints the eight labelled fields unchanged, followed by one advisory line naming the sibling and state. `dispatchResume` given an empty chain makes zero `claim` calls and zero `spawnWorker` calls and returns a refusal naming the held sibling.
- AC-STE-609.8: Post-ship, probe #63 keeps an unlocatable sibling as a note, because archived plans are permanent. It grades names-back with `sameRepository`: a release made from a sibling-directory worktree raises no "does not name this repo back" violation when the sibling's plan names the primary checkout (red on HEAD). A sibling that names an unrelated path still raises it (control).
- AC-STE-609.9: Prose follows the code, edited in place: refusal #4 in `skills/ship-milestone/SKILL.md` (the "An unlocatable sibling is not a refusal" sentence is replaced); the refusal #4 matrix in `docs/ship-milestone-reference.md`, one row per state; the probe #75 row in `skills/gate-check/SKILL.md`; and the close-offer sentence in `skills/implement/SKILL.md`, which now orders the skill to surface the CLI's stderr `held:` lines. Budgets: `skills/implement/SKILL.md` stays at 358 split-lines (pinned exactly by the STE-584 and STE-590 suites) and its close-offer line still names `spans_repos`; the gate-check skill's line count and every absolute probe-row position are unchanged; `skills/` gains zero STE tokens. The pins in `tests/m_79b1f6-ste-589-sibling-ship-gate.test.ts` that encode "an unlocatable sibling does not refuse" are amended in the same commit, and the amendment is recorded in this FR as superseding that clause.
- AC-STE-609.10: The shared fixture keeps its meaning. `makeSpanFixture` builds both roots as git repositories with one commit and a toolkit-managed CLAUDE.md bound to one tracker project, so its existing callers still exercise an idle-capable sibling rather than turning `not-a-repository`. Each of the eight suites that import it is run before and after: every expected verdict that changes (the zero-FR sibling that shipped under SF-5's documented design, the unlocatable sibling that did not refuse) is amended in the same commit and listed in this FR's implementation notes, and every other assertion stays unedited and green.
- AC-STE-609.11: Every clause asserting new behaviour is falsifiable: it fails on the pre-change bytes, passes on the post-change bytes, and the direction is recorded per clause. Controls, negative guards and no-regression pins are exempt by construction.

## Technical Design

The state set lives in `spanningSiblingState`, so every consumer inherits it with no second walk. Sibling reads go through git: `git worktree list`, one `git grep` across local and remote-tracking refs for the milestone binding, and a parser read of each hit. The working-tree reader stays as the worktree leg. Identity and location both key on the git common directory, which also fixes the nested-worktree path. The CLI keeps its stdout contract and gains stderr lines, so no consumer breaks.

## Testing

Extend `makeSpanFixture` with real git roots: an unmerged branch, a second worktree, a nested worktree and a symlinked checkout. One fixture per state, driven through the refusal #4 front door as a subprocess, probe #75, the close-offer CLI, both resume scopes and the `/deliver` front door. Assert both directions: every non-idle state refuses, and the idle, partial and deadlock controls pass.

## Notes

- Refs are read without a fetch, so a teammate's unfetched branch is invisible. Fetching stays the operator's choice.
- An abandoned branch holding an active FR holds the gate until the branch is deleted or `--partial` is passed. That is fail-closed by design, and the refusal names the ref.
