# Deps resolve from a linked worktree

## Summary

A dependency entry names its sibling repository as a path one level up.
The toolkit resolved that path against the checkout it runs in.
A linked worktree usually sits in another directory, so the sibling looked missing there.
The path now resolves against the main checkout when the run is in a linked worktree.
Everywhere else nothing changes.

## Requirement

`resolveSiblingPath` resolves a `../<name>` entry against the main worktree's root when the consumer checkout is a linked worktree, and against the consumer checkout otherwise, so `/deps` and the deps researcher find a sibling cloned beside the main checkout from any worktree of it.

## Acceptance Criteria

- AC-STE-877.1: In a linked worktree (made with `git worktree add` in a directory that is not beside the sibling), `resolveSiblingPath(worktreeRoot, { path: "../<name>" })` returns `<main worktree root>/../<name>`, where the main worktree root is the first entry of `git worktree list --porcelain`.
- AC-STE-877.2: In the main checkout, and in a repository with no linked worktrees, the result is byte-identical to today: `resolve(consumerRepoRoot, entry.path)`.
- AC-STE-877.3: When git cannot be run, the directory is not a git repository, or no main worktree can be found (a bare common directory), the function falls back to `resolve(consumerRepoRoot, entry.path)` and does not throw for that reason.
- AC-STE-877.4: Unchanged: a `path` that does not start with `../` still throws `DepsManifestShapeError`.
- AC-STE-877.5: Run from a linked worktree, `/deps list` reports a sibling cloned beside the main checkout as `present`, and the deps researcher does not list it under missing deps. The deps skill and the deps-researcher agent say that the sibling path is resolved against the main checkout.
- AC-STE-877.6: `bun test` from `plugins/dev-process-toolkit` reports 0 failures, and its skip identities equal the trunk baseline by name.

## Technical Design

Reuse the main-worktree lookup that STE-609 added for relative `spans_repos` paths: realpath of `git rev-parse --git-common-dir`, compared with the checkout's own, and the first `git worktree list --porcelain` entry as the main root. If no exported helper exists, extract one into `adapters/_shared/src/` and have both callers use it. A failed git spawn returns null and the caller falls back, as AC-STE-676.6 requires. The signature of `resolveSiblingPath` does not change.

## Testing

Real git fixtures in a temp directory: a main checkout with a sibling beside it and a linked worktree under another parent; a main checkout; a plain directory with no git; and a subdirectory of the worktree.

## Notes

From consumer report gist 68968900, gap 1. Spawned workers run in linked worktrees under a separate parent directory, so this is the case they hit.
