# A shipped milestone's Epic can be closed from the repository that planned it

## Summary

The release ceremony tells the agent to close a shipped milestone's Epic.
The tracker write gate refuses that write in every repository, so the step can never run.
A new checked command runs four checks first.
This repository planned the milestone, the milestone shipped, every sharing repository is done, and every child is done.
When all four pass, the gate lets that one Epic move to Done, and nothing else.

## Requirement

In a repository that declares a shared tracker container, an agent can close a shipped milestone's Jira Epic through exactly one checked path. Every other write to an Epic stays refused.

## Acceptance Criteria

- AC-STE-699.1: A new module `adapters/_shared/src/epic_close.ts` runs as `bun run epic_close.ts <projectRoot> <EPIC-KEY> --children <listing>` and is listed in `RECEIPT_WRITING_SUBCOMMANDS` with no subcommand, so `RECEIPT_ANNOUNCING_MODULES` carries it.
- AC-STE-699.2: The module writes and announces one `epic-close` receipt naming the key only when all four checks hold: (a) the git index of `<projectRoot>` tracks `specs/plan/<M>.md` or `specs/plan/archive/<M>.md` where `<M>` equals `milestoneIdFromEpicKey(<EPIC-KEY>)`; (b) that plan's `shipped_in` passes the shipped plan/ship coherence rule, so a CHANGELOG heading for the stamped version exists; (c) every `spans_repos` sibling the plan declares is idle by the shipped sibling-release check; (d) the listing holds at least one child and every child's status category is done.
- AC-STE-699.3: Each failing check refuses in the NFR-10 shape, names the check that failed and its remedy, exits non-zero and writes no receipt. A missing or unreadable `--children` listing refuses the same way.
- AC-STE-699.4: With an announced `epic-close` receipt for a key, `pre-tracker-write-gate` permits `transitionJiraIssue` on that key when its input carries only the issue key and the transition.
- AC-STE-699.5: With that receipt still present, the gate refuses: a `transitionJiraIssue` on the key that also carries `fields`, `update` or a comment; any `editJiraIssue` on the key; a transition on any other key; and a receipt file that no registered module announced.
- AC-STE-699.6: Without the receipt, a transition on an unowned Epic is refused as today. Its remedy names `epic_close.ts` as the path for a shipped milestone's Epic and no longer tells the agent that the owning repository can make the write. The STE-649 refusal-text pins are amended in the same commit.
- AC-STE-699.7: `shared_tracker_live_grader.ts` mirrors AC-STE-699.4 and AC-STE-699.5, and the existing test that pins its module list to `RECEIPT_ANNOUNCING_MODULES` stays green.
- AC-STE-699.8: The `/ship-milestone` post-ship step that closes an Epic-keyed milestone's Epic orders saving the Epic's children listing, then running `epic_close.ts`, then the transition. On a refusal the Epic stays open and the refusal is reported verbatim.
- AC-STE-699.9: Permit and forbid legs run through the shipped `.sh` wrapper on recorded payloads. Each of checks (a) to (d) has a twin that differs from the permit leg only in that check.
- AC-STE-699.10: Removing any one of the four checks, the status-only restriction, or the key match turns at least one named test red.
- AC-STE-699.11: `bun test` from `plugins/dev-process-toolkit` reports 0 failures, and its skip identities equal the trunk baseline by name.

## Technical Design

### Root cause

`ticket_ownership.ts` refuses any container verdict whatever binds it. The gate grants ownership only through a tracked FR file, a create in the session, or a receipt, and no flow writes a receipt for an Epic. So the close that `/ship-milestone` orders cannot pass in any repository.

The fix adds one more receipt kind on the existing trust path. The new module composes the shipped helpers for plan coherence, sibling idleness and child listings, and keeps no copy of their rules. The gate's ticket path admits a status-only transition when an `epic-close` receipt names the key.

## Testing

Synthetic transcripts, recorded payloads and temporary git repositories, with fake keys only. The gate is driven through its shipped hook entry point, with one twin per check and mutation controls.

## Notes

Origin: a shared-Jira field report against v2.99.1. Linear milestones carry no status, so there is nothing to close there and the rule is Jira-only. No operator-consent fallback, by operator ruling.
