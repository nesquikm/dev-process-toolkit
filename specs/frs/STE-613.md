# Every way of changing directory moves the commit with it

## Summary

Four ordinary ways of changing directory leave the test-first guard reading the session's own repository while the commit lands in another one.
The guard sees an empty staging area there and waves through a commit that stages a feature request and its test.
The directory model now follows each of them, and resolves the directories a command computes for itself when the answer is fixed by the command.
That shrinks the set of commits whose target nobody can name.

## Requirement

STE-597's directory model moves the running directory only when a segment's first token is exactly `cd`, and `applyCd` takes the first argument verbatim (`adapters/_shared/src/commit_target_repo.ts:546-548`, `:489-500`). Four shapes therefore resolve to the wrong tree. `cd -P <B>` resolves `<session>/-P`, `checkoutRootOf` walks up from there, and the session's own root comes back (`:57-65`). `cd -- <B>` does the same with `--`. `builtin cd <B>` and `pushd <B>` fall through to `parseGit`, which answers null, so the directory never moves. Measured on the installed 2.86.0 hooks (skeptic repro `verify-hooks/drive.ts`, rows W01-W04): the session is in checkout FE0 with nothing staged, and checkout B stages `specs/frs/GF-99.md`, `src/app.py` and `tests/test_app.py`. All four shapes give `repo=FE0`, and the /tdd hook exits 0 in silence. The control `cd <B> && git commit` gives `repo=B`, and the hook exits 2. This is the wrong-tree defect STE-597 set out to close, surviving through four more doors. The gate-check hook still refuses these shapes without evidence, only because it performs no classification.

Separately, STE-597 names every directory computed by a substitution or a variable as unresolvable. That is correct wherever the value is unknowable. Some values are fixed by the command itself, though, and calling them unknowable leaves a residual that STE-614 must then treat as "target unknown". A rough spec-time regex scan of 85,948 distinct Bash commands found the following. The replay in AC.7 replaces these numbers with measured ones.

- 266 commands pair a `$VAR` directory (after `cd` or `git -C`) with a git … commit word sequence. In 213 of them, every such variable is assigned earlier in the same command.
- 7 commands commit through `git -C $(pwd)` or `git -C $(git rev-parse --show-toplevel)`, the idiom STE-597's own test calls "the everyday idiom".

Required model (added to the shared recogniser from STE-601):

1. **`cd` options.** `-L`, `-P`, `-e` and `-@`, alone or combined (`-Pe`), are skipped. `--` ends option parsing. `cd -` and a bare `cd` stay unresolvable, as today. When `CDPATH` is set and non-empty in the hook process's environment, a relative `cd` or `pushd` operand that does not begin with `.` or `..` is unresolvable, naming `CDPATH`: the shell may pick a directory the model cannot.
2. **`builtin cd` and `command cd`** are `cd`.
3. **The directory stack.** `pushd DIR` moves and pushes. `pushd -n DIR` pushes without moving. `popd` returns to the previously modelled directory. `popd` with an empty modelled stack, `pushd +N`, `pushd -N` and `popd +N` are unresolvable, and the reason names the word. A parenthesised subshell restores the stack as well as the directory.
4. **Home.** `~` and `~/…` expand to the home directory of the hook process, which runs as the same OS user as the session's shell. `~user` stays unresolvable.
5. **In-command variables.** A segment that consists only of `NAME=value` assignments, or `export NAME=value`, binds NAME for later segments in the same scope. The value may be a literal or may reference names already bound. A prefix assignment (`NAME=v cmd`) binds nothing for later segments, which is shell semantics. A subshell's bindings do not escape it. `unset NAME` removes the binding. A loop variable (`for NAME in …`) is unresolvable inside the loop. A value built from any substitution other than the fixed forms in item 6, from a backtick, or from an unbound name leaves the name unexpanded, and the existing unresolvable rule applies.
6. **Fixed computed directories.** `$PWD`, `${PWD}`, `$(pwd)`, `` `pwd` ``, `$(pwd -P)` and `$(pwd -L)` are the running directory. `$(git rev-parse --show-toplevel)` and `$(git -C DIR rev-parse --show-toplevel)` are the checkout root of the running directory, or of DIR, through the injected root lookup. Every other substitution stays unresolvable, including `$(dirname $(pwd))` and `$(mktemp -d)`.

Pins amended by item 6, named here rather than slipped in. In `tests/commit-target-repo.test.ts`, the round-2 clauses asserting that `git -C $(pwd) commit`, `git -C $(git rev-parse --show-toplevel) commit`, `(cd /s/b && git -C $(pwd) commit)` and `cd $(pwd)/sub && git commit` are unresolvable now assert the resolved checkout, and the quoted/unquoted agreement clause now asserts both spellings resolve alike. In `tests/hook-modules-pre-commit-tdd-orchestrator.test.ts`, the clause "`git -C $(pwd) commit` with a staged test file and no /tdd evidence → exit 0 + a Reminder naming the substitution" now asserts exit 2, because the target resolves and the staged test raises the requirement. The unexpanded-global-option rule (`git -c user.name=$(whoami) commit`, `--git-dir=$(pwd)/.git`) is unchanged: those options can name any tree.

## Acceptance Criteria

- AC-STE-613.1: `cd -P <B> && git commit`, `cd -L <B> && …`, `cd -Pe <B> && …`, `cd -- <B> && …`, `builtin cd <B> && …` and `command cd <B> && …` each resolve to `<B>`. Controls: `cd - && git commit` and `cd && git commit` stay unresolvable, with the STE-597 wording unchanged. With `CDPATH=/x` in the resolver's environment, `cd b && git commit` is unresolvable naming `CDPATH`, while `cd ./b && git commit` and `cd /abs/b && git commit` still resolve; with `CDPATH` unset or empty, `cd b && git commit` resolves as at HEAD.
- AC-STE-613.2: `pushd <B> && git commit` resolves to `<B>`. `pushd <B> && popd && git commit` resolves to the session's checkout. `pushd -n <B> && git commit` resolves to the session's checkout. `(pushd <B>) && git commit` resolves to the session's checkout, because the subshell restores the stack and the directory. `popd && git commit` with an empty modelled stack, `pushd +1 && git commit` and `popd +1 && git commit` are unresolvable, with `unresolved` naming the word.
- AC-STE-613.3: `cd ~/x && git commit`, where `~/x` is a checkout under the hook process's home, resolves to that checkout. `cd ~other/x && git commit` is unresolvable.
- AC-STE-613.4: `B=<abs B>; git -C "$B" commit`, `B=<abs B> && cd "${B}" && git commit`, `S=<abs parent>; D=$S/b; git -C "$D" commit` and `export B=<abs B>; cd $B && git commit` each resolve to `<B>`. Scope and semantics are graded in both directions. `B=<abs B> git -C "$B" commit` (a prefix assignment) is unresolvable. `(B=<abs B>); git -C "$B" commit` is unresolvable. `B=<abs B>; unset B; git -C "$B" commit` is unresolvable. `R=$(mktemp -d); git -C "$R" commit` is unresolvable and names `$R`. `for d in <A> <B>; do git -C "$d" commit; done` is unresolvable.
- AC-STE-613.5: `git -C $(pwd) commit`, `git -C "$(pwd)" commit`, `git -C $PWD commit` and `` git -C `pwd` commit `` resolve to the running directory's checkout. `git -C $(git rev-parse --show-toplevel) commit` from a subdirectory resolves to its checkout root. `(cd <B> && git -C $(pwd) commit)` resolves to `<B>`. `git -C $(dirname $(pwd)) commit` stays unresolvable. `git -c user.name=$(whoami) commit` and `git --git-dir=$(pwd)/.git commit` stay unresolvable, with their STE-597 clauses unedited. Each pin amendment named in the Requirement is made in place, and no other existing clause in either suite is edited.
- AC-STE-613.6: The wrong-tree defect, graded through the shipped hook wrappers on two `makeSpanFixture` git checkouts. The session is in FE0 with nothing staged, and B stages an FR file, a source file and its test. With no evidence, `pushd <B> && git commit`, `cd -P <B> && git commit`, `builtin cd <B> && git commit` and `cd -- <B> && git commit` each make the /tdd hook exit 2, naming B's staged paths; each exited 0 at HEAD. The permit side: the same four commands with /tdd evidence present proceed (no exit 2). `pushd <FE0> && git commit`, with only a README staged in FE0, exits 0 with empty stderr and no evidence. The unchanged control `cd <B> && git commit` exits 2 before and after.
- AC-STE-613.7: Real-traffic replay, using the helper from STE-601 over the same corpus. This FR's Falsifiability section records the number of commit-bearing commands whose target moves from unresolvable to resolved, the number whose resolved target changed, and every command in either set, hand-classified as correct or wrong. Wrong resolutions are zero, or each is named with its fix. The number of commit-bearing commands still unresolvable after this FR is recorded as the residual that STE-614 handles. An empty corpus is reported as not measured.
- AC-STE-613.8: The "Recognised command shapes" table in `docs/hooks-reference.md` gains the rows of items 1 to 6, each graded by the table-driven test from STE-601. No file under `skills/` changes, and no `STE-<N>` token is added under `skills/`.
- AC-STE-613.9: Falsifiability. Every clause asserting new behaviour (AC.1 to AC.6) fails on the pre-change bytes and passes on the post-change bytes, with the direction recorded per clause in this FR. Controls, unchanged-behaviour pins and the still-unresolvable rows are exempt by construction.

## Technical Design

The directory model becomes a small state record carried through the shared recogniser's scopes: the directory, a modelled stack and a variable map. A parenthesised scope snapshots all three and restores them on close. Expansion stays conservative. Only a closed set of fixed forms and literal in-command bindings resolve, and everything else keeps the STE-597 unresolvable wording. Home expansion reads the hook process's home. The injected checkout-root lookup answers the `rev-parse` form, so tests stay filesystem-free where they are today.

## Testing

Extend `tests/commit-target-repo.test.ts` with option, stack, home, variable and fixed-form groups. Every resolving clause is paired with a still-unresolvable sibling that differs by one token. Hook-level wrong-tree pairs go in `tests/hook-modules-pre-commit-tdd-orchestrator.test.ts`, driven through the bash wrapper. Amended pins are edited in place, and the diff shows only their expectation lines. The replay numbers land in this FR.

## Notes

- Gate-check was never fooled by these shapes, because it classifies nothing. The /tdd hook was.
- Resolving the fixed forms shrinks the residual whose target is unknowable.
- The skeptic measured zero real commits through the four wrong-tree shapes, so this fix is latent.
