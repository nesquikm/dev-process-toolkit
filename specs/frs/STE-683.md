# Bun count fallback stops subtracting skips twice

## Summary

The test count parser has a fallback for bun output that lacks its summary line.
That fallback takes the pass counter as the total.
The stage evidence then subtracts skipped tests from that total a second time.
So a run with skipped tests reports fewer passes than it had.
This fix makes the fallback total count failures and skips too, as the summary line does.

## Requirement

### Steps to reproduce

1. Save bun output that ends with `5 pass`, `2 skip` and `1 fail` and has no `Ran N tests across M files` line.
2. Call `deriveRunCounts({ output, stack: "bun" })`.

### Expected

pass 5, fail 1, skip 2.

### Actual

pass 2, fail 1, skip 2: the fallback total 5, minus 1 fail, minus 2 skip.

## Acceptance Criteria

- AC-STE-683.1: Regression: `tests/m_0cac80-ste-683-bun-fallback-total.test.ts › bun output with no Ran line reports the pass counter as pass` fails before the fix and passes after it.
- AC-STE-683.2: When bun output has no `Ran N tests` line, `parseTestOutput(output, "bun")` returns `total` equal to the last `N pass` counter plus failures plus skipped, the meaning the `Ran` line carries; output that has the line parses unchanged.
- AC-STE-683.3: `deriveRunCounts` on such output reports `pass` equal to the last `N pass` counter, and `formatClosingLine` renders the skip-inclusive total.
- AC-STE-683.4: Reverting the fallback total reddens at least one test.
- AC-STE-683.5: `bun test` from `plugins/dev-process-toolkit` reports 0 failures, and its skip identities equal the trunk baseline by name.

## Technical Design

### Root cause

`parseBun` in `test_count_parser.ts` returns `total: lastPass` on its fallback path, while `deriveRunCounts` in `deliver_stage_evidence.ts` derives bun `pass` as `total - fail - skipped`, which assumes the `Ran N tests` meaning. The fix goes in the parser, so every reader of `total` gets one meaning.

## Testing

A fallback fixture with skips and failures, read through both the parser and the stage evidence; the existing `Ran`-line fixtures stay unchanged.
