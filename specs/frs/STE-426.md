# STE-426: Refresh the driver scaffold snippet and stale documented defaults {#STE-426}

## Summary

The smoke driver's own scaffold snippet is stale in two independent ways, and a third documented default has drifted from what the toolkit now emits.

The snippet writes ten shell command patterns and omits the file-tool surface and both tracker tool families entirely, even though the threat model, the allow-list matrix and the spawn-pattern pre-flight's own remedy all state the allow-list must cover exactly that union. Anyone following the snippet literally would have the chain's file tools and every tracker call denied at the first step. Both legs quietly scaffolded from the tracked settings file instead, which is the only reason the run worked.

The same snippet's entries are glob-shaped, which two separate gate probes flagged on every run — one as a shape advisory, the other as a staleness note recommending migration. So each run carries two advisories that originate in the driver's own scaffold rather than in the plugin being tested, diluting the signal the run exists to read.

## Requirement

The driver's inlined scaffold MUST be usable verbatim, MUST match the tracked settings file's shape so it stops generating self-inflicted gate advisories, and the documented defaults MUST match what the current toolkit emits.

Verified 2026-07-27:

- The Phase 1 step 6 snippet (`.claude/skills/smoke-test/SKILL.md:253-266`) contains 10 `Bash(...)` patterns and no `Edit` / `Write` / `Read` / `Grep` / `Glob` entries and no `mcp__linear__*` / `mcp__atlassian__*` families — while the tracked `.claude/settings.json` carries 23 entries including those surfaces.
- Both `/gate-check` runs flagged the glob-shaped forms: probe #35 (`setup_permissions_shape`) reported 9 glob-shaped Bash rules as an advisory, and probe #69 (`upgrade_staleness`) raised a NOTES row recommending the upgrade path. `/simplify` independently observed the overlap and declined to touch the authorization surface.
- The documented task-tracking block shows `branch_template: {type}/{ticket-id}-{slug}`; `/setup` emitted `{type}/m{N}-{slug}`, the milestone-keyed form shipped in M106 (v2.48.0). Nothing asserts on that line, so no fixture mis-scores — drift only.

## Acceptance Criteria

- AC-STE-426.1: The Phase 1 step 6 scaffold snippet covers the same tool-surface union the threat model and allow-list matrix require, so scaffolding it verbatim produces a runnable chain.
- AC-STE-426.2: The snippet's entry shapes no longer trigger probe #35 or probe #69 on a freshly scaffolded test project — a clean run's gate output carries neither advisory.
- AC-STE-426.3: The documented task-tracking block shows the current branch-template default.
- AC-STE-426.4: A meta-test pins the snippet against the tracked settings file's tool-surface union, so the two cannot drift apart again silently.

## Technical Design

The snippet and the tracked settings file should not be maintained as two hand-written copies — that is what allowed them to diverge. AC-STE-426.4's meta-test is the minimum guard; deriving the snippet from the tracked file at documentation-build time would be stronger, if the repo has a mechanism for it.

The probe #35 / #69 clearance is a shape change (glob form to the current canonical form) rather than a content change, so it should not alter what the children are actually permitted to do. Worth asserting that explicitly during implementation.

## Testing

- A scaffold-then-gate integration case asserting neither advisory appears.
- A byte assertion on the documented branch-template line.
