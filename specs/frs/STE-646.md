# The repoint declares, flips and verifies with one outcome or none

## Summary

The repoint could not carry a shared declaration, so the documented setup route led back to the writer now guarded.
Its declare route accepts the shared tag and the Jira issue type and says whether it wrote anything, while the rows route refuses those flags and names the declare-first command.
The rows route checks the session before any row, restores the file when its receipt cannot be written, and verify tells an untouched config from a rewritten one.

## Requirement

The declare route does three things:
- It accepts `--shared <tag>` and `--issue-type <type>`, and says whether it wrote anything.
- It refuses those flags on the rows route, and refuses a same-project Linear team change, each with a remedy that names the legal command.
- Row 2's and row 3's own-side refusals name the declare-first command.

The rows route checks CLAUDE_CODE_SESSION_ID before any row, and restores CLAUDE.md byte for byte if its receipt cannot be written. `--verify` separates "nothing was rewritten" from "rewritten and kept every status".

Covers B-2 (medium), B-3 (medium) and B-4 (low). Builds on the previous FR's `repoint: true` writer option.

## Acceptance Criteria

- AC-STE-646.1: `repoint_tracker_binding.ts <root> jira <boundProject> --shared <tag> --issue-type <type>` exits 0 and prints a `declare` line. The file then declares repo_tag, min_dpt_version, the tag in default_labels, jira_issue_type and the stop paragraph.
- AC-STE-646.2: A declare run with neither flag on an already-consistent file prints `declare` plus a `nothing written` line, exits 0, and leaves CLAUDE.md byte-identical.
- AC-STE-646.3: `--shared` or `--issue-type` on the rows route exits 1 before any row line is printed, with CLAUDE.md byte-identical and a remedy naming the declare-first command.
- AC-STE-646.4: On the declare route, a Linear `--team` that differs from a key-shaped bound team exits 1 byte-identical, with a remedy naming `re-run without --team`. A display-name bound team is replaced by a key-shaped `--team` with exit 0.
- AC-STE-646.5: The § 0c sentence of `docs/setup-reference.md` states that the shared answer is passed as `--shared <tag>` (plus `--issue-type` on Jira) to the repoint command, and step 7b.6 states that a shared Jira declaration passes `--issue-type`.
- AC-STE-646.6: Row 2's own-side refusal (no repo_tag) and row 3's (no jira_issue_type) each name the declare-first command.
- AC-STE-646.7: With CLAUDE_CODE_SESSION_ID unset or path-unsafe, the rows route exits 1 before printing any row line, the refusal names CLAUDE_CODE_SESSION_ID, and CLAUDE.md, `git status` and `.dpt/` are unchanged.
- AC-STE-646.8: When the receipt write fails after the CLAUDE.md write, CLAUDE.md is restored byte for byte, the command exits 1, and the refusal says CLAUDE.md was restored.
- AC-STE-646.9: A successful repoint still leaves exactly one `repoint` receipt and the flipped binding.
- AC-STE-646.10: `repoint_tracker_binding.ts` still contains none of writeFileSync, appendFileSync, renameSync, copyFileSync, openSync or Bun.write.
- AC-STE-646.11: `--verify` on a config byte-identical to the one the repoint recorded prints a line beginning `verify UNCHANGED` and exits 0.
- AC-STE-646.12: `--verify` on a rewritten config that keeps every snapshot status prints `verify PASS` and exits 0.
- AC-STE-646.13: `--verify` on a rewritten config that drops a status prints `verify FAIL` naming it and exits 1.
- AC-STE-646.14: The repoint receipt's evidence carries `trackerConfigSha256` of the config at write time, taken from the same receipt as the snapshot `--verify` compares.

## Technical Design

parseRepointArgs gains `shared` and `declaredIssueType`; declare and resume pass them to the writer and print the route line, the writer's diff and one summary line, each flattened through oneLine. The rows route refuses either flag before any row. tracker_receipts exports assertReceiptSession, which writes nothing and runs before decideRows. writeTrackerSubsection gains `commit?: () => void`, called after the read-back succeeds; a throw restores the old bytes and rethrows, and a failed restore names `git checkout -- CLAUDE.md`. The commit closure writes the receipt carrying `trackerConfigSha256`; verifyRepoint reads snapshot and sha from the same latest receipt.
