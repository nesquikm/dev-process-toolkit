# The supervisor mints the spawn receipt a worker cannot

## Summary

A delivery worker must put a spawn receipt in its stage report.
Only the session that spawned the worker can pass the check behind it.
So a worker can never make its own receipt.
The default check command is also missing on every machine.
Now the supervisor makes the receipt and hands it over.
The check is found through the plugin registry.

## Requirement

### Steps to reproduce

1. Run /deliver so that it spawns a worker; the spawn ledger's `.owner` sidecar records the supervisor's session id.
2. Inside the worker, run `bun run spawn_receipt.ts <handle> <ledger> <name> <host>` with the values the spawning tool reported.
3. Run it again with a fifth argument that wraps agent-toolkit's `owned.py`.

### Expected

Each run prints one `- spawn:` receipt line on stdout.

### Actual

Run 2 fails because the default check `spawn-agent-owned` is not on PATH and is shipped by nothing. Run 3 exits with the `ownership-unresolved` hard stop: `owned.py` exits 3 because `.owner` names the supervisor's session, not the worker's.

## Technical Design

### Root cause

`owned.py` proves that the calling session owns the ledger, and only the supervisor does, so the check is right to refuse a worker. The receipt was simply placed on the wrong side. `DEFAULT_OWNED_CHECK` names a binary that no plugin installs. The registry order prefers the directory source because, for that kind of install, the cache `installPath` holds a stale copy.

## Testing

Front-door tests use a fake config dir that holds each registry shape plus a stub `owned.py`, and cover the refusal when both are absent. Prose pins check the deliver surfaces.

## Notes

Operator ruling 2026-10-21: the supervisor mints the receipt, and the grader does not change.
