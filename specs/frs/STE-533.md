# Every user-facing stage emits the status block instead of narrating

## Summary

The stage skills each close with their own prose report, and the shapes have drifted apart. This wires the status block into every user-facing stage so the block replaces the narration rather than riding beside it. The capability tokens those closing summaries must emit are probe-enforced today, so they move inside the block and stay literal. A stage that keeps its paragraphs has not adopted the contract.

## Requirement

Each user-facing stage closes with exactly one status block; prose narration is capped; every literal capability token the stage must emit survives inside the block.

## Acceptance Criteria

- AC-STE-533.1: The adopting stages are this closed list of ELEVEN, resolved by operator decision 2026-08-31 and named here because the original AC required a list and did not supply one: best-practices, brainstorm, deps, gate-check, implement, report-issue, setup, spec-archive, spec-review, spec-write, upgrade. The boundary is principled rather than a matter of taste — it is exactly the set of skills that already carry a closing-summary contract, so each one has an existing contract to replace. It deliberately is NOT the deliver stage vocabulary: that set omits brainstorm, which the original request named first, and three of its five members have no closing summary to replace. The list is stated in one place and read from there; the test enumerates it rather than sampling it, and a stage absent from it is out of scope by declaration rather than by oversight.
- AC-STE-533.1a: The adopting stages emit their OWN fence banner, graded against the eleven, and `deliver-stage-result` stays /deliver's, graded against its five-stage vocabulary. One banner, one owner, one vocabulary each. Resolved by operator decision 2026-08-31 as a root-cause fix rather than a workaround: the milestone had reused one artifact for two different jobs — a machine hand-off between ceremony stages and a human-facing closing summary for eleven skills. Measured proof they were never one artifact: nine of the eleven emit a stage value the shipped /deliver grader refuses outright, and that grader REQUIRES prose before its fence (a bare fence is a snippet) while this FR's whole claim is that the block replaces the prose. Two contracts that cannot both be satisfied by the same bytes are two contracts. Widening the deliver vocabulary was rejected: it would tell the worker-capture grader that a brainstorm run is a valid ceremony hand-off, which is false.
- AC-STE-533.2: The block REPLACES FREE-FORM NARRATION, and the line cap governs that narration alone. A stage emitting its former multi-paragraph prose report alongside a compliant block FAILS — riding beside the narration was the rejected alternative at design time, and this is what makes the rejection enforceable. The cap does NOT reach the structured report sections that earlier milestones mandate and test; those are governed by AC-STE-533.2a. Resolved by operator decision 2026-08-31, after the REFACTOR pass found the cap as originally written contradicted shipped contracts in /implement, /setup and /gate-check: it capped a report at twelve lines of prose while those same skills mandated sections that cannot fit, which would have shipped two contradicting rules and a green suite — the dead-rule defect AC-STE-533.5 exists to prevent, pointed the other way.
- AC-STE-533.2a: The sections exempt from the cap are a CLOSED list, named in one place and read from there. Membership is not a matter of taste: an entry is admissible only if a SHIPPED AC or probe requires that section, and the list cites that AC or probe per entry. An entry with no such citation FAILS, which is what stops the list becoming a dumping ground for anything inconvenient to shorten. Exempt does not mean optional — a listed section that stops being emitted FAILS too. Both directions are asserted, because a carve-out checked in one direction only is unguarded in the other, and this repository has recorded that exact class going unguarded more than once. Known members at time of writing include the verification-evidence and advisory-notes sections in /implement, each required by an M132 and an M136 acceptance criterion and pinned by their milestone test files.
- AC-STE-533.3: Every literal capability token a stage is required to emit is still emitted, inside the block. The `closing_summary_capability_keys` probe greps for those literals and is not weakened, relaxed, or scoped away by this change; the test asserts a token survives the rewrite for at least one stage per token family.
- AC-STE-533.4: The shipped hundred-byte closing-summary floor still clears on the compact block, including on a run whose every section takes the empty fallback. That floor is the regression signal that the summary fired at all, and a shorter report must not silently disarm it.
- AC-STE-533.5: Where the block supersedes a previously mandated report shape — `/spec-write` section 7's two-table-plus-prose shape and its explicit "do not collapse to a single line" instruction — the superseding is written down at the surface that mandated it. A contract left standing while nothing satisfies it reads as a passing test over a dead rule; the test asserts the old mandate is amended, not merely disobeyed.
- AC-STE-533.6: Exactly ONE block per stage report. A report carrying two blocks fails, and so does one carrying the block plus the free-form multi-paragraph narration it replaced. The block is the last thing in the report EXCEPT for sections admitted by AC-STE-533.2a, which may follow it — the original "last thing in it" wording is superseded here, deliberately and in the same commit, rather than left standing as a rule nothing satisfies.
- AC-STE-533.7: Mutation-verified per stage, each mutation asserted to have applied. Reinstating a stage's paragraphs turns AC-STE-533.2's assertion red; deleting one capability token turns AC-STE-533.3's red.
- AC-STE-533.8: The adoption grader runs on a real gate probe over the eleven, and the registration is an ORDERED reference that a runtime path executes — not a descriptive mention. The registration is checked with the repository's own reference classifier, because a guard that stays green by classifying its subject unreachable certifies the opposite of what it claims, and the module carries the `import.meta.main` front door that makes the order executable rather than merely written. What the probe grades is the AUTHORING SURFACE: per stage, that its SKILL.md documents a closed status-block fence, that it no longer emits `/deliver`'s hand-off banner (one banner, one owner), and that every cap-exempt section listed for it is still emitted. Non-vacuity is asserted by mutation: a tree in which all eleven keep their fence and one drops a listed exempt section must still redden. **The earlier wording of this AC was wrong, and is corrected here rather than quietly narrowed.** It required the probe to detect NARRATION in SKILL.md files — "all eleven could keep every paragraph, add a fence, and score zero" — which is structurally impossible because the two halves of this module grade two different subjects. `scanStageBlockAdoption` grades an AUTHORING SURFACE: a SKILL.md is documentation, so prose around its fence is legitimate and cannot be a violation. Narration is a property of a RENDERED REPORT, and that is `verifyStageReportAdoption`'s subject — it is where the prose lead-in cap and the both-narration-and-block refusal live. Measured 2026-08-31: eleven SKILL.md carrying sixty narration paragraphs above AND below a compliant fence score `clean — all 11 adopting stages emit the status block`. The achievable contract is the one stated above; the impossible one is not weakened into silence, it is withdrawn in writing. Authorized by operator decision 2026-08-31 together with the public probe-count increase it costs; adoption grading is a new capability with no existing probe to join, so this does not reverse the milestone's decision to extend an existing probe for the word rule.

## Technical Design

Adoption is per-stage and each stage's rewrite is independent, so the closed list in AC-STE-533.1 doubles as the work breakdown.

The capability tokens are the hard part. Roughly forty keys carry map-fixed rendered prose in `/spec-write` section 7, and that prose is a real share of what makes closing summaries long. The literal token is what the probe greps; the long rendering beside it is not. So tokens move into the block verbatim and their renderings shorten — the checked half is preserved exactly, the unchecked half is what gets cut.

The hundred-byte floor is measured on the whole report, and the block clears it comfortably; AC-STE-533.4 pins the worst case rather than the typical one.

## Testing

AC-STE-533.3 is tested per token family rather than per key, because forty per-key assertions would pin the map's current contents rather than the survival property.

The both-shapes-present case in AC-STE-533.6 is asserted directly, since it is the failure this FR exists to prevent and it cannot be inferred from either half passing alone.

## Notes

This is the milestone's riskiest FR: it edits surfaces that a shipped probe and a smoke fixture both grade. The two-table shape and the byte floor are named in the ACs precisely so the collision is deliberate.
