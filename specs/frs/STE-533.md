# Every user-facing stage emits the status block instead of narrating

## Summary

The stage skills each close with their own prose report, and the shapes have drifted apart. This wires the status block into every user-facing stage so the block replaces the narration rather than riding beside it. The capability tokens those closing summaries must emit are probe-enforced today, so they move inside the block and stay literal. A stage that keeps its paragraphs has not adopted the contract.

## Requirement

Each user-facing stage closes with exactly one status block; prose narration is capped; every literal capability token the stage must emit survives inside the block.

## Acceptance Criteria

- AC-STE-533.1: The adopting stages are a closed list, named in the spec and readable from one place. A stage absent from that list is out of scope by declaration rather than by oversight, and the test enumerates the list rather than sampling it.
- AC-STE-533.2: The block REPLACES narration. Prose before it is capped at a stated number of lines, and a stage emitting its former multi-paragraph report alongside a compliant block FAILS. Riding beside the narration was the rejected alternative at design time; this AC is what makes the rejection enforceable.
- AC-STE-533.3: Every literal capability token a stage is required to emit is still emitted, inside the block. The `closing_summary_capability_keys` probe greps for those literals and is not weakened, relaxed, or scoped away by this change; the test asserts a token survives the rewrite for at least one stage per token family.
- AC-STE-533.4: The shipped hundred-byte closing-summary floor still clears on the compact block, including on a run whose every section takes the empty fallback. That floor is the regression signal that the summary fired at all, and a shorter report must not silently disarm it.
- AC-STE-533.5: Where the block supersedes a previously mandated report shape — `/spec-write` section 7's two-table-plus-prose shape and its explicit "do not collapse to a single line" instruction — the superseding is written down at the surface that mandated it. A contract left standing while nothing satisfies it reads as a passing test over a dead rule; the test asserts the old mandate is amended, not merely disobeyed.
- AC-STE-533.6: A stage report carrying both narration and a block fails, and so does one carrying two blocks. Exactly one block per stage report, as the last thing in it.
- AC-STE-533.7: Mutation-verified per stage, each mutation asserted to have applied. Reinstating a stage's paragraphs turns AC-STE-533.2's assertion red; deleting one capability token turns AC-STE-533.3's red.

## Technical Design

Adoption is per-stage and each stage's rewrite is independent, so the closed list in AC-STE-533.1 doubles as the work breakdown.

The capability tokens are the hard part. Roughly forty keys carry map-fixed rendered prose in `/spec-write` section 7, and that prose is a real share of what makes closing summaries long. The literal token is what the probe greps; the long rendering beside it is not. So tokens move into the block verbatim and their renderings shorten — the checked half is preserved exactly, the unchecked half is what gets cut.

The hundred-byte floor is measured on the whole report, and the block clears it comfortably; AC-STE-533.4 pins the worst case rather than the typical one.

## Testing

AC-STE-533.3 is tested per token family rather than per key, because forty per-key assertions would pin the map's current contents rather than the survival property.

The both-shapes-present case in AC-STE-533.6 is asserted directly, since it is the failure this FR exists to prevent and it cannot be inferred from either half passing alone.

## Notes

This is the milestone's riskiest FR: it edits surfaces that a shipped probe and a smoke fixture both grade. The two-table shape and the byte floor are named in the ACs precisely so the collision is deliberate.
