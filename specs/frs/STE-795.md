# TDD rounds record whether they claimed a file change

## Summary

The waste metric can never be measured today, because no TDD round records whether it changed a file.
Each TDD round now records what it claims in its own result block.
A round that lists no files counts as a round that changed nothing.
The record is marked as claimed, so no reader mistakes it for a measured change.
Review rounds stay not observable.

## Requirement

The tool-call timeline records, for each TDD round whose result block parses, whether the round claimed a file change, so the `zero_yield_round` rule and the trend's `waste` metric become observable.

## Acceptance Criteria

- AC-STE-795.1: A `tdd-write-test`, `tdd-implement` or `tdd-refactor` round whose result text parses as a `tdd-result` block records `tree_changed: true` when its `files:` list is non-empty and `tree_changed: false` when it is empty, with `tree_disposition: "claimed"` in both cases.
- AC-STE-795.2: A TDD round whose result does not parse, and every `tdd-spec-review` and `spec-review-audit` round, keeps `tree_changed: null` and `tree_disposition: "not-observable"`.
- AC-STE-795.3: On a timeline holding two `tdd-implement` rounds that claim no files and one that claims a file, `zero_yield_round` is observable with value 2 (tripped at its threshold of 2); on a timeline whose rounds are all not observable it stays skipped with today's reason.
- AC-STE-795.4: The `TimelineRound` type admits `tree_changed: boolean | null` and `tree_disposition: "claimed" | "not-observable"`; the timeline schema id stays `tool-call-timeline/v1`, since an added value is backward compatible for every reader in the repo.
- AC-STE-795.5: `docs/retro-reference.md` says the round record is the round's claim, not a measured diff, and gives the reason in one sentence.
- AC-STE-795.6: `bun test` from `plugins/dev-process-toolkit` reports 0 failures, and its skip identities equal the trunk baseline by name.

## Technical Design

In `tool_call_timeline.ts`, `roundStatus` returns the parsed block alongside the status for the `tdd-result` skills; the round push sets `tree_changed` from `block.files.length > 0` and `tree_disposition: "claimed"` when the block parsed. `evaluateZeroYieldRound` in `retro_rules.ts` already counts observed rounds with `tree_changed === false`, so it needs no change beyond any pinned test text. Tests that pin `tree_changed: null` for parsed rounds are amended with an `Amended by AC-STE-795.1` comment.

## Testing

Unit tests on `buildTimeline` with synthetic transcripts: a forked round whose notification body holds a `tdd-result` with `files: []`, one with two files, one unparsed, and a spec-review round. A `retro_rules` test runs `zero_yield_round` over the built timeline.

## Notes

Decision: claimed, not measured. Forked rounds run in the background on the shared tree and never commit, and the timeline is folded from the transcript at session end. A measured per-round diff needs a tree snapshot at both edges of each fork, which nothing takes today.
