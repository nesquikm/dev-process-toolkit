# Import refuses a ticket it cannot read for bug detection

## Summary

Import decides whether a tracker ticket is a bug from the ticket's own answer.
When that answer cannot be read, import treats the ticket as a plain feature.
A bug then lands without its bug sections, and the gate never grades it.
This fix makes import refuse such a ticket before it writes anything.

## Requirement

### Steps to reproduce

1. Call `importFromTracker` for Linear ticket STE-1 with an ownership context whose listing item for STE-1 carries `"labels": null`.
2. Repeat with a Jira listing item that has no `fields.issuetype`.
3. Repeat with listing pages that do not hold the ticket at all, in an unshared binding.

### Expected

Each call refuses in the NFR-10 shape, naming the ticket and what could not be read, with no FR file written and no tracker sync.

### Actual

Each call writes a plain FR with no `kind: bug` and syncs it to the tracker.

## Acceptance Criteria

- AC-STE-682.1: Regression: `tests/m_0cac80-ste-682-import-unreadable-ticket.test.ts › a Linear item whose labels are not a list refuses the import` fails before the fix and passes after it.
- AC-STE-682.2: With an ownership context on Jira or Linear, `importFromTracker` refuses in the NFR-10 shape, before any FR file write or tracker sync, when no readable answer holds the ticket, or when that answer lacks the field bug detection reads (Linear: a `labels` list; Jira: `fields.issuetype.name` as a string); the refusal names the ticket and the missing field.
- AC-STE-682.3: A readable ticket that is not a bug imports byte-identical to today, and a readable bug ticket imports as it does today.
- AC-STE-682.4: Removing the refusal reddens at least one test.
- AC-STE-682.5: `bun test` from `plugins/dev-process-toolkit` reports 0 failures, and its skip identities equal the trunk baseline by name.

## Technical Design

### Root cause

`isBugTicket` in `import.ts` returns `false` when `rawTicketItem` finds no item, and reads a missing Linear `labels` list or Jira `issuetype` as "not a bug". The STE-680 notes accepted this because the ownership check refuses first, but that check refuses only an unreadable fetched ticket, not a missing item or a missing field.

Detection returns one of three answers — bug, not a bug, unreadable — and import throws on unreadable before `renderFRFile` runs.

## Testing

Fixtures for a null Linear labels field, a Jira item with no issue type, and pages that lack the ticket; plain and bug controls stay byte-identical.

## Notes

Listed as a known defect of v2.99.0.

Out of scope and unchanged: an import with no ownership context, or on a tracker other than Jira or Linear, reads no ticket answer and imports a plain FR, as before.
