# Renders follow new footage, stay in sync and hit a loudness target

## Summary

The first real video run found three faults in the final render.
Re-recording a clip did not re-render, because the cache ignored the clip's content.
Picture drifted behind the voice on clips with a variable frame rate.
The final mix was much quieter than web video usually is.
The render now keys on file content, keeps clips on their placed times, and normalises loudness.

## Requirement

- **Cache key.** The render stage key covers the bytes of every clip, voice segment audio and music file the edit list references.
- **Frame rate.** The drift is reproduced first with a real variable-frame-rate clip. The renderer then owns constant-frame-rate normalisation, so no recorder has to provide it.
- **Loudness.** One-pass loudness normalisation runs on the final mix, after voice and music are mixed. A new optional style key sets the target, default −16 LUFS. QA measures it.
  - The filter also caps true peak at −1.5 dBTP and loudness range at 11 LU, which are loudnorm's usual web values. It then resamples to 48 kHz, because loudnorm raises the sample rate internally.
  - A cut with no voice and no music carries a silent track that no target can describe. When that track measures at or below −70 LUFS, which is ebur128's absolute gate, QA skips the loudness check.

## Acceptance Criteria

- AC-STE-674.1: The render stage's cache inputs include a SHA-256 of the bytes of each clip `src`, each voice segment audio file and the music file the EDL references, and the render stage version is bumped; a test rewrites one clip with different bytes and an unchanged `edl.json` and asserts render runs, and with identical bytes asserts it is skipped. The same pair of assertions holds for the music file and for one voice segment.
- AC-STE-674.2: Mutation test: removing the clip bytes from the render inputs turns the clip assertion in AC-STE-674.1 red.
- AC-STE-674.3: A real-ffmpeg test builds a variable-frame-rate clip, renders a three-clip EDL that places it first, and measures with ffprobe the time of the second and third clips' first frames. The plan records this measurement against the unfixed renderer, with the offset found and its cause.
- AC-STE-674.4: After the fix, the test in AC-STE-674.3 asserts each clip's first frame lands within one frame (1/30 s) of its placed time, and the final duration equals the EDL end within one frame.
- AC-STE-674.5: The style parser accepts `loudness.target_lufs`, a number from −30 to −5 inclusive, default −16; a non-number or out-of-range value refuses naming `loudness.target_lufs`; an unknown key under `loudness` refuses naming its path; `video_init` writes the key with its default.
- AC-STE-674.6: `buildFfmpegArgs` applies one `loudnorm` filter with `I=<target>` to the mixed audio after `amix`, and to the voice alone when there is no music; the per-input music gain stays where it is. Snapshot fixtures pin both graphs.
- AC-STE-674.7: QA measures the final cut's integrated loudness and adds a reason when it is more than 1 LU from the target; a real lavfi fixture render passes this check, and a fixture rendered without normalisation fails it.
- AC-STE-674.8: `bun test` from `plugins/dev-process-toolkit` reports 0 failures, and its skip identities equal the trunk baseline by name.

## Technical Design

Hash the referenced files into the render stage inputs through the existing stage key, and bump the stage version. Reproduce the drift with a generated variable-rate clip before choosing the fix; normalise frame rate in the per-clip filter chain where the renderer controls it. Add the loudness key to the closed style schema and one loudnorm filter after the mix. QA reads integrated loudness from an ebur128 pass.

## Testing

Stage-cache tests with a recorder of stage runs; real-ffmpeg placement and loudness renders on small lavfi fixtures; graph snapshots; style fixtures; mutation test.

## Notes

Measured on the first video: final cut −20.5 LUFS integrated, picture about 9 s behind the voice after 70 s, stale cut reused after re-recording.
