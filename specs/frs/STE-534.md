# Word caps on FR narrative sections, on the probe that already exists

## Summary

The altitude probe caps the summary section at six physical lines. Real summaries run three to four lines carrying 160 to 198 words, so the cap has roughly twice the headroom it needs and has never fired on length. This adds a word rule to the same closed rule set and widens it to two more narrative sections, each with its own number.

## Requirement

A word rule joins the closed rule set on the existing FR altitude scanner, with per-section caps of eighty words for Summary, a hundred and twenty for Technical Design, and sixty for Notes. No new probe id, no public-surface count change.

## Acceptance Criteria

- AC-STE-534.1: A `word_cap` member joins the scanner's closed rule union in `adapters/_shared/src/scan_fr_summary_altitude.ts`. A violation names the file, the line it anchors at, the rule, and the section it was measured over — a rule id alone cannot tell the reader which of three caps was breached.
- AC-STE-534.2: The caps are eighty words for Summary, a hundred and twenty for Technical Design, sixty for Notes, measured over the section body only, excluding the heading. Each number is a named constant, not a literal repeated at each comparison.
- AC-STE-534.3: The four existing rules stay scoped to Summary ALONE. Technical Design and Notes legitimately carry backticks, AC-IDs and paths, so widening the `backtick`, `ac_id` or `path_token` rules to them would fail nearly every FR in the repository. The test asserts a Technical Design section full of backticks and paths yields no violation of those three rules while still being measured for words.
- AC-STE-534.4: Requirement, Acceptance Criteria and Testing are uncapped, and the test asserts a deliberately long Acceptance Criteria section produces zero violations. Acceptance Criteria is the binary contract and is the largest section by measurement at 596 words average; leaving it uncapped is a decision, and an unasserted decision is indistinguishable from an oversight.
- AC-STE-534.5: The probe id `fr_summary_altitude`, its error severity, and the README's `81 probes` count are all unchanged by this FR. The test asserts the count line and the probe id together, because the whole reason this rule joined an existing probe rather than becoming a new one was to avoid moving those numbers.
- AC-STE-534.6: A section that is absent yields no violation and no note, so files predating the rule stay byte-identically green. Vacuity is per section: an FR with a Summary but no Notes is measured for one and silent on the other.
- AC-STE-534.7: The scanner is run over this repository's own active FRs in the same commit that introduces the rule, and the result is asserted to be non-vacuous — at least one section actually measured. A dogfood over an empty tree passes while proving nothing, and this repository had zero active FRs before M137.
- AC-STE-534.8: Mutation-verified, each mutation asserted to have applied. Raising a cap past the measured maximum turns AC-STE-534.2's assertion red; widening the backtick rule to Technical Design turns AC-STE-534.3's red; capping Acceptance Criteria turns AC-STE-534.4's red.

## Technical Design

The scanner today locates one heading by exact match and walks to the next level-two heading. The generalisation is a table from section name to the cap and the rule set that applies there, which keeps the walk unchanged and makes AC-STE-534.3's asymmetry data rather than control flow.

Word counting is over whitespace-delimited tokens of the section body. Markdown syntax is counted as written; a rule that tried to discount formatting would need a markdown parser and would disagree with what the author sees.

The dogfood in AC-STE-534.7 asserts a measured count rather than an absence of violations, because an absence over an empty tree would be vacuous.

## Testing

AC-STE-534.3 is the discriminating test: one fixture section carries backticks, an AC-ID and a path, and the assertion is that exactly one rule family fires over it. Asserting only that it passes, or only that it fails, would miss the asymmetry.

Fixtures are built at the measured sizes from this repository rather than at round numbers, so the tests fail if the caps are set where nothing real would ever breach them.

## Notes

Eighty words is a little under half of today's measured average summary of 210. The number came from the design session, not from the data.
