# /brainstorm must raise the machine-readable refusal when AskUserQuestion is unavailable

## Summary

Every other interactive skill in the toolkit, when it cannot ask the operator a question, refuses in a way a machine can recognise. Brainstorm refuses in prose, or asks anyway and ends the turn, or proceeds under assumptions — three different behaviours across three test runs, none of them detectable. It is the only skill whose first-action clause never names the refusal marker, and the only one that failed on all three runs. The correlation is exact.

## Requirement

Brainstorm's unavailable-ask path routes through `requireOrRefuse` and surfaces the canonical `<dpt:requires-input-refused>v1</dpt:requires-input-refused>` marker, matching the four skills that already pass. The refusal ships as a set per the STE-401/402 pattern: helper call, registered token, rendered closing-summary prose, and a `/gate-check` probe with positive and negative fixtures. Separately, `assertFirstTurnShape` stops scoring a genuine contract breach as merely inconclusive.

## Acceptance Criteria

- AC-STE-479.1: `skills/brainstorm/SKILL.md`'s FIRST ACTION clause names the `<dpt:requires-input-refused>v1</dpt:requires-input-refused>` marker verbatim, byte-matching the clause shape used by `/deliver`, `/setup`, `/spec-write`, and `/report-issue`.
- AC-STE-479.2: Under non-tty stdin the skill's first tool call is an `AskUserQuestion` `tool_use` or a `requireOrRefuse` raise; prose-ask-then-end-turn and proceed-under-assumptions are both eliminated, and no `Write` / `Edit` / `NotebookEdit` precedes it.
- AC-STE-479.3: The refusal token is registered in `CANONICAL_CAPABILITY_KEYS` and has a rendered prose row in the closing-summary static map.
- AC-STE-479.4: A `/gate-check` probe asserts the clause shape with a positive fixture (a compliant skill passes) and a negative fixture (a skill with the marker removed fails) — proven non-vacuous in both directions.
- AC-STE-479.5: `assertFirstTurnShape` returns `violation`, not `vacuous`, when the skill made no scaffold write but emitted neither an ask nor a refusal — the breach names itself instead of scoring as inconclusive.
- AC-STE-479.6: A meta-test asserts that every skill carrying a FIRST ACTION clause names the marker, so the next skill to grow one cannot repeat the omission.

## Technical Design

The A/B control is single-variable and measured. Of the five skills carrying a FIRST ACTION clause, four name the marker (`/deliver`, `/report-issue`, `/setup`, `/spec-write`) and all four scored `ok-refused` on every leg; `/brainstorm` omits it and scored `vacuous askIndex=-1` on all three legs with zero marker occurrences. Per-leg behaviour differed — linear proceeded under stated assumptions, jira refused in prose (first tool call `Skill`, breaching STE-251 AC-STE-251.1), none ended the turn on "Reply with 1, 2, or 3", a silent no-op under `claude -p` — which is why the fix must be the byte-checkable marker rather than stronger prose.

AC-STE-479.5 is the second-order half: a scorer that reports `vacuous` for a genuine breach cannot name what went wrong, so the same defect stays invisible even after the marker lands.

## Testing

Positive and negative probe fixtures; meta-test across all FIRST ACTION clauses; unit test on `assertFirstTurnShape`'s violation/vacuous discrimination with a fixture that made no scaffold write. `bun test` full root.
