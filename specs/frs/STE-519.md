# The confirm gate names the worker's bridge

## Summary

The pre-spawn confirm gate shows the operator a record of what the run has decided, and that record is the command's own bytes rather than a retelling. It carries seven labelled fields today, none of which says anything about the worker's remote-control bridge.

This adds an eighth. The operator sees the name the worker will be reachable under before anything is spawned and before anything is claimed, and can confirm it, edit it, or drop the bridge for this run.

Dropping has to render something rather than nothing. The record refuses on a blank field by design, so an operator declining the bridge renders a defined value rather than an empty one. Editing the name changes a field, not a step, so the rule forbidding an operator from re-placing a step at this gate is untouched by it — and saying so is part of the change, because the two edits sit at the same prompt.

## Requirement

The decision record carries a labelled field naming the worker's remote-control name, and the gate lets the operator confirm it, edit it, or drop the bridge.

## Acceptance Criteria

- AC-STE-519.1: `DECISION_FIELDS` carries `remote_control` as its eighth and last entry, with the first seven byte-identical and in the same order.
- AC-STE-519.2: `decideDelivery` assembles the eighth field from the derivation module for every argument kind that produces a record at all.
- AC-STE-519.3: A record whose eighth field is absent or blank refuses under the existing completeness rule in `renderDecisionRecord`, naming that field. No new refusal path is added — the rule that a partial record is a refusal already covers it.
- AC-STE-519.4: An operator dropping the bridge at the gate renders the literal value `none` rather than an empty field, because an empty field is a refusal and would abort the run the operator was trying to continue.
- AC-STE-519.5: `verifyResumeGateRender` grades the eighth field: a capture carrying the first seven fields with values and the eighth as a bare label is not a whole record. Asserted directly, not inferred from the predicate reading `DECISION_FIELDS`.
- AC-STE-519.6: The operative surface states that editing the remote-control field changes a field and not a step, and that the rule forbidding an edit from changing a step's placement is unaffected.
- AC-STE-519.7: The operative surface states the precondition in these terms: bridging a worker grants no capability a bridged orchestrator lacks, and that holds only while the orchestrator is itself bridged. The gate names it; nothing enforces it.
- AC-STE-519.8: The operative surface states that relocating who answers a prompt does not relax the gate taxonomy — irreversible and outward-facing actions stay per-action human decisions, and a phone is a human.
- AC-STE-519.9: Sibling-surface parity: every surface stating the record's field count states eight — `skills/deliver/SKILL.md`, `docs/deliver-reference.md`, and the comment blocks of `adapters/_shared/src/deliver_decision.ts` and `adapters/_shared/src/resume_gate_render.ts`. Mutation-verified in both directions, so deleting the update from either surface alone turns the assertion red.

## Technical Design

Appending rather than inserting is what keeps this cheap. `DECISION_FIELDS` is exported and `resume_gate_render.ts` imports it precisely so the two cannot drift when a field is added, and the shipped test suite drives its assertions off that constant rather than off a hard-coded count. So the code follows the constant; what does not follow is prose, and four surfaces state the count in words.

The completeness rule already refuses on an absent or blank field, and reusing it is deliberate: a field that could be silently empty is a field nobody checks, which is the failure the rule exists for. That is also what forces the drop case to render a value. `none` is an answer; blank is an abort.

AC.7 records a property the design accepts rather than enforces. The equivalence argument that makes bridging a worker safe depends on the orchestrator being bridged too, and this gate does not test that — no readable signal for it was found, which is why the alternative design that would have enforced it structurally was rejected as blocked rather than as worse. Since nothing enforces it, the gate has to say it, or the next reader assumes something checked.

## Testing

`DECISION_FIELDS` gets an assertion on its eighth entry and on the first seven being unmoved. The completeness refusal is exercised with the eighth field absent and with it blank, both asserted to name that field.

The render predicate is asserted directly against a capture whose eighth field is a bare label, rather than relying on it reading the constant — a predicate that imports `DECISION_FIELDS` and then fails to apply it to the new entry would pass an inferred test.

Parity is asserted by reading all four surfaces and comparing, and mutation-verified by reverting each in turn.
