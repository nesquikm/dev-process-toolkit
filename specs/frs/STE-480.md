# Probe #37 must surface stale prose references, not only directory-tree leaves

## Summary

After a file is deleted, the probe that hunts for references left behind reads only directory listings inside fenced blocks. Ordinary sentences that name the deleted file survive untouched. A freshly scaffolded project is left carrying an instruction to delete a file that is already gone, which the reader cannot act on and has no way to recognise as stale.

## Requirement

The scan reports prose mentions alongside tree leaves, distinguishable by kind so the existing edit policy — delete tree leaves, record prose for operator amendment — still holds unchanged. The surviving references in the shipped cross-cutting specs are cleaned in the same change.

The count of "four" written here at authoring time was an estimate and is wrong: widening the probe surfaces **46** rows against the pre-fix specs, of which exactly **one** — `specs/technical-spec.md:472` — is a reference to the deleted placeholder file. Most of the rest are not stale at all. This is a marketplace repo, so its specs address plugin-relative paths, and resolving every token against the repo root alone mislabels them. Closing this FR therefore takes two halves, not one: a resolution rule (a token resolves under the project root **or** under any `plugins/<name>/` sub-root carrying a `.claude-plugin/plugin.json` manifest, and `<placeholder>`-templated expressions are skipped because they name a path shape rather than a path), which accounts for 32 of the 46; and then the genuine path corrections, which account for the remaining 14.

## Acceptance Criteria

- AC-STE-480.1: `scan_cross_cutting_spec_refs.ts` returns `proseMention` hits from outside fenced blocks; existing `treeLeaf` behaviour and the M118 fence info-string scoping are unchanged.
- AC-STE-480.2: Probe #37 reports prose mentions at advisory severity and tree leaves at their current severity — the two kinds stay distinguishable and prose hits do not silently begin blocking.
- AC-STE-480.3: `specs/technical-spec.md` and `specs/testing-spec.md` carry no surviving reference to the deleted placeholder file; the unfollowable "Delete it then, not before" instruction is gone.
- AC-STE-480.4: A fixture with a prose-only stale reference makes the scan report exactly one `proseMention` and zero `treeLeaf` hits; removing the reference makes it report none.
- AC-STE-480.5: The unmanaged-tree guard from STE-434 still short-circuits the probe on projects the toolkit does not own — widening the scan does not widen the blast radius.

## Technical Design

The scanner currently reads the fence info string and scans only bare, `text`, and `tree` fences (M118 / STE-433, deliberate). Prose outside fences is never examined. Widening it to report prose mentions is additive: `kind: 'proseMention'` already exists in the return type and `/implement` § 4b′ already has a policy for it (record in the commit body, do not auto-edit). What is missing is the scan actually producing them from prose, plus the probe surfacing them.

Severity split matters: prose hits often need sentence restructuring rather than line deletion, so making them blocking would strand runs on judgment calls. Advisory keeps them visible without that.

## Testing

Unit fixtures for prose-only, tree-only, and mixed cases with mutation in both directions. Probe fixture asserting advisory severity for prose and current severity for tree leaves. Dogfood: the repo's own specs must be clean after the change. `bun test` full root.
