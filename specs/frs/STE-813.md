# The trend reports one run per FR and skill, with the settings it ran under

## Summary

The trend report labels each FR with the skill of whichever ledger row comes first in the file.
Now every skill that worked on an FR is its own run.
Each run names the settings it started under, or says the settings are unknown.
Each group also counts its runs per settings hash.
Settings never decide the grouping, and size and category stay report columns.

## Requirement

`/retro --trend` defines its run unit as one row per (archived FR, skill) and joins each run to the settings hash it started under.

## Acceptance Criteria

- AC-STE-813.1: The trend builds one run per (archived FR, skill) for every distinct `skill` among the FR's claimed ledger rows. Each run's sessions, output tokens and incomplete flag come from that skill's rows only, and the FR's changed lines are shared by its runs. An FR with claimed `implement` and `tdd` rows yields two runs, in two groups.
- AC-STE-813.2: Each run's `settings` is the `settings_hash` of the earliest STE-810 run-start row with the run's FR and skill. Failing that, it is the earliest row with one of the run's sessions and the run's skill whose `fr` is null or empty; a row naming a different FR never matches. Failing both, it is the literal `"settings unknown"`. A ledger written before this release reads `"settings unknown"` on every run.
- AC-STE-813.3: Each group gains `runs_detail`, one entry per window run in window order with keys `fr`, `skill`, `settings` and `sessions` (session aliases, never raw ids), and `settings`, a list of `{ hash, runs }` counting the window's runs per value, `"settings unknown"` included, sorted by count then hash.
- AC-STE-813.4: Groups stay keyed by (skill, category, size). No settings value is a group key, and the existing group cells keep their meaning over the new run unit.
- AC-STE-813.5: The report schema becomes `dpt-retro-trend/2`, and every reader of trend reports in the repo accepts it.
- AC-STE-813.6: `docs/retro-reference.md` describes the run unit, the settings join order and the two new group keys.
- AC-STE-813.7: `bun test` from `plugins/dev-process-toolkit` reports 0 failures, and its skip identities equal the trunk baseline by name.

## Technical Design

`collectRuns` in `retro_trend.ts` groups each FR's claimed rows by `skill` instead of reading `claimed[0]`. A run gains `fr`, `settings` and `incomplete`. The settings join reads `readRunStarts(root)` once per report. `runs_detail` reuses the report's alias map. Pinned STE-776 tests that encode the first-row skill are amended with an `Amended by AC-STE-813.1` comment.

## Testing

Trend fixtures with a two-skill FR, run-start rows matching by FR, matching by session only, and absent, plus a mixed window that exercises the per-hash count.

## Notes

Design rule: settings are keyed by skill only. Size is unknowable at run start, and the AC count predicts size at chance.
