# Read both frontmatter spellings when inferring the release bump

## Summary

The bump inferrer reads a camel-cased field. The writer emits the snake-cased one, and the reader preserves what is on disk.

An FR handed over as read therefore falls through to the default, which is the additive category. A milestone of pure fixes returns a minor version with a rationale stating the wrong thing, and nothing throws.

The same shape elsewhere is safe only because its call sites spell the mapping out. That sentence is half the fix.

## Requirement

The bump inferrer accepts either spelling of the fields it reads, so an FR passed exactly as read from disk yields the same answer as a hand-mapped one. Both prose surfaces that call it state the mapping. The gap is two fields wide, not one: the tracker reference carries the same mismatch in the same function and closes in the same change.

## Acceptance Criteria

- AC-STE-544.1: `inferBump` returns the same version and rationale for an FR passed with `changelog_category` as for the equivalent FR passed with `changelogCategory`; a pure-fix milestone at 2.75.1 yields a patch bump on both.
- AC-STE-544.2: The category is resolved through one exported reader that prefers the camel key, falls back to the snake key, and only then applies the `Added` default, so the default can no longer mask a present-but-unread value.
- AC-STE-544.3: The tracker reference is resolved through a second exported reader accepting either the flat camel key or the nested frontmatter block, and the breaking-change rationale names the tracker id rather than degrading to the full title.
- AC-STE-544.4: `FrSummary` declares both accepted shapes for both fields, and the stale header comment describing the single-shape contract is corrected.
- AC-STE-544.5: Existing camelCase callers are unaffected — the shipped suite passes with no assertion rewritten, which is what distinguishes a widened reader from a changed one.
- AC-STE-544.6: `skills/ship-milestone/SKILL.md` and `docs/ship-milestone-reference.md` both state that the value passed as the category is the FR's `changelog_category` frontmatter value. The skill clause adds no `STE-<N>` token: that ceiling measures exactly 246 of 246, so one token reds the gate.
- AC-STE-544.7: The stale hand-check workaround recorded in `specs/plan/M139.md` is removed, since the condition it warns about no longer holds.

## Technical Design

In `adapters/_shared/src/version_bump.ts`: widen `FrSummary` (:15, :18) with optional `changelog_category` and `tracker?: Record<string, string>`; export two readers beside it — `categoryOf(fr)` preferring `changelogCategory`, falling back to `changelog_category`, then `"Added"`; and `trackerRefOf(fr)` preferring `trackerId`, else the first value of the nested `tracker` block. Point the fix-class predicate (:81) at `categoryOf` and the breaking rationale (:73) at `trackerRefOf(breaking) ?? breaking.title`. Correct the stale header comment (:9).

The reader is the enforcement point on purpose: it fires without the caller's cooperation, and the caller here is a model reading prose. A named seam at the call site would move the same failure up one level.

## Testing

`adapters/_shared/src/version_bump.test.ts` gains two legs, plus one prose-conformance leg elsewhere.

- AC.1 / AC.2 — a table of three archived Fixed FRs built twice, once with `changelog_category` and once with `changelogCategory`, asserting byte-equal `{version, rationale}` from both. The as-read arm must be shown to have been broken before the fix: assert the pre-fix answer (`2.76.0`, additive rationale) is *not* what the fixed reader returns, so the leg cannot pass vacuously on a reader that ignores both keys.
- AC.3 — an FR marked breaking supplied with only the nested `tracker` block; assert the rationale names the tracker id, with a control asserting the unfixed path degrades to the title.
- AC.5 — the existing 15 assertions run unmodified. A rewritten assertion here would hide exactly the regression this AC exists to exclude, so the leg is that the file's prior expectations are untouched.
- AC.6 — a conformance assertion that both prose surfaces contain the mapping clause, and that the skills tracker-id token count is still at or under its ceiling. Measure it the way the enforcing test measures it, not by eye.
- AC.7 — assert the workaround line is absent from the M139 plan and that the plan's other content is unchanged.

## Notes

The decisive evidence is a control already in the repo: `branchTypeFor` has the identical camel-reading-snake shape and is not defective, because both its call sites document the mapping. Same shape, opposite outcome, one variable — so prose alone can hold a contract, and a reader that needs no prose is what makes it durable.
