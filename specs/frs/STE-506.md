# The toolkit declares its own verification

## Summary

This repository ships two agent-driven drivers and declares no verification block at all, so the contract it is about to make mandatory does not apply to itself. Neither driver's slug matches the discovery heuristic either, which is a fact worth writing down rather than patching, because widening that heuristic would make discovery guess.

## Requirement

Frontmatter-declared candidates are discoverable, the slug heuristic stays as narrow as it is, and this repo declares its own block.

## Acceptance Criteria

- AC-STE-506.1: `scanCandidateCheckSkills` recognizes a skill declaring `verify: true` in frontmatter regardless of slug, asserted end-to-end rather than assumed from the prose.
- AC-STE-506.2: The slug heuristic is deliberately NOT widened, and the FR records why: widening it to catch conformance and smoke shapes would make discovery guess, and discovery must never guess.
- AC-STE-506.3: This repo's CLAUDE.md declares a `## Verification` block naming a driver, so the toolkit is covered by the contract it ships.
- AC-STE-506.4: Multiple candidates still list and ask, never guess.

## Technical Design

The discovery scan matches a slug containing `drive`, `check` or `verify`, or frontmatter carrying `verify: true`. This repository's two agent-driven surfaces live at `.claude/skills/conformance-loop` and `.claude/skills/smoke-test`, and neither slug matches. The repo also has no `## Verification` block, so the declared path does not apply either. The toolkit that is about to require a drive is invisible to its own discovery.

AC.1 asserts the frontmatter arm actually works end-to-end. It is documented, and a documented arm that no test exercises is exactly the shape M126's audit found four times when it mutation-tested pins that could not fail.

AC.2 is a decision recorded as an acceptance criterion because the obvious fix is the wrong one. Adding `conformance` and `smoke` to the slug patterns would make this repo discoverable and would also make discovery fire on any project with a `smoke-test-fixtures` skill or a `conformance-report` skill. Discovery's shipped contract is that it never silently runs an undeclared skill and never guesses between candidates; a wider slug net makes it guess more often, at the cost of the one property that makes the offer trustworthy. The narrow net plus an explicit declaration is strictly better, and the declaration is what AC.3 supplies.

AC.3 is the dogfooding clause. The block this repo declares carries three keys: `verify_skill: smoke-test`, naming a driver that resolves on disk; `verify_mode: manual`; and `run_cmd: none`, which is what STE-504's detection measures on this tree — no `dev` or `start` script, no Makefile `run` target, no `## Running` heading — rather than a value the block asserts for itself. `none` stays honest only while detection stays silent here; the moment it fires, the declaration is a lie and must be rewritten.

`verify_mode: manual` is the consequential choice in that block, and it is recorded here rather than left as a comment beside a test. The reason is the shape of this repository's drivers: `smoke-test` and `conformance-loop` each spawn a multi-hour headless `claude -p` chain, so firing one automatically is infeasible at per-FR cadence — the run would outlast the session that started it. `advisory` was considered and is rejected by name. It is strictly worse than `manual` here, not a gentler version of it: advisory would auto-fire the driver on every FR, time out, and emit a soft warning the operator quickly learns to ignore — the same wall-clock spent to train the reader that the row means nothing.

The cost of `manual` is stated plainly, because it is real and it is not paid off elsewhere. The toolkit now declares the contract on itself and still never drives it: the dogfooding is discharged for the DECLARATION HALF and not for the DRIVE HALF. The Notes below say a contract the shipping repository exempts itself from is a contract nobody has run, and `manual` does not retire that sentence — it narrows what remains unrun. What M131 achieves here is that the toolkit is no longer invisible to its own discovery and no longer silent about which driver would verify it. What it does not achieve is a driver that has actually been run under the contract.

## Testing
