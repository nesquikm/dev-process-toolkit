# Video workspace, keys and ignore rules

## Summary

A project keeps its video settings in a committed folder inside the toolkit's own directory.
The voice service key lives in a local secrets file that git must ignore.
The toolkit ignores that file and the per-video work folders, and an upgrade step adds those rules to existing projects.
One readiness check says whether the project can make videos, and why not.
No key value is ever printed or written anywhere by the toolkit.

## Requirement

- **One path source.** Every video path and the secrets-file path are built by `dpt_paths.ts`, never by hand-written `.dpt` literals.
- **Tracked by default.** `.dpt/video/` (config, style, scenarios, footage, music) is committed; only `.dpt/.env` and `.dpt/video/work/` are ignored, by two named lines in the toolkit-owned `.dpt/.gitignore`.
- **Existing projects.** A `/upgrade` migration entry adds the two lines to projects bootstrapped before this release.
- **Typed config.** `config.yaml` names the TTS provider and voice, the recorder, and the music source; `style.yaml` holds the house style. Both are validated, and an invalid value refuses naming its key path.
- **Keys.** `.dpt/.env` is read without touching `process.env`, and its values never reach output, errors or written files.
- **Readiness.** One predicate and front door answer "can this project make a video", checking config, the needed keys, and that git really ignores `.dpt/.env`.

## Acceptance Criteria

- AC-STE-663.1: `dpt_paths.ts` exports `videoRoot`, `videoConfigPath`, `videoStylePath`, `videoScenariosDir`, `videoWorkRoot`, `videoWorkDir(slug)` and `dptEnvPath`; a meta-test finds no `.dpt/video` or `.dpt/.env` string literal in `adapters/` outside `dpt_paths.ts`, with a planted control proving the scan finds one.
- AC-STE-663.2: `DPT_GITIGNORE_BODY` gains the lines `.env` and `video/work/`; in a temp git repo after `writeDptGitignore`, `git check-ignore` reports `.dpt/.env` and `.dpt/video/work/demo/final.mp4` ignored and `.dpt/video/config.yaml`, `.dpt/video/style.yaml` and `.dpt/video/scenarios/a.ts` not ignored.
- AC-STE-663.3: Migration entry `dpt-gitignore-video` (`introduced_in: 2.96.0`, kind `script`): `detect` applies exactly when `.dpt/.gitignore` lacks either line; `apply` appends only the missing lines and keeps every other byte; a second `detect` after `apply` reports nothing to do.
- AC-STE-663.4: `parseVideoConfig` accepts `tts.provider` ∈ {`elevenlabs`, `google`} with `tts.voice` (required) and `tts.model` (optional), `recorder.kind` ∈ {`web`, `ios-sim`, `android-emu`, `footage`, `command`} with its kind-specific fields, and `music.source` ∈ {`elevenlabs`, `file`, `none`} with `music.file` required for `file`; any other value or unknown key refuses in the NFR-10 shape naming the key path.
- AC-STE-663.5: `parseVideoStyle` accepts `pacing.words_per_minute`, `captions.enabled` and `captions.position`, `music.level_db`, `banned_effects` (default `[slow_zoom, ken_burns]`), `humor` ∈ {`none`, `light`, `playful`} and `layout.viewport`; an absent `style.yaml` yields the documented defaults, and an unknown key refuses naming it.
- AC-STE-663.6: `readVideoKeys(projectRoot)` parses `.dpt/.env` (`KEY=VALUE`, `#` comments, single or double quotes, blank lines) and leaves `process.env` unchanged, asserted before and after.
- AC-STE-663.7: `videoReadiness(projectRoot)` returns `{ ready, reasons }`: not ready when config is absent or invalid, when the provider key is missing (`ELEVENLABS_API_KEY` for `elevenlabs`, `GOOGLE_TTS_API_KEY` for `google`), when `music.source: elevenlabs` lacks `ELEVENLABS_API_KEY`, or when `git check-ignore` does not report `.dpt/.env` ignored; each reason names its remedy. The front door `video_readiness.ts <projectRoot>` prints `ready` or one reason per line and exits 0 either way.
- AC-STE-663.8: A sentinel key value planted in `.dpt/.env` appears in no refusal message, no front-door output and no file the video modules write, across every test in this FR and STE-664.
- AC-STE-663.9: `bun test` from `plugins/dev-process-toolkit` reports 0 failures, and its skip identities equal main's by name.

## Technical Design

New path helpers in the shared path module. The ignore body gains two lines; the migration entry reuses the existing gitignore writer's byte-preserving pattern. A new video module holds the config, style and env parsers and the readiness predicate, which asks git about ignore status rather than reading ignore files. Parsers return typed values or throw the canonical refusal.

## Testing

Temp git repos for the ignore matrix and the readiness check. Fixture files for each schema refusal. A literal scan with a planted control. A sentinel key grepped across captured output and written files.

## Notes

Operator decisions 2026-10-12: keys in project-local storage, never the home directory; config committed; work dir ignored.
