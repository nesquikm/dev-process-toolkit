# A shared tracker container is declared once and read by code

## Summary

Several repositories can point at one Jira project or one Linear project, but the setting that keeps their tickets apart is read only by the model, never by code.
This change gives that declaration one reader, returning the repository's ownership label, the oldest toolkit version allowed to write, and whether the container is shared.
A malformed declaration stops the run with a named reason instead of being dropped.
Every later guard in this milestone asks the same reader.

## Requirement

Measured at HEAD `ac1f3cb` (v2.86.0):

- `readWorkspaceBinding` in `adapters/_shared/src/workspace_binding.ts` keeps `team`, `project` and `default_labels` and drops every other line (`:22-26`, `:94-101`). A declared `repo_tag` never reaches executed code. Repro: a `### Jira` block carrying `repo_tag: glacy-be` and `default_labels: [glacy-be]` reads back as `{"project":"GF","defaultLabels":["glacy-be"]}`; the control key `default_labels` from the same block is parsed.
- Non-test TypeScript names `repo_tag` in two modules only (`create_idempotency_probe.ts`, `closing_summary_capability_keys.ts`); the probe's `runCreateIdempotencyProbe` and `assertRepoTagForwarded` have no production caller. `skills/gate-check/SKILL.md` names `repo_tag` zero times (control: `spans_repos` three times).
- The rule's only home is repoint precondition #2 in `docs/setup-reference.md`, a hand check. Zero of the 35 CLAUDE.md files in the operator's workspace declare the key.
- Protection is one-sided: a repository that declares nothing still adopts a tagged sibling's ticket (repro S10/S11 in the FR-adoption verification).
- Nothing reads a toolkit version floor anywhere (0 hits); nothing pins a plugin version in consumer repositories.

### The declaration

Two free-form keys inside the ACTIVE tracker sub-section (`### Jira` or `### Linear`) under `## Task Tracking`. Never a top-level key: probe #21 (`task_tracking_canonical_keys.ts`) closes the top level at four keys and already scopes sub-section content out.

- `repo_tag: <lowercase-kebab>` — this repository's ownership label. Its presence IS the declaration that the container is shared. The same value must also appear in `default_labels`, so every create forwards it.
- `min_dpt_version: <X.Y.Z>` — the lowest toolkit version allowed to write into the shared container.

### The one reader

`readWorkspaceBinding(claudeMdPath, adapterKey)` returns `{ team?, project?, defaultLabels?, repoTag?, minDptVersion?, shared }`. `shared` is always present and is `true` exactly when a non-empty `repo_tag` is declared. With no declaration the return is the pre-change return plus `shared: false` and nothing else.

A malformed declaration is a thrown refusal in the NFR-10 three-line shape — a verdict line naming the key, the value and the rule broken; `Remedy:`; `Context: file=<rel>, adapter=<key>, helper=readWorkspaceBinding` — never a silent drop. The refusal classes:

1. `repo_tag` not matching `^[a-z0-9]+(-[a-z0-9]+)*$`;
2. `repo_tag` absent from `default_labels` — raised through `assertRepoTagForwarded`, so tag membership keeps its one definition and its existing `RepoTagBindingError`;
3. `min_dpt_version` not strict `X.Y.Z` (no `v` prefix, no pre-release suffix);
4. `repo_tag` with no `min_dpt_version`, or `min_dpt_version` with no `repo_tag`;
5. either key written twice in the sub-section — never last-wins;
6. a floor below `FIRST_GATED_DPT_VERSION`, the release that ships this milestone's write gate, because such a floor admits clients that carry no gate at all;
7. a CLAUDE.md that exists but cannot be read — a typed refusal naming the path, where today a raw `readFileSync` error escapes. An absent file stays `{ shared: false }`.

An empty `repo_tag:` value with no floor is the undeclared state, byte-for-byte the same as an absent key (absent and empty are one declaration, as the create probe already rules).

### The running version and the floor

A new `adapters/_shared/src/dpt_version.ts` exports `runningDptVersion(pluginRoot?)`, reading `version` from `<pluginRoot>/.claude-plugin/plugin.json`. `pluginRoot` defaults to `CLAUDE_PLUGIN_ROOT` when set, else the plugin root derived from the module's own location. The version is never a literal. An unreadable manifest, or one whose version is not strict `X.Y.Z`, is a typed refusal. `checkVersionFloor(binding, running)` returns ok, or a refusal naming both versions; equal passes. The toolkit keeps one semver comparison: the private `compareSemver` in `adapters/_shared/src/migrations/coverage.ts` is exported and reused, not copied.

`FIRST_GATED_DPT_VERSION` is one exported constant — a historical fact, not the running version.

### The receipt store

Consumed by every later FR in this milestone.

- `adapters/_shared/src/dpt_paths.ts` gains `receiptsDir(projectRoot, sessionId)` → `<projectRoot>/.dpt/ledger/receipts/<sessionId>`, beside the other durable machine-local state under `ledger/`; no other module composes that path.
- A new `adapters/_shared/src/tracker_receipts.ts` exports `writeReceipt`, `readSessionReceipts` and the announcement prefix `dpt-receipt: `, which every writer prints followed by the receipt's absolute path.
- The session id comes from `CLAUDE_CODE_SESSION_ID`. Measured: Claude Code 2.1.276 exports it to the Bash tool, including inside a child session, where it matches the parent session's scratchpad id. When it is absent, empty, or not a single path-safe token (`/`, `..` or whitespace), `receiptsDir` and the writer refuse and write nothing — it never falls back to the newest-transcript heuristic in `find_current_session.ts`, which mis-keys two sessions sharing one checkout.
- A receipt is one JSON object: `{ v: 1, kind, sessionId, root, adapter, container, subject, decision, evidence, createdAt }`. `kind` is an open string: this milestone writes `create`, `reuse`, `import` and `binding`; later milestones add their own kinds through the same writer, never a second store.
- Receipts inherit the existing `ledger/` rule of `.dpt/.gitignore`, so they are never committed, the CLOSED three-rule set is untouched, and no nested ignore file is written. In a checkout with no `.dpt/.gitignore` yet, the writer creates it through the existing `writeDptGitignore` before its first write, and never rewrites one that exists; that canonical file, which `/setup` normally commits, is then the only untracked path the store can leave.
- Readers skip and count malformed receipt files, and never return a receipt from another session's directory.

### The front door

`bun run adapters/_shared/src/workspace_binding.ts <projectRoot>` resolves the active mode, prints the binding as one JSON line and a second line `running=<version> floor=<ok|refused>`, exits 1 with the refusal on stderr and empty stdout when the declaration is malformed, and exits 0 printing `shared:false` when nothing is declared. Every prose order that names the reader now names something a reader can run.

### Fixture and docs

- `tests/_span_fixture.ts` gains `claudeMd(root, opts)` (mode, project, team, default labels, repo tag, floor, optional paragraph appended to the sub-section) and `pluginManifest(dir, version)`. Existing callers are unchanged.
- `docs/patterns.md` § Schema L Workspace binding table lists both optional keys and the refusal rules.

## Technical Design

The reader keeps its line parser and adds one validation pass over the two new keys, so an undeclared file takes exactly the old path. Tag membership is delegated to the existing forwarding guard rather than restated. The running version and the floor comparison live in one small module that the probes, the front doors and the hook all import. Receipts are plain JSON files under the decided-for repository, keyed by the session id Claude Code exports to tools, under the already-ignored ledger directory, so the closed ignore set stays closed. A command-line entry turns the reader into something prose can run.

## Testing

New suite `tests/shared-declaration-reader.test.ts` over `makeSpanFixture` two-root trees: the refusal matrix, each class beside its one-change control; the floor in both directions; the relocated pair. `workspace_binding.test.ts` takes the 16 pin moves and nothing else. The old-client leg extracts `workspace_binding.ts` and `task_tracking_canonical_keys.ts` from `git show ac1f3cb:` into a scratch directory and runs them on the post-change fixture. Receipt legs run inside a `git init` fixture and call `git check-ignore`. The front door is spawned with `Bun.spawn`. Mutations to record: delete the validation pass; derive `shared` from the floor alone; let the store fall back to a guessed session id.

## Notes

Closes the reader half of the tag findings; the create, listing, claim and hook FRs consume it. A declaration lives in each branch's CLAUDE.md, so it must reach every live branch before a sibling writes. Clients too old to read it are handled by the stop paragraph in STE-603.
