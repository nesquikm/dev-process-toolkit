# Skills describe each other correctly

## Summary

A skill describing its own behaviour is graded by its own tests. A skill describing a sibling's behaviour is graded by nothing, and six such cross-references are wrong.

Two orchestrators say their read-only audit fork runs a test command; it has no shell, and each child says so. One advertises an enforcement that does not exist. One names a flag its sibling never had, one a phase, one a step. One remedy names a command nobody can type.

## Requirement

Every statement one skill makes about another is true, and each corrected cross-reference is asserted against the sibling it names rather than restated in both places.

## Acceptance Criteria

- AC-STE-570.1: `/tdd` and `/spec-review` describe the test command they pass their audit fork as reference context, naming the orchestrator as the party that verified GREEN and the fork as unable to run anything. The capability is untouched: read-only is the design, and the claim was the defect.
- AC-STE-570.2: That is asserted FROM BOTH SIDES by one reader. A test derives each audit fork's toolset from its agent frontmatter and reds when an orchestrator's description of that fork claims a capability the toolset does not carry. Granting the fork `Bash` would red it just as loudly as reinstating the claim, which is what makes it a contract rather than a spell-check.
- AC-STE-570.3: `/deps` states its capability-token contract in the wording `/best-practices` already uses — a backticked literal token, narrative paraphrase insufficient — with the `closing_summary_capability_keys` probe-coverage assertions and the `CANONICAL_CAPABILITY_KEYS` registration claim removed. Four sites, not one: the claim is made four times in that file.
- AC-STE-570.4: Registration claims are graded against the registry. A test asserts that every capability token a skill claims is registered in `CANONICAL_CAPABILITY_KEYS` is in fact there, and that the owner recorded for it is the skill making the claim — the `deps_*` tokens were absent AND the five present ones are owned by a different skill, and only an owner-aware check sees the second half.
- AC-STE-570.5: `skills/docs/SKILL.md`'s frontmatter description names the precondition the skill's own refusal remedy states — at least one of `user_facing_mode` or `packages_mode` true in the `## Docs` block — instead of a `/setup --docs` flag that does not exist.
- AC-STE-570.6: Flags a skill attributes to a sibling are graded against that sibling's `argument-hint` and flag-routing branches, so an invented flag reds. This is the generalisation of AC.5 and the reason it is worth building: the same class produced the `/ship-milestone` → `/docs` defect that STE-566 fixes.
- AC-STE-570.7: `LEGACY_MONOLITH_HINT` carries the same "Claude can invoke it; it is not on the slash menu" parenthetical its sibling `UPGRADE_STALENESS_REMEDY` already carries, so an operator reading the gate report is not told to type a command that is off the menu. The byte-pinned reproductions of that literal move with it, and the two constants are asserted to agree on the caveat rather than each carrying its own copy.
- AC-STE-570.8: A remedy that names a skill is asserted to be typeable by whoever is told to run it: a test cross-references every skill named in a remedy literal against that skill's `user-invocable` frontmatter and reds when a `user-invocable: false` skill is named without the caveat. `/upgrade` is discovered through probe #69 rather than through the slash menu, which is exactly what the remedy should say.
- AC-STE-570.9: `/tdd` names the `/implement` phase that actually invokes it, asserted against the `## Phase` headings in `skills/implement/SKILL.md` rather than against a literal — so renumbering the phases reds the sibling that cites them.
- AC-STE-570.10: The `spec-research` citation resolves. `/spec-write` § 0b labels the spec-research seed as step 2.5, mirroring the deps-research label beside it, so the fork's statement about its parent is true. The edit is INLINE: `skills/spec-write/SKILL.md` sits at the NFR-1 cap, so the file's line count is asserted unchanged by this FR.
- AC-STE-570.11: Line counts are re-measured, not assumed. Every skill file this FR touches is measured before and after with the same counter `tests/skill-nfr-1-length.test.ts` uses, and the cap the assertion compares against is read from that test rather than restated — a shipped test in this repo was once found pinning a number one off from the cap it named.
- AC-STE-570.12: Falsifiability. AC.2, AC.4, AC.6, AC.8 and AC.9 are mutation-tested, and each mutation is first measured to return clean against unmodified code — these are checks that did not exist, and an assertion that would also pass on the old code proves nothing. Every mutation is routed through the throwing `mutate` helper.

## Technical Design

The general shape is the fix: every one of these is a statement about another file, and this repo has no reader that grades cross-references. That is why they drift while each skill's own suite stays green, and why the corrections here ship with readers rather than alone.

Four readers cover the six findings. Each takes the claim from the citing file and the truth from the cited one, so neither side can be edited into agreement with a stale copy of the other.

The two citation fixes assert against the cited structure, not the cited text: a phase renumbered is drift, a phase reworded is not.

## Testing

Every reader is exercised in both directions. A check that only reds when the citing file is wrong would pass if someone "fixed" the drift by changing the cited file's behaviour instead — which, for the fork-capability finding, would mean granting `Bash` to a deliberately read-only agent.

Each mutation is measured against unmodified code first. Five of these ACs add a check where none existed, and the only way to know such a check works is to watch it fail on the code that motivated it.

## Notes

`/ship-milestone`'s statement about `/docs`'s flags is the same class and is fixed in STE-566, which owns the findings that break a consumer. The sibling-flag reader built here (AC.6) and the docs-invocation reader built there overlap in intent; if the two converge on one module, this FR lands last and adopts it rather than shipping a second one.
