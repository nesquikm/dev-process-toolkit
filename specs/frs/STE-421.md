# STE-421: Replace raw-log capability-key greps with assistant-scoped assertions {#STE-421}

## Summary

The runtime fixtures check that a skill emitted its capability rows by searching the raw captured transcript for the row's name. That method is unsound in both directions, and it is load-bearing for four fixture groups plus an entire phase.

It produces false passes because the captured transcript contains far more than the skill's own output. When a child reads a skill document that happens to list the row names, those names land in the transcript as tool results, and the search finds them. On the 2026-07-27 run five separate rows read present this way on both legs while the skill had in fact emitted none of them — including two rows that are mutually exclusive by construction and cannot both be true.

It also produces false failures, because at least one fixture searches for a hyphenated spelling while the runtime emits the underscored one. A probe that fires correctly still scores as broken.

This is exactly the false-green class the runtime fixtures exist to prevent, which makes it the most self-defeating finding in the set.

## Requirement

Capability-row emission MUST be asserted against a machine-checkable projection of the child's own assistant output, never against the raw transcript, and every assertion token MUST match the form the runtime actually emits.

Measured 2026-07-27 on both legs' `/spec-write` capture, using the bundled `extractAssistantText` projection:

| key | raw hits (linear / jira) | assistant hits |
|-----|--------------------------|----------------|
| `spec_write_draft_default_applied` | 3 / 3 | 0 / 0 |
| `spec_write_commit_default_applied` | 3 / 3 | 0 / 0 |
| `branch_gate_default_applied` | 1 / 1 | 0 / 0 |
| `spec_research_no_matches` | 3 / 3 | 0 / 0 |
| `spec_research_invoked` | 3 / 3 | 0 / 0 |

Fixtures 1a, 5a and 6 would each have scored PASS on this run, where `/spec-write` refused and emitted nothing.

The dangerous direction is fixture 1b, which asserts a token is *absent* and reads presence as a marker-contract regression: on the marker-absent capture the token appears in assistant text as explanatory prose following a correct refusal, so the documented assertion reports a regression that did not occur.

The false-negative direction is fixture 3c, which greps `cross-cutting-spec-stale-file-refs` while the verdict block rendered `cross_cutting_spec_stale_file_refs` 8 times and the hyphen form 0 times.

## Acceptance Criteria

- AC-STE-421.1: Every Phase 2.X and Phase 9 capability-key assertion resolves its evidence through an assistant-text projection of the capture, not through a raw-transcript substring search.
- AC-STE-421.2: A regression fixture built from the 2026-07-27 `/spec-write` capture asserts that all five keys in the table above score ABSENT — the same capture on which the raw-log method scores them present.
- AC-STE-421.3: An absence-asserting fixture distinguishes an emitted capability row from the same token appearing in explanatory prose, so a correct refusal cannot be scored as a marker-contract regression.
- AC-STE-421.4: Every assertion token in the fixture set is verified against the token the runtime emits; the stale-file-refs fixture asserts the underscored form and fails if the runtime form changes.
- AC-STE-421.5: A skill run that genuinely emits its capability rows still scores PASS — the assertions are non-vacuous in the positive direction, not merely stricter.

## Technical Design

`extractAssistantText` already exists and is the projection the drivers should have been using; both legs of the 2026-07-27 run adopted it manually for their own analysis, which is how the discrepancy surfaced. The work is to route the documented fixture assertions through it and to correct the token spellings.

A stronger option worth weighing during implementation: have skills emit capability rows inside a machine-parseable envelope rather than as bare tokens in prose, so the assertion is a structured lookup instead of a substring search. That removes the prose-versus-emission ambiguity AC-STE-421.3 has to work around, at the cost of changing every emit site.

The minimum viable change is the projection swap plus the spellings; the envelope is the durable fix.

## Testing

- Unit coverage for the assertion helper over a capture where the token appears only in a tool_result payload (must score absent) and one where it appears in assistant text (must score present).
- A pinned regression fixture per AC-STE-421.2, using the real 2026-07-27 capture.
- A prose-versus-emission discrimination case per AC-STE-421.3.
- A positive-direction case per AC-STE-421.5 so the suite cannot pass by asserting everything absent.

## Notes

Recorded independently by both legs, which is unusual — the Jira leg filed it as a numbered high-severity finding and the Linear leg as a driver-side methodological caveat. It was re-measured a third time during loop-level aggregation before being written up here.

The general lesson generalizes past this FR: a grep against a transcript that contains the specification being tested can never be sound.
