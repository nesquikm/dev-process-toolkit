# One tool call written twice is read as one call

## Summary

The commit gate refused a commit after a valid test-driven run.
The session log held the run's skill call twice, once with a time and once without.
The gate read the copy as a second call, so the run's window closed before its receipt.
This fix reads every copy of one call as that one call.
Then the window stays open in both orders, and two real calls still split it.

## Requirement

### Steps to reproduce

1. Build a session transcript with a timed Skill tool_use for `dev-process-toolkit:tdd` (id `toolu_dup_01`), then an untimed copy of the same record with the same id on a later line.
2. After the copy, add the Bash call that runs the gate-receipt front door and its result announcing one `dpt-receipt:` line for a receipt that verifies.
3. Run `pre-commit-tdd-orchestrator` against a staged tree of source plus test files with that transcript.

### Expected

The commit is allowed: one call, one window, and the receipt is inside it.

### Actual

The commit is refused as `between-windows`. The untimed copy enters the line bounds and closes the call's own window before the receipt. With the copies in the reverse order the same transcript is allowed.

## Acceptance Criteria

- AC-STE-695.1: Regression: `tests/m_b1c081-ste-695-duplicate-tool-use.test.ts › a timed call followed by its untimed copy keeps the window open past the receipt` fails before the fix and passes after it.
- AC-STE-695.2: Skill tool_use records that share one non-empty id are one call. It takes the earliest transcript line of any copy and the timestamp of the first copy that carries a parseable one. A copy never bounds the window of its own id, by line or by time.
- AC-STE-695.3: The duplicate permits in both orders (timed first, untimed first), and a receipt announced between the two copies is inside the window in both orders.
- AC-STE-695.4: The refusal twin differs only in the defect: the same fixture with the second record carrying a different id still refuses as `between-windows`. Two distinct calls still split the window, and id-less calls are never merged.
- AC-STE-695.5: An `is_error` result for the id retires the merged call, whichever copy it follows. A call whose copies are all untimed still opens no window.
- AC-STE-695.6: Mint Bash tool_use records that share one id are one call at the earliest line. An unresolved duplicated mint is reported once in the incomplete runs, at that line.
- AC-STE-695.7: A mint's results are graded once per tool_use_id: the first result decides, and later copies add no announcement, no misread and no incomplete run.
- AC-STE-695.8: Removing the Skill-call collapse, merging id-less calls, keeping the latest line instead of the earliest, or grading a second mint result each reddens at least one named test.
- AC-STE-695.9: All three command gates that use the scan (commit gate-check, commit TDD, PR spec-review) read duplicates this way, and the session library keeps exactly one transcript file read.
- AC-STE-695.10: `bun test` from `plugins/dev-process-toolkit` reports 0 failures, and its skip identities equal the trunk baseline by name.

## Technical Design

### Root cause

`scanSkillCalls` in the session library pushes one call per record. Claude Code can write one tool_use twice, and the untimed copy keeps the id. `lineBounds` holds every call's line, so a later copy becomes the next bound of its own call.

The fix merges records by id before bounds, lineBounds and windows are built: earliest line, first parseable stamp, id-less records kept apart. The mint map keeps its first line per id, and a set of graded ids skips repeated results. Everything stays inside the existing read; no new file access.

## Testing

Unit tests over synthetic transcripts with fake ids and temporary paths drive the three command gates through their shipped hook entry points. Each AC gets a permit case and a twin that differs only in the defect, plus the mutation controls.

Origin: a field report against v2.101.0, 2026-10-26. It refutes the STE-619 belief that untimed calls are near-unreachable. Out of scope: the tracker-write gate's own reader repeats both mint twins; file it as a follow-up.
