# A retrospective can seed a bug report and travel with it to brainstorm

## Summary

A retrospective that finds a problem has no way into a bug report today.
The report command takes no input file and uploads at most three files.
This lets the report start from a saved retrospective.
Its findings become the suggested answers, and every question is still asked.
The retrospective rides along as a fourth file, and brainstorm reads it back.

## Requirement

### The flag

`skills/report-issue/SKILL.md` `argument-hint` becomes `'[--full] [--dry-run] [--redact-identifiers] [--from-retro <file>]'`, extending the STE-720 hint. The file must resolve, after symlinks, inside `<projectRoot>/.dpt/ledger/retro/` and pass `parseRetroReport` from `adapters/_shared/src/retro_report.ts` (STE-719). A report with `tripped_count` 0 has nothing to file. Each of the three failures is an NFR-10 refusal before the first prompt, with no temp directory created. Under non-tty stdin that refusal is the first-turn action the Socratic Loop Contract already allows.

### Suggested answers

New module `adapters/_shared/src/report_issue_retro.ts` exports `retroPromptDefaults(report)`, returning four strings, one per canonical prompt:

1. What happened: `<N> retro rule(s) tripped: <id> (<value> <unit>, threshold <threshold>)`, one clause per tripped rule.
2. Expected: `Every retro rule within its threshold.`
3. Severity: the report's `suggested_severity` (`low` or `medium`).
4. Reproducible: `Run /dev-process-toolkit:retro <scope id>.`

The four prompts are still asked, one at a time, in the canonical order, each as an `AskUserQuestion` call. The suggested answer is the first option, labelled `(from retro)`. The operator's answer always wins. The prompt texts, their order and the Socratic Loop Contract are unchanged.

### Payload

- § 6 becomes four files maximum: `report.md`, `metadata.json`, `transcript.jsonl` (full mode only), `retro.json` (`--from-retro` only, a copy of the input file).
- Under `--from-retro` the skill calls `report_issue_payload.ts` with `--from-retro`, so the identifier pass of STE-720 always runs over every payload file, `retro.json` included, with or without `--redact-identifiers`. Before it scrubs, the front door seeds its alias map from the `sessions` list of `retro.json` with `seedAliasMap` (`session_aliases.ts`, STE-719). A session the retro report calls `s1` is then `s1` in every payload file, matched by `sessionDigest`, and a session it does not name takes the next free number.
- `metadata.json` gains `retro_included: true` under `--from-retro` only. Without the flag the key is absent, so a default `metadata.json` keeps its v3.0.0 key set; a reader treats an absent key as false. `report.md` keeps its five sections; `## Curated Context` gains one line naming `retro.json` when included.
- The `gh gist create` line in § 8 gains `[retro.json]`, present only under `--from-retro`. The closing-summary file-list rationale reads three files maximum without the flag, as today, and four with it.

### Capability row

`report_issue_retro_seeded` fires when `--from-retro` seeded the run. It is added to `CANONICAL_CAPABILITY_KEYS` and `KEY_OWNER_SKILL` in `closing_summary_capability_keys.ts`, and to the report-issue row of the `/spec-write` § 7 map. That row is extended in place, so `skills/spec-write/SKILL.md` gains no line and no `STE-<n>` token (it sits at the 358-line cap in split-lines, 357 by `wc -l`, and six tests pin its 358 split-lines, several also its 54 tokens; the M_d1b4b7 line budget names them).

### Brainstorm intake

`skills/brainstorm/SKILL.md` § 0 fetches `retro.json` with `gh gist view <id-or-url> --raw -f retro.json` when `retro_included=true` in `metadata.json`; an absent key fetches nothing. It treats the tripped rules as part of the seed.

## Technical Design

The defaults and the input check are code, so tests grade them; the skill prose only says where they enter the existing flow. The path rule keeps the flag from uploading an arbitrary file. The fourth file reuses the STE-720 front door, so no second scrub path exists, and the seeded alias map keeps its session aliases consistent. Brainstorm needs one fetch line, because its seed parsing is already free-form.

## Testing
