# Recorded decisions, docs and test pins follow settings to their new home

## Summary

Many recorded decisions and documents still name CLAUDE.md headings as the home of project settings.
This change adds dated supersession notes to each decision the move reverses.
It rewrites the documents that state the old home, and the schema stability rule.
Tests that pinned generated CLAUDE.md headings move to the settings file.
The release is a major version, as the stability rule requires.

`specs/requirements.md` NFR-2 gains an amendment with five clauses. From v3.0.0 project settings live in `specs/settings.yaml`. The CLAUDE.md headings are a read-only legacy home through 3.x, and the legacy read is removed in 4.0. Absence of `task_tracking` in the settings file, or of `## Task Tracking` on a legacy tree, is canonical `mode: none`. A missing heading on a settings-file tree never means `mode: none`. Through 3.x a settings-file tree in a tracker mode carries a generated binding stub in CLAUDE.md for pre-3.0 hooks; 3.x never reads it, and its removal is scheduled for 4.0.

`docs/patterns.md` "Why the section heading is the single probe anchor" gains the same kind of note, naming the front door of STE-708 as the anchor.

### Test pins

Each FR rewrites the pins its own change turns red, since every FR's full-suite AC must hold on its own commit: STE-710 owns the template pins, STE-708 the Schema L prose pins, STE-711 the registry pins. This FR owns the pins on the docs it rewrites and a final sweep. Tests whose fixtures are legacy trees stay unchanged, because the legacy home is still read. A test that reads this repository's own CLAUDE.md for a moved setting is rewritten to read through the loader, so it holds before and after the dogfood migration. Budget: at drafting about 74 test files pin `## Task Tracking` and about 160 reference CLAUDE.md; most build legacy fixtures and should need no edit.

### Defaults unchanged

Operator rule, 2026-11-04: the milestone changes no toolkit behaviour by default; only the config home moves. This FR owns the milestone's proof, `tests/m_94e6f7-defaults-unchanged.test.ts`. It runs two fixtures, each pinned against literals captured from v2.101.4: a tree with no settings file (one legacy, one unmanaged), and a tree whose settings file holds only moved keys. It compares the readers' values, the shipped hook wrappers' exit code, stdout and stderr, `upgrade_offer.ts`, and the probes of STE-709. Two differences are allowed and listed in the test: a citation or remedy naming `specs/settings.yaml`, and probe #69's warn-only `settings-file` row on an unmoved managed tree. A legacy tree whose only tracker heading sits inside an HTML comment is one of the no-settings rows, with no allowed difference (AC-STE-706.5, AC-STE-708.12).

## Technical Design

Notes are appended, never rewritten into the original AC text, so each archived decision still reads as it was made. One test reads the archived files and checks every row.

The config-home scan is line-scoped with a legacy escape, so a doc can still describe the fallback.

Test pins follow the subject rather than the bytes. A pin on the generated layout moves to the settings file, and a legacy fixture pin stays.

All gate-check edits land in one commit, then one reviewed re-base, as the freeze ruling allows.

## Testing

Per-row supersession reads, the NFR-2 clause check, the config-home scan with a control, the rewritten template pins against pre-change bytes, and the freeze test on the re-base commit.
