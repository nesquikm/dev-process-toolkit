# An opt-in capture hook records each Bash and Skill call as a privacy-safe row

## Summary

The session log cannot say what the working tree looked like when a call ran.
This adds an opt-in hook that writes one small row for each Bash or Skill call.
Rows carry a call class, a toolkit skill name, content hashes and counts.
They never carry command text, file paths, the working directory or branch names.
The hook is off by default, stays fast, and never blocks a call.
No gate reads its rows.

## Requirement

Timestamps and error flags come from the transcript (STE-717). A live hook is justified only for what the transcript cannot hold: the tree state at call time, the staged diff size at a commit, and rows that outlive transcript cleanup. This FR adds that hook and nothing more. Where it says "per D<n>", it implements the branch the STE-714 decision table names.

### Setting

`specs/settings.yaml`, read through the M_94e6f7 settings loader:

```yaml
tracking:
  tool_calls: { enabled: false }   # enabled: true | false; absent means false
```

`loadProjectSettings` (`project_settings.ts`, M_94e6f7) gains `tool_calls` (closed key set `{enabled}`, the same shape as `token_stats`) in the closed key set of `tracking`; an `enabled` value outside `true`/`false` throws `SettingsShapeError`. A legacy-only or settings-less tree reads `false`, since no legacy home carries the key; the CLAUDE.md binding stub that M_94e6f7 generates holds no `tracking` key either. Writers write to the home `loadProjectSettings` reports. `/setup`, through `writeProjectSettings`, writes `tracking.tool_calls: { enabled: false }` beside `tracking.token_stats` in `specs/settings.yaml`; on a legacy tree no legacy home gains the key, which reads `false` until /upgrade moves the tree, and `docs/settings-reference.md` documents the key, its type, its default and "no legacy home". The hook treats every read error as off.

### Registration

`hooks/hooks.json` gains `"${CLAUDE_PLUGIN_ROOT}"/templates/hooks/process/tool-call-capture.sh` under PreToolUse and under PostToolUse, matcher `Bash|Skill` (or one `Bash` and one `Skill` entry per event, per D4), each with `"timeout": 2` (seconds). The wrapper is `exec bun run "${CLAUDE_PLUGIN_ROOT}/templates/hooks/_lib/hooks/tool-call-capture.ts"`, like `session-token-ledger.sh`.

### Fast path

The entry module statically imports only Node built-ins and `../session.ts` (`parseHookPayload`). It finds the checkout by walking up from `payload.cwd` to the nearest directory holding a `.git` entry, with no child process. When that directory has no `specs/settings.yaml`, it exits 0 at once. Otherwise it loads `project_settings.ts` by dynamic `import()`, reads the flag, and exits 0 when off. `dpt_paths.ts`, `commit_target_repo.ts`, `pr_target_repo.ts`, `gate_receipt.ts` and `gate_reuse_key.ts` are loaded by dynamic `import()` only after the flag reads true. A flag-off run spawns no child process.

### Row — schema `tool-call/v1`, one JSON line per hook event

Path: `toolCallLedgerPath(root, sessionId)` = `<root>/.dpt/ledger/tool-calls/<sessionId>.jsonl`, a new composer in `dpt_paths.ts` that calls `assertPathSafeSessionId`. Under `ledger/`, so `DPT_GITIGNORE_BODY` (`setup/dpt_gitignore.ts`) needs no new rule.

Closed key set:

| Key | Value |
|---|---|
| `schema` | `"tool-call/v1"` |
| `event` | `"pre"` or `"post"` |
| `tool_use_id` | the payload's `tool_use_id`, or `null` |
| `tool` | `"Bash"` or `"Skill"` |
| `class` | Bash: `commit` (`resolveCommitTargetFromPayload(payload).isCommit`), `pr-create` (`resolvePrTargetFromPayload(payload).isPr`), `gate-receipt` (`announcesGateReceipt` or `runsGateOutcome`, both from `gate_receipt.ts`), else `other`. Skill: `skill` |
| `skill` | Skill calls only: the skill name when it starts with `dev-process-toolkit:`, else `"other"`; `null` for Bash |
| `ts` | the hook's own ISO wall-clock |
| `tree` | `worktreeDigest` of the session checkout, only on `pre` of a `commit` Bash call and on both events of a Skill call; else `null` |
| `diff` | `{ files, insertions, deletions }` summed from `git diff --cached --numstat` in the commit's resolved target checkout, only on `pre` of a `commit` call; `null` when unresolvable or otherwise |
| `scope` | `"main"`, or `"fork"` when D1 found a distinguishing field and it marks the call |
| `exit_code` | present only when D2 found one: the PostToolUse Bash exit code |

The session id lives in the file name only. No raw `tool_input`, `tool_response`, `description`, `cwd`, path or branch is written.

### Behaviour

Every run exits 0 with empty stdout and stderr: flag off, malformed stdin, no checkout, unsafe session id, a git failure or an unwritable ledger all write nothing and stay silent. Each row is one `appendFileSync` of one line.

## Technical Design

One entry module for both events, branching on the event name. The flag check comes first, so a consumer who never opts in pays only process start and one small file read. Classification reuses the commit and pull request front doors the gates use, so a commit is recognised the same way everywhere. Git work runs only on commit and Skill calls, where tree state is the point. Rows append to a per-session file, which avoids cross-session write contention. Failure is silent, and the gaps it leaves are counted by the timeline reader.

## Testing

Wrapper-driven subprocess tests over temp repos, a marker-module import check, a planted-identifier privacy test, a latency suite, an Out of Scope needle test and mutation controls.
