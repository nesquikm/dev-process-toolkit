# Correct the tracker-less plan/FR id equality clause — it is unsatisfiable in general

## Summary

A Phase 4 verify row demands the milestone plan's minted identity be byte identical to the FR's. Two consecutive mints differ in their final character, and a milestone containing two FRs cannot be byte identical to both. The clause is unsatisfiable in general, not merely near missed on one run.

The shipped enforcing contract requires only that a plan derive its own filename from its own recorded identity, and that self derivation held on both artifacts of the live run. The criterion is wrong and the code is right.

This was never executed live before the 2026-08-08 conformance run, which is why it survived authoring, review and audit inside its own milestone.

## Requirement

Delete the equality clause from the acceptance criterion and from the Phase 4 verify row, keep the self derivation half verbatim in both, and re anchor the enforcing pin onto the surviving half rather than deleting it.

## Implementation notes

Baseline owned before any edit: **6955 pass / 15 skip / 0 fail**. Final: **6972 / 15 / 0**.

### The correction contained the defect it was correcting

The AUDIT stage found it, and it is the finding worth the whole FR. Deleting the equality clause left the row's opening path intact: *"The plan lands at `specs/plan/M_<TAIL>.md`"* — and `<TAIL>` is bound by the AC-STE-448.7 row **directly above** as the FR's filename stem.

Under the deleted clause that path was coherent, because equal ids implied equal tails. With equality gone, the row's own next clause says the plan mints independently, so **the path contradicted itself three clauses later** and directed the operator to a filename a healthy run does not produce. On the run that prompted this correction the FR is `3Y2FQW.md` and the plan `M_3Y2FQV.md`.

So a row rewritten specifically to stop stating a rule no run can satisfy went on stating one, in its first sentence, through the whole RED → GREEN → REFACTOR cycle. **This FR's own test pinned the wrong literal** (`toContain("specs/plan/M_<TAIL>.md")`) as a must-not-be-taken-with-the-edit guard, so the defect was actively held in place by the correction's own guard. Rebound to `<PLAN-TAIL>` with a clause defining it against the plan's own id, the difference from the FR's tail stated as expected rather than exceptional, and the pin moved onto the rebound form **plus a ban on the stale one** — a ban alone is satisfied by deleting the path entirely.

The `not a duplicate of the row above` connective was stranded by the same deletion: with equality gone, the reason offered applied verbatim to AC.7 and proved too much. The real distinguisher is the **artifact**, not the property, and the row now says so.

### An assertion that could not fail, in the FR about assertions that cannot fail

AC.7's "the corrected rule passes" half was tautological. `writePlan` named files with `milestoneIdFromUlid(id)` and `selfDerives` re-derived with the same function — same function on both sides, so every `expect(selfDerives(...)).toBe(true)` was unfalsifiable for any state of the toolkit. STE-448's § Audit findings names this exact shape, in this milestone.

Closed with a negative control: a plan whose FILENAME derives from one mint while its recorded `id:` is another — the "counter, another mint, a stale rename" the row itself warns about. Mutation-verified: forcing `selfDerives` to return `true` now reddens AC.7, where before it changed nothing.

### Two guards that lived in the wrong suite

AC.3's real requirement — anchored onto the *surviving* half — was enforced only transitively by AC.6's distinguishing mutation in a different describe. An anchor on `Recompute the stem…` is unique, sits inside the row, and satisfies every AC.3 assertion while guarding the wrong sentence. Now asserted locally. And `pinAnchor` took the FIRST regex match; a second occurrence-count pin added earlier would have silently redirected every AC.3 and AC.6 measurement onto it. Now requires exactly one.
