# The target-repo sweep admits a plan that actually declares one

## Summary

A milestone plan can declare which repository its work belongs to, and the toolkit routes on that declaration. But the suite that guards the feature asserts that no real plan on disk declares one, so the first genuine use turns the gate red. The capability ships and its own test forbids anyone from using it.

## Requirement

The non-regression sweep in `tests/m129-ste-495-target-repo.test.ts` walks every plan file on disk — `specs/plan/` and `specs/plan/archive/` alike, via its own `allPlanFiles()` — and asserts each one's `readTargetRepoDeclaration` reports `declared === false`. Every positive case in that suite is a synthetic fixture; nothing exercises a real declaring plan, and nothing can, because the sweep forbids one existing.

Measured 2026-09-16: writing the first plan that declares a target repository turned the suite red, and the sibling meta-test `AC-STE-582.8` — which asserts that suite exits with zero failures — failed with it. Two failures, one cause, and the cause is a correct use of a shipped feature.

The sweep is asserting the wrong invariant. What it should protect is that an UNDECLARED plan routes to the invoking repository and never goes looking for another tree, which is the behaviour the declaration was added without disturbing. It should not assert that the declaration is unused.

## Acceptance Criteria

- AC-STE-600.1: The sweep asserts that every plan declaring no target repository routes to the invoking repo with the full chain, and that the probe is never consulted on that path. That invariant survives unchanged.
- AC-STE-600.2: A plan that DOES declare a target repository is admitted by the sweep rather than failing it, and its declared routing is asserted rather than skipped.
- AC-STE-600.3: The sweep still fails when an undeclared plan routes anywhere other than the invoking repo, proving the rewrite did not weaken it into a tautology.
- AC-STE-600.4: The sibling meta-test asserting the target-repo suite exits clean passes without being edited, because the suite it grades is genuinely green.

## Technical Design

Partition rather than forbid. The sweep splits the plan list on the declaration it already reads, asserts the undeclared group routes to the invoking repo with the probe never consulted, and asserts the declared group routes as declared. The existing count assertion covers both groups together so no plan silently escapes the walk. No production module changes — the routing code is correct; only the test's premise is wrong.

## Testing

The rewrite must fail on a mutant. Pin it with a fixture whose undeclared plan routes somewhere other than the invoking repo, which the rewritten sweep must still reject — AC.3 exists so the partition cannot be satisfied by a sweep that asserts nothing about either group. Run the sibling meta-test unedited as the second signal.
