# Token rows are claimed by the FR whose run produced them

## Summary

Today only a small share of the token ledger is claimed by an FR.
One session often works on several FRs, so its rows are shared.
The ledger hook now splits a session's rows at each recorded run start.
It claims each part for the FR of that run.
These claims are settled, so a later claim never moves them to the shared design bucket.
A session with no recorded run start is written exactly as before.

## Requirement

The token-ledger capture attributes each assistant message to the run that produced it, using the STE-810 run-start rows, and writes claimed rows per (skill, model, FR) so claim coverage rises without changing any token total.

## Acceptance Criteria

- AC-STE-811.1: The ledger hook attributes each usage-bearing transcript line to the latest run-start row of the same session and the same skill whose `started_at` is at or before the line's `timestamp`. The line's FR is that row's `fr`. When that is `null`, it is the `fr` of the latest run-start row of the session, of any skill, with a non-null `fr` and a `started_at` between that row's start and the line. `(main-loop)` lines, and lines with no such row, are unattributed.
- AC-STE-811.2: The hook writes one row per (skill, model, FR) for attributed lines, with `claimed_by: <FR>` and `claim_source: "run"`, and one row per (skill, model) for unattributed lines, written as today. For every (skill, model), the four token sums and `message_count` across the session's rows equal today's single-row values.
- AC-STE-811.3: `filterRowsForFR` treats a row with `claim_source: "run"` as settled. It is selected for its own FR and never demoted to the design bucket. It is never selected or re-claimed for any other FR, including when its session is in that FR's lineage.
- AC-STE-811.4: The STE-698 carry rule applies to unattributed rows only. Re-running the hook on the same transcript and run-start rows yields the same ledger bytes.
- AC-STE-811.5: For a session with no run-start rows, the hook writes rows byte-equal to the rows it writes today.
- AC-STE-811.6: `bun run adapters/_shared/src/claim_coverage.ts <projectRoot>` prints one line `claimed=<n> total=<m> output_tokens_claimed=<a> output_tokens_total=<b>` over the ledger, counting a row as claimed when its `claimed_by` names an FR (the design bucket excluded).
- AC-STE-811.7: `docs/retro-reference.md` describes the attribution rule and the settled-claim rule.
- AC-STE-811.8: `bun test` from `plugins/dev-process-toolkit` reports 0 failures, and its skip identities equal the trunk baseline by name.

## Technical Design

Add `parseTranscriptTokenUsageByRun(transcriptPath, starts)` to `token_usage.ts`, built on the same line walk as `parseTranscriptTokenUsage`, which becomes the zero-starts case. `TokenLedgerRow` gains optional `claim_source: "run"`. `writeSessionRows` carries prior claims only onto rows without a fresh `claimed_by`. The hook reads `readRunStarts(root, session)` from STE-810 before parsing. `filterRowsForFR` skips foreign `claim_source: "run"` rows before the lineage branch. The hook reads run starts through a light `run_start_ledger.ts` (built-ins only), so the STE-717 fast path still loads no snapshot module.

## Testing

Fixture transcripts with timestamps and run-start rows: two `tdd` runs for two FRs in one session, an `implement` run with a null FR that inherits from a later `tdd` start, a pre-B session, and a re-fire. A claim test shows a run-claimed row surviving a second FR's lineage claim.

## Notes

Coverage before this release, measured on this repo's ledger on 2026-11-16: 27 of 918 rows claimed.
